# 評価資料

`python -m noema dataset` で `evaluation.jsonl` を再生成する。学習器より先に定めたテンプレートと種41に基づく資料で、ファイル本体は再生成可能なためGit管理外とする。`challenge.jsonl` は別に手書きした42例で、学習・エポック選択には用いない。再生成元は `noema/challenge.py`。

各行の `text` は原文、`language` はja/en、`supported` は対応範囲、`graph` は正解意味構造。`spans` はPython文字インデックスによる半開区間 `[start,end)` の注釈で、UTF-8バイト位置やUTF-16の位置ではない。`group` は日英・言い換えの同じ意味を表す単位。`combination` は述語と実体の組合せ、`pattern` はテンプレート族を識別する。

同じ概念組合せ、意味グループ、テンプレート族、同一原文を異なる分割へ入れない。基本は学習60%、検証20%、最終評価20%の組合せ割当で、一部の文型が作れない組合せは除外する。学習は基本語順、検証は受動文または場所の前置、最終評価は対象または時間の前置を含む。省略された主体は主に学習と手書き例で確認する。日英の文型は完全に同じ構文範疇ではなく、個別の資料である。

現在の生成資料は6,322例。学習3,944例、検証1,256例、最終評価1,122例で、日英は同数。未対応例は各言語で学習4、検証4、最終評価7例だけなので、未知入力全体を代表する資料ではない。対応例も組合せを展開した人工文であり、独立した6,000件の人手収集データと同等には扱えない。

現在の学習注釈で明示数量は2だけ、名前はAkiだけ、時間は未指定・今日・明日だけとなる。数量3と未見のHanaは手書き例に含め、未学習値での失敗を測る。数量ヘッドの候補は未指定と0〜10、時間ヘッドには時制や昨日もあるが、候補の存在は学習済みであることを意味しない。形式言語側は非負整数と任意の名前を扱えるため、直接記述の範囲と自然言語解析の精度を分けて評価する。

トークナイザーの1サブワードが述語と否定接尾辞をまたぐ場合、トークンの範囲ラベルは述語を優先する。否定の正解は独立した文分類として保持する。原文の注釈自体は変更しない。2つの実体・述語を1トークンへ割り当てざるを得ない注釈は学習時にエラーとする。

資料中の名詞・動詞表とテンプレートは、正解付きデータの作成にだけ使う。推論時の個別補正規則として利用しない。自然文を追加する場合は、先に注釈・分割を確定し、評価済みの最終評価資料へ合わせたモデル選択を避ける。
