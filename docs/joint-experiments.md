# 共同役割割当てと学習資料の拡張

役割を各対象で別々に選ぶと、主体が2個になり、文全体として成立しない出力が生じた。新しい復号処理では、学習した役割の確率と文の役割構成を使い、型が成立する全割当ての中から最も確率が高いものを選ぶ。割当てが同率なら未確定にする。対象を補ったり、予測した役割構成を変更したりはしない。

確信度には、成立する割当て間の相対確率だけでなく、元の役割確率も残す。制約によって候補が1個になっただけで確信度を1に上げない。数量の対象は引き続き学習した関係分類器で選び、共同割当てで決まった対象の役割へ結び付ける。数字列の一部だけを数量として取り出した場合も棄却する。

## 復号処理だけを変更した比較

既存のv4重みを固定したまま、新しい処理を開発資料で再校正した。その後、すでに失敗分析に使ったcorpus-v2の旧最終評価を回帰資料として測定した。[全結果](../reports/joint-v5.json) に開発・回帰の値を保存した。

| 入力モデル | 言語 | 回帰資料の確定率 | 確定出力の完全一致率 |
|---|---|---:|---:|
| XLM-R | 日本語 | 78.57% | 99.83% |
| XLM-R | 英語 | 74.10% | 76.25% |
| MiniLM | 日本語 | 89.29% | 81.04% |
| MiniLM | 英語 | 85.09% | 83.53% |

確定率は上がったが、英語では誤った役割を確定する件数も増えた。制約を満たす割当てが、原文の正しい意味とは限らない。この結果だけでは新しい処理を標準採用できないため、旧v4の復号処理・重み・選択記録を保持し、新版とは別に実行できるようにした。

## 学習資料の拡張

既存の学習用組合せから11,640件を追加した。数量は1桁から5桁へ広げ、12種類の新しい名前を用いた。肯否・時間・数量・態の選択を独立に抽選し、対象を先に置いた文と括弧付きの場所句も含めた。これらは学習資料の作成規則であり、解析器には読み込まない。

開発用・回帰用の文章と正解は変更せず、分割ごとのハッシュが一致することを確認した。追加例でも実際の注釈付き表面形を比較し、保留分割の構文パターンや概念の組合せを学習へ混ぜない。固定した名前や数量は [マニフェスト](../reports/corpus-v2-augmented-manifest.json) に記録した。

全22,362件について、文字範囲と概念・役割・数量・固有名が正解構造と整合すること、同義グループの正解が一致することを [内部監査](../reports/corpus-v2-augmented-audit.json) で確認した。この監査だけでは、日本語や英語の文自体が正解の意味を表すかは証明できない。

```powershell
python -m noema.augment --output artifacts/corpus-v2-augmented.jsonl --manifest reports/corpus-v2-augmented-manifest.json
python -m noema.annotation_audit artifacts/corpus-v2-augmented.jsonl
python -m noema features --dataset artifacts/corpus-v2-augmented.jsonl --model minilm --output artifacts/corpus-v2-augmented-minilm.pt --offline --batch-size 32
python -m noema.train_structured --dataset artifacts/corpus-v2-augmented.jsonl --features artifacts/corpus-v2-augmented-minilm.pt --epochs 30 --decoder joint-v1 --regression-test --output artifacts/joint-v6-minilm
```

XLM-Rも同じ条件で比較する。基盤モデルは固定したまま、分類器だけを学習する。以前のモデルや資料を上書きせず、別の出力先を使う。新しい確認評価については、予測を取得する前に [固定条件](confirmation-protocol.md) と [そのハッシュ](../reports/confirmation-protocol-record.json) を記録した。実行結果は以下に記載する。

## 拡張資料での30エポック学習の結果

両モデルの学習を完了し、開発用成績だけに基づいて日本語はXLM-Rの20エポック時点、英語はMiniLMの30エポック時点を選んだ。[選択記録](../reports/routed-v6-selection.json) の重みと閾値は、新しい確認評価を行うまで固定する。開発用では日本語402/410件、英語764/775件を確定し、確定出力はどちらも全件正解だった。

| 言語 | 旧最終評価＝回帰資料 | 確定率 | 確定出力の完全一致率 | 未対応の誤確定 |
|---|---:|---:|---:|---:|
| 日本語 | 756件中749件確定、749件正解 | 99.07% | 100.00% | 0 / 109 |
| 英語 | 892件中884件確定、884件正解 | 99.10% | 100.00% | 1 / 116 |

同義グループ894個のうち全例が確定した741グループでは、意味構造もすべて一致した。これは [回帰集計](../reports/routed-v6-regression.json) の結果であり、失敗分析に使った資料の再測定を独立した最終評価とは呼ばない。全候補の成績・選択エポック・実行環境は [モデル別報告](../reports/joint-v6.json) に残した。

別の [手書き回帰資料](../reports/routed-v6-hand-regression.json) では、日本語は14件中12件が確定し、正解は11件だった。「猫が犬に追われる」の主体と対象が逆転した。英語は14件中13件が確定し、13件とも正解だった。日本語の「猫を追う」、句点なしの短い文などで未確定も残る。学習資料の受動態が主に「によって」を使い、主体省略を受動態で表している偏りがあるため、これらの違いを含む一般的な文型の検証と改善が必要になる。

実際の `Analyzer` でもモデルの固定・評価モードと反復一致を確認した。現在の実験構成は次のように実行できる。

```powershell
python -m noema analyze --checkpoint artifacts/routed-v6 --language ja --text "犬が猫を追う。" --offline
```

この回帰成績の改善によって、言語全体の完成、任意の自然文への対応、利用者による読み書きの検証を済ませたことにはしない。

## 予測前に固定した確認資料での結果

モデル・閾値・言語別の選択を固定したまま、新しい300種類の意味を日英それぞれ2通りで書いた1,200文と、未対応144文を評価した。資料は人の自由記述ではなく、事前に指定した構文による人工文である。旧回帰資料で使った概念の組合せを含むため、意味の組合せまで完全に未知という条件でもない。作成後の文の点検は [記録](confirmation-v1-review.md) に残し、予測取得前の [資料ハッシュ](../reports/confirmation-v1-manifest.json) と一致する入力を使用した。

| 言語 | 確定／対応範囲内 | 確定率 | 正解／確定 | 完全一致率 | 未対応の誤確定 |
|---|---:|---:|---:|---:|---:|
| 日本語 | 552 / 600 | 92.00% | 551 / 552 | 99.82% | 4 / 72（5.56%） |
| 英語 | 394 / 600 | 65.67% | 391 / 394 | 99.24% | 0 / 72（0.00%） |

**確認評価は不合格だった。** 英語の確定率が80%を下回り、日本語の未対応誤確定率も追加条件の5%を超えた。英語では、主語と動詞の間に場所句を挿入した131文のうち確定は19文にとどまった。日本語の未知概念の誤確定は、熊・象・鹿を含む4文で生じた。確定出力の誤りは日本語の否定1件、英語の時間3件だった。

[全集計](../reports/confirmation-v1-result.json) に層別成績・実行環境・重み・閾値を保存した。全4文が確定した同義グループは110組、そのうち109組の意味構造が一致した。両言語6文ずつの反復と単独／一括実行の意味一致、および全確定出力のNoema往復を検査した。

この結果を見た後の改善に対して、この資料は回帰資料となる。閾値を動かして今回の確認結果を置き換えない。次の実験では、一般的な場所句の挿入、句点の有無、日本語受動態の「に」、主体を省いた能動文を学習資料へ追加する。未知概念は文単位の未対応ラベルに加え、実際の範囲へ既存の「概念なし」クラスを教える。これらの作成規則や未知語一覧を推論時には読み込まない。
