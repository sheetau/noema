# 原文を保つ文字モデルの位置対応

公開コーパスの開発512文書中4文書が、「…」のNFKC展開で文字位置を保てず失敗した。原文そのものを書き換えず、文字モデルの正規化後の各位置と、元の文字範囲を対応付ける。

固定した文字モデルと語モデルの重みは変更しない。文字モデルには既存と同じNFKCの文字ID列を渡し、原文に直接書かれた単一文字の追加トークン（現在は空白）も保持する。原文内の`[MASK]`等は文字列として扱い、モデルの制御トークンに変換しない。モデル自身のCLS・SEPだけを別に付加する。元の変換器は比較と再現のため保持し、新しいアダプターから利用する。

位置対応はUnicodeの正規化だけから作る。正規化した接頭辞を順に比較し、変更された末尾の文字に原文の範囲を割り当てる。範囲が重なる出力文字を一つのまとまりに統合し、原文全体を重複・欠落なく覆うことを検査する。展開・合成・結合文字の並べ替えを含め、原文の単位を途中で分割しない。

まとまりの先頭に対応するモデルの分割ラベルを、原文のまとまりの先頭へ戻す。まとまり内部には新しい文・語境界を作らない。原文の全ての文字をそのまま保持して後段へ渡す。語の名前、句読点ごとの意味補正、参照先の正解は使わない。

最初に位置対応の単体検査を行う。続いて前回と同じ開発512文書を全て解析し、前回成功した508文書との出力差分、失敗4文書の回復、同じ定義での参照評価を報告する。先頭8文書と回復4文書は反復一致を検査する。文字IDが変わらない場合は文字モデル出力の一致も確認する。

展開・合成・結合文字・全角文字・空白・未知文字・特殊トークンに見える原文を別の合成入力で検査する。これは原文保持の検査であり、入力の意味を正しく解釈できた証拠とはしない。資料・モデル・コードのハッシュ、Unicode版、生成・辞書の禁止経路0回を保存する。学習・閾値調整・test分割の評価は行わない。

初回の実行では512文書の予測後、合成入力の全角空白で語モデルの処理が停止した。語トークナイザーが語を空出力にすると、上流のバッチ処理が語番号の末尾を切り落とすためだった。初回の予測・ログ・コード版を保持し、符号化されなかった語だけをモデル既定のUNK一つに置く処理を追加する。原文の語は変更せず、既に符号化できた語のトークン列が変わらないことを検査する。語別・空白文字別の変換表は用いない。修正後に全512文書と合成入力を再実行する。
