# 同じ核から複数の引数を読む

## 構成規則

既存の引数・量化・引用・共有の意味を再利用する。追加するのは、一つの適用の複数引数を別の枝へ配置する表記規則であり、新しい意味関係ではない。

引数が二つ以上ある語では、従来の `side_slot` を最初の枝位置とする。最後の状況引数があればその位置、なければ中央の引数位置である。この位置以外で最初の引数を、本文の続きに残す位置として確保する。残りの位置を元の引数順に並べ、最初の枝位置の後へ付ける。

枝がk本なら、この公開順序の先頭k個の引数を枝で読む。他の引数は元の順序で本文の続きから読む。任意の引数を選んで枝に移すことはしない。枝数は0から引数数−1までであり、最低一つの引数を本文の続きに残す。例えば三引数で状況型がなければ枝順は第2、第3引数となり、第1引数は本文に残る。状況型が第1引数なら枝順は第1、第3引数となり、第2引数が本文に残る。

各核から先の線を、次の主円に到達するまでたどる。途中で線が分岐する場合も、同じ核に属する経路として全てたどる。到達した主円のx座標を比較し、最も右の経路を本文の続き、それ以外を左から順に引数の枝とする。入口のx座標が同じ場合は拒否する。接続全体を木として検査するため、別の経路との再合流や輪は許可しない。各枝の内部にも同じ規則を適用する。

描画では、円の別々の接続口に加え、その核から既に出ている線の途中も分岐候補にする。新しい線と既存の線の接触は分岐の始点に限り、その先で再び触れることを禁止する。円周から曲がり・分岐までの距離と、矢印形を作らない制約は共通の幾何検査に従う。

複数枝の配置では、一つの複合語を末尾まで配置してから別の枝へ移る。枝の入口だけを先に並べると、語の続きが通れなくなるためである。枝の内部に別の枝がある場合は、内側の枝から配置を完了する。いずれも配置の探索順であり、読み方や意味を変える規則ではない。

線の候補は、それ自体が適法なだけでなく、未配置の経路の次の円へ接続できることを確認してから選ぶ。最初の候補が他の接続を塞ぐ場合は、同じ円の配置で別の線を試す。回り道には既存の円と線の両方を障害物として使い、外側の罫線から45度の線で迂回して戻る。横線の位置を三本の罫線の外へ広げたり、線の交差・再合流・円への斜め入射を許可したりはしない。この先読みは次の円までの確認であり、任意の長さの文を必ず配置できるという証明ではない。

構文は元の引数順で再帰的に読むため、図上の枝の左右順が束縛変数の命名順を変更しない。引用に入る際の環境のリセットと、各枝をちょうど一式として全て読む規則を維持する。共有頭 `and_shared` は同じ終端対象を表す一本の枝だけを取る。

## 配置できない場合

複数枝を置けないときは、枝順の末尾から一本ずつ本文の続きへ戻す。前方の枝を残したまま途中の引数だけを抜くことはしない。配置上の縮退は記録し、構文や参照先の変更とは区別する。円の配置、線の入射・間隔、中心線、再合流の禁止を緩和しない。

## 確認する境界

最初に三引数・二枝を実図形で確認し、引数の交換、型から決まる異なる枝順、引用、束縛、枝の不足・余りを区別する。生成器のイベント情報を復号へ渡さず、保存SVGから読む。旧一本枝の読み方も保持する。本文への適用と外観評価が済むまで、複数枝が配置できることだけで完成・固定とはしない。

四引数・三枝も確認する。検査用の型位置の定義と四引数の定義は既存のabove・give・redから作り、新しい意味primitiveを追加しない。

試作の描画は `compile_statement(..., multiple=True)` で選択する。旧既定は保ち、新読取器は両方を読める。幾何読取の `multiple_branches=True` では全枝を `branch_groups` で返し、一本目だけを全体と誤認しないよう旧 `branches`・`side` 欄は返さない。
