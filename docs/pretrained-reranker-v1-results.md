# 既存の関連度分類器を追加学習なしで使った結果

学習済みの関連度分類器を、そのままNoemaの概念照合に使う実装を追加した。対象語だけの入力では日本語15/19・英語10/19、原文全文では日本語8/19・英語11/19だった。Noemaの語別学習や生成なしに照合は動くが、関連する物体や場所を出来事の意味と取り違える問題が残った。このまま翻訳器へは採用しない。

## モデルと入力

[事前条件](pretrained-reranker-v1-protocol.md)を固定し、[BAAI/bge-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3/tree/953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e)を使った。二列の文章から関連度を返す`XLMRobertaForSequenceClassification`であり、指示文や生成処理は不要である。公開の分類ヘッドを含めて固定し、今回の追加学習パラメーターは0。実測のパラメーター数は567,755,777だった。

対象語または全文と、原文と同じ言語のNoema概念定義を、そのまま二列入力した。指示文、対象を囲む記号、正解ラベル、候補ID、型による絞込みを入力へ加えていない。概念ごとの分類層や対訳辞書を作らず、既存の91概念の定義を入れ替え可能な候補として扱う。定義が必要なことと、モデルが任意の未知概念を理解できることは別である。

評価資料は観察済みの[v6](../data/definition-probe-v6.json)全50範囲で、日本語・英語それぞれ既知19、未知6を含む。方式を選ぶための開発や新しい採用試験ではなく、既存資料を使う診断である。原文の対象範囲を正解として与えているため、自然文全体の翻訳精度とも区別する。

## 結果と誤り

| 方式 | 日本語の概念正解 | 英語の概念正解 | 日英とも正解 |
| --- | ---: | ---: | ---: |
| 既存MiniLM・学習済み3係数 | 12/19 | 14/19 | 12/19 |
| 固定reranker・対象だけ | 15/19 | 10/19 | 10/19 |
| 固定reranker・全文 | 8/19 | 11/19 | 6/19 |

対照は[以前の実験](broad-matcher-v1-results.md)で保存した同じ行・91候補の予測を、ハッシュ検査して再集計した。既存方式にはNoemaの教師資料で学習した共通3係数がある。今回の方式には追加学習がないが、異なる事前学習モデルでもあるため、差を一つの構造変更だけの効果とは解釈しない。[対照の集計](../reports/pretrained-reranker-v1/baseline-evaluation.json)、[対象だけの集計](../reports/pretrained-reranker-v1/isolated-evaluation.json)、[全文の集計](../reports/pretrained-reranker-v1/sentence-evaluation.json)を保存した。

対象だけの入力では、日本語「売った」に対して小売の場所、英語`drank`に対して飲む容器、`opened`に対して窓を選んだ。関連度が高い概念でも、その語の意味と同じとは限らない。全文入力では、メッセージが夜遅くに届いた文の対象`message`に対して、到着する出来事を選んだ。全文の内容に関係があっても、指定された対象の意味ではない。

対象だけの入力には構造上の限界もある。「鍵」と「問題を解く鍵」、低温の「冷たい」と「冷たい反応」は、同じ対象文字列だけを渡すと全候補のスコアが同じになる。この資料では日英合わせて4組が該当した。[同一入力の監査](../reports/pretrained-reranker-v1/isolated-collisions.json)。全文入力でも英語の`cold reception`を低温へ対応させる誤りが残った。

未知例のスコアと既知正解のスコアには重なりがある。今回は閾値を選ばず、全て研究用の候補順位として返した。全文の確定出力は0件であり、これを未知例の拒否に成功した証拠とは扱わない。関連度の値やそのsigmoidを、そのまま意味一致の確率にできる根拠も得られていない。

## 計算量と検証

同じ二列文字列を一度だけ処理し、元の行へ復元した。CPU float32・8スレッド・batch 16で、対象だけの4,186組は約132秒、全文の4,550組は約193秒だった。これは50範囲分の照合時間であり、モデルの読込み時間や原文の範囲抽出は含まない。語彙を追加しても分類層の再学習は不要だが、候補数に応じた推論量は増える。

全439テストが通過した。生の文字列だけがモデルへ渡ること、候補順への独立性、重複入力の復元、長文の切断をせず拒否すること、非有限値の拒否を検査した。実モデルは全層eval・重み固定で、4組の同一バッチについて反復と直接forwardが完全一致した。生成・辞書等の禁止経路5種の呼出しは全て0回だった。

再現検査ではモデルを再読込みし、同じ4組を再計算して保存値との完全一致を確認した。加えて両方式の保存済み全スコア行列から、各50行の予測・集計と対照の集計を再計算した。全8,736組のモデルforwardを再実行した検査ではない。[再現検査](../reports/pretrained-reranker-v1/verification.json)

実行環境はPython 3.12.10、PyTorch 2.13.0 CPU、Transformers 4.57.6。モデルのrevision・重み・トークナイザー・コード・入力・出力のハッシュと時間は[実行記録](../reports/pretrained-reranker-v1/run.json)に保存した。

```powershell
artifacts/kwja-venv/Scripts/python.exe -m scripts.probe_pretrained_reranker
artifacts/kwja-venv/Scripts/python.exe -m scripts.probe_pretrained_reranker --verify-only
```

固定revisionのモデルをHugging Faceのキャッシュへ取得済みであることと、以前の対照予測が必要になる。実験スクリプト自体はオフラインで読み込み、既存出力を上書きしない。

既存モデルの利用は、語を一つずつ追加学習する以外の経路として実装できた。一方、このモデルをそのまま使う二つの入力条件では、文脈と対象範囲を同時に識別できず、意味一致の精度も不足する。既存の対象範囲を扱う判定器にこのモデルの表現を移す場合も、関連度と語義一致の差を評価する必要がある。今回の19概念へ個別修正を加えたり、関連度の高い候補を確定訳にしたりして、広い自然文への対応が進んだとは扱わない。
