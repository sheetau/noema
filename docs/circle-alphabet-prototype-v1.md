# 円と線による書記体系の試作01

`concept/alphabet-concept.md`と`concept/noema-alphabet-concept.png`を基に、現行Noemaの構文からSVGと例文画像を生成する。指定されたtxtファイルはなく、同名のmdファイルを参照した。既存のv1/v2の文字資源や二作品の本文は変更しない。字形を見て調整するための独立した試作である。

## 部品と組合せ

- 円の半径は6・14・22の3種類。点は句点として別に扱う。
- 円の中心と横線はy=0・24・48の3本の基準線上に置く。基準線は本文では描かない。
- 直線は縦・横・45度。円に接続・交差する直線の延長は、その円の中心を通る。
- 大円を構文の操作、中円を参照や内容、小円を型の細分や綴りに使い、位置と接続線の組合せで同じ群の役割を区別する。この対応は今回の設計上の規約である。
- 名前・数値・文法版は、それぞれ異なる二重円の導入部と綴り部品の列から作る。綴り部品は既存の32字と一対一に対応する。
- 範囲の開始と終了は斜線の部品、空の引数列は山形の一部品にする。文の終わりには点を置く。

単に既存32字を新しい32字へ置換する方式ではない。解析済み構文の役割ごとに主字を組み立て、必要な名前や数値の綴りを組み合わせる。同じ`a`でも「個体の型」と「仮定の開始」は異なる字形になる。`s`も主張と脱引用で異なる。一方、名前の中の`s`に主張や脱引用の意味を追加しない。

語の意味は、その語の定義と意味規約によって保持する。例えば例文の`ab`は「信頼する」という規約を持つが、綴りだけからその語義を自動で発見したり、別の意味へ分類し直したりしない。全文表示では定義・型・参照も同じ書記規則で描ける。

## 生成方式

現行0.8〜0.16の構文木から、役割を付けた字形要素の列を作り、その列をSVGへ描画する。主字と綴りの規則から必要な字形だけを作るため、あらゆる名前や合成語の字形をフォントへ事前登録しない。旧字形の私用領域を上書きせず、既存の解析器を変更しない。

構造付きの字形列から正規化済みNoemaへ戻し、構文木が一致することを検査する。これは画像から文字を読むOCRではない。SVGには元の役割と綴りを付け、同じ情報をJSONでも保存する。

```powershell
python -X utf8 -m scripts.proof_circle_alphabet
python -X utf8 -m scripts.circle_alphabet -i examples/v014/circle-alphabet-samples.noema -o output/alphabet-circle-v1/own.svg
python -X utf8 -m scripts.project_work check --tests tests/test_circle_alphabet.py
```

例文画像は`output/alphabet-circle-v1/sentences.png`、部品表は`components.png`、宣言を含む全文は`sample-complete.svg`。元のNoemaは[例文ファイル](../examples/v014/circle-alphabet-samples.noema)、規則は[試作仕様](../data/circle-alphabet-prototype-v1.json)に保存する。長い名前を一字形にまとめた結果が用紙幅を超える場合、切り落とさずエラーにする。`--width`または`--scale`で調整できる。

## 例文と確認範囲

例文では`aa`を人、`ab`を信頼する関係、`ac`をアキ、`ad`をナオとする。肯定文、否定文、全称と存在を含む文を描画した。画像では本文の主張を掲載し、宣言は付属のNoema・全文SVGで確認できる。

8件の検査で、円・直線の幾何規則、32種の綴り部品と主字の区別、役割に応じた字形の変更、0.8〜0.16の代表例の構文往復、誤った役割の拒否、SVGの構造を確認した。人物別の記述構成や局所的な文化規約の例も含む。例文画像と部品表は実際に描画して目視した。

人が読み違えないことや、手書きでの速さは未評価である。まず円の大小、線の長さ、文字同士の間隔、綴り部の密度、範囲記号の目立ち方を画像で確認し、利用者の反応を受けて調整する。標準字形への採用は、その調整後に行う。
