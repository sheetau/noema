# 二作品の新書式移行に向けた全宣言の点検

現行円文字で二作品を全文表示するには、本文だけでなく、その型・定義・基本関係の規約と名前を対応させる必要がある。[点検報告](../reports/manuscript-transfer-v1.json)は、選択中の正本にある全宣言を調べ、移行作業の対象を確定する。新書式の完成報告ではない。

対象は [work-state.json](../data/work-state.json) が選ぶ登録簿・監査報告の二作品である。カント6,061宣言、アインシュタイン6,255宣言を元の順序で保持する。各意味規約と識別表記の内容ハッシュを既存監査と照合し、現在の円文字辞書の証拠も確認する。本文、意味判断、固定字体は変更しない。

## 参照と再利用の区別

点検は定義本体、関数参照、引用内部を含む静的な参照をたどる。カント4,870宣言、アインシュタイン5,018宣言が本文のいずれかの主張から到達できる。残りの宣言も保存する。定義の存在だけでその内容を主張したことにはならず、到達できないことだけで削除してよいとも判断しない。

共有ライブラリには、既存の定義を名前だけ変えて保存した対応表がある。この点検では、対応表が示す元の定義を実際に読み、改名後の型と本体が第12版辞書の定義に一致することを確認する。さらに、二作品の同名宣言がその元定義に一致するときだけ、構造上の再利用候補として記録する。同じ記号名でも本体が異なれば候補に含めない。

この一致は、原文の語義の一致や引用内部の置換を許可する証拠ではない。同じ本体を持つ異なる定義名を統合すると、その名前を含む記述の同一性が変わりうる。候補の適用には、意味規約、引数の役割、引用と参照の区別を保つ確認が必要になる。字形はこの段階では割り当てない。

基本宣言には本体がないため、型が同じという理由で再利用候補に含めない。継承した依存名の対応は、元の宣言が一致する場合に限って補う。これも依存先の意味を認定する検査ではない。

人名・書名などの識別表記は、既存の識別注釈から別欄へ保存する。原語の綴りは識別対象の意味説明を代替せず、綴りの一致から同一対象とも推定しない。

## 版と処理量

両正本について、版ヘッダーだけを明示的に0.16へ変更した候補を正規化し、宣言と文の構造がそのまま保たれるかを調べる。候補は正本へ適用せず、0.14の意味判断を自動的に0.16へ移したとも扱わない。新書式へ移す際は、元の版、候補の版、対応関係を明示する。

構造の節点数は、現行書式の展開後8,192節点という上限と同じ計数器で求める。これは字形数、図形数、行数、ページ数、読解負担の推計ではない。共有によって同じ構文を短く表示しても、展開後の節点数は減らない。既存上限は変更しない。

全宣言を含む文書群には、定義と参照の範囲、巻やページの順序、完全な宣言集合、本文の終端を明示する仕組みが必要である。語形は意味規約と照合して定め、番号・ハッシュ・登録順から生成しない。文書固有の番号表や不可視のASTを復号に使って、可視文書の完成とはしない。

## 再現と個別調査

```powershell
python -X utf8 -m scripts.project_work check --module scripts.manuscript_transfer --prepare --tests tests/test_manuscript_transfer.py --verify reports/manuscript-transfer-v1.json
python -X utf8 -m scripts.manuscript_transfer kant-1784 s5k
```

全項目は `output/manuscript-transfer-v1/kant-1784.json` と `einstein-1905.json` に保存する。各行は元の記号、意味規約、直接依存、引用内部の依存、参照する本文の位置、構造上の共有候補を持つ。報告は保存した一覧の内容ハッシュを固定する。個別調査コマンドは現在選択中の正本を読み、その定義と依存・使用箇所を表示する。

この点検では、基本関係の一般的な定義、二作品の全ページの図形復号、画像OCR、人の独立した読解を成立済みとはしない。これらはそれぞれの証拠によって判断する。
