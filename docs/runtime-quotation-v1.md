# 関数を経由する引用評価の制限

[引用層の最初の試作](ranked-quotation-v1.md)で見つかった、引数の関数を通じて評価層の制限を回避できる問題を、後継の評価器で修正した。旧評価器では成功する例を保存し、同じ文書を新評価器では実行時に拒否する。一方、下位層の記述を調べる呼出しと、人物ごとに異なる内容を持つ記述は評価できる。

今回変更したのは実行時の意味解釈である。構文解析器の関数型に評価層を加える変更は行っていない。したがって、解析に通っても、実際に呼び出した関数の評価層によって拒否される式がある。標準版への採用、静的な型検査による実行可能性の保証、カント本文の著者主張への統合は引き続き未完了である。

## 評価時の規則

通常の最上位では、どの層の記述も評価できる。層 `r` の記述を評価している間に、別の記述を評価する場合、その層は `r` 未満でなければならない。違反時には内容を実行する前にエラーを返す。拒否を偽や未指定の値に置き換えない。

引用から取り出した関数にも、その時点の上限を保持する。後でその関数を呼ぶときは、保持した上限と呼出元の上限のうち厳しい方を適用する。関数を返す関数、質問に含まれる関数、列や入れ子の列に含まれる関数にも同じ規則を適用する。既存の関数に制限を付けても、元の関数そのものの上限を変更しない。

引数として渡す関数の本体が解析時には分からなくても、呼出し先の実際の評価にこの制限が適用される。別の評価器から受け取った関数や、解釈関数から同期的に開始した別文書の評価も、呼出元の上限を引き継ぐ。例外で終了した場合は以前の上限へ戻し、別スレッドの独立した評価には影響させない。

計算結果を再利用する場合も、上限をキャッシュキーに含める。最上位で評価済みの真理値を、そのまま制限下で返すと、本来必要な拒否を飛ばしてしまうためである。引用値は従来どおり発行した評価器だけが受け入れ、無限の記述領域への量化は有限の既知一覧で代用しない。

## 検査した範囲

8経路（直接適用、定義呼出し、解釈関数、関数の返却、同じ関数の返却、質問、列、関数の等値比較）について、上限3種類と評価対象4種類を組み合わせた96例を検査した。許可される48例では結果と内容の実行を確認し、拒否される48例では内容が実行されていないことも確認した。

追加115テストには、この96例に加え、次の検査を含む。

- 旧評価器で成功した制限回避を再現し、後継評価器で拒否する。
- 定義と式のキャッシュを個別・同時に有効化しても、制限を回避しない。
- 解釈関数が返す既存の関数・質問・列・入れ子の列に制限が残る。
- 別評価器の関数、解釈関数からの直接呼出し、評価器の再入でも制限が残る。
- 例外後の上限復元と、別スレッドの独立した評価を確認する。
- 人物ごとの内容の4組合せを保持し、引用の帰属だけでは内容を評価しない。
- カントの一般的な制約条件を引用した文は、その条件を実行せず保持できる。

旧試作の23テストも通過した。新しい二例は長形式・短縮形式・固有文字の往復、CLI解析、SVGのXML検査を通過した。SVGの目視検査は行っていない。

## 再現方法と成果物

[制限違反の例](../examples/v015/runtime-quotation-rejected.noema)と[許可される例](../examples/v015/runtime-quotation-accepted.noema)は、関数の評価内容を共通にし、取り出す引用の層を変えた文書である。どちらも解析可能だが、前者は後継評価器で実行時エラーとなる。

```powershell
python -X utf8 -m scripts.check_runtime_quotation --verify-only
python -X utf8 -m pytest tests/test_runtime_quotation.py -q
python -X utf8 -m noema.ranked parse -i examples/v015/runtime-quotation-accepted.noema
```

Pythonから使う場合は、モデルを明示して後継評価器を選ぶ。

```python
from pathlib import Path
from noema.ranked import parse
from noema.guarded_ranked_semantics import evaluate_document

doc = parse(Path("examples/v015/runtime-quotation-accepted.noema").read_text(encoding="utf-8"))
result = evaluate_document(doc, individuals=("person",), situations=("now",),
                           primitives={"touch": lambda: True})
assert result == [{"kind": "ask", "value": True}]
```

[後継評価器](../noema/guarded_ranked_semantics.py)、[検査器](../scripts/check_runtime_quotation.py)、[保存した検査結果](../reports/runtime-quotation-v1.json)は専用の成果物として追加した。既存の評価器と標準CLIは変更していない。値のクラスも評価器ごとに異なるため、旧評価器の関数・内容・引用値を混用しない。

## 完成判定との関係

この変更で、確認した関数経由の制限回避を実行時に拒否できるようになった。解析だけで実行時の拒否を検出する仕組み、論理体系の無矛盾性、任意の式の停止性を証明した結果ではない。Pythonの解釈関数は信頼するモデル実装であり、任意の外部コードを隔離する仕組みでもない。

カントの記述に必要な、異なる判断内容を扱う機能は維持した。次に本文へ接続する際は、対象者・職務・内容・許可の範囲を同じ変数へ結び、固定した一人分の内容を全員へ適用しないことを確認する必要がある。新しい原文対応範囲は増やしておらず、248件・566文書の集計と二作品の意味確認済み区間0件は据え置きである。
