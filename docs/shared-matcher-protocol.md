# 概念定義を入力する共通判定器の試験条件

固定したMiniLMの特徴から、対象範囲と概念定義が対応するかを共通の小型モデルで学ぶ。
概念ごとの出力重み・ID埋め込み・単語辞書は持たず、候補の追加で学習パラメーター数を増やさない。
これは正解の対象範囲を与える概念選択の試験であり、完全な意味解析器ではない。

## 予測前に固定する条件

- エンコーダーは `resources/models.json` のMiniLM固定リビジョン。CPU・float32・8スレッド・eval、重み固定。
- 対象の文脈範囲平均、対象範囲だけの文平均、全文平均を、それぞれ単位長に正規化する。
- 定義は既存の日英説明を別々に正規化して平均し、再び単位長にする。本文やラベルを定義へ追加しない。
- 共通のスコアは3種類のコサインの重み付き和と、階数32の双線形項。
  双線形項は `0.25 * tanh(q_proj @ d_proj.T / sqrt(32))` として変化幅を制限する。
  入力は特徴ベクトルだけで、概念ID、正解の型、役割は渡さない。
- 初期のコサイン係数は文脈1・単独0・全文0。定義側の射影は0、入力側はPyTorch既定初期化。
  追加パラメーター数は49,155。語彙数と無関係。
- 損失はスコアの10倍に対する交差エントロピー。AdamW、学習率0.002、weight decay 0.001、
  batch 128、20 epoch、seed 17。線形な3係数だけの比較も同条件で行う。

## 学習と選択

既存 `artifacts/corpus-v9.jsonl` のtrain/dev区分を使う。新しい語彙ごとの訓練例は作らない。
15概念のうち `ae`（鳥）、`bc`（助ける）、`ah`（公園）を開発用に留保する。
これらを一つでも含む**文全体を学習から除く**。残り12概念の正解範囲を、概念と言語ごとに128件、
ハッシュ順で抽出する。同一文・同一範囲の重複は除く。学習時の候補定義も12概念だけ。

開発資料はdev区分から留保3概念それぞれ言語ごとに48件を選び、学習文との一致を除く。
開発時は既存15概念から選ぶ。各epochと未学習epoch 0について日英平均の先頭正解率を計算し、
最高のepochを採用する。同点なら早いepochを選ぶ。これは概念を留保したモデル選択であり、
この3概念の成績は最終的な未知概念への汎化を証明する成績ではない。

## 確認

選択後だけ、91概念すべてを候補としてv1/v2の回帰と、新資料v3を評価する。
v3は過去の定義照合資料で扱っていなかった追加50概念と対応外8組。
既存15概念とv1/v2の追加26概念のどちらとも概念が重ならないことを検査する。
同じ作成者の小規模資料であるため、外部の独立評価とはしない。

未学習の文脈・単独・全文コサインも同じ資料で記録する。確認結果でモデル、epoch、閾値を選び直さない。
追加概念は学習損失の正例・負例のどちらにも含めない。定義の特徴を計算すること自体は学習ではない。
対応外入力にも候補は返るため、スコアを確信度にせず、確定出力や誤確定率として集計しない。
すべての候補を検索するこの試験は、確定率80%・意味構造完全一致率95%の判定とは別である。

資料、コード、選択例、定義、モデル、重み、学習履歴、全予測のハッシュと結果を保存する。
既存の出力先は上書きしない。実験結果だけで本番翻訳を切り替えない。
