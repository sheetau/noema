# 原則の内容・採用・履行・置換

カント第17区間の後半には、民衆の思考の発展が政府の原則にも作用するという記述が続く。その記述に必要な準備として、原則を条件付きの行為内容として組み立て、規範上の採用、実際の履行、別内容への置換を区別した。新しい原始概念は追加していない。既存の記述付き要求関係と、Noemaの関数・引用・量化を用いる。

今回の構成は、原則を義務として採用する場合の候補である。経験則や信念を含む原則一般の定義でも、原文の語義の確定でもない。政府への作用を既に記述したという著者主張は加えず、親文書の22主張をそのまま保存した。

| 定義 | 区別する内容 |
| --- | --- |
| `rxv` | 指定した人が条件に該当するなら、同じ主体が指定の扱いをするという一般原則 |
| `rxw` | その条件に該当する人が実際にいること |
| `rxx` | 指定の規範源が、主体にその職務で原則内容を満たすよう要求していること |
| `rxy` | その要求があり、同じ原則内容も同じ状況で成立していること |
| `rxz` | 同じ原則への要求が、異なる二状況の間で成立または消失すること |
| `rx2` | 同じ比較状況で、二つの原則内容の真偽が違う実例があること |
| `rx3` | 旧原則への要求が失われ、新原則への要求が生じ、内容の違いにも実例があること |

原則の対象者は、非空で重複がなく、範囲と一致する列として指定する。適用条件と扱いには、それぞれNoemaで定義した関数を渡せる。「原則」という新しい単語に説明を預ける必要はない。主体・対象範囲を固定した上で、適用条件と扱いは状況に応じて評価する。したがって同じ原則でも、該当する人の変化により履行状態が変わり得る。

条件に該当する人がいなければ、条件付き原則の内容は真になり得る。適用例の存在は`rxw`で別に確認する。一方、空の対象者一覧や、不完全・重複のある一覧を、条件に該当する人がいない場合と同一視しない。外側の引数列が空であることも検査し、余分な引数を黙って捨てない。

採用`rxx`は、原則内容を実行評価せずに述べられる。原則が守られているか分からなくても、要求が存在することは別に記述できる。履行`rxy`だけが同じ内容を評価する。ここでいう採用は規範上の要求の存在であり、採択行為や制度的な正当性を説明したものではない。

置換では、規範源・主体・職務・内容記述・引数列・極性を揃える。別の主体への要求や、否定内容への要求を、同じ原則の採用へ流用しない。旧原則も残したまま新原則を追加する場合は、`rx3`の置換には該当しない。二状況が異なることだけを要求しているため、時間的な先後、制度的な変更行為、変更の原因は別途結ぶ必要がある。

内容の比較は、同じ状況で真偽が異なる実例を探す。記述名が違うだけでは内容が変わった証拠にしない。また、実例が見つからなくても同義とはしない。調べる状況が少ない場合や、対象者ごとの扱いは異なるのに両原則がともに偽になる場合もある。未知の内容を偽として補うこともない。

原文側の`iaradoption`、`iarfulfillment`、`iarreplacement`は、これらを既存の要求関係`h7k`へ接続する。政府の組織的な構成や、尊厳に即した扱いそのものは今回定義していない。関数引数に名前を付けただけで、それらの意味を完成扱いにはしない。集団の発展から政府の変化への因果関係、作用の時刻、自らにとっての有益さ、機械との対比も残る。

検査では、二人に対する条件と二種類の扱いの64通り、旧・新原則への要求の前後状態16通りを調べた。適用対象の変化、同じ内容の別記述、別の規範源・主体・職務、引数列・極性の取り違え、空の比較範囲、未知の条件・扱い・要求を対照に含めた。103テストが通過した。通常表記・短縮表記・独自文字の往復、CLIでの三文書の解析、抽出文書のSVGのXML構造も確認した。SVGの見た目の検査は今回行っていない。
