# ラテン語の呼びかけと、判断能力の構成的な読み

[カント冒頭の更新草案](../examples/v013/kant-reasoned-judgment.noema)では、ラテン語の呼びかけの目的bkを、後続ドイツ語の目的bmの別名にしていた処理を変更した。両者を異なる定義で記述し、著者が後者で前者を説明する談話関係を保持する。説明関係から、二つの目的の完全な同義性を要求しない。

## 語義の確認と、採用した解釈

[Lewis and Shortのsapio項、II.2](https://alatius.com/ls/index.php?met=up&ord=sapio)では、分別・判断に関わる語義を確認できる。[Allen and Greenough §456](https://dcc.dickinson.edu/grammar/latin/complementary-infinitive)では、敢えて行うことなどを表す動詞が、同じ主体の行為を不定詞で補う構造を説明している。また、同じ句は[ホラティウス『書簡集』I.2.40–41](https://www.thelatinlibrary.com/horace/epist1.shtml)にもある。カントの後続ドイツ語だけを語義の根拠にしてはいない。

今回の実装では「評価する事柄について、理由に支えられた判断を行える」という構成的な読みを採った。ただし、理由・評価範囲・方法による形式化は実装上の解釈であり、資料から一意に導かれる語義でも、知恵一般の必要十分条件でもない。この区別を[語義確認の記録](../data/latin-motto-review-v1.json)に明記する。資料は原文を検討するために参照したもので、実行時に語を検索する仕組みは追加していない。

## 判断を構成する関係

[汎用の判断能力の定義群](../examples/v013/reasoned-judgment.noema)は、既存の能力の7定義にya・ybを加えたもの。基本記号を持たず、次の関係を引数として受け取る。

- 誰が、どの判断行為を行うか。
- その判断が、どの事柄についてのものか。
- その判断に、どの理由を用いたか。
- その理由が、その判断を支えるか。
- どの事柄を、現在の評価対象に採るか。

yaは、同じ判断行為について、主体・対象・理由・支持が結び付くという命題内容である。理由が存在するだけ、別の判断を支えるだけ、理由として用いたが支持にはならない場合を区別する。

ybは、評価する事柄が少なくとも一つあり、その全てについてyaを達成する方法があるという条件である。達成は以前のxdにより、明示した評価対象の結果について判定する。事柄ごとに違う方法を選んでもよく、一つの方法で全事柄を処理できることは要求しない。現在の状況で全ての判断を既に実行したことも要求しない。

カント草案ではfa〜feが上記五関係の意味規約を持ち、bkがybを命題内容にする。判断・理由・支持の一般的な理論や、支持の評価基準まで今回で確立したわけではない。語に新しいラベルを与えるだけで済ませず、どの関係がどの対象に結び付くかをNoemaの定義で述べている。

## 二つの呼びかけを接続する

| 定義 | この草案での内容 |
| --- | --- |
| bk | 指定範囲の事柄について、理由に支えられた判断ができるという目的 |
| bl | bkへ向けて勇気を持つよう促す発話 |
| bm | 自分自身の理解能力を使うという目的 |
| bn | bmへ向けて勇気を持つよう促す発話 |

判断能力があっても現時点で自分の理解能力を使っていない例と、理解能力は使うが判断を支える理由がない例を区別した。呼びかけは、目的を既に達成したという事実の主張には変換しない。二つのNoema記述は別に保持するが、特定の解釈内で偶然同じ真偽になることは禁じない。

原文の六区間への参照と、ラテン語の箇所をドイツ語の箇所で説明する向きは維持する。標語の主張boは、従来どおりドイツ語の呼びかけbnを指す読みを保持している。引用全体を含む指示範囲、audeの行為性と勇気を持つことの違い、原刊の確認は残る。このためラテン語の完全な意味確認とは数えず、確認済み全文単位はカント0/20・アインシュタイン0/282のままである。

## 検査と再現

判断の引数を入れ替えたり、理由や支持を欠いたりする8例、事柄ごとに方法を変える場合など6例、ラテン語・ドイツ語の目的と呼びかけを区別する11例を検査した。空の評価対象や、利用できない方法を能力の成立には数えない。著者への帰属が、引用した目的内容の評価を引き起こさないことも確認する。

```powershell
python -S -m scripts.compose_reasoned_judgment
python -S -m scripts.check_reasoned_judgment --verify-only
python -S -m noema parse --input examples/v013/kant-reasoned-judgment.noema --output artifacts/kant-reasoned-judgment.json
python -S -m noema render --input examples/v013/kant-reasoned-judgment.noema --alphabet v2 --output artifacts/kant-reasoned-judgment.svg
python -m pytest -q
```
