# 学習済み関連度モデルをそのまま使う照合条件

正負定義の追加学習ではNoemaへの転用失敗が残った。次は、文対を直接評価する既存の学習済み分類器を固定して使う。語別の追加学習、指示文、生成、対訳検索は行わない。

モデルは[BAAI/bge-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3/tree/953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e)、revision `953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e`、Apache-2.0。公開の`XLMRobertaForSequenceClassification`と単一logitのヘッドをそのまま読み込む。因果言語モデルや指示文を用いる別系列のrerankerは使わない。safetensors、remote code無効、CPU float32、eager、seed 17、8スレッド、eval・重み固定とする。未読込み・余分な重みがある場合は停止する。

観察済みの定義照合v6全50範囲を既存91概念で評価する。日本語・英語それぞれ既知19範囲、未知6範囲である。候補の定義は原文と同じ言語を使う。今回は追加学習を行わず、開発で方式や閾値を選ばない。既存MiniLMの3係数方式の保存済み結果も、ハッシュ検査して比較する。

二つの入力条件を独立に報告する。一つは正解範囲の文字列と定義、もう一つは原文全文と定義。どちらも文字列をそのまま二列入力し、指示や対象標識を付けない。前者は文脈を失い、後者は文中の対象を指定できないため、どちらも意味抽出の完成方式とはみなさない。関連度による候補順位に、既存の事前学習をどこまで利用できるかの診断である。

全候補を評価し、同じ二列文字列は一度だけ推論して元の行へ戻す。型による候補の絞込みは行わない。batch 16、長さ256以内とし、超えたら停止して切断しない。出力は生logitで順位付けし、ID順を同点処理に用いる。未知入力の先頭スコアを記録するが、関連度を意味一致の確率と呼ばず、閾値で確定させない。

実装では、正解ラベル・候補ID・語の対応表をモデル入力へ混ぜないこと、候補順の独立性、重複入力の復元、長文・非有限値の拒否を検査する。実モデルでは生成禁止の監視、直接forwardとラッパーの一致、同一バッチの反復一致、重み固定を確認する。全スコア・入力・依存ファイルのハッシュを保存し、保存スコアから全予測と集計を再計算する。

この資料は既に観察済みで、小規模かつ正解範囲を使う。独立した採用試験や全文の意味構造一致率ではない。未知の比喩を含む対では、対象だけの入力が同じ場合に区別できない制約も報告する。結果が良くても主画面の翻訳器へ直接採用せず、文脈と対象範囲を同時に扱うための根拠として用いる。
