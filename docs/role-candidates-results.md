# 格解析の取りこぼしを候補の比較で扱う

**意味役割を判定する相手を、既存PASの関係先から原文中の全基本句へ広げた。** 旧評価と新しい評価の両方で、指定した42項すべてが候補に入った。新評価の役割正解は31/42件にとどまり、候補の網羅性の改善を意味理解の完成とはしていない。

## 変更した処理

学習済みの基本句特徴が述語と判定した基本句について、それ自身以外の全基本句を比較する。語彙一覧、金の位置情報、助詞の表層に依存する補正は使わない。既存の格ラベルは入力特徴として残すが、格解析で関係が見つからなかった基本句も候補にする。文外の「著者」等の推測から人物を新設しない。

複数の格ラベルが同じ相手に付く場合は、候補を重複させず複数ビットで表す。未接続には専用のビットを使う。文脈ベクトルと5分類の共通ヘッドは前回の構成を保ち、単語や動詞ごとの出力クラスを増やしていない。

候補を広げると無関係な基本句も増えるため、注釈した述語の4役割に当たらない候補を `none` として学習する。時間等の意味は原文解析の証拠に残る。別の未注釈述語は負例にしない。

## 固定条件

[比較条件](role-candidates-protocol.md)と[新しい8述語群16文](../data/role-candidates-v2.json)を `a545fee` で予測前に保存した。学習16群32文と開発4群8文は前回と同じ。前回の評価8群16文は既知の回帰資料とし、新評価には別の8群を用いた。どちらも人工的な短文であり、広い自然文の性能の証明ではない。

線形層と64次元tanh層を200エポックまで学習し、開発損失で方式とエポックを選んだ。選択はMLPの49エポック時点だった。[選択記録](../reports/role-candidates-v2/selection.json)を保存してから新評価を解析した。新評価では線形層が32/42、選択済みMLPが31/42だったが、結果を見て方式を切り替えていない。

## 候補が増えた効果と限界

| 指標 | 旧評価・従来方式 | 旧評価・候補拡張 | 新評価・従来方式 | 新評価・候補拡張 |
| --- | ---: | ---: | ---: | ---: |
| 指定項が候補に入る | 36/42 | 42/42 | 36/42 | 42/42 |
| 指定項の役割が正解 | 31/42 | 34/42 | 30/42 | 31/42 |
| 注釈した述語の全役割が正しく余分もない | 8/16 | 8/16 | 6/16 | 7/16 |
| 無関係な基本句への余分な役割付与 | 0 | 0 | 0 | 0 |

従来方式は保存済みの前回のMLPで、新方式と同じ固定エンコーダーの出力を使って比較した。旧評価では主体が10/16→16/16となった一方、場所は5/6→2/6へ後退した。新評価も主体10/16→14/16、対象16/16→15/16、受け手0/4→0/4、場所4/6→2/6だった。

無関係な基本句への役割付与が0であっても、関係のある相手に別の役割を付ける誤りは残る。新評価でMLPは候補62組中49組を正しく分類し、誤り13組はいずれも注釈した項に対する役割の不一致だった。noneが増えるだけで高い正解率に見えないよう、指定項の正解31/42を別に示した。

新評価の「銀食器は工房で職工によって磨かれた」では主体・対象・場所がそろった。一方、受け手を主体や対象と判断する誤りは解消していない。「魚が川で漁師に捕まえられた」では川を対象とした。

さらに、注釈した一つの名詞が複数の基本句に分かれる問題がある。「パン職人」「調理場」「参加者」等では同じ注釈範囲に複数の主辞が重なり、異なる役割が付く例があった。今回の判定は、重なる候補がすべて正しい役割であることを要求する。正解が一つ含まれたことだけで成功にしない。この保守的な主辞照合は、修飾や構成要素をまとめた事物の解析が完成したことを意味しない。

「注釈した述語の全役割」の判定は、4役割とその候補だけを対象とする。他の述語・数量・否定・照応等を網羅した意味構造の一致率ではない。95%以上の完成条件は引き続き未達である。

## 検証と実行

未接続の句が候補に入ること、文外参照から候補を作らないこと、同じ相手への複数の格が一つの候補になることを検査した。正解役割が全部含まれていても余分な役割があれば、注釈フレームの完全一致にしないテストも追加した。全229テストが通った。

別プロセスで固定特徴から学習し直し、両方式の全重み・200エポックの損失・全分割の評価が一致した。保存したモデルを使うAPIから新評価16文を原文から解析しても、保存した候補・役割・確率と一致し、反復一致も確認した。[検証記録](../reports/role-candidates-v2/verification.json)

実モデルの初期化と全72文の解析では、文章生成・辞書・標準の辞書付き出力処理・seq2seq・typoへの到達を失敗とする検査を有効にし、すべて0回だった。[実行条件](../reports/role-candidates-v2/run.json)

Python 3.12の[日本語解析用環境](japanese-pas-results.md#再実行)で、新しい保存先を指定する。

```powershell
& artifacts/kwja-venv/Scripts/python.exe -m scripts.train_role_candidates --output reports/role-candidates-reproduction --artifacts artifacts/role-candidates-reproduction
```

推論は `RoleAnalyzer("reports/role-candidates-v2", "artifacts/role-candidates-v2").analyze(text)` で行える。戻り値は解析証拠と役割候補であり、完成したNoemaの意味構造ではない。旧保存モデルの候補方針も明示的に保持する。

[全候補と教師](../reports/role-candidates-v2/evidence.json)、[全評価](../reports/role-candidates-v2/evaluation.json)を保存した。次の課題は、分割された事物の扱いと、受け手・場所を含む役割の区別である。候補に含まれたことを理由に誤った意味を確定したり、完成条件を小さな資料へ限定したりしない。
