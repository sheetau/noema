# Noema 0.4：既存の語から複合語を作る

0.4では、対象や場所の語に性質をつなぎ、辞書に個別登録していない複合語を作れる。基本語91語と32文字は0.3から変更していない。新しい構造記号は語の内部をつなぐ `-` で、文書の先頭は `noema d d` とする。

## 「赤い本」を一つの語で指定する

```text
noema d d
vac i fo j jx-sai.
```

`jx` は本、`sai` は赤い。組み合わせた `jx-sai` は「赤いという性質を持つ本」で、第1文は子供がそのような本を読むことを述べる。基本語の定義を知っていれば、複合語全体を別に暗記する必要はない。

最初に対象か場所の語を置き、後ろに1個以上の性質の語を `-` でつなぐ。`jx-sai-sak` は赤くて大きい本、`mab-saq` は熱い水、`lac-sak` は大きい学校になる。性質を複数書いた場合はすべてを満たす対象を指す。性質の順序は意味を変えず、正規形では概念IDの順にそろえる。同じ性質の重複は入力エラーにする。

これは語の組合せから明示した性質を表す規則であり、文化的な含意や新しい分類名を推測する規則ではない。たとえば「赤い本」から特定の政治的な本を指すとは解釈しない。「本＋赤い」と「紙＋赤い」も同じ概念にまとめない。

## 組み合わせられる性質

| 性質 | 語 | 基本語の型 |
|---|---|---|
| 空腹である | `wm` | 対象 |
| 疲れている | `sag` | 対象 |
| うれしい | `sah` | 対象 |
| 赤い・青い | `sai`・`saj` | 対象・場所 |
| 大きい・小さい | `sak`・`sal` | 対象・場所 |
| 開いている・閉じている | `sam`・`san` | 対象・場所 |
| 濡れている・乾いている | `sao`・`sap` | 対象・場所 |
| 熱い・冷たい | `saq`・`sar` | 対象・場所 |

「読む」のような出来事や、「所持する」のように別の対象との関係を必要とする状態は、そのまま複合語の性質にはできない。動作主名詞、道具名詞、関係節などは別の規則を必要とするため、この版では追加していない。

型の検査は、事実として成立するかという判定ではない。たとえば物の語に空腹を付ける記述が文法上の型を満たしても、それを現実の正しい状態と認定することはない。色、大小、温度の基準も基本語の定義どおり文脈に依存し、数値や比較対象を補わない。

## 数量・名前・参照

```text
noema d d
vac i qo n "葵" o aki j jx-sai-sak m c o books.
ku i p aki j p books k fo.
```

第1文は葵が赤くて大きい本を2冊読む。数量は複合語全体に付き、この場合は条件を満たす本を2冊数える。第2文では、同じ葵と同じ2冊を明示して、子供へ渡すと述べる。複合語にも従来の数量 `m`、名前 `n`、参照の登録 `o` を使える。

同じ複合語を別々に書くだけでは、同じ物を指すとは限らない。同じ対象を続けて述べるときは `o` と `p` を使う。引用符内の名前に `-` があっても複合語とは解釈せず、その名前の文字として保存する。

## 性質を否定の外へ出さない

```text
noema d d
u [ vac i fo j jx-sai ].
```

この文は「子供が赤い本を読む」という内容を否定する。解析器は複合語を、独立した「本が赤い」という肯定文へ分解して否定の外へ追加しない。複合語を含む項、数量、参照、否定の構造をそのまま保存する。複雑な量化や存在の推論を行う機能は設けていない。

性質が成立する日時と場所は未指定である。主節に「昨日」を付けても、性質へ時刻を自動的に配布しない。性質がいつ成立したかを明示して述べるには、参照を使って別の状態文を書く。

```text
noema d d
e sai i jx o book.
s vac i fo j p book.
```

これは、その本が過去に赤かったことと、今日子供がその本を読むことを別々に述べる。今日も赤いとは補わない。

## 編集・保存・旧版との関係

`python -m noema edit` の「複合語を作る」で対象と性質を選ぶと、対応する語を入力位置に挿入できる。文全体は「検査する」で確認する。旧版を開いた場合は、複合語を使う前に先頭を `noema d d` へ変える。0.3の語や文法は0.4でも同じ意味になる。

```powershell
python -m noema parse --input examples/compound-diary.noema
python -m noema render --input examples/compound-diary.noema --output artifacts/compound-diary.svg
python -m noema format --input examples/chase.json --edition 0.4
```

意味JSONでは、各対象の `concept` に基本概念のID、`qualifiers` に性質のID列を保存する。数量、固有名、解析の確信度を性質に混ぜない。旧版からの変換では性質の空列を追加し、空列だけなら旧版へ戻せる。性質を持つ対象を0.1〜0.3へ変換する操作はエラーになる。性質を捨てたり、否定の作用範囲が違う文へ置き換えたりしない。

固有文字でも結合記号 `-` はそのまま使う。文字コードと字形は [アルファベットの仕様](alphabet.md)、基本語は [語彙参照](lexicon-v03.md)、文の役割・時間・質問などは [0.3の入門](writing-v03.md) を参照する。自然言語解析器が複合語を自動抽出できるようになったわけではない。

## 練習と解答

1. 子供が熱い水を飲む文を書く。
2. 葵が赤い本を3冊読む文を書き、次の文で同じ本を先生に渡す。
3. 子供が小さい本を読む、という内容を否定する。

それぞれの解答例は次のとおり。参照名や役割の順序は変えてよい。

```text
noema d d
vab i fo j mab-saq.
```

```text
noema d d
vac i qo n "葵" o aki j jx-sai m d o books.
ku i p aki j p books k zr.
```

```text
noema d d
u [ vac i fo j jx-sal ].
```
