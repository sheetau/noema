# 検証と記録管理の改善

## 保存したもの

言語の構文・評価器・意味規約・原文・既存の判断・検査報告・旧検証器は変更していません。改善前の言語変更は `1a3848c` です。

旧READMEの377,712バイトと旧進捗文書の271,520バイトを、それぞれ `README.history.md` と `docs/written-progress-history-through-20261020.md` に保存し、Gitの改善前の内容とバイト単位で一致することを確認しました。元の改行とエンコーディングも維持しています。

## 実行方式

`scripts.project_work` は、既存の検証関数を同一プロセスで呼び出す新しい入口です。過去の証拠が固定している検証器を編集せず、実行中だけ解析・カタログ・レビュー読込みをキャッシュ付きの関数へ切り替えます。失敗時も元の関数へ戻します。

SQLiteには圧縮JSONと依存ハッシュを保存します。ファイル内容、文書集合、検証器群、Pythonの版を使って再利用を判定します。カタログや原文に変更があれば失効します。元の入力を読み直さずに更新日時だけで通す方式ではありません。

一回の同期的なレビュー検証では、重複したハッシュ一覧をまとめて照合します。結果を受理する前に入力集合を再ハッシュし、途中の変更があれば中止します。テスト全体やセッション全体を一つの固定スナップショットとは扱いません。既存のテスト関数は毎回実行します。

全体監査は、変更がないときは保存結果と依存入力を照合します。変更時には旧監査器で再集計し、個別文書の検証済み宣言名一覧を再利用します。集計で参照しない全文ASTを保持し続ける必要もなくしました。原文範囲の結合・数式の所属・完成件数の規則は旧関数のままです。`--full` は永続キャッシュを迂回します。保存値は辞書の順序も維持し、既存の生成物の再現に影響させません。

## 判断の参照

登録簿の形式2（今回のファイルは `semantic-review-index-v113.json`）は、元の完全な判断記録と現行文番号を直接参照します。元の記録の八要件・根拠・全原文範囲を従来の検証器で検査したうえで、現行文の内容、依存定義と意味規約、関連する識別表記の一致を確認します。文番号の変更は明示的な対応が必要です。意味が変わる場合は引き継ぎを拒否します。

元の記録や古い登録簿は削除しません。今後、本文を更新するたびに十二の大きな判断ファイルを複製する必要がなくなります。新たな原文の判断はアシスタントまたは人が従来の要件に従って作成し、テスト結果から自動生成しません。

## 維持する作業ルール

AGENTS.mdとWORKFLOW.mdに、一文または意味要素群を先に計画し、局所検査をまとめ、統合の区切りに全体監査する手順を記載しました。正本の指定は `data/work-state.json` に集約しています。長い履歴は検索して読み、READMEへ毎回の作業結果を追記しません。

SQLiteは正本の代用にはしていません。証拠本文をDBに移すと固定ハッシュやGitの差分閲覧に影響するため、今回の用途ではファイルを残し、再生成可能な索引とキャッシュだけをSQLiteへ移しました。ダッシュボード、常駐サービス、goalの自動再開処理は追加していません。

## 検証

入力改変、同じサイズ・更新日時の改変、検証器の変更、キャッシュ値の破損、元の証拠の変更、意味規約の変更、判断の重複、不完全な原文範囲、文番号の移動、関連する名前の変更を検査します。新規・変更・削除された対応報告が集計へ反映され、保存結果が失効することも確認します。

実データ1,196文書・483対応報告で、次を確認しました。所要時間は同じ環境での一回の観測値です。実行中に別の検証が重なった区間もあり、厳密な単独性能試験や将来の全作業時間の予測ではありません。

| 操作 | 秒 | 確認 |
| --- | ---: | --- |
| 旧登録簿の全体監査、キャッシュなし | 473.151 | 保存済みv1集計と完全一致 |
| 新入口で初回の全体キャッシュ作成 | 308.143 | 同じv1集計と完全一致。事前の局所検査でカタログは作成済み |
| 同じ全体監査を再利用 | 1.920 | 同じv1集計と完全一致。入力約715MBをハッシュ照合 |
| 簡潔な登録簿へ移行 | 5.884 | 元の12判断を保持、新たな意味確認なし |
| 新登録簿をキャッシュなしで検証 | 124.755 | キャッシュ使用時と全結果が一致 |
| 新登録簿によるv2集計の作成 | 1.893 | 原文範囲・数式対応・確認済み件数・対応報告を保持 |
| 一件の対応報告を追加した差分検査 | 4.370 | 重複報告を検出対象に含め、対応分量や完成件数は水増ししない。削除後の集計も完全一致 |

差分検査は、実際の第四文報告を一時的に別名で追加したもので、新しい原文の意味判断を行う試験ではありません。一時ファイルは削除済みです。通常の新規文書では、その文書の解析と新たな意味検査の時間が加わります。

登録簿は188,334バイトから5,351バイトになりました。従来の引き継ぎ判断12ファイル計2,630,131バイトは保存したまま、今回の移行では同様のコピーを追加していません。途中のメモリ観測では、旧方式に約4.3GB、新方式に約190MBの例がありました。ピークメモリを一定条件で比較した測定ではありません。

回帰検査111件、および実際の第四文の5テストと保存済み報告の再現を確認しました。数値の根拠と入力ハッシュは [検証記録](../data/validation-workflow-v1.json) に保存しています。
