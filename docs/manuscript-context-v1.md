# 文脈に依存する参照を型で区別する

二論文には、著者や時計などの個体、文章を提示する状況、数、有限列、関数を文脈から受け取る宣言がある。引数がないという理由だけで、全てを固有名へ置き換えることはできない。今回、正本の全ての0引数primitiveについて実際の結果型と引用内の直接参照を点検した。

| 結果型 | カント | アインシュタイン |
| --- | ---: | ---: |
| 個体 | 467 | 799 |
| 状況 | 40 | 22 |
| 数 | 2 | 12 |
| 有限列 | 2 | 3 |
| 関数 | 0 | 234 |
| 合計 | 511 | 1,070 |

例えば、アインシュタインの著者表示の文脈は状況型で、著者本人は個体型である。共通の光速度は有理数を真偽値へ写す関数型の値として保持され、単なる個体名ではない。型の分類は意味の同一性や語義の説明済み判定を与えない。

## 本文から取り出した二つの文脈付き定義

カント正本の主張12（0始まり）は、第三段落第一文から第二文への本文順序を述べる。文中の二箇所・提示状況・本文順序の関係を、それぞれ個体・個体・状況・関数として受け取る4引数の局所定義へ変換した。出来事の時間順序や因果へ読み替えない。

アインシュタイン正本の主張42は、名称を著者本人へ適用し、同じ提示が同じ文書の著者表示として行われることを述べる。名称と人物が異なる条件を保持し、提示・名称・人物・文書・状況・三つの提示関係を8引数として明示した。既存の下位定義は本体を変えず、文書内の可視名へ改名した。表示の真正性や自筆性は追加しない。

`scripts.context_abstraction.abstract` は、選んだ0引数定義の直接のprimitive依存を、元の型に対応する値または関数引数へ変換する。既存の型付き引数・適用・定義を使うため、新しい基本関係・共通辞書項目・書式版は追加しない。名前は文書内の複合名であり、数値の名前表は使わない。

引用の内部に文脈の名前がある場合は変換を拒否する。値を引数へ変えることと、引用された名前を保存することは別の問題だからである。依存定義の中に隠れた文脈入力がある場合、0引数関数そのものへの参照、別規則が必要な明示的関数適用も拒否する。対応できない入力を同じ意味だとして処理しない。

## 検証と未完の範囲

[型付き定義](../examples/v016/manuscript-context-templates-v1.noema)は計3定義で、個別の文脈の値や原文の主張は含めない。[入力の役割と対応](../data/manuscript-context-interfaces-v1.json)には、旧正本の宣言・主張・意味規約・新しい引数の型を保持する。これは変換を検査する証拠であり、円文字の復号に使う名前表ではない。

元の文脈入力を戻した結果を正規化し、二つの元の宣言群と厳密に一致することを確認する。保存した円文字も第12版375語の読解器で復元する。1つの真偽だけを確認するのではなく、二値の個体域・二つの状況を使って本文順序、名称と人物の相異、三関係の成立条件、全ての対象引数と状況の取り違えを38件の診断で調べる。これは引数結合の診断であり、全関係解釈の総当たりではない。

**この成果物は、文脈入力を明示した条件付きの定義である。二つの元の主張を移行済みとは数えない。** 著者・箇所・文書などの指示対象と関係の意味規約を、本文の中で導入して接続する作業が残る。引用に現れる文脈名を保つ経路も必要である。名前だけを置いて意味を説明済みとする方法や、全ての文脈入力を新しい共通語にする方法は採らない。

```powershell
python -X utf8 -m scripts.project_work check --module scripts.check_manuscript_context --prepare --tests tests/test_context_abstraction.py --verify reports/manuscript-context-v1.json
```
