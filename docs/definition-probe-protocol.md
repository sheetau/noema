# 概念定義との比較：事前に固定する探索条件

この検査は、既存エンコーダーの重みを一切学習せず、Noemaの概念を定義文で追加できるかを調べる小規模な探索である。プロンプトによる生成、文の検索、学習済み分類器、文ごとの修正規則は使わない。定義文はエンコーダーへのデータであり、命令文ではない。

## 予測前に固定する資料と処理

- `data/definition-probe-v1.json` の日英48組、計96文を使う。各言語は対応する概念40件、語義違い・未知概念8件。入力文全体ではなく、指定した範囲の意味のみを評価する。例えば対象語以外に未対応の語があっても、この検査の未対応入力とは数えない。
- 対応範囲を正解から与える。範囲抽出の性能は測らない。既存の15概念から14件、文語の追加概念から26件を含む。資料は開発者がこの探索用に書いたものであり、利用者の文章や無作為抽出した一般文章ではない。
- 候補は文語0.3の91概念すべて。既存の英語定義と日本語定義をそのまま使う。予測を見て定義・正解・文を変えない。定義文の記述が概念の区別に十分かどうかも、この方式の制約に含める。
- モデルは `resources/models.json` で固定済みのXLM-Rと多言語MiniLM。CPU・float32・evalモード・8スレッドまでの決定論設定を使い、モデル・実行環境・資料・コードのハッシュを保存する。
- 各定義の注意マスク平均を単位ベクトルへ正規化する。日英定義のベクトルを平均し、再び正規化して各概念の代表とする。
- 入力表現を3通り比較する。(1) 指定範囲だけを単独で符号化して注意マスク平均、(2) 全文中の指定範囲に重なるトークンの文脈ベクトル平均、(3) 全文の注意マスク平均。特殊トークンは(1)(3)の平均には入り、(2)では位置範囲がないため除く。全文平均は範囲の区別をしない対照条件である。
- 全91候補とのコサイン類似度を求め、同点は概念ID順とする。正解の概念種別による候補の絞込みをしない。途中切断された文・定義、トークンのない範囲はエラーにする。

MiniLMの平均方法は[公式モデル説明](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2)の注意マスク平均に合わせる。文ベクトル向けのモデルの内部トークンが、そのまま概念分類に適するとは仮定しない。XLM-Rも、未学習のコサイン比較は単純な基準であり、モデルが持つ知識全体の上限を測るものではない。

## 集計と解釈

言語・モデル・入力表現ごとに先頭候補の正解率、上位3候補への正解包含率、既存／追加概念の内訳、日英の候補一致、全候補上位3件と得点を保存する。最低6件を再推論し、数値の反復一致を検査する。

未対応8件については最も近い候補と類似度を記録する。棄却閾値はこの資料から選ばない。コサイン類似度を確信度や確率と呼ばない。既知の正解・既知の誤り・未対応の得点分布を比較し、棄却方法を後続の別資料で検証する必要を判断する。

正解範囲を与えても先頭候補の正解率が95%に届かない場合、この単純方式だけを意味解析器へ置き換える根拠にはしない。95%に届いた場合も、範囲・役割・否定・時間・未対応判定を検査していないため、意味構造完全一致率95%を達成したとはしない。元の確定率80%以上・確定出力の構造完全一致率95%以上という採用基準は変更しない。

この探索を見た後の改良は同資料上では回帰比較として扱い、採用判断には別の未使用資料を使う。
