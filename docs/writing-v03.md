# Noema 0.3で文章を書く

0.3は、出来事・状態を述べる文、質問、依頼、条件をつないで書くための版である。91概念を持ち、主体・対象・受け手・場所に加えて、出発地・到着地・道具・受益者を指定できる。0.1と0.2の文章は、それぞれの版の規則で引き続き読める。

## 最初の文

```text
noema c c
vac i qo n "Aki" j jx.
```

これは「Akiが本を読む」。`vac` は読む、`i` は主体、`qo n "Aki"` は名前で指定した人物、`j` は対象、`jx` は本を表す。文末に `.` を置く。ヘッダー `noema c c` は文法版と語彙版を指定する。本文では単語間を空白で区切る。改行と空行も空白として扱うので、段落を分けても意味は変わらない。

まず代用文字で書き、固有文字の形を覚えながら表示を切り替えられる。32文字と代用文字の対応は [文字一覧](../examples/alphabet.svg)、文字の入力・保存方式は [アルファベットの仕様](alphabet.md) を参照する。代用文字は発音記号ではない。

## 対象と役割

| 標識 | 役割 | 用例の読み方 |
|---|---|---|
| `i` | 主体・状態の担い手 | `i qo n "Aki"` Akiが |
| `j` | 対象 | `j jx` 本を |
| `k` | 受け手 | `k fo` 子供に |
| `l` | 出来事の場所 | `l lac` 学校で |
| `z` | 出発地 | `z tp` 家から |
| `2` | 到着地 | `2 lac` 学校へ |
| `3` | 道具 | `3 man` ペンを使って |
| `4` | 受益者 | `4 fo` 子供のために |

```text
noema c c
vae i qo n "Aki" z tp 2 lac.
vad i qo n "Mio" j mao k fo l lac 3 man.
```

第1文はAkiが家から学校へ移動する。第2文はMioが学校で子供に向けて、ペンを使って紙に書く。到着地と出来事の場所は別の役割として保存する。役割の順を変えてもよいが、同じ役割を一つの節に2回書くことはできない。

使える役割は述語ごとに決まる。たとえば「食べる」には出発地を指定しない。場所の役割には場所の語が必要で、「学校へ」の代わりに「犬へ」を書けば型エラーとなる。一方、状態の一部は物と場所の両方を担い手にできる。`sak i lac.` は学校が大きいという状態を述べる。

省略した役割と `?` は、どちらも未指定である。「主体を省略した」ことから話し手や直前の人物を補わない。数量・時間・名前も、書かれていない情報は未指定のままにする。

## 名前・数・同じ対象の参照

```text
noema c c
vac i qo n "Aki" o aki j jx m c o books.
ku i p aki j p books k qo n "Mio".
```

第1文はAkiが数量2の本を読む。第2文は、そのAkiが、その2冊の本をMioに渡す。`o aki` と `o books` で対象を登録し、`p` で参照する。参照名は自由に選ぶ文字列で、`books` の英語としての意味は解析しない。正規形では参照名を `na`、`nb` などに統一する。

名前には `n "…"` を使い、引用符内のUnicode文字をそのまま保存する。語彙にない物を名前だけで新しい種類として定義することはできない。たとえば `maa n "Aki"` は人を指定するが、`maq n "Aki"` はAkiと名付けたコンピューターになる。

数量は `m` の後に32進で書く。`a=0, b=1, c=2, …, 7=31, ba=32, bb=33`。数の先頭の余分なゼロは禁止する。物質の数量は、文脈で区切った部分の個数を表す。水の量を勝手にリットルへ解釈しない。単位付き測定、分数、範囲、全称量化はこの版では表さない。

## 状態を別の文で詳しく述べる

```text
noema c c
sab i qo n "Aki" j mal o bag.
sai i p bag.
sak i p bag.
```

これは「Akiが鞄を所持する。その鞄は赤い。その鞄は大きい」。属性を表す述語を共有参照へ結び付ければ、新しい形容詞付きの単語を作らずに説明を組み立てられる。「大きい」は比較対象を未指定にした概念であり、寸法を主張しない。所有者と物の属性を一つの概念へまとめず、各文の意味を保持する。

新語の字面だけから意味を推測する規則は設けていない。追加語の `ma…` は対象、`la…` は場所、`va…` は出来事、`sa…` は状態という分類上のまとまりを持つが、末尾の文字は辞書で学ぶ必要がある。既存の2文字語もそのまま使う。形を変えるだけで新しい概念を作る生産的な派生規則は、今後の仕様対象として残している。

## 時間・否定・質問・依頼・接続

これらの規則は [0.2の文法](writing-v02.md) を引き継ぐ。時間は `e/f/g` が過去・現在・未来、`r/s/t` が昨日・今日・明日、`q "2026-09-27"` が日付である。相対日付を実行日の絶対日付へ置き換えない。

```text
noema c c
s vac i qo n "Aki" o aki j jx o book.
u [ t vac i p aki j p book ].
b vac i c j p book.
d vaf i p aki j p book z lac 2 tp.
y [ t wm i p aki ] [ t vaa i p aki j mad ].
```

順に「今日Akiが本を読む」「明日Akiがその本を読むことを否定する」「その本を読む主体を尋ねる」「Akiがその本を学校から家へ運ぶよう依頼する」「明日Akiが空腹なら、明日Akiがパンを食べる」を表す。

`u [ … ]` の否定範囲、質問の `b`、回答を求める役割の `c`、依頼の `d`、条件の `y [ 条件 ] [ 帰結 ]` は別々に保存される。`w` は両方、`x` は少なくとも一方を表す。条件を因果関係や反事実条件へ読み替えない。文の順序だけから出来事の時間順も推定しない。

## 入力と保存

```powershell
python -m noema edit
```

表示された `http://127.0.0.1:8765` をブラウザーで開く。「検査する」で意味構造と固有文字表示を確認し、「正規形にする」で参照名と役割順を整える。「固有文字にする」は同じ文章を固有アルファベットへ置き換える。語彙検索のボタンで語を挿入できる。文章・意味JSON・SVGをそれぞれ保存する。入力文はサーバーのログやディスクへ自動保存しない。終了はターミナルでCtrl+Cを押す。

CLIの `parse`、`format`、`render`、`script` でも同じ規則を使う。`format --edition 0.3` で旧版から移行できる。逆方向の変換は、旧版にない概念・役割・作用範囲を含む場合にエラーとなる。意味を捨てて変換することはない。

自然言語の `analyze` は別の実験系であり、91概念の全体にはまだ対応していない。直接記述できる範囲と、日英から自動抽出できる範囲を分けて評価する。

## 語彙の追加と版管理

概念定義、語形、許可する役割、役割が受け取る型を [版付き資源](../noema/resources/language-v03.json) に保存する。概念の追加時は正例と拒否例、正規形の往復、旧版との変換を検査する。既存IDの意味や語形を上書きしない。定義の変更が必要なら新しいIDと版を発行し、旧定義を保持する。モデルのクラスタ番号や学習順を語彙IDに使わない。

この版での自動検査は、定めた意味構造の保存を確認する。未知の書き手が資料だけで読み書きできるか、字形を誤認しないか、必要な語が足りるかは、利用者による別の検証が必要である。
