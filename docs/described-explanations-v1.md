# 原因説明で採用した要因の記述を保持する

[原因説明の定義群](../examples/v013/described-explanations.noema)は、ある要因を原因として説明に採用したことを、その要因と結果が真であることから分ける。既存0.13の式への言及を使い、1基本関係・3定義を追加した。構文と文字体系は変更していない。

## 真偽が同じでも、説明の要因は同じとは限らない

前のカント草案では、原因の要因と結果を命題内容の値としてahへ渡していた。命題内容の同一性は全状況での真偽の一致である。そのため、評価する全状況で「理解能力が不足する」と「決意と勇気が不足する」がともに真なら、二つの要因をahで区別できない。同じ引数に対して、一方だけを採用するとは述べられなかった。

新しいeaは、性質の記述と、その性質を述べる対象をそれぞれ受け取る。記述はNoemaで定義した性質を指す。原語の文字列、外部リンク、説明のないラベルを内容の代わりに渡してはいない。

```text
要因についての対象と性質の記述
結果についての対象と性質の記述
説明を採用する文脈
```

例えば、ある人の決意と勇気の不足を、その人の未成熟の原因として説明に採用できる。二つの対象は別々の引数なので、装置側の不調を別の対象側の状態についての説明に採用する場合も、同じ関係を使える。対象・説明の向き・文脈を取り替えると別の関係になる。

記述の区別には限界がある。正規化した構文が同じなら同じ記述と扱うが、異なる定義名が同じ機構を指すかは自動判定しない。今回の修正は、異なる説明が真偽の一致だけで潰れる問題を解消するものであり、因果機構の同一性を完全に判定する仕組みではない。

## 採用・成立・対比を分ける

| 記号 | 条件 |
| --- | --- |
| ea | 指定した要因の記述を、指定した結果の原因として説明に採用する基本関係 |
| eb | 両方の記述を対象へ適用し、指定状況で両内容が成立する |
| ec | eaとebがともに成立する |
| ed | 同じ対象・結果・文脈で、選択した要因は採用し、除外した要因は採用しない |

eaやedだけでは、要因・結果の内容は真でなくてもよい。誤った原因説明を採用したことも記述できる。逆に、ebだけでは原因として説明に採用したとは言えない。ecでも、介入効果や因果機構の存在を証明したことにはならない。

ebとecは記述を評価する脱引用を含む。現行の引用規則では、これらを参照する式をさらに引用できない。edは記述をそのままeaへ渡し、脱引用しないので、引用されるカントの定義に接続できる。この制約は回避せず、検査で保持した。

## カント草案への接続

[更新した冒頭草案](../examples/v013/kant-described-explanations.noema)には、理解能力の不足bj、決意の不足bq、勇気の不足br、後二者の論理積bsを独立した定義として置いた。原因説明bdはbsを採用し、bjを採用しないことを、未成熟bcと組み合わせる。各要因を同じ人へ適用し、結果は同じ未成熟の定義bfを指す。

旧ahは比較用に宣言を保持しているが、新しいbdからは呼び出さない。bsとbjの内容値が同じ検査例でも、bdが説明の対比を保持できる。能力の評価範囲、離脱後の達成方法、六つの本文箇所からの参照は前の草案を引き継ぐ。

ここで記述したのは、採用した原因説明に従う分類である。客観的な因果の成立や、責任を負わせる規範的な正当性までは定義していない。また、決意不足と勇気不足を論理積で読む選択は先行草案のままで、原文の不足の作用範囲を確定したとはしない。能力・離脱・ラテン語の意味確認も残るため、全文単位の完成数はカント0/20・アインシュタイン0/282を維持する。

## 検査と再現

要因の真偽・結果の真偽・二要因の採用可否を組み合わせた16例を検査した。原因として採用しない単なる同時成立、内容が偽でも採用された説明、同じ真偽表を持つ異なる記述を区別する。カントの11例では、対象・結果の記述・文脈・説明の向きの取り替えや、二要因とも採用してしまう場合を検出した。

旧ahでは同じ内容値を渡すため対比が成立しないことを、関係値が真の場合と偽の場合の2例で確認した。本文への帰属では、能力・原因・内容の計算をせずに六区間の記述を参照できることも検査する。これらは指定した有限解釈についての検査であり、原文との同義性や現実の因果関係の証明ではない。

```powershell
python -S -m scripts.compose_described_explanations
python -S -m scripts.check_described_explanations --verify-only
python -S -m noema parse --input examples/v013/kant-described-explanations.noema --output artifacts/kant-described-explanations.json
python -S -m noema render --input examples/v013/kant-described-explanations.noema --alphabet v2 --output artifacts/kant-described-explanations.svg
python -m pytest -q
```

[検査記録](../reports/described-explanations-v1.json)に入力ハッシュ、定義の対応、確認範囲を保存する。今回の構成・検査・解析・表示はモデルやソルバーを使わない。
