# 読み書きの利用者確認

文法の自動テストは、意味の保存や不正入力の拒否を検査する。人が資料を読んで未掲載の組合せを書けるか、固有文字を識別できるかは、別に実際の利用者へ確認する。現在保存しているブラウザー操作の記録は自動操作による動作確認で、利用者の成績には数えない。

## 試す手順

`python -m noema edit` を実行し、`http://127.0.0.1:8765/practice` を開く。文語編集画面 `/writing` の「読み書きを試す」からも開ける。読む12問、書く6問があり、役割交換・否定・省略・数量・相対時間・名前・参照・質問・条件・複合語・移動の方向を確認できる。

最初に [0.3の入門](writing-v03.md) と [複合語の入門](writing-v04.md) を読む。課題中の手引き・語彙・文字一覧も参照してよい。読む課題は代用文字と固有文字を切り替えられる。文字の識別を確かめる場合は、固有文字で最初に回答し、分からなかった語や混同した文字を記録する。代用文字で解答を確認した後の固有文字の回答を、独立した初見の成績と扱わない。

回答を確認すると、読む課題は選択肢、書く課題は正規化した意味構造で採点する。参照名と役割の順序が違っても同じ意味なら一致する。任意の同義表現をすべて同一化する採点器ではないため、各問が指定した基本語を使う。解答を見た後の再回答は、最初の回答と区別して保存する。

## 記録と判定の範囲

結果JSONには課題版・内容のハッシュ、表示方式、各回答の正誤と解答参照の有無、任意の所感を保存できる。名前や連絡先は求めず、回答をサーバーのファイルや外部サービスへ自動送信・保存しない。「自分で回答した結果であることを記録する」は自己申告であり、利用者の身元や試験条件の検証機能ではない。

確認するのは、初回回答の正誤、繰り返し間違える役割や作用範囲、混同した文字、資料を読んでも書けなかった内容である。正答数だけで必要な語彙が十分かを判断せず、自由記述の所感も設計へ反映する。この18問の正解や自動操作の成功だけで、言語全体の習得容易性を証明したとはしない。

利用者による実施結果はまだ得られていない。自動確認では、誤った役割の選択、解答参照、役割順を変えた正しい文、固有文字表示、結果の保存が動作し、保存例の `self_reported_human` が `false` であることを検査した。
