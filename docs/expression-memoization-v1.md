# 同じ束縛で評価した式の結果を再利用する

有限評価器に、式の計算結果を再利用する `memoize_expressions=True` を追加した。前回は計算上限に達した相対性原理の13対象・二法則・二候補履歴のモデルを、同じ1,500万ステップの上限内で最後まで評価できた。Noemaの文書、量化の範囲、法則や基本関係の解釈は変更していない。

従来の `memoize_definitions` は、基本型の引数と結果を持つ定義の呼出し全体を再利用する。今回の問題では、関数を引数に取る定義の内側で、同じ履歴・記述・法則の照合を多くの組合せについて繰り返していた。新しいオプションは、定義全体だけでなく、内部の同じ式の評価結果も再利用する。

## 再利用の条件

キーは、構文上の式の位置と、その式が参照する自由変数の値である。例えば外側の `x` だけを使う式を、内側の `y` の全値について繰り返す場合、`y` が変わっても再計算する必要はない。一方、式が両方を使うなら両方の値を区別する。

量化、命題内容、関数抽象が導入した束縛変数は、外側の自由変数から除く。関数が外側の変数を捕捉している場合は、その依存を保持する。引用された式は閉じた記述として扱い、引用するだけでは実行しない。

再利用する結果は、個体・状況・真偽・有理数・命題内容・発話という基本型に限る。関数、列、質問、式記述の結果は再利用せず、関数を勝手に同じものへ統合する処理も行わない。自由変数の値が関数の場合は、その関数オブジェクト自体を区別する。有限個の入力を試して、異なる関数を同一と認定することはない。

キャッシュは一回の評価内だけに存在する。別のモデルや文書へ持ち越さない。成功した評価結果だけを保存し、再利用時もステップを消費する。型検査、計算上限、全有理数・無限の列・式記述領域への有限量化の拒否を維持した。論理演算の枝の評価方法も変更していないため、偽の前件の後ろにある未対応の量化が黙って無視されることはない。

オプションの既定値は無効である。有効にする呼出側は、同じ入力への結果が変わらず、副作用や呼出し回数に意味を持たせない基本解釈を与える必要がある。時間依存の観測関数や乱数を返す関数を、そのまま安全に再利用できるという機能ではない。

```python
rows = evaluate_document(
    document,
    individuals=individuals,
    situations=situations,
    primitives=primitives,
    max_steps=15_000_000,
    memoize_definitions=True,
    memoize_expressions=True,
)
```

## 検査結果

元の13対象のモデルは、定義の再利用だけでは現在も1,500万ステップを超える。式の再利用を併用すると原理全体が成立するという結果を得た。第二法則・第二履歴での不一致、記述の欠落、逆方向の範囲欠落、空の法則範囲、座標系対の欠落、追加した第三座標系での不一致という六つの反例は全て拒否した。結果は、記述の集合と適合値の集合を直接比較する独立した計算とも一致する。

変数依存の小さい検査では、同じ基本関係への呼出しが36回から12回になり、結果は変わらなかった。これはその検査内の呼出し数であり、全般的な速度向上の倍率ではない。入れ子の関数、異なる関数引数、状況ごとの命題内容、列の集計、質問の答え、引用と脱引用、型エラー、計算上限と未対応領域も検査した。

新規11件と既存4件の再利用に関する検査が通過し、その後の全936テストも通過した（508.75秒）。元文書のバイト一致、新しい検証記録の入力ハッシュ、既存の進捗集計の再生成一致も確認した。過去の検証記録は更新せず、当時の実行器のハッシュを保持している。

今回の変更で、前回小さいモデルに分けていた検証の一部を元のモデル全体で実行できた。任意の規模で実行できることや、任意の物理系について原理が正しいことを証明した結果ではない。元の文書・検証記録は当時のものとして保持し、今回の結果を別の記録へ保存した。原文との意味一致を確認済みの区間数は変わらない。
