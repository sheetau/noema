# 提示・応答・発話行為の関係を結ぶ

同じ発話行為について、提示、受領、理解、受諾、辞退、依頼・助言・約束・命令の表明、内容の実現を別々に記述する。[共有Native](../examples/v016/shared-speech-v1.noema)は19定義で、既存の提示・帰属7定義を保持し、12定義を追加した。[型・役割・解釈の規約](../data/shared-speech-basis-v1.json)に引数の意味を明示する。

新しい基本宣言はないが、社会的な解釈入力まで無くしたわけではない。依頼の表明、理由による評価、引受け、指示権限の行使表明などを関数の引数として渡す。ここで追加したのは、それらを同じ話者・受け手・行為・記述へ結ぶ構成と、入力の意味規約である。依頼や約束の意味を論理演算だけへ還元した、あるいは表面の文から自動認定できるという主張ではない。

## 提示から理解・応答まで

既存の[発言の帰属先](speech-principals-v1.md)から、rfo/rga/rgb/rhe/rhf/rhg/rhhを順にspeechpresented、speechattributed、speechdelegated、speechownvoice、speechothervoice、speechvoicepair、audiencewithinへ改名し、本体と語義を保持した。発話が本人の声に帰属することと、本人の信念・真理・許可は別である。

speechtoは、同じ生起する発話行為で同じ人が一人の受け手へ提示する条件である。受け手を一人指定しても、他の相手へも提示した可能性を排除しない。

| 定義 | 追加する条件 |
| --- | --- |
| speechreceived | 同じ行為から、同じ対象・発話記述を受領した |
| speechunderstood | 受領した同じ記述を理解した |
| speechaccepted | 同じ発話を明示的に受諾した |
| speechdeclined | 同じ発話を明示的に辞退した |

受諾と辞退は互いの否定ではない。無応答では両方が成立せず、相反する記録を与えれば両方が成立することもある。このモジュールでその矛盾を自動修復しない。受諾して実行しない場合、受諾を表明せず対象行為が実現する場合も分けて記述する。

## 何を求め、何を引き受けたか

発話記述は対象から発話値を作る閉じた関数の記述、行為記述は行為者から命題内容を作る閉じた関数の記述として保持する。speechtargetedは、提示した同じ発話記述と、対象行為・行為者を解釈関係targetsで結ぶ。表面が質問であっても、明示された解釈の下で依頼の対象を記述できる。ただし質問形だけから依頼を推測しない。

| 定義 | 行為者と追加条件 |
| --- | --- |
| speechrequest | 受け手の行為について、その引受けを求める表明がある |
| speechadvice | 受け手の行為を指定目的に適すると話者が評価し、その同じ理由を同じ発話で受け手に示す |
| speechpromise | 話者自身の行為を、同じ発話で同じ受け手に対して引き受ける表明がある |
| speechcommand | 受け手の行為について、話者が指定役割の指示権限を行使すると表明する |

これらは相互排他的なラベルではない。一つの発話で依頼と助言を兼ねることを許す。助言は「理由を示す助言」という読みであり、全ての助言の形式を網羅しない。引受けの表明から話者の誠実さや有効な義務を、権限の行使表明から権限の正当性を導かない。評価の根拠を述べることと、その評価が実際に正しいことも別である。

## 記述した内容と実現

上の判定では、引用した行為や発話内容の真理を評価しない。requestrealizedとpromiserealizedだけが行為記述を明示的に脱引用し、指定した後続状況で内容を評価する。依頼では受け手、約束では話者を行為者に固定する。

この実現条件は、実行が発話を原因として生じたことや、約束の全条項を履行したという認定ではない。期限、解除、撤回、不履行、規範的有効性を加える場合は、それぞれの条件を結ぶ必要がある。未評価の行為を引用できることと、実現を問う際に未知の行為入力を評価できることを混同しない。

## 検査と次の接続

[検査記録](../reports/shared-speech-v1.json)は提示・応答128モデル、発話行為288モデル、実現32モデルを含む。68の束縛診断では、関係の各引数を一枠ずつ変え、別の話者・受け手・発話・対象・記述・理由・状況を借りると成立しないことを確認する。二値の小さな領域を用いる診断で、全ての引数の直積の証明ではない。

[組合せ例](../examples/v016/requests-promises-v1.noema)では、問いの形の依頼・理由提示型の助言が表明されていても受領・理解・受諾はまだなく、対象行為だけは後続状況で成立する入力を与える。別の約束では話者の引受けはあるが、話者の行為は実現しない。真偽が等しい別記述や発話の働きの変更を、元の解釈関係へ無断で代入しない。

次は円文字への接続に加え、問いへの部分回答、受諾・訂正・撤回を会話の前後状態へ結ぶ構成が必要である。今回の記録は発話行為の自動分類や社会的規約の完成を示すものではない。二作品の採用本文・意味判断・固定字体は保持する。
