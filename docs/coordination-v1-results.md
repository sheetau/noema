# 学習済みの並列関係を取り出す検査

固定したKWJAの係り受け分類器から、追加学習・生成・辞書補完なしで並列関係を取得する処理を実装した。公開KWDLCの公式開発512文書では、並列辺の適合率71.99%、再現率70.60%、F1 71.29%だった。**この出力をNoemaの集合へそのまま確定する方式は採用しない。** 構文の誤りに加え、並列関係だけでは「両方」「どちらか」や共同／分配を区別できないためである。

## 実装した範囲

WordModuleは複数の係り先候補ごとに種別を予測する。係り先のtop-kの先頭と、その候補に対応する種別のargmaxを組にして取得した。同点時に候補がずれないよう、係り先だけ別のargmaxで選び直さない。元の予測は変更せず、自己参照・循環・未知の係り先・不正な経路は不整合として保存する。

`P`という並列種別を持ち、経路も整合する直接の辺だけを抽出する。通常の係り受け`D`、同格`A`、不完全並列`I`は別に保持する。「と」等の文字列による判定はない。新しい語彙クラス、対訳表、例文検索も追加していない。

返す範囲は助詞等を含む基本句であり、意味的な成員の名詞範囲そのものではない。並列の両端には述語や修飾句も入り得る。辺を推移的にまとめて集合を作ることや、文語0.6への自動変換は行っておらず、APIも`research_syntactic_coordination`・`semantic_interpretation: unresolved`を返す。

## 注釈と結果

予測前に[検査条件](coordination-v1-protocol.md)を固定した。原コーパスの基本句行に実際に注釈された係り先と種別を使い、両端の句範囲と方向が完全一致する場合だけ正解とした。以前の不備を避けるため、注釈にない語彙主辞を取得して正解にする処理はない。原文・基本句位置は修正済みコーパスとも全件照合した。

[全件の報告](../reports/coordination-v1/development.json)は次のとおり。KWDLCは既存モデルの学習にも用いられている資料であり、未知資料での独立した最終評価ではない。

| 指標 | 結果 |
| --- | ---: |
| 解析成功 | 512 / 512文書 |
| 正解の並列辺 | 619 |
| 予測した並列辺 | 607 |
| 一致した並列辺 | 437 |
| 余分な辺／欠落した辺 | 170 / 182 |
| 適合率／再現率／F1 | 71.99% / 70.60% / 71.29% |
| 並列辺集合の文書完全一致 | 317 / 512 |
| 基本句と並列辺集合の文書完全一致 | 234 / 512 |
| 不整合な係り受け経路を持つ予測基本句 | 109 |

空の正解に正しく空を返す文書だけで成績が高く見えないよう、正解の有無でも分けた。

| 文書群 | 文書数 | 辺集合の完全一致 | 基本句も含む完全一致 | 余分な辺を出した文書 |
| --- | ---: | ---: | ---: | ---: |
| 正解の並列辺がある | 318 | 151 | 106 | 98 |
| 正解の並列辺がない | 194 | 166 | 128 | 28 |

欠落182辺の内訳は、端点の句がない31辺、係り先が違う80辺、係り先は合うが種別が違う66辺、経路が不整合な5辺だった。範囲抽出だけを改善しても、係り先・種別の誤りは別に残る。正解に並列のない文書で出した余分な辺は30辺だった。

## 検証と未解決事項

全512文書で、保存済みの従来解析と原出力が完全一致した。先頭8文書は再推論による反復一致を確認した。[保存結果の検証](../reports/coordination-v1/verification.json)では原コーパスから512件の正解を再構築し、全指標を再現した。[実行条件](../reports/coordination-v1/run.json)にモデル・依存ライブラリ・ソース・資料のハッシュを保存した。生成・辞書など禁止経路5種の呼出しは全て0回だった。

候補と種別の対応、同点、循環・不正経路、文ごとの句番号、句境界の不一致、失敗の分母、保存判断の改変検知、例外時のフック解除を含む全368テストが通過した。

```powershell
artifacts/kwja-venv/Scripts/python.exe -m scripts.probe_coordination
artifacts/kwja-venv/Scripts/python.exe -m scripts.probe_coordination --verify-only
```

中断から再開するときは`--resume`を使う。保存条件が変わっていれば拒否する。本文を含む解析記録は`artifacts/coordination-v1`へ保存し、Gitには件数・ID・ハッシュを含む報告を残す。

次に必要なのは、成員の範囲と、並列が表す意味を文脈から区別する共通の判定処理である。句間の構文精度を、集合の意味保持や全文の意味構造一致率へ読み替えない。英語の並列抽出、広い自然文への対応、95%以上の意味構造一致、辞書に依存しない逆変換は未達である。
