# 文字範囲と対象間の関係を学習する分類器

2026-09-27の最終評価では、**日英とも採用基準に達していない**。開発用データでは言語ごとにモデルを選ぶことで基準を満たしたが、未使用の文型・概念の組合せに対する成績が下がった。文語0.3の完成度と、この意味解析実験の成績は別に扱う。

## 構成と変更の理由

固定したXLM-RまたはMiniLMのトークン表現を、原文の各文字へ対応付ける。日本語のサブワード境界が名詞・助詞・活用語尾の境界と重なる問題に対して、文字位置ごとの範囲抽出を学習できるようにした。文字種・トークン内の相対位置・学習する文字埋め込みを加え、小型の双方向GRUと線形ヘッドで、範囲・概念・役割・時間・肯否・対応範囲内かどうかを分類する。エンコーダーの重みは更新しない。

数量は、抽出した文字範囲から十進整数として読む。0〜10などの有限ラベルへ丸めない。固有名も抽出範囲をそのまま保存する。数量を主体・対象などへ直接分類する方式では、別の対象へ数量が付く誤りが残ったため、数量範囲と対象範囲の関係を学習する小型ヘッドを追加した。文字間の距離も学習入力に含めるが、「一番近い名詞に付ける」といった固定規則にはしていない。

BIO範囲は文法的に成立する系列として復号する。数量は十進数字の範囲に限り、数字列の途中に数量の開始を置かない。概念や役割を自然言語の単語表で補正する処理はない。型・役割・範囲の不整合は未確定として返す。

学習するパラメーターはXLM-Rを入力とする分類器で374,451個。実行環境はCPU版PyTorch 2.12.0、Transformers 4.57.6、float32。重み・データ・復号処理のハッシュと実行環境を保存する。復号処理が学習時と異なるチェックポイントは、確信度の条件が未検証になるため読み込みを拒否する。

## 資料の分割とモデル選択

新しい [資料のマニフェスト](../reports/corpus-v2-manifest.json) は、モデル学習前に固定した。学習・開発・最終評価で、概念の組合せと実現された構文パターンを分離する。抽出範囲を役割ラベルへ置き換えた実際の表面形でも重複を検査し、名前も分割ごとに変えた。数量を含む対象や場所、肯否、時間の組合せを広げている。

各モデルの学習中は開発用データだけでチェックポイントと閾値を選ぶ。言語別に、完全一致率95%以上かつ未対応入力の誤確定率5%以下で確定率が最大になる閾値を採用した。この5%は追加した開発上の制約であり、元の必須条件である確定率80%以上・完全一致率95%以上は変更していない。

その後、開発用の採用条件を通ったモデルの中から、各言語の確定率が最大のものを選んだ。日本語はXLM-Rの40エポック時点、英語はMiniLMの15エポック時点となった。この [選択記録](../reports/routed-v4-selection.json) を保存してから、最終評価を実施した。推論時は利用者が指定した言語に従ってモデルを選び、入力内容を見て都合のよいモデルへ切り替えない。

## 結果

| 分割 | 言語 | 対応範囲内の件数 | 確定件数 | 正解件数 | 確定率 | 確定出力の完全一致率 | 未対応の誤確定 |
|---|---|---:|---:|---:|---:|---:|---:|
| 開発 | 日本語 | 410 | 344 | 344 | 83.90% | 100.00% | 3 / 77 |
| 開発 | 英語 | 775 | 710 | 677 | 91.61% | 95.35% | 5 / 149 |
| 最終 | 日本語 | 756 | 525 | 524 | 69.44% | 99.81% | 2 / 109 |
| 最終 | 英語 | 892 | 607 | 549 | 68.05% | 90.44% | 0 / 116 |

日本語の最終評価では、役割の重複・不整合が124件、対応範囲判定による棄却が94件、数量に関する構造不整合が13件あった。英語では、役割の重複・不整合が222件あり、確定出力でも58件で主体または対象が一致しなかった。開発用の採用点を通るだけでは、未見の語順に対する汎化を保証できない。

同じ意味の組に属する894グループのうち、構成する全例が確定したのは365グループ、その中で意味構造が一致したのは338グループだった。分割時に重複する文型を除いているため、すべてのグループに両言語が残っているわけではない。[最終評価のJSON](../reports/routed-v4-final.json) に集計と未対応例の種類別内訳を保存した。

チェックポイントを実際の `Analyzer` に読み込み、固定エンコーダーの学習可能パラメーターが0、全層が評価モードであることを確認した。反復した解析結果も一致した。手書きの旧回帰資料では日本語12件確定中10件正解、英語13件確定中13件正解だった。これは以前から使っている資料であり、新たな最終評価とは扱わない。

## 再実行

```powershell
python -m noema dataset --edition 0.2 --output artifacts/corpus-v2.jsonl
python -m noema features --dataset artifacts/corpus-v2.jsonl --model xlmr --output artifacts/corpus-v2-xlmr.pt --offline
python -m noema features --dataset artifacts/corpus-v2.jsonl --model minilm --output artifacts/corpus-v2-minilm.pt --offline
python -m noema.train_structured --features artifacts/corpus-v2-xlmr.pt --epochs 40 --output artifacts/attachment-v4-xlmr
python -m noema.train_structured --features artifacts/corpus-v2-minilm.pt --epochs 30 --output artifacts/attachment-v4-minilm
python -m noema analyze --checkpoint artifacts/routed-v4 --language ja --text "犬が猫を追う。" --offline
```

言語別の選択は `python -m scripts.select_routes`、固定したモデルの評価は `python -m noema.evaluate_structured`、選択済み構成の集計は `python -m scripts.report_routes` を使う。各コマンドの引数は `--help` で確認できる。選択・評価結果は既存のディレクトリーを上書きせず、新しい出力先へ保存する。自然言語解析の対象語彙は旧版の15概念で、0.3の追加語彙を学習済みとはしていない。

今回の最終評価資料は成績と失敗を確認したため、以後の変更では回帰検証用となる。次の改善では役割の関係分類と学習資料の多様性を見直し、既存の正解や条件を変えずに検証する。達成を判断するための新しい独立評価も必要である。個別文に対する補正規則を追加して成績を合わせる方法は採らない。
