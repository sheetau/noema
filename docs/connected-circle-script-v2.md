# 円と線の連結書記・試作02

試作01は、構文記号と名前の綴りに固定形を割り当てていました。利用者の求める、意味・文法・隣接関係によって変わる連結書記へ方式を変更します。既存の正式なNoema本文・字形資源・検証器は保持し、今回も独立した試作です。

## 描画単位

字形表に載った文字を並べません。通常の定義を展開し、意味関係と順序付きの参加者を取り出して、文全体の連結構造を生成します。入力の識別子を改名しても、解釈規約が同じなら同じ図になります。未知の語義を綴りから推測する処理はありません。

1. 原始関係の意味を[例文の解釈規約](../data/connected-circle-reading-v2.json)で明示する。
2. 通常の定義を合成する。同じ順序の参加者を持つ連言では、参加者と関係の境界を共有する。
3. 文法の範囲と役割の向きを配置に反映する。否定・選言・条件の境界を越えて参加者を融合しない。
4. 隣接する円の大きさ、高さ、共有する接合部を見て、線の出入口と経路を決める。

同じ関係が続いても、保存済みの語の画像を並べません。前の関係の出口が次の関係の入口になり、接合部の円と接続経路も変わります。「信頼」に「助ける」を合成した例では、三つの原始関係が二つの参加者を共有し、境界の円は前後両方の関係に属します。単一関係を一形にする場合と、複数関係が連続した一形になる場合を同じ生成規則で扱います。

「肯定的」という修飾は、見込みを表す核の同心円へ吸収します。同じ原始関係の複数の意味部品は、異なる段の円を同じ縦軸に置き、重なる一形にします。重なった円の隣へ斜線を接続するときは、無関係な円の縁を斜めに横切らないよう、両側を水平に入出する経路へ変更します。

## 幾何と接続の規約

- 円の半径は8・20・32、中心と横線の高さは0・40・80。表示には基準線を含めない。
- 線は縦・横・45度。円に触れる線は、その円の中心を通る方向に限る。点を参照の標識に使う。
- 例文は、一文につき全インクが一つにつながる。語境界で切らない。文間で切る。自動改行は未実装で、長い文は横長SVGに保持する。
- 参加者の標識は局所規約で登録した点／小円の列。同じ参加者は同じ標識を持つが、主語・対象で高さと接続が変わる。標識の列は長さを固定せず、アルファベットや数字の綴りへ対応させない。
- 構成の向きは参加者の局所順序と役割から決める。役割が逆なら意味部品の上下も反転する。論理範囲の入れ子では内部の向きが交互に変わり、両端の小円と内向きの腕が範囲を保持する。
- 連言は共有する中間の接合、選言は分岐して合流する経路、条件は下降する経路。否定は子構造の入口・出口の核を大円と斜線で変形し、その対で範囲を示す。

現試作の意味部品は「見込み・肯定的・行為・依存・利益」。これらは線上の位置や円の規模を変える操作です。原始関係はその組合せとして規約に記載します。接合と範囲を再帰的に構成するため、完成字形を有限のフォント一覧として用意する設計ではありません。ただし現行パーサの深さ制限と計算機の資源制限はあります。

## 例文の解釈

「信頼する」を、相手に肯定的な見込みを持ち、自分の選択を相手に依存させることの連言と読む、局所的な例です。「助ける」は相手の利益になる行為とします。自然言語の全用法を覆う定義ではありません。原始関係の意味が一意に幾何から発見されるわけではなく、意味部品の規約を学ぶ必要があります。

[Noema原文](../examples/v014/connected-circle-samples.noema)には定義と七文を保存しました。「信頼全体の否定」と「肯定的な見込みはあるが依存しない」は別の範囲として保持しています。肯定的な見込みと依存を別々に否定した文へ置き換えません。

## 再生成と検査

```powershell
python -X utf8 -m scripts.project_work check --module scripts.proof_connected_circle_script --prepare --tests tests/test_connected_circle_script.py tests/test_circle_alphabet.py --write-report reports/connected-circle-script-v2.json
```

`output/alphabet-circle-v2/` に、例文画像 `sentences.png`、融合と否定範囲の比較 `fusion-and-scope.png`、文字だけの `writing.png`、一文ずつのSVGと構造JSONを生成します。出力は再生成可能な成果物としてGitの対象外、実装・規約・原文・検査・ハッシュ報告をGitで保存します。

検査は、画像の塗りつぶしによる実接続、三段・三サイズ・放射接続、識別子改名不変、役割反転、定義変更、複合時の接合変更、論理範囲の区別を対象にします。七文の意味構造は、二者間の三関係を両方向について独立に変えた64解釈で、既存のNoema評価器と比較します。同じ通常定義の再利用はキャッシュし、連言内の同一関係は共有します。繰り返す定義が15段になっても、同じ意味を不要に長い字形へ展開しないことを確認します。

展開後の式も共有構造を持つDAGとして保存し、JSONへ出力するときに共有部分を指数的に複製しません。元の定義と使用箇所は原文の構文木に残します。

## 次に調整する範囲

まず利用者と、連結体の印象、円の重なり、線の密度、融合の程度を調整します。試作01の有限部品表に戻す変更は行いません。

現在描けるのは、個体定数を引数に持つ二項関係、通常の定義、主張、連言・選言・条件・否定です。引用・量化・数値・高階適用などは未対応として拒否します。二作品の全文をこの新方式で描ける状態ではありません。

原文、解釈規約、展開後の意味構造、描画対応を保持し、SVGのメタデータから同じ形を再生成できます。これは画像だけからの復号、全入力での字形の単射性、人による読み取り精度を保証するものではありません。現在の有限部品と小さい例文で方向を検証した段階であり、広い意味領域の部品規約・範囲の読みやすさ・長文の改行は、その後の設計課題です。
