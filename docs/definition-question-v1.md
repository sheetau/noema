# 表題の定義質問と、冒頭での回答の提示

カントの表題にある「啓蒙とは何か」という問いを、冒頭第一文の定義提示へ接続した。問いと回答の双方で、既存の`bi`が表す啓蒙の性質記述を参照する。原語を表す未説明の識別子に置き換えず、同じNoemaの定義を問いの対象と回答に用いる。

この追加は、問いへの回答を提示する文書であるという表題の枠付けを部分的に表す。最初の定義文だけで本文全体の説明が十分だと認定したり、後続の論述を回答から除外したりするものではない。既存の15主張はそのまま後続させ、表題と第一文を結ぶ帰属の主張を先頭に一つ追加する。

## 質問の答えを記述として扱う

答えの型は`i[h[a] e]`、すなわち個体から状況ごとの内容へ対応する性質の記述である。質問は既存の`g[...]`と`j v[...]`で構成し、新しい文法演算子は追加しない。

| 定義 | 内容 |
| --- | --- |
| `rqqp` | 参照記述と候補記述を同じ個体・同じ状況へ適用し、全個体・全状況で真偽が一致するかを検査する。 |
| `rqqq` | `rqqp`を候補条件とする、性質記述型の質問を作る。 |
| `rqqr` | 同じ参照から、質問全体の層1の記述を構成する。 |
| `rqqs` | 質問の提示、候補を概念説明として提示したこと、本文順序、回答としての関係を同じ著者・文脈で結ぶ。 |
| `hzic` | 表題の問いと、冒頭第一文にある`bi`の説明提示を結ぶ。 |

候補条件は、性質の外延が一致するという形式的な核である。自然言語で「何であるか」を説明する際の十分さや理解の成立まで、この条件に還元したとはしない。同じ外延を持つ別名や冗長な式も候補として認める。一方、著者がどの記述を提示したかは構文的な記述の同一性で照合し、別名を自動的に代入しない。

この違いにより、候補としては一致する二つの記述でも、それぞれを用いた質問の引用は区別できる。答えの正しさも、回答としての提示とは独立である。`rqqs`は候補条件を実行せず、著者が誤答や不十分な回答を提示したことも表せる。正しさを調べる場合に限り、`rqqp`または`h[質問][候補]`を明示的に評価する。

候補の検査には層0の性質記述の脱引用があるため、質問全体の記述は層1で保持する。`rqqr`による引用の構成時には内容を実行しない。具体的な候補を検査できても、全ての性質記述を有限個の候補で代用して列挙することはしない。

## 本文への接続

`hzia`は表題内の質問箇所を指す局所参照、`hzib`はこの型の質問を著者が指定箇所に提示する関係である。二つの基本記号に引数と意味規約を与えた。`hzib`は表題内の埋め込まれた問いも扱い、著者が現実の聞き手へ回答を要求した出来事とは区別する。

回答側は新しい帰属関係を作らず、既存の概念説明の提示`ua`と回答としての提示`hzcs`を使う。本文順序は`ue`、著者・文脈・冒頭の定義箇所は既存の`wa`・`wh`・`wb`を共有する。先頭に加える主張が、元の冒頭段落の主張`cp`と別の著者や別の定義箇所を指さないことを検査する。

対応範囲は`kant-1784:u0005`の「回答」という枠付け、`u0006`の質問、および既存`u0008`の第一文である。新しい二単位の空白を除く38文字を部分対応に加える。第一文は従来から対応範囲に含まれており、重複加算しない。啓蒙の語義、能力・原因・離脱の解釈、説明としての十分さが未解決なので、二つの表題単位も意味確認済みにはしない。

## 検証

四個体を二組に分けた真偽パターンと二状況を使い、参照と候補の16パターンずつ、全256組を検査する。さらに四個体・二状況の各一箇所だけを変える8例で、個体や状況の取り違えを検査する。直接の候補条件、質問への具体候補適用、引用した質問を評価してからの候補適用が一致することを確かめる。

提示の有無・箇所の区別・順序・回答関係は32組合せで検査し、誤答の提示を認める場合も正答へ変わらないことを確認する。著者・文脈・質問箇所・回答箇所・参照記述・回答記述の取り違え、順序と回答の逆転、未提示、同じ箇所への潰し込みも検査する。未知の内容は候補評価時に拒否し、提示だけなら内容を実行しない。記述型の全回答の有限列挙と、引用層が異なる候補の誤用も拒否する。

有限診断には既存の短絡評価変換を使う。二例では元の評価・キャッシュなしとも一致することを確認する。元の15主張と全宣言の保存、通常・短縮・固有文字の往復、専用CLI解析、意味説明と型の対応も検査する。[検査報告](../reports/definition-question-v1.json)と[意味規約](../data/definition-question-basis-v1.json)を保存する。

```powershell
python -X utf8 -m scripts.check_definition_question --verify-only
python -X utf8 -m pytest tests/test_definition_question.py -q
```

この接続で冒頭の語義上の未解決点が消えるわけではない。参照先`bi`の内容を引き続き点検し、原文が求める説明と外延的な候補条件の差を埋める必要がある。表題の質問と冒頭の説明が同じ対象を扱うという、本文の構造上の接続を今回の成果とする。
