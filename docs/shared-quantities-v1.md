# 測定量・単位換算・容器の個数

同じ量を別の単位で表すこと、異なる対象の量が等しいこと、容器の個数が等しいことを分けて構成した。[共通Nativeモジュール](../examples/v016/shared-quantities-v1.noema)は、既存の有理数算術4基本宣言、量と次元の13定義、複数の3定義を再利用し、測定・部分・内容物を結ぶ10定義を追加する。新しい基本関係の意味や文法演算子は追加していない。

[公開規約](../data/shared-quantities-basis-v1.json)には全引数の型・役割を記録する。再利用した宣言は名前の対応を除いて本体を保持する。有理数の大小比較・加算・加法逆元・乗算は、以前からある意味規約のまま `rationalbelow`・`rationaladd`・`rationalnegate`・`rationalmultiply` として使う。既存の [quantities](quantities-v1.md) と、実数版の定義・証拠は保存している。

## 次元・量の種類・単位

次元は基底軸から有理数指数への関数で表す。`dimensionproduct` は指数の加算、`dimensioninverse` は符号反転、`dimensionquotient` は両者の合成、`dimensionpower` は指数への乗算である。`dimensionequal` は各軸の指数の一致を検査し、`basisdimension` は指定軸だけが1、ほかが0であることを要求する。`dimensionless` と `dimensionisscalar` も従来の本体を保つ。

`quantitycompatible` は、量の種類と次元が一致し、単位尺度が両方とも正であることを要求する。同じ次元だけでは、同じ種類の量と認めない。`quantityequal` はこの条件に加えて「左の読み×左の尺度＝右の読み×右の尺度」を要求する。`quantityproduct`・`quantityquotient` は結果次元と尺度換算後の数値を検査し、商では分母が非零であることも要求する。

この換算は乗法的な正の有理数尺度を扱う。読みへ定数を加える原点変更、対数単位、無理数尺度をこの条件へ混ぜない。旧実数切断の量を削除したり、有理数の検査で実数全域を証明したことにしたりはしない。

## 測定対象と状況への接続

`unitregistered` は、単位・量の種類・次元・尺度・状況を同じ登録関係で照合し、尺度の正値も検査する。例えば単位名だけが一致しても、別の尺度や種類を渡せば、その組の登録がない限り成立しない。登録関係は文書から渡す入力であり、その現実への根拠や規約全体の整合性を処理系が認定するものではない。

`amountat` は、登録済みの単位について、同じ対象・種類・単位・読み・状況が測定関係を満たすことを要求する。この定義は量の大きさを扱い、読みは非負の有理数に限る。既存の `quantityequal` 自体は符号付きの数も扱えるため、この制限は数式一般へ広げていない。

`sameamount` と `amountless` は、左右の対象について `amountat` を満たした上で、同じ種類・次元の尺度換算後の値を比較する。二対象の量が等しいことは、二対象が同じ個体であることを意味しない。異なる状況で測った値を、同じ時点の比較へ自動的に合成することもない。測定の誤差区間や確信度を表す場合は、この正確な読みの関係とは別に記述する。

## 部分の量を合計する条件

`partitionof` は、同じ全体と状況について、次の四条件を要求する。

- 部分の列に同じ個体の重複がない。
- 各部分がその全体の部分である。
- 異なる部分の各順序対について、重なりがない。
- その列が全体を過不足なく尽くすという範囲の指定がある。

異なる名前であることだけから、部分の重なりのなさや完全な範囲を推測しない。空列の場合も、全体を尽くすという条件は省略しない。

`amountsum` は、`partitionof` に加え、各部分と全体が同じ種類・単位・次元・尺度・状況で `amountat` を満たし、部分の値の和が全体の値に等しいことを要求する。値を返す関数を渡すだけでは足りず、各値を測定関係と照合する。全体の値が部分の和と異なれば、部分の範囲が正しくても `amountsum` は不成立となる。任意の量について、部分の値を常に足せるという推論規則は設けていない。

空の部分列は和が0となるが、成立には完全性の指定と、同じ全体についての0という測定も必要になる。「測定がない」ことを0へ変換する構成ではない。

## 容器と中身を別々に数える

`assignedmembers` は、容器列などを明示した割当関数で写し、順序と重複を残した内容物の列を作る。`containercontents` は、その同じ割当先が各容器の内容であることを照合する。内容と容器の引数順は固定し、包含の向きを入れ替えない。

`countedcontainers` は、内容の割当が成立し、重複のない容器列の個数が指定数に等しいことを要求する。`containeramount` は、この同じ割当で得た内容物の列について `amountsum` も要求する。二容器が同じ一部分を指す場合、容器数は二つでも、量の合計では部分の重複として拒否する。異なる部分が重なる場合も、重なりの条件で拒否する。

[統合例](../examples/v016/containers-and-amounts-v1.noema)では、仮定した測定値として、水の二部分を250 mLと500 mL、全体を750 mLとし、米の二部分を400 gと600 g、全体を1,000 gとする。水は二つの容器、米は二つの袋に割り当てる。容器・袋の個数はいずれも2だが、この値から体積や質量を導かない。それぞれ同じ定義を使って、部分範囲と測定の一致、0.75 Lと1 kgへの換算を検査する。単位尺度はmL・gを1、L・kgを1,000と明示し、単位名から自動補完していない。

## 検証範囲

有限検査は、種類・次元・尺度・有理数の読みを変える換算1,024モデル、登録・測定・正値条件を変える48モデル、部分・重なり・完全性・内容・合計値を変える64モデルからなる。加えて、測定と単位登録の全5引数、部分・非重複・完全性の全3引数を、他の入力を固定したまま一つずつ変える24件の結合診断を行う。これは全ての測定対象や次元体系に対する証明ではない。

33テストでは、既存宣言の本体保存、二題材の統合、順序と重複、空の全体、各部分と全体の測定欠落、状況の混在、対象の同一性と量の等しさ、否定、未知入力の拒否も検査する。有限評価で使う算術は厳密な有理数演算であり、浮動小数点の近似で一致を判定しない。検証結果と依存ハッシュは[報告](../reports/shared-quantities-v1.json)に保存する。
