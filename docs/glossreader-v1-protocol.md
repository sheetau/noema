# 語義照合を学習済みの二つのエンコーダーを使う条件

関連度分類器の転用では意味の取り違えが残ったため、語の文脈表現と定義を対応させるために学習されたGlossReaderを確認する。[原論文](https://aclanthology.org/2021.semeval-1.100/)と[後続論文](https://aclanthology.org/2022.lchange-1.22/)を参照し、[2023年10月再学習版の公開重み](https://zenodo.org/records/10530146)を固定する。論文発表時の重みと同一とは呼ばない。

## 出典と読込み

公開記録の作者はMaxim RachinskyとNikolay Arefyev、モデルの利用条件はCC BY 4.0。ファイル`best_model.ckpt`は4,479,483,789 bytes、公開MD5は`fe0f589ab57e36e6eb88667ccf697742`である。取得後にサイズとMD5を検査し、ローカルSHA-256も記録する。取得済みの接頭部を保持し、範囲指定応答を確認した分割取得を使う。未完成ファイルをモデルとして読み込まない。

[公開推論コード](https://github.com/deniskokosss/deepchange_at_axolotl/blob/08f8a6141faa43f5ba84bbace8a9688e9ed22ae2/code/gr_vectorize.py)の構成を確認する。コードのApache-2.0と重みのCC BY 4.0を区別する。公開スクリプトは実行せず、`torch.load(weights_only=True)`でテンソルを読み、文脈用・定義用のXLM-R largeへそれぞれ厳密に割り当てる。余分な成分や不足した重みは拒否する。設定・トークナイザーは`FacebookAI/xlm-roberta-large`の`c23d21b0620b635a76227c604d44e43a9f0ee389`へ固定し、基盤モデルの未学習重みで代用しない。

全層の重みを固定してevalにし、CPU float32・eager・8スレッド・seed 17で実行する。Noemaの追加学習は0。生成・指示文・辞書による候補の絞込み・語別の補正は用いない。

## 文脈と定義

原文をそのまま文脈エンコーダーへ入力し、注釈された文字範囲と重なる有効トークンの最終層を平均する。対象の非空白文字が全て有効トークンに覆われることを検査する。前後の文字と同じトークンを共有する場合は境界のはみ出しとして記録し、正確な文字単位の表現と呼ばない。

参照コードは接頭部と対象を別々にトークン化して位置を推定する。こちらでは原文全体のオフセットを使い、その位置との違いを全件記録する。切断を行う参照コードの処理も採らず、512トークンを超える入力は拒否する。この位置処理の違いを明示し、上流実装をそのまま再現した精度とは扱わない。

候補はNoemaの既存91概念の英語定義とし、定義用エンコーダーのCLS表現を使う。日本語の原文にも同じ英語定義を照合する。主指標は公開方式に沿う正規化なしの内積。候補の型や語形で除外せず、同点はID順で並べる。英語で学習した語義対応がNoema定義と日本語へ転用できるかは実測で判断する。

## 評価と検査

観察済みの定義照合v1〜v6と対象切替v1の計482範囲を使う。各言語の既知範囲196、未知45。全て正解範囲を与える診断で、独立した新規採用試験や全文翻訳ではない。対照は既存MiniLMの学習済み共通3係数方式を同じ行・91候補で再計算する。前回の対象切替の三条件とも、保存した結果をハッシュ検査して比較する。結果を見て定義、重み、閾値、位置規則を変更しない。

既知概念の正解、日英の一致、同じ文で対象を切り替えたときの正解、未知の先頭スコア分布を分けて報告する。候補の内積は意味一致の確率ではなく、今回だけで確定翻訳を行わない。

チェックポイントの成分・二つの重みの区別、反復語のオフセット、欠けた対象文字・不正な位置の拒否、トークン境界のはみ出しをテストする。実モデルでは日英の6対象・4定義で、反復と直接forwardの一致、重み固定、生成等の禁止経路の呼出しを検査する。全特徴と予測を保存し、再現検査では保存特徴から全482範囲のスコア・評価を再計算し、モデル再読込み後の小規模な特徴照合も行う。
