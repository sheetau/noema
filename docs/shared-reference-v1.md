# 共通の指示候補と前提

## 参照先の有無と内容の真偽

参照候補の存在、一意性、複数性を、参照先について述べた内容の真偽から分ける。既存の頁番号の指示 `rqso` は、同じ番号規約・親・番号・文脈の下で他の割当がないことを要求する。覆いの指示 `ryr` は、先行箇所と描写対象の対応を別の条件として持つ。この二つの構成を踏まえ、作品固有の引数を持たない候補関係と一意性を共通化する。旧定義を削除・変更せず、同じ本体だとする機械的な改名証明とも区別する。

今回の候補関係は、個体と評価状況から真偽を返す。`referenceexists` は候補の存在、`referencemissing` は候補がないこと、`referenceambiguous` は異なる候補が二つ以上あることを表す。`referencevalue` は指定個体が唯一の候補である条件、`referenceunique` はそのような個体がある条件である。候補関係を与える情報がないことを、候補が空であることへ置き換えない。候補範囲の完全性と選定基準は解釈入力に残す。

共通定義は[Nativeモジュール](../examples/v016/shared-reference-v1.noema)、型・引数の役割・意味は[公開規約](../data/shared-reference-basis-v1.json)へ保存する。新しい基本関係は導入しない。

## 話者・場所・時点と先行詞

`individualrole` は、指定文脈の指定役割に個体が一意に割り当てられている条件である。話者や指示場所の役割に使う。`situatedrole` は同じ構成を状況型の値に適用し、指示時点を表す。文脈と役割の識別子を明示するため、引用内の「私」を現在の話者へ、引用内の「今」を現在の発話時へ無断で変更しない。場所の粒度や、報告がどの文脈を採用するかは、与える対応関係で説明する。

`anaphoriccandidate` は、現在の言及からアクセスできる先行箇所があり、その箇所が候補個体を指し、現在の言及の適合条件も満たすという関係である。先行箇所・参照先・文脈を同じ存在証拠で結ぶ。二つの先行箇所が同じ個体を指す場合と、異なる個体を指す場合を区別する。一意に決まらないときに先頭の候補を採用しない。どの箇所がアクセス可能か、性・数・談話上の制約をどう判定するかは明示的な入力であり、自然言語の自動照応解析器ではない。

## 前提と主張内容の組

`presupposition` は、前提となる内容と、主張・問いの対象となる内容を一組にする構成定義である。既存の型付き関数と状況ごとの内容を使い、真偽型そのものは変更しない。`presupposed` と `atissue` でそれぞれの内容を取得する。

`licensedpositive` は前提と主張内容がともに成立すること、`licensednegative` は前提が成立して主張内容が成立しないことを表す。`unsupported` は前提が成立していないことを表す。前提が偽なら、肯定・否定の両判定は偽になる。これは内容が偽だと判定したこととは違う。評価に必要な関係が未知なら実行器は停止し、三番目の真理値へ自動変換しない。

`definitestatement` は、一意の参照先を前提とし、その同じ参照先が指定性質を満たす内容を組み立てる。「その王が来る」「その文書が届く」を同じ構成で扱える。参照先がない場合と複数ある場合はどちらも前提不成立だが、候補の診断関数で原因を区別できる。名前の綴りや英語の関数名で名詞の意味を代用せず、候補と性質の関係を与える。

`presuppnegate` は前提を保ち、主張内容だけを否定する。前提が成立しない場合にも成立してしまう `not(licensedpositive(...))` と区別する。問いにも同じ前提を保持し、質問であることだけから参照先や肯定回答の存在を導かない。

## 条件文での前提の範囲

`presuppif` は、左側の前提を要求し、左側の主張内容が成立する場合に右側の前提を要求する。主張内容は左から右への含意である。たとえば「王がいるなら、その王は来る」では、前件が偽の場合に後件の参照先を実在すると補わない。

`presuppglobalif` は、左右両方の前提を文全体で要求する別の読みである。文脈によって前提を全体へ投射するか、条件の内側に置くかが未決定なら、どちらかへ黙って固定しない。`presuppand` は、左側が成立する場合に右側の前提を要求する順序付きの結合であり、この前提の規約を保ったまま左右を交換できるとはしない。

「また来た」の一つの読みも、前の来訪があるという前提と、今回の来訪という内容を `presupposition` で組み合わせる。今回の内容を否定しても前の来訪の条件は残る。復元される状態を前提とする読みや、習慣の読みまでこの一例へ統合しない。

## 発話の種類と前提を一緒に保存する

`speechpackage` は、前提の内容と既存の発話値を、一つの型付き関数として組み合わせる。発話は主張・問い・指示の区別を持ったまま渡す。`speechvalid` は指定状況で前提を満たすか、`speechmatches` は保存した発話値が指定したものかを検査する。問いを主張として実行したり、前提が成立しない問いを肯定回答へ変更したりしない。

この組は既存の関数・内容・発話型だけで表現する。前提を付属JSONだけに記録してNative本文から失わせる方式ではない。既存の発話値の同一性は働きと状況ごとの内容によるため、話者・発話回数・文言の同一性を別途扱う場合には、既存の型付き引用と帰属を使う。

## 検証と残る範囲

候補が空・一つ・二つの場合と性質の真偽、否定、条件付き／全体の前提、引用内外の文脈交替、複数先行詞、前提付きの問いを有限モデルで検査する。王と文書という異なる話題で参照先の不存在と内容の否定を区別する。未知値、一般的な前提調整や照応の自動推測は成功したことに数えない。

省略の補完規則、曖昧な読みの選択履歴、社会的に共有する前提を会話へ導入・撤回する運用、円文字での共有語彙登録、第三者読解は引き続き検証が必要である。

[参照と前提の対照文書](../examples/v016/reference-presupposition-contrasts-v1.noema)は、候補の診断、肯定・否定・前提不成立、前提を保存した否定、問いの前提と働きを14の問いで検査する。[反復の前提を持つ文書](../examples/v016/repetitive-presupposition-v1.noema)では、共通の `chronology` と同じ行為者の出来事から過去の存在を構成する。「以前にも来た」という文全体の基本記号は置かない。

18テストと[検証報告](../reports/shared-reference-v1.json)に、候補・性質・指示対象・評価状況の64モデル、前提投射の16モデル、先行詞の4対照、引用内外の文脈と役割、反復の4対照を記録する。12件の引数結合診断は、アクセス・指示・適合の三関係について、他の値を固定し各引数を2値の領域で変更する。全自然言語の照応や前提の網羅性を証明する検査ではない。
