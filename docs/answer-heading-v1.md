# 論説全体を回答として位置付ける表題

「Beantwortung der Frage:」を、現在の論説を後続の問いへの回答として位置付ける表題の導入として記述した。既存の `hzic` は問いと冒頭第一文の回答提示を結び、`hzlt` は脚注で現在の論説を同じ問いへの回答として指す。今回の `hzs3` は、表題自身にある位置付けを加える。

一般形 `rqu5` は、導入箇所・文書・問いの箇所・文脈を受け取る。導入がその文脈に成立し、その文書内に記載され、その同じ文書を問いへの回答として指し、問いより前にあることを要求する。導入と問いの箇所を同一化しない。既存の行為の成立 `dg`、文書内の紹介 `hzjk`、回答としての言及 `hzjj`、本文順序 `ue` を合成し、新しい意味関係は増やしていない。

表題用の局所参照 `hzs2` は原文u0005の導入を指す。現在の論説 `hzik`、次行の問い `hzia`、表題と冒頭の提示文脈 `wh` は既存の参照を共用する。コロンによる後続の問いへの接続は、同じ問いを指すことと本文順序に反映する。句読点の字形の再現は意味記述の要件に加えない。

回答としての位置付けから、答えの正しさや説明の十分性は導かない。タイトルがこの論説を回答として提示することと、著者の説明が問いへ十分に答えることは別の判断である。実際の読者への質問、執筆日時、印刷作業、問いへの物理的な返信も追加しない。

四項目のテストでは、導入の成立・記載先・回答の位置付け・順序・箇所の区別の32組合せと、本文へ結んだ12対照を調べる。後者では冒頭の回答提示、脚注の自己言及、新しい表題の三文を同時評価し、表題だけが欠ける例を区別する。八つの未知入力を保留し、回答の正誤がどちらでも三文を記述できることを確認する。短絡変換とメモ化は使わない。形式報告は既存の集計器で部分対応として受理され、全体の意味判断は別のレビューからだけ加算されることも検査する。

```powershell
python -X utf8 -m scripts.compose_answer_heading
python -X utf8 -m pytest tests/test_answer_heading.py -q
python -X utf8 -m scripts.check_answer_heading --verify-only
```
