# 次回の確認評価の固定条件

この条件は、拡張学習資料での学習が進行中で、次回確認評価の予測を一度も取得していない段階で記録する。既存のcorpus-v2の最終評価は、失敗分析に使用したため今後は回帰資料とする。次の資料は新しい合成確認資料であり、人が自由に書いた文章の独立評価とは区別する。

## 対象と採用条件

対象は従来の15概念による単一出来事・状態である。主体、対象、受け手、場所、肯否、時間、数量、固有名を含める。日本語と英語を別々に集計し、対応範囲内の確定率80%以上、確定した出力の意味構造完全一致率95%以上を条件とする。未対応入力の誤確定率も報告し、開発時と同じ5%以下を追加条件として維持する。

モデルの候補は `joint-v6-xlmr` と `joint-v6-minilm` の2個に限定する。どちらも固定エンコーダー、同じ関係分類器、30エポックの学習、共同役割割当てを使う。チェックポイントと閾値は既存の開発資料だけで決める。言語ごとに上の開発条件を満たした候補から確定率が最大のものを選び、同率なら完全一致率、さらに同率なら候補名の辞書順で決める。対象となる重み・閾値・復号処理のハッシュを記録してから確認評価を実施する。

## 例の作成

乱数種は61027とする。対応範囲内は各言語600文とし、2通りの同義表現を持つ300意味構造を用意する。概念の組合せは拡張学習資料に含まれない既存の保留組合せから選ぶ。既存評価で組合せそのものを見た履歴は残るため、「すべての意味要素が評価者にも未知」という主張はしない。原文・意味構造の組合せを既存資料からそのまま複製しない。

名前はAiko、Yuna、Ken、Mary、Ahmed、Iris、数量候補は6、9、17、64、256、2026とする。各言語で全6述語、肯定と否定、相対時間の昨日・今日・明日、数量の明示と未指定、固有名、受動態の主体省略を含める。新しい名前や数量を含まない対照例も含め、全例を大きな数や固有名だけに偏らせない。

英文は、主体と述語の間の場所句、受動文で行為者の前に置く場所句、文頭の場所と時間の組合せ、主体の後の時間句を用いる。日本語は、主体の「は」、受動文の対象の「は」、時間・場所の順序変更、対象を先に置く語順を組み合わせる。表記の差だけを新しい構文の根拠にせず、実際の構成と役割を記録する。文が不自然・曖昧になる場合は、予測を取得する前の言語的な点検で修正し、その履歴を残す。

未対応例は各言語72文とし、未知の概念、複雑な量化、入れ子の作用範囲、複数出来事、様相、質問を各12文ずつ作る。質問はNoemaを直接書く場合には対応するが、今回の自然言語解析器の対象外である。支持された意味構造を持つ文として無理に注釈しない。

## 固定と実施

資料の内容、注釈、言語別・種別別件数、モデルの選択記録を保存し、それぞれのハッシュを検査する。注釈の内部整合性は機械検査し、原文と正解の意味が合うかは別に点検する。評価関数は確認資料を学習・閾値調整・候補選択へ渡せない経路から呼ぶ。実行後は全件を集計し、低成績の文型や概念を除かない。

基準を満たさなかった場合も結果を保存する。その資料を見て改善した後は回帰資料として扱い、同じ資料での再測定を新たな独立確認とは呼ばない。合成資料の通過だけで、利用者による読み書きの検証や自由な自然文の精度検証を済ませたことにはしない。
