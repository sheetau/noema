# 命令内容と、発出・受領・義務・実行（2026-10-14）

カントの軍人の例について、同じ本人に同じ行為の実行を求める発話を構成し、その発出、受領、職務上の要求、実行を区別した。命令の発出だけから正当な義務を導かず、受領や実行も補わない。

原文`kant-1784:u0012`の、上官から何かを命じられるという従属節に部分草案を対応させた。`anbefohlen wird`への接続では発出と提示を扱い、受領済みであることを必要条件に加えない。上官という役割関係、軍人の概念、命令権の正当性、後続の職務中の論評の害は未記述である。

## 定義

| 記号 | 保持する意味 |
| --- | --- |
| `rew` | 本人と実行条件を固定し、対象行為の実行を求める発話を返す関数 |
| `hzz` | `rew`の実行条件を既存の`zzq`へ固定する |
| `hzaa` | 同じ提示行為で、指定発出者が本人へ同じ行為についての発話を示す |
| `hzab` | `hzaa`と、その同じ提示・本人・行為・発話・状況での受領 |
| `hzac` | `hzaa`と、同じ本人・行為・出所の職務上の要求`hzn` |
| `hzad` | `hzac`が成立し、同じ対象行為が現在は実行されていない |

`rew`は本人から内容への文字列置換ではない。本人、行為、実行条件を型付きの式として組み合わせ、発話の働きを「指示」にする。主張や質問とは区別する。実行内容が現在偽でも、その実行を求める指示を記述できる。

作例では、`hzz`に本人を表す閉じた式を渡して発話の記述を作り、提示の受け手と職務要求の本人へ同じ参照を渡す。対象行為も、発話を適用する対象と職務上の要求で共通にする。記述の別名や別の本人への指示へ、同じ提示・受領を自動移転しない。

`hzaa`は発話一般を受け取れる。任意の発話記述を渡せば命令になるのではなく、命令の作例では`hzz`を用いた上記の構成を明示する。発話の構成、実際の伝達、規範状態を一つの条件に潰さない。

## 原文へ加えない条件

命令が示されたが本人が受け取っていない場合、`hzaa`は成立しても`hzab`は成立しない。職務上の要求が別にあるなら`hzac`は成立し得る。この場合にも、未実行だけから本人が命令を知っていたこと、故意、責任、制裁は導かない。

逆に、指示を受け取ったからといって`hzn`の職務上の要求が成立するとはしない。発話の発出者が上官であることや、正当な命令権を持つことは、提示された指示の働きだけでは確定しない。

提示と受領は、同じ粗い評価文脈で扱う。送信から受信までの遅延、履行期限、発出後に撤回・変更された命令、別の時点での履行は今回接続していない。
