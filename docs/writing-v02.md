# Noema 0.2の記述体系（開発中）

文語を優先して、人が文を書く記法を追加した。まだ語彙は旧版の15概念であり、言語全体の完成版ではない。旧版のノード宣言形式は引き続き0.1として読める。0.2は発音記号ではなく、固有文字の代用文字で記す。

## 文の組立て

```text
noema b b
ih i mu j si.
```

最初の行は文法・語彙の版を示す。本文は「追う・主体・犬・対象・猫」の順。`ih` が追う、`mu` が犬、`si` が猫、`i` が主体、`j` が対象である。各文の最後を `.` で区切る。`i mu` と `j si` の順は変えられるが、役割標識は省略しない。省略した役割は未指定となり、登場人物を補わない。

| 標識 | 意味 | 例 |
|---|---|---|
| i | 主体 | `i mu` 犬を主体にする |
| j | 対象 | `j si` 猫を対象にする |
| k | 受け手 | `k fo` 子供を受け手にする |
| l | 場所 | `l yf` 公園で |
| m | 明示数量 | `mu m c` 数量2の犬 |
| n | 名前 | `qo n "Aki"` Akiという名前の人物 |

数の表記は旧版と同じ32進で、`a=0, b=1, c=2, d=3, ... , 7=31, ba=32`。明示されていない数量は未指定のままとする。リテラルの名前は任意のUnicodeを保持する。

## 否定・時間

```text
noema b b
u [ ih i mu j si ].
t po i qo n "Aki".
```

第1文は犬が猫を追うことの否定。`u` は後続の式全体を否定し、角括弧で作用範囲を示す。単一の節なら括弧を省略して `u ih i mu j si.` と書ける。正規形では括弧を明示する。二重否定を勝手に消したり、否定を接続詞の内外へ移したりしない。

第2文は明日のAkiの睡眠を述べる。`e/f/g` は過去・現在・未来、`r/s/t` は昨日・今日・明日、`q "2026-09-27"` は絶対日付。時間標識を省略すれば未指定となる。時間を実行日時で補完しない。同じ節に複数の時間標識は置けない。この制限は次の意味構造拡張で検討する課題として残る。

`v` は肯否そのものが未指定であることを表す。普通の肯定文には不要。これは旧意味構造を損失なく表すための形式であり、「たぶん」「可能である」などの様相を表す語ではない。

## 同じ対象を続けて述べる

```text
noema b b
ih i mu o dog j si o cat.
no i p dog j p cat.
```

第1文で `o dog`、`o cat` と参照名を付け、第2文で `p dog`、`p cat` と参照する。第2文は「その犬がその猫を見る」。参照名は代用文字の列で、上例のdog/cat自体に犬・猫の意味はない。別の参照名へ置き換えても意味は変わらない。

参照していない同名詞・同名の人物を、同一対象と推測しない。未導入の参照や参照名の再定義はエラー。参照は文書全体の登場対象を識別するもので、量化された変数ではない。条件文内の登場対象に参照名を付けただけで、その出来事が現実に起きたとは主張しない。

## 質問と依頼

```text
noema b b
b ih i mu j si.
b ih i c j si.
d zg i qo n "Aki" j fo.
```

`b` は質問。第1文は命題全体の肯否を尋ね、第2文は主体の位置を `c` にして、猫を追う主体を尋ねる。未指定の `?` と、回答を求める `c` は異なる。`c` は質問文だけで使える。

`d` は依頼。第3文はAkiが子供を助けることを求める。同じ内容の断定文と同一の意味構造にはしない。敬意や強制力の段階は、現行の発話種別には含めていない。

## 文を接続する

```text
noema b b
w [ po i mu ] [ wm i si ].
x [ po i mu ] [ wm i si ].
y [ ih i mu o dog j si ] [ po i p dog ].
```

`w` は両方、`x` は少なくとも一方が成り立つことを述べる。`x` は排他的な「どちらか一方」ではない。`y` は第1式を条件、第2式を帰結とする。これらは必ず2個の角括弧を取る。出来事の順番や原因を接続詞だけから推論しない。時系列、因果、反事実条件を区別する拡張は未実装。

概念IDと人が書く語は分離した。文法標識は1文字、現在の概念語は2文字なので、書かれた列から区別できる。対応表は版付きの資源として保存する。語の見た目から意味が分かるとは仮定しない。

## 実行と旧版との変換

```powershell
python -m noema parse --text "noema b b ih i mu j si."
python -m noema format --input examples/chase.json --edition 0.2
python -m noema render --input examples/discourse.noema --output artifacts/discourse.svg
```

通常の `parse`、`format`、`render` は版を判別する。`format --edition 0.2` で旧意味構造を新記法へ移せる。逆変換は、旧版で表せる単一断定文だけに限る。複数文、質問、依頼、接続、入れ子の否定を旧版へ変換しようとした場合、意味を捨てずエラーにする。

0.2の意味JSONは `entities` と `utterances` を持ち、各発話には `speech_act` と式の木 `content` がある。正規化は役割の順と参照名だけを統一する。発話の順、参照の共有、接続の順、否定の作用範囲は保持する。
