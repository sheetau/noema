# 好ましい結果の受容と、その行為者の認識

カントu0015の「感謝する」に含まれる構造を説明するため、好ましい結果を誰の行為によるものと認めているかを記述した。実際の達成、本人による結果の受容、行為者に関する判断、実際の応答を分ける。これらだけで感謝を定義し終えたとはしない。

| 定義 | 内容 |
| --- | --- |
| `roo` | 同じ履歴の基準時までに、指定行為者・行為が対象者について目標を達成し、対象者が基準時にその状態を好ましく受け入れている |
| `rop` | 評価文脈ごとの履歴・順序・達成関係を用いて、受益対象・行為者・行為から`roo`の内容を作る |
| `roq` | 三者を順序付きの三個体列へ接続し、位置と重複を保持する |
| `ror` | 本人が同じ行為者について、同じ三者と基準記述の内容を、非空の判断候補全体で成立すると認めている |
| `ros` | 同じ応答者・対象者について、認識と実際の応答が同じ時点に成立する |
| `hzgk` | 達成を既存の状態変化・生起・関与・生成へ、結果の受容を`id`へ接続する |
| `hzgl` | 判断主体と対象を`fa`・`fb`へ結び、`hzgk`の記述を判断内容として扱えるようにする |

たとえば「ある人が私に望ましい結果を与えた」と本人が認めていても、その判断が誤っている場合がある。逆に、実際に結果を得て好ましく受け入れていても、誰の行為によるものかを認めていない場合がある。判断候補ごとに履歴と達成関係を指定することで、両者を区別する。現実の履歴を全候補へ無条件に流用しない。

達成の目標記述と、本人が受け入れる状態の記述を同じものに固定した。受益対象・行為者・行為の位置も保持する。別の行為者の関与、別の行為についての判断、応答先の取り違えで条件を満たしたことにしない。基準時より未来の達成も、既に得られた結果として数えない。

前段の`hzgj`による集団・時代を限定した応答へ、`ros`で認識を接続した。認識の対象となる過去の行為と、今回の応答行為は別の個体である。認識があっても応答がなければ`ros`は成立しない。応答があっても認識がなければ成立しない。ただし同時に成立することだけで、認識が応答を心理的に引き起こしたと判断しない。

既存の`id`は、自分の状態を好ましく受け入れる関係であり、相手への好意ではない。自分の利益を喜びながら相手を嫌う場合を、感謝と認定する定義は追加していない。相手への敬意や好意、情緒、感謝に基づく動機、恩返しの規範、感謝を表す発話の意味は残る。また、後続世代への間接的な利益、別人への恩恵に対する感謝、未達成でも善意に感謝する場合には、今回の直接的な達成とは別の説明が必要である。

[一般形](../examples/v014/recognized-benefits.noema)は1,811文字、[原文付き文書](../examples/v014/kant-recognized-benefits.noema)は199,357文字、[抽出文書](../examples/v014/recognized-benefits-core.noema)は4,239文字。七定義を追加し、原始記号と著者主張は増やしていない。親の宣言と15件の著者主張を保持した。[意味規約](../data/kant-recognized-benefits-basis-v1.json)と[検査記録](../reports/recognized-benefits-v1.json)を保存する。

実際の達成・受容、判断候補の達成・受容、認識対象への結び付き、応答の64通りを検査した。原文付き文書と抽出文書では、それぞれ16通りと八つの対照条件を確認した。追加19テストは誤認、未認識、応答の不在、未来の達成、空・反例付き候補、三者の順序と重複、関与・因果・対象の保持、引用、未確定入力、親文書と原文範囲の保存を扱う。CLI解析、正規形と固有文字v2の往復、SVGのXML検査が通過した。SVGの目視確認は含めない。

原文`dankbaren`への構成要素の部分注記であり、単語全体の意味確認ではない。好ましい受容と客観的な福利・道徳的評価は異なり、候補の選択や現実への接続も別途説明が必要である。感謝の全意味、後続本文、論文全文の意味一致は未完である。
