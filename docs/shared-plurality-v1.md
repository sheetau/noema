# 集団・行為の分配・対象の同一性・相互性

複数の人が関わる記述を、集団の範囲、出来事の同一性、対象の同一性、関係の向きに分けて構成した。[共通Nativeモジュール](../examples/v016/shared-plurality-v1.noema)は24定義からなり、新しい基本関係や文法演算子は追加していない。[公開規約](../data/shared-plurality-basis-v1.json)には各引数の型・役割・採用した読みを記録する。

既存の[集団を扱う定義](scoped-groups-v1.md)のうち、分担による被覆 `rp` と、一つの行為への全員の参加 `rr` は、本体を変えず `coveredgroups`・`collectiveaction` として再利用した。[複数内容の行為記述](plural-actions-v1.md)は、同じ本人・行為について複数の内容を満たすための構成であり、複数の行為者を一人ずつ量化することとは区別する。

## 集団の範囲と人数

集団は個体から真偽への性質として渡す。有限列から集団を作る場合は `memberof` を使い、その列に現れる個体を構成員とする。列の順序や重複は所属の真偽を変えないが、人数を表す `membercount` は `distinctmembers` で重複を拒否してから長さを比較する。二つの異なる名前が同じ個体を指す場合も、二人とは数えない。

重複検査はNativeの有限列・関数・foldで構成する。各要素について、後から調べる要素列に同じ個体がないことを要求する検査関数を組み合わせ、最後に空列へ適用する。数値指示関数、加算の外部実装、隠れた集合への変換を使わない。検査対象は明示した列であり、その列が現実の母集団を完全に列挙していることは別の主張となる。

| 定義 | 成立条件 |
| --- | --- |
| `groupincludes(group, included)` | includedの全員がgroupに入る。空集団も許す |
| `groupexists` | 構成員が存在する |
| `groupall` | 非空で、全員が指定性質を満たす |
| `groupplural` | 異なる二個体が存在する |
| `groupinjection` | 集団内の異なる個体への割当値が異なる |
| `coveredgroups` | 行為者群と対象群が非空で、全行為者に相手があり、全対象にも担当者がいる |

`groupincludes` の空集団への真と、存在を要求する `groupall` の空集団への偽を区別する。`coveredgroups` は分担を許し、各人が全対象へ関わることや担当の一意性までは要求しない。集団の所属基準を時間によって変える場合は、どの状況の所属を使うかを性質の定義に明示する。

## 同じ出来事と各人の出来事

`collectiveaction` は「ある出来事に全員が参加する」、`distributedaction` は「各人について参加する出来事がある」という量化の順序を保つ。後者では同じ出来事を選んでもよいため、別々の出来事を要求する `distinctactions` を設けた。これは、各人への明示的な出来事割当が `assignedactions` を満たし、割当値が異なるという構成である。

全員が同じ出来事に参加することだけでは、ほかに参加者がいないとは言えない。参加者を指定集団に限るときは、同じ出来事と状況に `exactparticipants` を加える。参加関係には、本人の能動的な関与を与える。共同意図や、各人が単独でも結果を起こせるという因果条件は、この関係だけから補わない。

## 同じ対象と別々の対象

`actionobject` は、出来事の発生、行為者の参加、対象への作用を、同じ出来事と状況で結ぶ。この関係を基に、対象と出来事の量化順序を変える。

| 定義 | 対象と出来事の条件 |
| --- | --- |
| `collectiveobject` | ある一つの候補対象へ作用する同じ出来事に全員が参加する |
| `eachobject` | 各人に候補対象と出来事がある。両方とも各人ごとに選べる |
| `sameobject` | ある同じ候補対象について各人に出来事がある。出来事は異なってよい |
| `assignedobjects` | 明示した対象割当について、各人にその同じ対象へ作用する出来事がある |
| `distinctobjects` | assignedobjectsを満たし、各人への割当対象が異なる |
| `exclusiveobjects` | assignedobjectsを満たし、各人が作用する候補対象は割当対象だけである |

「各人が別々の一台だけを点検する」には `distinctobjects` と `exclusiveobjects` を同じ割当で組み合わせる。`distinctobjects` だけでは、選んだ対象以外にも点検した機械がある場合を排除しない。`exclusiveobjects` の対象限定は明示した候補範囲内での限定であり、その範囲外について何も主張しない。

割当関数は対象選択の証人として渡す。ある割当で失敗しても別の割当が成功し得るため、一つの不成功を「どの割当も存在しない」と読み替えない。型付きの関数を量化する表現と、具体的な関数を渡して検査することも区別する。有限評価器は全関数の万能な探索器ではない。

[統合例](../examples/v016/collective-distributive-v1.noema)では、二人が同じ出来事で一台のピアノを運び、別の二つの出来事でそれぞれ別の機械を点検する。運搬では共同出来事と共通対象が成立し、点検では各人への分配・対象の相違・各人の対象限定が成立する。点検を共同出来事や共通対象として読む条件は不成立となる。運搬と点検にはそれぞれ出来事・対象・状況の作用関係を入力し、文全体を一つの基本関係へ置き換えていない。

## 相互関係の三つの条件

`reciprocalall` は、集団内の異なる全順序対に関係を要求する。`reciprocalpairs` は各人に少なくとも一人の双方向の相手を要求し、`reciprocalneighbors` は各人に関係を向ける相手と向けてくる相手を要求する。最後の二つの相手は、同じ人でなくてもよい。

三人の有向環では neighborsだけが成立する。双方向の鎖では neighborsとpairsが成立し、両端同士に関係がなければallは不成立となる。自己関係だけ、空集団、一人だけの集団は三条件とも不成立とする。これらは区別して採用する読みであり、自然言語の「互いに」を常に一つの条件へ自動変換する規則ではない。

## 検証範囲

検査は、二値領域で出来事64モデル、対象256モデル、被覆256モデル、四つの出来事割当について計256モデルを評価する。相互性には上記の差が現れる三人の領域を使い、異なる二人間の有向関係64モデルを評価する。人数・所属は二個体からなる長さ0〜4の31列を検査する。出来事・本人・対象・状況の結合は、他の証人を固定して各関係の各引数を変える11件の診断を行う。これを任意の巨大領域に対する証明とは呼ばない。

追加テストでは、否定の範囲、空の候補、未選択の対象、名前の同一指示、余分な参加者、異なる状況の混在を検査する。未知の関係と、評価領域外の個体値は従来の処理系が拒否する。未知を不成立へ変換する規則は追加していない。

```powershell
python -X utf8 -m scripts.project_work check --module scripts.check_shared_plurality --tests tests/test_shared_plurality.py --prepare --verify reports/shared-plurality-v1.json
```

[検査報告](../reports/shared-plurality-v1.json)は有限モデル・統合例・依存ファイルのハッシュを記録する。物質量と単位はこの個体数の定義だけでは表せないため、既存の量・単位の定義から別途一般化する。円文字の共有辞書への登録、学習文書、第三者読解も残る。
