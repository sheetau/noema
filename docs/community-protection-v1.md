# 共同体の保護と不干渉を提案内容へ結ぶ

カントu0013の共同提案に、保護と不干渉を組み合わせた内容を渡す構成を追加した。保護する側の共同体と、旧制度を望む側の共同体を別々の肯定条件で選び、同じ政策が両者に及ぼす効果を別々に検査する。

| 定義 | 内容 |
| --- | --- |
| `rks` | 政策なしでは脅威によって失われる活動が、政策ありでは脅威の有無の両方で保たれる |
| `rkt` | 政策なしで活動が可能なら政策ありで活動が保証され、どちらの側にも結果が存在する |
| `rku` / `rkv` | 政策・脅威・活動というNoemaの内容と、介入モデルの要因・目標が対応する |
| `rkw` / `rkx` | 同じ政策の実施、内容対応、保護効果／損失を生じさせない効果を合わせた内容 |
| `rky` | 基準時点で選んだ改革側の全共同体に保護、維持側の全共同体に不干渉を要求する政策内容 |
| `hzej` | 二つの対象群を、共同体の範囲と変更・維持を選ぶNoema内容から構成する |

保護の比較では、政策と脅威の有無を別々に切り替える。政策なし・脅威なしなら活動が成立し、政策なし・脅威ありなら活動が成立せず、政策ありなら両方の脅威設定で活動が成立することを要求する。脅威が現実に発生済みであることは要求しない。予防的な政策も、この構成の対象になる。

不干渉の比較では、政策の有無の両側に結果が存在することを要求する。政策なしで活動が成功する結果が一つでもあるなら、政策ありの全結果で活動が成功することを求める。これは全結果の組に損失がないという強い読みであり、平均的な悪影響がないことや、妨害が小さいこととは異なる。もともと活動が不可能な場合も、不干渉だけから実際の活動や改善を導かない。

効果の比較だけで、記号に保護という名前を与えたとは扱わない。介入後の各解を状況へ対応させ、その状況での政策・脅威・活動の内容の真偽が、モデルの各要因・目標に一致することを別に要求する。同じ政策で、共同体ごとに異なる活動やモデルを扱える。別の活動が保たれただけでは、その共同体の対象活動への不干渉とはしない。

対象の共同体は基準時点で固定する。結果時点で条件を満たさなくなった共同体を対象から取り除かない。変更側でないことを維持側の希望へ読み替えず、二つの群の存在・排他性・全共同体の分類を自動で仮定しない。対象が空なら、その側の普遍条件は空虚に成立するが、政策実施の条件自体は残る。

`hzej`の閉じた適用記述を、前版の共同提案の内容に接続した。提案者がこの内容を同じ行為で同じ相手へ提案できることを、先行する公的な情報進展と合わせて検査する。この場合、提案する内容の効果や実施状態は評価しない。提案可能性から、政策が実施済み、または保護が実現済みだとは結論しない。同じ真偽を持つ別名の提案内容への自動置換も行わない。

三変数の方程式256通りについて、介入結果を別の列挙手順で求めて比較した。各モデルには八つの割当て候補があり、複数解や無解を含む。重複変数、脅威要因の欠落、政策と脅威の同一視、無関係な世界対応・活動、政策未実施、対象群の取り違えも検査する。未知の方程式・内容・対応関係は偽で補わない。

[一般文書](../examples/v014/community-protection.noema)は5,136文字、[原文付き草案](../examples/v014/kant-community-protection.noema)は156,336文字、[抽出文書](../examples/v014/community-protection-core.noema)は9,333文字である。八定義を追加し、原始記号と著者主張は増やしていない。親文書の宣言と15件の主張を保持する。[意味規約](../data/kant-community-protection-basis-v1.json)と[検査記録](../reports/community-protection-v1.json)を保存する。

これは明示した因果モデルに基づく部分的な読みである。法的な地位、救済、補償、確率的な危険の低減など、保護の全用法を尽くさない。方程式と背景の現実的な妥当性、未知の脅威の網羅性も別の課題である。現在の`rkw`・`rkx`は政策実施とモデル上の効果を結ぶが、現実の観測状態がそのモデルの解であることまでは要求しない。実際の活動の成立や観測との整合性には、別の接続が必要である。変更した制度への合意、よりよい理解という当事者の判断、旧制度を望むこと、宗教制度・共同体の具体的な意味は、選択条件と活動内容へ次に接続する。君主の制度的位置、著者帰属と全文の意味一致確認も未完である。

検査器の256モデルと接続検査が通過した。追加の検査7件と既存の介入モデルの回帰検査7件、計14テストも通過した。三文書のCLI解析結果は構文木と一致し、抽出文書の固有文字v2のSVGをXMLとして検証した。SVGの目視確認は含めない。
