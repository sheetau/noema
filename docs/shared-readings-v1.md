# 省略の補完と未決定の読み

## 記述を合成し、読みを保留する

既存0.16の[型付き記述合成](quotation-construction-v1.md)を再利用する。閉じた関数記述と引数記述から適用式を作り、その構造を保持する。これは内容の実行や、自然言語から省略箇所を自動推測する処理ではない。[共通定義](../examples/v016/shared-readings-v1.noema)と[意味規約](../data/shared-readings-basis-v1.json)を公開し、基本関係を新設しない。

補完の例は、主体・所有者等の関係項・基準状況を受け取る発話ひな形である。「Akiは自分の師を褒め、Naoもそうした」には、NaoがAkiの師を褒める読みと、NaoがNaoの師を褒める読みを用意する。同じひな形で所有者の引数だけを変える。ひな形の中の変数を文字列置換せず、閉じた引数記述を適用するため、束縛されている別の変数を捕獲しない。

`ellipsisresult` はこの三引数ひな形への記述適用、`ellipsisvalid` は結果がその構成と厳密に一致する条件である。`ellipsislicensed` は元の箇所・補完先・文脈・根拠を同じ補完へ結び、二つの箇所の区別と構成の一致も要求する。許容される補完かという判断を、構文一致だけから導かない。三引数の共通関数は今回の用例向けであり、異なる型・引数数のひな形には既存の可変長の記述適用構文を使える。

## 候補集合と論理和

読みの候補は、発話記述の有限列としてNative本文に保存する。各記述は主張・問い・指示の働きも保持する。「Aという発話」「Bという発話」の二候補を持つことは、「AまたはB」を主張する発話を持つこととは異なる。候補を列挙するだけでは、どの候補の内容も実行しない。

`readingcontains` は記述の所属、`readingsambiguous` は異なる記述が少なくとも二つあることを判定する。列順や同じ記述の繰り返しで曖昧さを増やさない。記述は構文上の同一性で区別し、有限モデルで真偽が同じだからという理由で異なる読みを統合しない。一方、任意の同義な言い換えを自動判定する関数でもない。

`readingssingle` は現在列挙した記述が一種類であることを示す。列挙が尽くされたという別の条件も与えたときに限り、`readingsresolved` が成立する。空列は、列挙が完了していれば `readingsabsence`、未完ならまだ候補を得ていない状態である。いずれも、元の文の内容が偽であるという意味ではない。尽くされたという判断の根拠は、解釈入力として説明する。

## 読みの変更と根拠

`readingssubset` と `readingssame` は、列順・重複に依存せず候補の包含と一致を検査する。`readingnarrowing` は、残した候補が非空で全て旧候補に含まれる条件である。新しい候補を追加した修正を、単なる絞込みとして記録しない。

`readingrevision` は、同じ出典・文脈・根拠の下で、除外した各記述と追加した各記述にそれぞれ変更の許可があることを要求する。列挙の完了状態を変更する場合、または新しい状態を完了とする場合には、その候補列と完了状態への根拠も要求する。候補も完了状態も同じ更新は、意味の変更として数えない。関係は変更判断の記録であり、外部の資料が実際に十分であることを形式計算だけから証明しない。

`readinglinked` は、前の更新の出典・文脈・変更後状態と、次の更新の出典・文脈・変更前状態が一致する条件である。Native文書では旧候補列を残し、更新を順に記述する。古い候補の定義を上書きして履歴を消したり、別の文脈の変更を同じ履歴へ接続したりしない。新たな証拠で候補を追加し、以前の確定を撤回する更新も明示できる。

## 検証範囲

師への評価と文書の修正という二つの題材で、主体と関係項を引き継ぐ読み／変える読みを分ける。同じ真理値を持つ別記述、重複、空列、候補一つでも未完の列挙、論理和の単一発話、否定、未知の内容を検査する。補完の構成と根拠、更新の追加・除外・完了判断、前後状態の結合は個別に検査する。

記述の合成・比較は実行を含まない。明示的に評価する場合は、既存の引用層と計算量の制限がそのまま適用される。自然言語の全省略形式、候補の自動生成、根拠の十分性の自動認定、円文字での語彙登録と第三者読解まで検証済みとはしない。

[省略と候補列のNative文書](../examples/v016/ellipsis-readings-v1.noema)では、各題材の構成一致・二つの読み・列挙の完了・補完の根拠を確認する。内容を評価する対照では、二人の人物とそれぞれに対応する二つの対象を分離する。[修正履歴のNative文書](../examples/v016/reading-revisions-v1.noema)は、元の二候補、絞った一候補、別の根拠で再開した二候補を別定義のまま残す。

17テストと[検証報告](../reports/shared-readings-v1.json)に、長さ0〜3の候補列15通り、二題材の内容評価8通り、変更と根拠の256組合せ、補完の8引数を個別に変える9件の結合診断を保存する。標準実行器は含意の不要な枝も評価し得るため、未知の判断を偽へ埋めず停止する。有限の明示した解釈と、構造の保存を検査する範囲である。
