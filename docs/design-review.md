# 非生成型を維持した設計の見直し

2026-09-28の利用者の指定により、プロンプトで生成モデルへ翻訳を指示する方式は、今後も採用しない。サイトの主画面は、日本語／英語とNoemaの2入力欄を中心にしたシンプルなダークモードとする。

## 現在の構造と不足

現在は、固定したXLM-Rの文脈表現を、小型分類器で15概念・意味役割・否定・時間などへ変換している。分類器は単語ごとに別々のモデルではないが、概念クラスは固定されている。語彙を拡張するたびに注釈と分類器の更新を要するため、語彙を増やし続ける方式としては不十分である。文語側の91概念をすべて自然言語から抽出できる状態でもない。

32文字は英語を暗号化するための文字ではない。a–zと2–7は入力・保存用の代用記号で、固有字形と対応する。基本語全体は、意味の構成要素から系統的に導いていない。文字版2では文法機能による共通部品を導入したが、語中の各文字まで意味素として読める設計にはなっていない。これだけでコンセプトの合理体系を実現したことにはしない。

v7〜v9の人工文での分類器の反復改善を、言語体系の完成への中心作業として進めすぎた。既存の失敗報告は保持し、同じ固定クラスの学習例を増やすだけの改良を続ける前に、次の設計と比較を行う。

## 見直す対象

1. **意味の組合せ規則を先に定義する。** 対象、状態、変化、関係、数量、作用範囲を区別し、どの構成要素が語や構文のどこに表れるかを明示する。すべての概念を少数の要素へ完全分解できるとは仮定しない。分解できない基本概念の定義も必要になる。
2. **語彙の追加と分類器のクラス追加を切り離す。** 固定モデルで概念の定義を表現し、入力の文脈表現と比較する方式などを検証候補とする。これは語ごとの訓練例を不要にできるかという仮説であり、精度達成を約束するものではない。対訳文の検索・暗記を意味解析の成功に数えない。
3. **字形の構成にも役割を持たせる。** 文字番号への見た目の割当てだけで終わらず、意味の大分類や修飾・関係を、覚えられる少数の構成規則で表す。見た目の類似と意味の類似を一対一にはせず、文字を混同しないことも評価する。モデルの座標やクラスタ番号を永久的な意味にしない。
4. **既存モデルの利用と、Noemaへの対応付けを区別する。** モデルの既存の言語表現はそのまま使えるが、新しく定義したNoemaの概念・文法との対応は別途必要である。埋め込みを丸めるだけで役割抽出、同義性、完全可逆性が得られるとは仮定しない。

保証する可逆性は引き続きNoemaと意味構造の間に置く。自然言語からの抽出は評価対象であり、Noemaから自然言語へ表す際にも、元の言い回しや省略情報の復元を保証しない。

最初の[追加学習なしの概念定義比較](definition-probe-results.md)を実施した。定義だけで91概念を候補にできたが、正解の範囲を与えたMiniLMの文脈比較でも概念選択は日本語70.0%、英語72.5%だった。これは意味構造の成績ではなく、この単純方式を翻訳画面の解析器へ置き換える根拠にはしない。

文語側では、[0.5の状態からの語形成](writing-v05.md)を実装した。13状態に同じ作用を適用して、状態・変化・使役変化を区別する。派生語ごとの語彙登録を避け、形態素と意味構造の対応を明示する最初の拡張である。基本語全体の意味分解や字形自体の再設計を済ませたことにはしない。

続く[文字版2](alphabet-v2.md)で、役割・時間・参照・論理・発話・変化を共通骨格と区別線から構成した。旧文書の読込みを保ち、新旧字形を同条件で比較した。小さな表示で32字は区別できたが、旧字形より似た組が多い。構成の規則を覚えやすくなったか、人の誤読が減ったかは未検証である。

## 画面の変更

主画面を2入力欄と左右の変換ボタンに変更した。従来の文語編集は `/writing`、練習は `/practice` に分離する。主画面には語彙表やJSON表示を置かない。

自然言語からNoemaへは既存の凍結解析器を接続する。逆方向は今回、15概念の単文を意味構造から定型文へ変換する処理を追加した。生成モデルや学習資料の文検索は使わない。複合語、接続、質問、共有参照など、まだ意味を保持して表せない入力は未対応として返す。この限定した逆変換が、上記の語彙・文字体系の設計問題を解消したとはしない。
