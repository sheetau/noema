# 文語0.9：状況ごとの真偽を持つ命題内容

0.9は、0.8の真理値と、状況によって真偽が変わる内容を区別する。先頭は`i:`または`noema i i`。既存の宣言・定義・量化に、2つの型と2つの式を追加する。特定の能力・信念・規範を一つずつ組込み演算子にする方式ではない。

## 内容と真理値

| 型文字 | 意味 | 意味JSON |
| --- | --- | --- |
| `d` | 状況。文書が区別する状態・場合の領域 | `situation` |
| `e` | 各状況に真理値を対応させる命題内容 | `content` |

既存の`a`（対象）、`b`（有理数）、`c`（真理値）も使える。状況領域Wは非空とする。内容の意味領域はWから真理値への全ての関数である。内容を現在の一つの真偽へ縮めない。

状況が「可能」か、誰かにとって「実現できる」か、何らかの規範に「適合する」かは、型d自体には含めない。それぞれの関係を文書内で区別して定義する。状況を宣言しただけで、実際に起きることや物理的可能性を主張しない。

```text
b 変項 [ 真理値の式 ]
t [ 内容の式 ][ 状況の式 ]
```

`b`は状況型の変項を束縛し、各状況で本体がどう評価されるかという内容を作る。意味は`λw. 本体(w)`である。`t`は内容を指定された状況で評価し、真理値を返す。

例えば、`aa(w)`を状況wにおけるある出来事の成立、`ab()`を現在の状況と解釈すると、`t[b w[k aa[v w]]][k ab[]]`はその出来事が現在成立するかを表す。`b w[k aa[v w]]`自体は、現在以外でも評価できる内容である。

## 束縛と定義の引数

内容の本体から外側の変項を参照できる。内容の中で同じ変項名を束縛した場合は、最も内側の束縛が優先される。内容の状況変項を外へ持ち出すことはできない。正規化では束縛名だけを変え、参照する対象を変えない。

関数適用の引数は、その式で指定された値として渡す。真理値のパラメーターpを渡して`b w[v p]`と書くと、pの真偽を全状況で返す定数内容になる。pを計算した式が各状況で自動的に計算し直されるわけではない。変化する内容を渡すには、明示的に`b`で作った内容、または内容を返す定義を使う。

この違いは型検査だけでは誤りと断定できないため、仕様と対照例に含めた。意図して真理値を固定する記述も合法である。

内容どうしの`e`による同一性は、Wの全状況で同じ真偽になることである。現在の真偽が同じだけでは同一にならない。一方、全状況で同じなら、式の綴りが違っても内容の意味は同一になる。原文の語順、引用の字面、異なる証明方法や認識上の捉え方まで区別する型ではない。解析した式の構造自体は保存し、同値式へ勝手に書き換えない。

内容を扱えるだけで信念・意図・引用の言語体系が完成したとはしない。例えば同値な内容への態度を異ならせたい場合は、記述の仕方も扱う別の構造が必要になる。

## 実行しないことと実現する手段がないこと

[能力の例](../examples/v09/ability.noema)では、次の仮の基本関係を置く。全て文書内の記号で、自然言語からの辞書照合ではない。

| 記号 | 例で与える解釈 |
| --- | --- |
| `aa(actor,plan,now)` | 状況nowでactorが方法planを選んで実行できる |
| `ab(actor,plan,now,outcome)` | その実行について、状況outcomeが想定される結果の一つである |
| `ac(actor,situation)` | 状況situationでactorが対象の行為を実行する |
| `ad()` | 対象の行為者 |
| `ae()` | 現在の状況 |

`ba(actor,goal,now)`は、次の条件を全て満たす方法planが存在することとして定義する。

1. actorがnowでplanを選んで実行できる。
2. planには想定結果が少なくとも一つある。
3. その全ての想定結果で内容goalが真になる。

結果集合を空にして「全結果で成立する」を空虚に満たすことはできない。成功する結果と失敗する結果を併せ持つ方法を、確実な達成手段として扱うこともない。

`bb(actor)`はactorが対象行為を実行する内容である。例の3つの質問は、順に次を問う。

- 現在、その行為を実行していないか。
- その行為を確実に実現する手段がないか。
- その行為を実行しないことを確実に実現する手段があるか。

選択可能な方法の結果を変えると、次のように区別できる。ここでは現在は行為を実行していないとする。

| 方法の想定結果 | 今は実行しない | 実現手段がない | 実行しない手段がある |
| --- | --- | --- | --- |
| 成功のみ | 真 | 偽 | 偽 |
| 不実行のみ | 真 | 真 | 真 |
| 成功と不実行の両方 | 真 | 真 | 偽 |
| 結果なし | 真 | 真 | 偽 |

これは「想定結果に対して確実な達成手段がある」という能力の一つの操作的定義である。日常の「できる」は失敗の可能性を許す場合もあり、カントの`Unvermögen`の意味全体をこの定義で確定したわけではない。選択可能性や想定結果の範囲をどう定めるかという基本関係の説明も残る。

## 有限の解釈による検査

`noema.finite_semantics.evaluate_document`は、対象・状況の有限領域と、基本記号の具体的な解釈を与えて文書を評価する。実際の世界の事実を調べる処理ではない。定義を本文どおり評価し、質問は質問として結果を返す。

内容は与えた全状況の真偽表として評価する。内容型への量化は真偽表を全列挙するため、検査器では状況8個までとする。これは検査器の資源制限で、Noemaの内容領域を8状況へ制限する言語規則ではない。計算には明示的なステップ上限も設けた。

有理数型への量化は、有限の値で代用せず拒否する。有理数リテラル・演算の具体値は厳密な分数として扱えるが、有限の標本で有理数全域の命題を証明したことにはしない。誤った型の基本記号の結果や、未指定の基本記号も拒否する。

## 互換性と残る課題

0.8の文書は0.9へ意味を保って変更できる。0.9から0.8へは、新しい型・式を使っていない場合だけ戻せる。新しい内容を現在の真偽へ変えて旧版に押し込む処理は行わない。0.1〜0.7との新たな意味変換はまだ定義していない。

CLIの解析・整形・固有文字との往復・SVG表示に接続した。外部モデルは不要である。

```powershell
python -m noema parse --input examples/v09/ability.noema
python -m noema script --input examples/v09/ability.noema --alphabet v2
python -m noema render --input examples/v09/ability.noema --alphabet v2 --output artifacts/ability-v09.svg
```

カント冒頭の「自分の理解力を他者の指導なしで使う」という行為内容、状態からの離脱、原因、呼びかけ、標語の引用は、まだ全文として記述していない。今回の内容型を使ってこれらを組み立てる作業が必要である。全文の確認済み単位は引き続き0である。
