# 原文と概念定義を同時に符号化する共通判定

対象範囲と定義を別々に平均した3係数方式では、関連する物体と述語・状態の混同が残った。今回、固定MiniLMの二列入力で原文と候補定義を一緒に符号化する方式を試す。指示文、生成、概念別の分類重み、語別の補正は使わない。条件は予測前に固定する。

## 特徴と対照実験

- MiniLMの既存固定リビジョン・CPU・float32・eager・seed 17・8スレッドを使う。全重みを固定しevalで動かす。入力列Aは原文、Bは原文と同じ言語のNoemaの定義とする。日英の言語指定は入力の属性であり、正解概念や役割は入力しない。
- tokenizerのsequence IDと文字位置で、A内の対象範囲とB内の全内容トークンを別々に平均・単位長正規化する。特殊記号を定義平均へ含めない。二列の合計128トークンを上限とし、長すぎる組は切断せず失敗として検出する。Noemaの91定義は変更しない。
- 同じ原文・候補の組を複数の対象範囲で共有し、モデルのforwardを重複させない。評価の正解範囲を使う試験と、過去の構造解析が予測した範囲を使う試験を区別する。
- 対照方式は原文と同じ言語の定義を別々に符号化し、同じ対象範囲・定義内容トークン平均を使う。両方式のヘッドと学習条件を揃える。既存のMiniLM・日英定義平均・3係数方式も回帰の比較として残す。

## 学習と選択

- 既存の学習3,072範囲、開発288範囲をそのまま使う。学習12概念、開発の正例3概念という留保は維持する。開発の候補は今回91概念へ増やす。追加76概念は学習の正例にも負例にも使わないが、開発時の候補には含むため、モデル選択に全く無関係な概念とは呼ばない。
- 共通ヘッドは正規化した対象qと定義dから`[q, d, abs(q-d), q*d]`を作り、コサインに`0.25*tanh(network(features))`を足す。networkは線形と、幅64・tanhの浅いMLPを比較する。最後の層は0初期化で、初期スコアは両方ともコサインとなる。候補数に依存する重みや概念ID入力は持たない。
- スコア10倍の交差エントロピー、AdamW、学習率0.002、weight decay 0.001、batch 32範囲、20 epoch、seed 17。開発日英平均の正解率が最高のepochを選び、同点では早いepochを採用する。方式・ヘッドの選択も開発資料のみで行い、同点では独立方式、線形の順を優先する。全構成の確認結果を報告する。
- v4は観察済み回帰、新しいv5は20既知概念と6未知概念の日英対。今回の予測前に作成し、確認結果で特徴・係数・ヘッド・epochを変更しない。同じ作成者の少数例であり、広い入力の独立評価ではない。
- 以前の32文も観察済み回帰として、保存された予測範囲・役割logitを固定し、開発で選んだ照合器の全91候補スコアから同時選択を再計算する。

固定特徴からの再学習、候補順序・追加に対する共有ヘッドの性質、範囲と二列の分離、切断拒否、反復と直接forwardの一致、禁止経路の呼出し0を検査する。元の部品を変更せず、別の研究APIと記録を作る。未抽出の否定・時間・数量等、未知判定、広い対応範囲の課題は残り、全文を確定しない。
