# 既存モデルと概念定義だけで語彙を拡張する探索

**定義の追加だけで候補語彙を増やす処理は実装できたが、この単純な比較だけでは意味解析器を置き換えられない。** 最も良かったモデルでも、正解の範囲を与えた概念選択が日英とも95%に届かなかった。基盤モデルも分類器も追加学習していない。

## 条件と結果

[事前の条件](definition-probe-protocol.md)・[日英48組の資料](../data/definition-probe-v1.json)・比較コードを、予測前のコミット `5cdd2af` で固定した。40組は既知概念、8組は語義違いまたは未知概念である。候補は文語の91概念すべてとし、日本語と英語の既存定義を固定モデルでベクトル化した。意味構造、役割、否定、時間の正解は入力しない。文字範囲だけを正解から与える。

下表は各言語の既知40件について、先頭候補が正解概念と一致した割合である。確定出力率や意味構造完全一致率ではない。

| モデル | 入力の表現 | 日本語 | 英語 |
|---|---|---:|---:|
| XLM-R | 範囲を単独で符号化 | 2/40（5.0%） | 0/40（0.0%） |
| XLM-R | 文中の範囲の文脈ベクトル | 6/40（15.0%） | 8/40（20.0%） |
| XLM-R | 全文の平均 | 2/40（5.0%） | 1/40（2.5%） |
| MiniLM | 範囲を単独で符号化 | 25/40（62.5%） | 30/40（75.0%） |
| MiniLM | 文中の範囲の文脈ベクトル | 28/40（70.0%） | 29/40（72.5%） |
| MiniLM | 全文の平均 | 17/40（42.5%） | 18/40（45.0%） |

MiniLMの文脈ベクトルでは、既存分類器の対象外だった26概念中、日本語16件、英語15件を選べた。新しい概念ごとの分類ヘッドや訓練例は使っていない。ただし、事前学習でモデルがこれらの語を見ていないという意味ではない。上位3候補への正解包含率は日本語87.5%、英語90.0%。日英40組中33組で先頭候補は同じだったが、両方正解なのは26組にとどまる。言語間で一致しても意味が正しいとは限らない。

各モデルで最初の16文を同じバッチ形状で再推論し、トークンベクトルの数値が完全に一致した。CPU・float32・8スレッドで実行した。この検査は異なるハードウェア間の一致を保証しない。

## 誤りから分かった制約

- MiniLMの文脈表現でも、日英の「開けた／opened」は開いた**状態**へ、「閉めた／closed」は閉じた**状態**へ寄った。変化と状態を区別するNoemaの意味規則は、単純な類似度だけでは保持できていない。
- 「買った／bought」「売った／sold」は文中のパンや店へ寄った。対象範囲を指定しても、そのトークン表現が概念の独立した定義と一致するとは限らない。
- 「キーボードのキー」は、定義で明示的に除外してある物理的な鍵を選んだ。未知語や適用外の語義に対して、最も近い候補を返すだけでは棄却できない。
- MiniLMの文脈比較で、日本語の正解候補のコサイン値は0.279〜0.715、未対応入力の最高候補は0.249〜0.614だった。英語もそれぞれ0.285〜0.686、0.278〜0.568と重なった。これらの値をそのまま確信度には使えない。閾値をこの探索資料で調整して採用基準を通したことにはしない。
- XLM-Rの単純な平均では、多くの誤候補も0.99前後の高い類似度になった。これは今回の未学習の比較方法が不十分という結果であり、XLM-Rの特徴を使う学習済み解析器の能力や、モデルが持つ知識の上限を示すものではない。

## 次の設計判断

既存モデルは、単語をNoemaへ一つずつ教え直さずに使うための基盤になり得る。しかし「既存モデルをそのまま使う」ことと「新しい言語の意味規則を守れる」ことは同じではない。概念の候補生成と、型・変化／状態・意味役割・否定・未対応の検証を分ける必要がある。

この探索は本番の `Analyzer` や翻訳画面へ接続しない。固定した91クラスの分類器へそのまま拡大するのではなく、概念定義を入力として扱う共有の対応付けと、意味構成規則を次の比較対象とする。文字体系も、この結果だけでは合理的にならない。語と字形の構成規則を別途設計し、旧版の文章を読める状態で検証する。

元の確定率80%以上・確定出力の意味構造完全一致率95%以上は未達の課題として保持する。これから同資料を使う改善は回帰比較であり、採用判断には別資料が必要である。

