# 方針の安全性についての認識

カントu0016の `sieht ein` を、先行草案の「公的な理性使用を許す方針に危険がない」という内容へ接続した。[本文の改訂案](../examples/v016/kant-policy-recognition.noema)では、統治者がその内容を認識し、肯定判断を持ち、内容も成立するという部分的な読みを記述する。洞察や理解の一般的な定義を完成したとは扱わない。

既存の1,395宣言と先行16文を保持した。最後の部分内容の帰属文だけを改訂し、認識を含む内容へ置き換えた。5定義と5原始宣言を追加し、文数は17のままである。前の安全性だけの草案と同義な変換ではない。安全性が成立しても本人の認識がないモデルで、新旧の内容は異なる。

## 判断と真理の条件

| 定義 | 条件 |
| --- | --- |
| `rro` | 同じ人・対象記述・判断文脈について、非空の候補状況の全てで対象内容が成立する。 |
| `rrp` | `rro` に加え、本人が同じ記述を同じ文脈で認識する。 |
| `rrq` | `rrp` に加え、判断文脈で対象内容が実際に成立する。 |
| `hzninsight` | 同じ統治者に、方針安全性の記述 `hzmsafety` と上記の条件を結び付ける。 |
| `hznattribution` | 認識を含む内容を、著者・本文箇所・原文範囲・文脈へ帰属する。 |

例えば、本人が残した候補では全て安全だが、実際の評価文脈では危険な場合、`rrp` は成立しても `rrq` は成立しない。実際に安全であっても、本人がその記述を認識していなければ両方とも成立しない。候補が空なら `rro` も成立しない。

認識と候補の関係には対象記述を渡す。真偽が一致する別の記述を認識しているだけでは、この対象についての認識にはならない。また、人と判断文脈を同じに固定する。別人の判断や別時点の認識を流用しない。

## 危険の評価と認識の評価

判断の候補と、政策を採った場合の想定結果は別の関係である。判断の各候補で、同じ方針の想定結果を選び、その結果の許可と不利益を調べる。方針の対象者・活動・提示項目は、元の基準文脈に固定したまま保持する。

今回の内容では、行為記述の評価、方針の評価、安全性についての認識という評価の入れ子を、既存0.16の段階付き引用で表した。安全性の記述は段階2、認識を含む内容の引用は段階3となる。文法や実行時の制限は変更していない。著者への帰属を評価するときに、引用された認識や政策安全性を実行する必要はない。

認識条件を評価するときも、許可対象の発言が実行されたことや、現在すでに許可が発効していることを要求しない。許可を採った場合の危険と、現在の許可を区別する先行草案の条件を継承する。

## 原文対応と未解決事項

原文対応は `sieht ein` の `[485, 494]` と、前回の安全性の `[539, 649]` を非連続な二範囲として記録する。途中の「立法についても」という限定や、後続する法文案・率直な批判まで記述済みには数えない。非空白文字の追加は8文字である。

`sieht ein` の部分的な読みとして真なる肯定認識を採ったが、どのように理解したか、根拠が妥当か、偶然正しかっただけかは説明していない。候補状況と記述への認識も解釈入力として残る。知識や洞察の十分条件ではなく、矛盾した信念や論理的全知の一般問題も未解決である。

先行草案の危険・公的使用・理解力・臣民の意味に関する課題も残る。全従属節や段落の意味一致は未確認であり、意味確認済み区間数は増やさない。

## 再現手順

93件の検査項目を確認した。認識の有無、二候補の選択、現在と候補での真偽の64組合せに加え、人・時点・記述の取り違え、未知の解釈、本文の入れ子評価16組合せ、著者帰属を検査した。本文と抽出文書のCLI解析、SVGのXML検査も通過した。SVGの目視検査は行っていない。

本文の検査では、項目を与える七つの原始関数を固定した閉じた記述を返すNoema定義で解釈し、残りの関係も状態を変更しない関数として与える。既存の評価キャッシュを利用し、「候補では安全だが現在は危険」という同じ例をキャッシュなしでも照合した。比較検査は最初の1,500万ステップ上限では停止したため、検査用上限を1億へ広げて完了させた。処理系の既定値や文法は変えていない。

```powershell
python -X utf8 -m scripts.compose_policy_recognition
python -X utf8 -m pytest tests/test_policy_recognition.py -q
python -X utf8 -m scripts.check_policy_recognition --verify-only
python -X utf8 -m scripts.audit_written_progress_extended --verify-only
python -X utf8 -m noema.constructed parse -i examples/v016/policy-recognition-core.noema
```

生成器は既存の成果物を上書きせず、保存内容が再構成と一致するかを確認する。長形式・短縮形式・固有文字の往復と、[専用の検査記録](../reports/policy-recognition-v1.json)の再現を確認した。有限モデルの検査は、原文の意味一致や現実の政策に関する証明とは区別する。
