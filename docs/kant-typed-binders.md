# 型と複数引数の束縛

量化とlambdaを、nativeの六つの基底型と再帰型へ接続する。型の構成を一つの前置文法で表し、作品ごとの型番号や型ごとの基本宣言を追加しない。既存のindividual量化とindividual一引数lambdaは従来の短い形を保持する。

## 型を読む規則

基底型はindividual、number、truth、situation、content、messageの六つ。それぞれ一つの型語で表す。再帰型は次の順序で読む。

| 構成 | 後続を読む順序 |
| --- | --- |
| sequence | 要素の型を一つ |
| description | 記述対象の型を一つ |
| question | 引数の型列を一つ |
| function | 引数の型列、その後に結果の型を一つ |

型列は「継続・一つの型」を必要な回数繰り返し、「終端」で閉じる。空の列は終端だけで表す。したがって関数の最後の引数型と結果型、lambdaの最後の引数型と本文を取り違えない。型の入れ子でも同じ規則を適用する。

descriptionの順位は、既存の `quote_raise` をdescription型の前に重ねて表す。この位置では型の順位を一つ増やす操作であり、後続がdescription以外なら拒否する。順位の反復数と型の入れ子の深さは別に数える。現在の描画資源制限として順位は128までとする。

## 束縛との接続

型付きforall・existsは、型を一つ読んでからその型の変数を束縛し、本文を一式読む。型付きlambdaは、型列を読み終えてから、宣言順にすべての変数を束縛し、本文を一式読む。ゼロ引数も複数引数も同じ規則で扱う。変数名は従来のnative正規化順で復元し、[外側への参照規則](kant-binding-scope.md)をそのまま適用する。

型の表記には式の引数を枝として付けず、語彙の区切りも入れない。型語や型列の継続・終端が、式の位置に単独で出た場合は拒否する。型の読取後にはnativeの型検査を通すため、number変数をindividual引数として使うことや、lambdaの引数名の重複を許さない。

## 字形

型付きforall・existsは大円の左円周上に中円中心を置き、大円中心線をそれぞれ左・右へ向ける。型付きlambdaは中円中心を大円の右円周上に置き、大円中心線を右へ向ける。従来のindividual一引数lambdaは同じ円配置で中心線が左を向くため区別できる。

六つの基底型は、小円中心を大円の左円周上に置く族とし、individualから順に右・右下・下・左下・左上・上の中心線で区別する。斜線は既定どおり大円の上下端と同じ高さまで直進して終わる。小円中心に線を入れない。

四つの再帰型は大中同心円と、円周から外への終端斜線を用いる。sequenceは右下、descriptionは左下、questionは左上、functionは右上。型列の継続・終端は、大円の左円周上に中円中心を置き、大円中心線をそれぞれ下・上へ向ける。これらは公開された固定の文法表であり、文書の登録順によって字形を割り当てない。

既存の全30根語と文法形を含む69異体で衝突がないこと、実際の接続後にも識別できることを確認した。どの追加形も、偏心内包を許す配置ではない。

## 証拠と残件

[構造報告](../reports/kant-typed-binders-v1.json)には、六つの基底型、四つの再帰型とその入れ子、空の引数列、順位、複数引数の各参照位置、宣言順の交換、引用、外側参照を含む26例を記録した。図形から元の構文・型が一致し、保存済みカント40文も新しい読取器で同じ構文へ戻る。本文と既存辞書の語義は変えていない。429件の局所・回帰検査が成功した。

進捗ファイルの置換がWindowsのアクセスエラーで一度停止したが、保存済み28ステップを入力・実装のハッシュ照合後に再利用し、全66ステップを完了した。検査結果を意味判断として転用する処理はない。

新しい共通の構造検査器 `kant_structural_trial.py` は、文法例の生成・復号と保存済みSVGの確認を小さいチェックポイントに分ける。今後の文法拡張で同じ保存・再開・報告処理を再利用できる。既存の検証器は保持する。

見本は `output/kant-typed-binders/index.html`。`forms.png` が追加字形、`inspection.png` が同倍率の文の抜粋である。型ヘッダーは大円の連なりが多く、外観の完成例ではない。一般部分式の枝、未対応の式構成、文書宣言、行・頁の復号、許容形の使用範囲と反復の調整は引き続き残る。外観の確認前に固定しない。
