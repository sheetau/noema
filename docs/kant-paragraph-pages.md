# 保存本文を段落と物理ページへ組む

## 先行計画

元ページの四段落と40項目の順序を配置へ引き継ぐ。意味関係の追加はなく、既存の公開本文reader、保存図形の接続、行端の線による折返し、順序付きページの復号を組み合わせる。各項目を別々の行に固定しない。接続できる隣接項目は同じ流れにし、段落の終わりでは流れを閉じる。

読取の図形予算を超える前、または保存図形の限定した接続候補が成立しない箇所では、完結項目の境界で別の流れに分ける。拒否された接続を記録する。入力自体の不正や読取失敗を、この配置上の拒否として握りつぶさない。円や既存線を変えずに済む範囲の処理であり、接続できない項目の再配置や、綴りの圧縮は別途必要になる。

段落の先頭には通常の行間より余白を加える。ページ内の行順とページ順だけを読取器へ渡し、段落ID、項目ID、接続の履歴、元構文を復号には使わない。段落の区分は組版情報であり、平坦なNoema構文から元の段落IDまで復元できるとは主張しない。文法上の束縛や引用は既存の構文境界が決める。

長い処理では接続試行と折返しをcheckpoint関数で個別の保存単位にする。入力図形、辞書・既読文書、幅、実装のハッシュを固定して使う。保存したテスト結果を意味判断に置き換えない。最後は実SVGの各ページから項目列を回収し、独立に読んだ入力と一致させる。

元kant-pageは629円・18行、従来の公開綴りによる同じ40項目は2,825円である。単に段落へ詰めれば元の密度になるとは考えない。長い接続、同形の反復、綴りの冗長さと許容形の利用は、全体の外観を確認しながら改善する。
