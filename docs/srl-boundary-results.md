# 語境界を保つ句の抽出

**語の途中で句が始まらないように系列を推定し、語単位の不正なBIO列を解消した。** 語彙別の補正、助詞の付け足し、追加学習は行っていない。モデルの重みと分類確率を共通にした比較で、日本語の指定範囲は既存資料24/36→26/36、新資料9/19→11/19となった。英語の指定範囲には後退がなかった。

これは句の抽出の改善であり、広い自然文の翻訳や全文意味構造一致率95%以上を達成した結果ではない。主画面の翻訳方式は置き換えていない。

## 変更した処理

前回は、サブワード列をBIO制約付きで推定してから各語の先頭ラベルを取り出していた。語の途中に開始ラベル `B-X` が出ると、それが脱落して不正な語単位の列になることがあった。

今回は、語に `B-X` を選んだ場合はその先頭を `B-X`、残りのサブワードを `I-X` にする。`I-X` と `O` は語内で繰り返す。この展開を満たし、語の間でもBIOが整合する系列のうち、全サブワードの分類確率の和が最大になるものを選ぶ。単に不正な `I-X` を `B-X` に書き換える処理ではない。開始だけでなく役割や範囲外の候補も含めて、文全体で選び直す。

語の区切りは固定したStanzaの結果を使い、英語・日本語で処理を分岐させていない。文頭・文末の特殊トークンは範囲外とする。モデルのラベル一覧に継続用の `I-X` がない場合は、複数サブワードにまたがる `B-X` を候補にできない。分類ラベルを新しく作ることはしない。

語境界自体が不適切なら、この制約で正しい意味範囲を失う可能性がある。整合するラベル列が得られたことだけでは、意味が正しいとは判定しない。

## 固定条件と結果

[比較条件](srl-boundary-protocol.md)と[新しい8組](../data/srl-boundary-v1.json)を `3a27d71` で保存した。初回起動は、在庫に継続ラベルがないことを検出して比較予測前に停止した。その扱いを `2550860` で明記してから実行した。モデル・述語検出・分類層は[前回](srl-span-results.md)と同じであり、正解の述語位置は入力していない。

| 資料 | 言語 | 指定した役割・範囲の完全一致（従来→語境界制約） | 文内の指定条件がすべて一致 | 不正なBIO列 |
| --- | --- | ---: | ---: | ---: |
| 既存16組 | 日本語 | 24/36 → 26/36 | 7/16 → 8/16 | 2 → 0 |
| 既存16組 | 英語 | 35/36 → 35/36 | 15/16 → 15/16 | 0 → 0 |
| 新規8組 | 日本語 | 9/19 → 11/19 | 2/8 → 3/8 | 1 → 0 |
| 新規8組 | 英語 | 19/19 → 19/19 | 8/8 → 8/8 | 0 → 0 |

指定範囲の改善は日本語で各資料2件、後退は両言語・両資料で0件だった。述語検出が余分に出した位置も含めて、計78の述語位置を処理した。省略の確認例では両方式とも主体を追加しなかった。

既存資料は開発時に結果を知っていた回帰資料である。新規資料も少量の人工文にとどまる。また、余分な役割や語義などを網羅した正解ではないため、英語の19/19を全文意味構造一致率100%とはしない。

## 直った例と残る失敗

既存の「雨が降れば、主催者は試合を延期する。」では、「延期」に対する「主催者は」「試合を」を正しい役割・範囲で返せるようになった。新規の「装置が壊れたら、技術者は部品を交換する。」でも、「技術者は」「部品を」が取り出せた。

一方、既存の「降れ」に対する出力は整合した列になったものの、「雨が」の項は取得できていない。ラベル列の不正をなくすことと、必要な意味要素を取り出すことは別である。

新規の「三人の囚人が警察に釈放された。」は依然として囚人をA0とし、受動態の役割を誤った。「若い写真家が雪に覆われた山を撮影した。」では、主体と対象をまとめた大きなA1範囲が残る。授与文では「隣人に」「小包を」の助詞が範囲に含まれず、従属節の「と」が落ちる例もある。これらを今回の境界制約で解決したとはしない。

次に必要なのは、日本語の役割・節関係を学習済みのモデルから取得できるかの検証と、抽出した句の概念・作用範囲を意味構造へ接続する処理である。語彙表や個別の文型補正の追加で代替しない。

## 検証と再実行

小さい系列について、可能な語単位のBIO列を全列挙し、展開後の確率和を最大にする解と実装が一致することを検査した。1サブワードの語だけなら通常のBIO推定と一致する。ラベル在庫の欠落、不正な語境界、原文の絶対位置、予測からの集計再現も検査対象にした。

全48入力で両方式を反復して出力が一致し、従来方式の32入力は前回保存した出力とも一致した。公開実装との前処理・制約・分類ロジットの互換検査も通った。これは語境界制約が公開デコーダーと同じであるという主張ではない。

別プロセスで述語検出から再実行し、全予測・判定・集計・互換検査・実行条件の5ファイルが一致した。全217テストが通過した。[再現性の記録](../reports/srl-boundary-v1/reproducibility.json)

モデルの準備は[前回の手順](srl-span-results.md#再実行)を使う。新しい出力先を指定して実行する。

```powershell
python -m scripts.probe_srl_boundaries --output reports/srl-boundary-reproduction
python -m pytest -q
```

[実行条件](../reports/srl-boundary-v1/run.json)、[全予測](../reports/srl-boundary-v1/predictions.json)、[判定](../reports/srl-boundary-v1/assessment.json)、[集計](../reports/srl-boundary-v1/summary.json)を保存した。各方式は同じモデル呼び出しの確率を使い、評価注釈は予測後の判定にだけ渡す。既存の公開互換APIは保ち、比較用API `predict_variants` で両方式を選べるようにした。
