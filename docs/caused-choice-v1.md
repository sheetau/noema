# 同じ能力増加に対する因果モデル内の依存

前段で記述した行為の選択能力の増加に、思考の発展への依存を表す条件を追加した。発展を取り除いた側でも同じ増加が起きるなら、この依存条件は成立しない。**指定した因果モデル内の強い候補**であり、カントの因果機構を実証したものでも、原文の唯一の解釈でもない。

## 増加がないことと、調べられないこと

[一般定義](../examples/v016/caused-choice.noema)の `rxf` は、前段の増加判定 `rxe` と同じ活動・方法・結果・時系列を使い、判定に必要な情報が揃っているかを確認する。非空で重複のない完全な活動一覧、両端を含む有効な履歴、区間内の全活動の実行・不実行能力の評価、正の増加上限を要求する。増加そのものは要求しない。

この評価条件を満たして初めて、`rxe` が偽であることを「この解釈で指定された増加条件を満たさない」と扱う。方法の評価不足や不正な時間順序による失敗を、増加がない証拠へ流用しない。

## 同じ方程式に対する二つの介入

`rxg` は既存の構造方程式の解と介入の定義を使う。観測割当ては介入前の方程式を満たし、要因、対応する前件、評価条件、結果が成立していなければならない。その同じモデルで要因の方程式だけを真または偽に固定し、両側に解があることを確認する。

| 比較する側 | 全ての解に要求すること |
| --- | --- |
| 発展を表す要因を真へ固定 | 前件が成立し、能力増加を評価でき、増加が成立する |
| 同じ要因を偽へ固定 | 前件が成立せず、同じ能力増加を評価でき、増加が成立しない |

解がない側を成功とは数えない。複数の解がある場合に、都合のよい一つだけを選ぶことも認めない。これは要因への強い依存であり、他の原因でも同じ増加が起こる場合や、要因が増加の一部だけに寄与する場合を全て扱う条件ではない。

## 本文の内容と比較先の一致

[本文草案](../examples/v016/kant-caused-choice.noema)の `iakcausal` は、選んだ思考の発展の記述を同じ本人について実行し、各解の開始点での真偽が要因と一致することを要求する。変数に「発展」という意味を付けただけで、発展の内容を検査済みにはしない。

`iakchecked` と `iakeffect` は、各解の時間経過において、前段と同じ行為の選択能力を実際の方法と結果から評価する。活動一覧・評価範囲・増加上限は、元の開始点で固定する。仮定側で都合のよい活動一覧や上限へ切り替えない。実行内容とその否定、方法空間と結果の評価基準も共有する。

さらに `iakaligned` が、観測割当てに対応する開始点・終了点・全履歴・履歴内の時間順序を、前段の条件文と照合する。別の時点で起きた増加を、観測された帰結として使わない。仮定側には別の時間点を使えるが、それぞれが判定に必要な履歴の条件を満たす必要がある。

`iakschema` は、この依存条件を前段の能力増加と連言し、残りの社会的・政治的条件を同じ語義・本人・起点・終点で保持する。前件が偽の仮定で増加を断定せず、ひな形を著者へ帰属するだけでも内容を実行しない。親文書の全宣言と先行21文を保存し、最後の部分注記を更新した。

## 検査と解釈上の限界

因果条件の45件のテストが通過した。一般定義では二変数の結果方程式16通り、観測の不整合、要因・前件の不一致、解の不在、評価不足、未知入力を検査した。本文では実際の発展と能力増加の定義を接続し、発展なしでも増加する反例、未評価の方法を含む反例、観測履歴の取り違えを調べた。仮定の開始点で別の活動一覧を提供しても、それへ切り替わらないことも確認した。

有限診断には既存の明示的な短絡評価と、[字句的な関数の再利用](closure-caching-v1.md)を選択する後継評価器を用いた。前件が偽の場合に旧評価器で生じた実行量の超過を、条件と上限を変えずに解消した。後継評価器の102件の検査も通過した。キャッシュなしの照合は一般の依存条件の基準例を対象とし、本文全体のキャッシュなし評価とは区別する。三文書の長形式・短縮形式・固有文字の往復とCLI解析、抽出文書のSVGのXML検査も通過した。これらは原文との意味一致、モデルの実証、字形の目視確認を代替しない。
