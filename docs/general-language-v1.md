# Noemaの共通仕様と語彙の使い方

Noemaでは、対象、数、真偽、状況、命題内容、発話、関数、問い、記述、列を型で区別し、定義と束縛によって組み合わせる。文の全体を一つの基本語へ置き換える必要はない。新しい対象や文化固有の概念は、その役割、関係、適用する文脈を説明して導入する。

この仕様は構文0.16と採用済みの円文字を使う。型付き構文は[0.14までの仕様](spec-v014.md)、[引用階層](ranked-quotation-v1.md)、[0.16の記述構成](quotation-construction-v1.md)を合わせて参照する。表示と復号の正本は[円文字仕様](circle-writing-v2.md)である。既存の二作品の本文、意味判断、辞書の語義は変更しない。[共通辞書](../output/general-language-v1/index.html)は語義、型、引数順、依存語、出典を一つの入口から参照するためのものとなる。

## 文を組み立てる単位

| 単位 | 保持する区別 |
| --- | --- |
| 個体・関係 | 誰／何が、誰／何に、どの状況で関係するか。役割が異なる引数を交換しない |
| 真偽と内容 | 今回の評価での真偽と、状況ごとに評価できる内容 |
| 主張・問い・発話 | 主張する、答えを求める、指定した基本的な働きの発話を行う |
| 仮定 | 仮定した条件の下の言説。現実で条件や帰結が成立したとの主張を加えない |
| 関数・量化 | 任意型の引数と結果、束縛の範囲、全称と存在の順序 |
| 記述・引用 | 対象の値と、その表し方。引用中の内容は言及だけで実行しない |
| 列 | 順序、重複、空列を保つ。集合として使う場合は別途重複禁止などを要求する |
| 定義と基本宣言 | 既存の意味から合成した概念と、解釈上の基本関係として説明を要する概念 |

例えば「各人に読んだ本がある」と「全員が読んだ一冊がある」は存在束縛の位置が異なる。発話を引用する場合も、引用した発話の話者と現在の話者を同一化しない。引数の型が同じでも、役割の順序は意味の一部である。

型に適合する関数や列を渡せるため、文を一つの固定した役割数へ揃える必要はない。否定、条件、量化、引用を入れ子にし、定義を呼び出して別の構成の一部にできる。実装上の深さ・評価回数・有限モデルの上限は、未知の命題を真または偽に補う規則ではない。上限に達した検査は未完として扱う。

## 辞書の四つの層

[版を固定したカタログ](../data/general-language-catalog-v1.json)には1,909項目がある。項目数は表現力の点数ではない。

| 層 | 項目数 | 再利用の条件 |
| --- | ---: | --- |
| 共通語 | 375 | 型、意味、引数役割、文脈条件を保持する |
| 今回の共通追加 | 19 | 有限確率9、解釈・表出等10。既存構文で定義する |
| 分野別の意味規約 | 1,488 | 単位・尺度・制度・比較域など、その語に必要な条件を保持する |
| 作品内の参照補助 | 27 | 固定事例の対象を指す。別作品へ同じ参照先のまま流用しない |

1,489項目は基本宣言、420項目は合成定義である。基本宣言にも型と意味規約があるが、合成による説明済みの概念として数えない。今回19定義に新しい基本宣言はない。ただし、態度の表出や制度上の権限などの関係を引数として渡す必要は残る。関係の意味を説明し、その成立の根拠を与える作業まで不要になったわけではない。

分野別語の掲載は、その全てについて別分野の翻訳を意味審査したという宣言ではない。元の語義を保持し、関係の項を別の対象へ置けるように整理したものである。固有の作品・制度に関わる条件が語義に含まれる場合は、それも保持する。名前を一般的にしただけで条件を消してはいけない。

## 未知の概念を導入する

まず、対象そのもの、性質、出来事、状態、制度上の役割のどれを導入するかを決める。次に必要な引数の役割と型を列挙し、既存の関係で説明できる部分を定義する。残る基本関係については、何を認める関係で、何を認めないか、どの文脈や根拠を必要とするかを記す。

文化固有の制度なら、参加者、役割、成立の条件、行為、規範、時期を分けられる。同じ名前でも共同体によって条件が違えば、語義と文脈を別に登録する。色・痛み・味・感情などの経験に関わる関係は、その経験の区別と帰属条件を説明する。物理量や真偽の式だけに還元できたことにはしない。

定義した語は別の文でも同じ意味で使う。一文の結論全体を判定する専用の基本語を設けたり、原文を引用文字列で格納しただけで意味を記述したことにしたりしない。文の結論に合わせて比較域、尺度、証拠、規約を入れ替えることも認めない。

## 発話の働きと意図した読み

基本の `message.force` は主張・質問・働きかけの3種を保持する。約束、助言、謝意、宣言などの社会的な働きは、同じ発話行為に話者・受け手・内容・規約を結ぶ合成層で扱う。基本的な働きと社会的な分類は一対一である必要がない。例えば問いの形の依頼を、問いというだけで自動的に依頼と認定することはしない。

自分の現在の発話行為を指して「この行為で引き受ける」「この行為で態度を表す」と記述すれば、明示された規約の下で遂行的な発話を構成できる。過去の発話を報告した文や引用の出現は、現在の行為の出現とは異なる。社会的な成功、権限、受領、理解はそれぞれ別の条件である。処理系の `perform` は外部の組織を操作したり、実際の社会的効果を発生させたりするAPIではない。

[追加仕様と型・役割](../data/general-pragmatics-basis-v1.json)は次を定める。

- 比喩の特徴対応型では、源の特徴、先の特徴、対応写像、字義の記述、意図した記述、読みの根拠を保持する。二対象の同一性や全特徴の移転は要求しない。
- 換喩では、二対象の関係と、当該の出現でどちらを指したかの選択を分ける。
- 反響と距離を表す皮肉では、字義が偽であることを必須にしない。意図した読みを単なる字義の否定へ固定しない。
- 態度の表出は、その態度を報告したこと、内心でも成立すること、受け手が理解したことと別である。謝意なら何を誰からの利益として受け止め、その人へどのような肯定的態度を示すかを態度の内容として記述する。「感情」というラベルだけでは具体的な内容を説明したことにならない。
- 制度上の宣言は、宣言したことと実効を分ける。実効には、その同じ宣言への権限・手続の適格さ・前提・制度的な結果を結ぶ。
- 物語内の内容は、物語枠・語りの声・評価状況を保つ。物語内での成立を現実へ移さない。
- 敬意や社会的距離の表示は、共同体の慣行、示した態度、内心の態度、実際の身分を分ける。

これらは代表的な構成である。全ての比喩や皮肉を一つの定義へ押し込める必要はない。別の用法がこれらの条件に合わなければ、字義・意図・評価・参照のどこが異なるかを明示し、既存の構成を組み替える。

## 確率と不確定性

[有限確率の仕様](../data/general-probability-basis-v1.json)では、重複のない有限事例列、非負の有理数の重み、総和1を要求する。事象の確率は条件を満たす事例の重みの和である。事例を数えた割合、実際に起きたという真理、ある人が信じていることとは区別する。

条件付き確率は、条件事象の重みが正である場合に定める。0の場合の値を0と補わない。独立性は同時確率と積の一致で検査し、情報源が異なるだけでは補わない。更新では同じ事例範囲の事前確率と尤度を使い、正の総和で正規化した事後分布を照合する。

未知の事象判定、未知の重み、根拠のない尤度は計算入力として拒否する。確率区間、複数の読み、未確定の参照先、相反する情報は、それぞれ別の構成で表す。有限確率の検査結果を無限分布の証明へ広げない。実数や無限領域を扱う場合は、既存の関数・量化・実数切断に測度等の条件を明示して構成する。

## 表現幅の確認方法

[表現分野と区別の一覧](../reports/general-language-review-v2.json)は、現在36分野について構成と既存文書・証拠を対応させる。日常的な会話、物語、制度、観測・数式などへの応用を併記する。応用の説明文自体は、その自然文を翻訳して意味審査した記録ではない。実行済みの構文・意味診断と分けて表示する。[読書と配送の作用域対照](../data/general-scope-contrasts-v1.json)と[抽選と仮説更新の確率対照](../data/general-probability-contrasts-v1.json)は、入力解釈と実行結果を保存した例である。

不足を探すときは、二つの意味が同じ構文に潰れないか、必要な対象を参照できるか、引用・仮定・条件の範囲が残るかを調べる。有限の小さな領域で区別できる反例を使い、関係の引数を一枠ずつ変えて束縛を診断する。全ての語の組合せや全モデルの総当たりは行わない。

同じ構文と語義・参照先が保存されていれば既存の意味判断を継承する。円文字の配置変更や新しい構成には、実図形を読み戻す検査を別に行う。構文解析の成功、有限モデルでの区別、自然文の意味確認、実図形の復号は別の証拠である。

辞書の全1,909宣言について、実図形と正規化した構文の一致を確認した。1,522宣言は同一の構文・token列・依存先・描画復号実装・SVG内容に基づく既存成功を継承し、387宣言を新たに描画・復号した。追加語彙と対照用の使用例148記録も別に復号した。旧証拠のうち作業対象を選ぶ `work-state.json` だけが変わった8件は、固定されている意味入力と検証器による診断部分を継承し、現在の作業対象との対応を含む旧レポート全体が再検査済みだとは扱わない。元の証拠と差分は保持する。

共通仕様の再検査では、既存の全履歴を読み直す必要はない。新しい定義に必要な依存語だけを読み、対照例を小さな有限領域で評価する。表示の変更には `scripts.general_language_ink` または `scripts.general_catalog_ink` を使い、`--run`・`--out` を新しいパスに指定する。同一入力での中断再開は `--resume` を付ける。実行は記録単位で進み、失敗箇所の後も続く。確率と作用域の保存証拠は `project_work check --module scripts.check_general_probability --verify reports/general-probability-v1.json` と `--module scripts.check_general_scope --verify reports/general-scope-contrasts-v1.json` で照合できる。

今回の整理は、二作品でしか使えない固定構文から離れ、異なる話題にも同じ型・規則・語義を再利用できることを確認するためのものとなる。あらゆる人間の意味を有限の試験で網羅したという主張はしない。未登録の経験的概念、文脈上の暗黙の解釈、韻律や言葉遊びの効果は、必要な内容や関係を明示して追加する。自動翻訳、暗黙の意図の自動推定、人による読解性の実証は、言語の構成可能性とは別の課題として保持する。
