# 文の種別と仮定範囲

## 接続前の計画

式の29構成子は既存の円・枝から読める。欠けているのは文の assert / ask / perform の区別と、suppose の条件・子文の範囲である。語義や原典ごとの専用語は追加せず、本文の型、自己終端する式、既存の範囲終端を再利用する。

native の文規則では、assert は truth、perform は message、ask は truth または question を本文に取る。したがって標識なしの本文を truth → assert、message → perform、question → ask と読める。truth を ask にする場合だけ ask_truth を先行させる。この標識は question 型には使わない。これにより全ての文に同形の頭を付けず、型が同じ assert と ask だけを明示的に区別する。

suppose は専用頭、truth 型の条件式、非空の子文列、types_end の順とする。式・型・列・内側の suppose は自分の終端まで読むため、外側の終端とは混同しない。suppose / ask_truth の頭と suppose の終端には引数枝や語内の無線接続を付けない。条件・本文内の枝は従来の引数順に従う。子文同士は同じ描画列に順番に接続し、子文専用の区切り形を挿入しない。

条件と各子文はそれぞれ自由変数環境を空にして読む。変数名の通し番号も各境界で0に戻す。条件の束縛を子文へ持ち越さず、前の子文の束縛を次の子文へ持ち越さない。これは native の statement_node と同じ規則である。引用内の変数範囲は既存規則を維持する。

ask_truth は大円と左上円周上の小円、南西方向の半径線。suppose は同じ円対と北東方向の半径線を使う。小円の中心は大円周上にあり、偏心した内包を使わない。上方向の半径線は小円への近接制約に違反するため採用しない。既存の語形との衝突は公開形表で拒否する。三罫線・接線方向・間隔・分岐配置は元の生成器を利用する。

## 確認範囲

小さな文種別対照、返り値の型から決まる文、兄弟文と入れ子仮定の束縛、引用・列の終端を実SVGから復号する。不正な本文型、空の仮定、終端不足・過剰、範囲外参照、頭や終端の余分な枝を拒否する。保存図形は再描画せず読み直す。

この規則は一つの文とその仮定範囲を対象にする。辞書宣言、文書の行・頁境界、全作品の配置と利用者による外観確認は別に残る。構文一致の検査を新しい意味判断や外観完成と扱わない。
