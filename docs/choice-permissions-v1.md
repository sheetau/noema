# 希望する話題・程度の全組合せへの許可

カント第17区間の「望むだけ、望む話題について論じよ。ただし服従せよ」という引用を記述するため、選択範囲と許可、順序付きの発話引用を分ける基盤を追加した。既存の規範定義 `rdm` を再利用し、五つの合成定義を加えた。文法演算子とライブラリの原始関係は増やしていない。

## 選択範囲を狭めて全称を成立させない

`rtr` は同じ本人・基準文脈について、活動候補の話題と程度が本人の希望範囲に入ることを表す。希望する話題と程度を独立に選べるという読みであり、活動候補を現に行われた行為だけに限定しない。

`rts` はその全対象への積極的な許可と、同じ対象への反対要求の不在を要求する。出所・本人・役割・活動・閉じた行為記述を保持する。活動内容を評価して実行を求める処理ではない。選択範囲は基準文脈で固定し、許可の成立は内容を評価する状況で調べる。

ただし、未許可の活動を候補から除けば、`rts` だけでは残った候補を全て許可したことになってしまう。`rtt` は、各本人の希望する話題と程度の全組合せに、それと一致する候補が存在することを要求する。`rtu` は網羅性と許可を合わせた内容である。

例えば二つの話題と二つの程度を選べるなら、四つの組合せが対象となる。一つの組合せに候補がなければ網羅性が不成立になり、候補はあるが許可されていなければ許可条件が不成立になる。話題または程度の希望範囲が空なら全称条件は真であり、希望や実行の存在を補わない。

網羅するのは明示した希望範囲である。入力側が実際の希望を省略していないか、候補の話題・程度と行為記述が適切に対応するかは、その入力の意味規約と別の検証が必要になる。型が合うだけで任意の候補一覧を正しいものと認定する仕組みではない。

## 許可を述べる内容と、服従を求める内容

`rtv` は二つの内容の閉じた記述から、許可内容を述べる主張と、服従内容を求める指令の記述を順序付きの列として作る。構成時には内容を実行しない。指令の引用が存在することと、指令に従うことは区別される。後半への服従を前半の許可の成立条件として自動で付け加えない。

これは許可を述べる発話としての試作であり、許可を新設する遂行的発話や、原文の「ただし」に当たる談話関係の全意味ではない。また、カントが実際に読者へ命令したと断定する変更でもない。原文では「誰だけがこれを言えるか」という上位の条件の中に置かれており、その接続は残る。

程度は個体型の対象として参照する。単位付きの連続量、望む量を上限としたそれ以下の量への許可などは、この基盤だけでは定義していない。例の服従内容も入力として残しており、命令の出所・対象範囲・履行条件を説明し終えたとは扱わない。

## 検証

[定義文書](../examples/v016/choice-permissions.noema)は6宣言・本文0文、[作例](../examples/v016/choice-permissions-example.noema)は24宣言・5質問である。本文への接続前に、46テストで次の区別を検査した。

- 候補の欠落、許可の欠落、反対要求、服従の成否を変えた16組合せ。
- 四つの話題・程度の組合せのいずれを除いても網羅性を満たさないこと。
- 希望しない選択肢まで許可を要求せず、別人への許可を借用しないこと。
- 出所・本人・役割・活動・評価状況の取り違え。
- 引用の順序、内容、主張と指令の種類の取り違え。
- 未知の許可・服従・希望範囲を引用の構成時には評価せず、直接の評価では未知として拒否すること。

長形式・短縮形式・固有文字の往復、保存文書と検査記録の再現、二文書のCLI解析、作例のSVGのXML検査が通過した。SVGの目視検査は行っていない。有限モデルの検査であり、希望の内容や自由選択表現全般の意味を確定した証拠ではない。

```powershell
python -X utf8 -m scripts.compose_choice_permissions
python -X utf8 -m pytest tests/test_choice_permissions.py -q
python -X utf8 -m scripts.check_choice_permissions --verify-only
```

[意味条件](../data/choice-permissions-basis-v1.json)と[検査記録](../reports/choice-permissions-v1.json)を保存した。カント本文への帰属、論じる行為と服従内容の具体化、話者・聞き手と国家・軍隊の条件、段落全体の意味確認は未完である。今回は原文対応範囲や意味確認済み区間数を増やしていない。
