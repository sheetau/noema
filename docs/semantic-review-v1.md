# 原文単位の意味確認

全文Noemaで記述できたと判断するには、原文の内容とその提示の仕方を、参照先と作用範囲を保って表せたことを確認する。原著者の物理理論や哲学上の主張が真であることの証明は、翻訳の完成条件ではない。偽の主張、未証明の仮説、相反する見解も、そのような内容として言語で記述できる必要がある。

一方、Noemaの式が何を意味するかが未説明なら、原文との意味一致を確認できない。演算子の意味、基本概念の規約、引数の役割、指示対象の同一性は言語側の課題である。実験や現実の測定を実施したかという問題と、電荷・速度・測定をどのような概念として表しているかという問題を分ける。

確認は次の順で行う。数式だけでなく、本文の主張・留保・比喩・名詞の説明にも同じ区別を適用する。

1. **固定した原文を指定する。** 原文単位、文字範囲または数式要素、版とハッシュを記録する。原刊との相違は原文の変更と分けて記録する。
2. **意味上の関係を列挙する。** 例えば等式の連鎖A=B=Cは二つの等式として点検する。否定、量化、時間、条件、例外、程度を省かない。
3. **記号と参照先を固定する。** 同じ記号や代名詞が何を指すかを、本文前後の文脈へ結ぶ。個々の単位を孤立させて全概念を再定義する必要はないが、参照する定義と文書の版は確定させる。
4. **原文の提示の役割を保つ。** 定義の導入、主張、仮定、質問、他人の見解の引用、結論の提示を区別する。条件関数を定義しただけでは、著者がその内容を述べたことを記述したことにならない。
5. **余計な条件と欠落を調べる。** 原文の式を表すために場の方程式全体を前提にするなど、別の主張を混ぜない。逆に数値の等値だけで実際の微分、測定、同じ物体への帰属を済ませない。
6. **言語側の意味を確認する。** 未知の名詞を原語の綴りや説明のない基本記号で代用しない。基本概念として採る場合も意味規約を明示し、合成概念と区別する。検査用の仮の解釈と、公開する意味規約を混同しない。
7. **根拠と限界を記録する。** 構文・型・往復、代数的な同値、有限の対照例、原文の読解は、それぞれが確認する範囲を記す。検査例の全通過を、原文との完全な意味一致に自動変換しない。
8. **単位全体を再読して判断する。** 関係・範囲・参照・提示の役割・概念説明がそろっているかを確認する。原文の曖昧さが残る場合は、保持した曖昧さと採用した解釈を区別する。未処理項目があれば部分対応のままにする。

この確認方法は、目標を短い数式の転記へ縮めるものではない。最終的には二作品の全単位を、文脈を共有するNoema文書として記述する必要がある。原文の文字範囲が100%になっても、内部に未説明の語や未接続の主張があれば完成ではない。

最初の具体例として、[M0390の五つの等式](density-formula-v1.md)を点検した。式だけの条件と必要な三微分への接続は検査したが、旧新の物体・系・出来事への参照と、直前の導入表現の接続は残る。このため意味確認済みの原文単位数は増やしていない。[確認記録](../data/density-formula-review-v1.json)は未解決項目を明示する記録であり、完成認定書ではない。

現在の進捗集計器は、正の意味確認済み件数が提出された時点で停止する。この保護は維持する。実際に全項目を満たす単位ができた段階で、その単位別の根拠と判断を読める形で集計へ接続する。今回、構文検査や数式検査だけで完成件数を増やす仕組みは加えない。
