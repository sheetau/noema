# 文語0.14：有限列と順次集計

0.14では、任意の有限長の列を一つの値として扱う。列は要素の順序と重複を保持する。区間、手順、論証の項目などを、項目数ごとに別の関数を定義せずに記述するための拡張である。版指定は`n:`または`noema n n`とし、32文字の字形は増やさない。

## 型と構文

| 記法 | 意味 |
| --- | --- |
| `j[T]` | 型Tの要素からなる有限列の型 |
| `l[T][要素 …]` | 順序と重複を保つ列。`l[T][]`は空列 |
| `d[列]` | 長さ。非負整数に等しい有理数の値 |
| `a[列][位置][値]` | 0始まりの指定位置にその値がある、という真偽 |
| `m[左列][右列]` | 同じ要素型の二列を順に連結した列 |
| `q[列][初期値][更新関数]` | 先頭からの順次集計 |

更新関数の型は`h[S T] S`である。Sは集計状態の型、Tは列の要素型である。Sには数値だけでなく、真偽、列、関数なども使える。列の要素型も既存の型から自由に構成でき、入れ子の列を許す。型と式の入れ子は、実装上の128段制限を引き継ぐ。

文書位置では`d`は定義、`a`は仮定、`q`は質問、`l`は発話実行を表すが、式位置では上表の構文として一意に解析する。型位置の`j[T]`と式位置の発話`j s[...]`等も区別する。

JSONでは列型を`{"kind":"sequence","element":T}`、列構成を`{"kind":"sequence","element":T,"items":[式,…]}`とする。他の式は以下のフィールドを持つ。余分なフィールドも拒否する。

| kind | 他のフィールド |
| --- | --- |
| length | sequence |
| position | sequence, index, value |
| concat | left, right |
| fold | sequence, initial, step |

## 意味と定義域

列の値の領域は、要素型Tの領域から作る、長さ0以上のすべての有限列である。文書中に現れた列だけを領域にはしない。長さは要素の出現回数であり、異なる要素の数ではない。

位置判定は、位置が整数であり、0以上かつ列の長さ未満であり、その位置の要素と指定値が等しい場合だけ真になる。負数、範囲外、非整数の位置は偽とする。範囲外の値を0等で埋めたり、分数の位置を丸めたりはしない。値を直接取り出す部分関数とはせず、定義域を含む関係として扱う。

等しい列は同じ長さを持ち、各位置の要素がそれぞれ意味上等しい。関数が要素なら関数の外延的な等しさ、式記述が要素なら正規化した記述の等しさを使う。関数を含む列をPythonオブジェクトの参照一致で判定しない。

順次集計は、列`[x₀,…,xₙ₋₁]`と初期値s₀に対し、`sᵢ₊₁ = 更新(sᵢ,xᵢ)`としてsₙを得る。空列では初期値をそのまま返し、更新関数は呼ばない。一般の更新関数には結合則・交換則を要求せず、並べ替えによって結果が変わり得る。数値の加算を言語本体へ新たに固定したものでもない。

例えば、初期値を空列とし、各要素を現在の列の先頭へ付けると逆順になる。

```text
n:
d aa[input j[b]] j[b][
  q[v input][l[b][]][i[state j[b] item b][m[l[b][v item]][v state]]]
].
s[e[k aa[l[b][n p b b n p c b n p d b]]][l[b][n p d b n p c b n p b b]]].
```

ここで`n p b b`、`n p c b`、`n p d b`はそれぞれ1、2、3である。[手順の順序の例](../examples/v014/procedure-order.noema)は、この反転と、各要素を二回ずつ並べる操作を記述する。数値は項目の識別値として用い、物理や加算の基本関係を必要としない。実際の手順の実行や、繰り返せば同じ効果になることは断言していない。

## 引用・量化・実行制限

0.13の引用規則を保持する。列の要素、添字、集計の初期値や更新関数、連結の両辺を含め、引用内には脱引用を直接にも定義経由でも隠せない。閉じた列式を引用してから脱引用することはできる。

有限列の型に対する量化は記述できるが、有限解釈器はその実行を拒否する。要素型が有限でも、空でなければ列全体の領域は無限になる。記述型などの空領域から作る列には空列しかない場合もあるが、現実装はその特例を自動判定しない。すべての列を答える質問、列を引数に取る関数の全域比較も同様に拒否する。個々の列の長さ・各位置・集計の検査と、すべての列についての証明は区別する。

実行値は変更不能の要素タプルと、正規化した型のJSON文字列を持つ。外部の基本関係が返す列は、型・要素の型・入れ子を検査し、関数要素の適用結果も検査する。更新関数の呼出し、列の検査、要素比較はステップ予算の対象になる。連結では、コピーする要素数をメモリ確保前に予算へ計上する。言語の意味上は任意の有限長を扱うが、実行時間・メモリ・深い関数適用には処理系の限界がある。無限列や連続曲線を有限列へ暗黙に置き換えない。

通常記法・短縮記法・固有文字・SVG・JSONを同じ解析器へ接続した。旧版の文書を0.14へ上げても意味を変更しない。列や列演算を使う文書の0.13以前への変換は拒否する。

## 時計の経路への部分適用

[有限経路の草案](../examples/v014/einstein-finite-paths.noema)は既存の時計草案へ8定義を加え、15基本記号・103定義となった。物理の基本記号は追加していない。

| 定義 | 内容 |
| --- | --- |
| ia | 各出現に性質が成立する。空列では真 |
| ib | 各出現の有理数値の和。空列では0 |
| ic | 区間時間と進み率の積の和 |
| id | 空でない列で、各区間時間が正、各速度と進み率が同じ光速についてhaを満たす |
| ie | idの条件と、全継続時間・経過・遅れの値の接続 |
| if | 出発点、隣接区間の終始点、到着点が順に接続する |
| ig | 同じ点へ戻るifと、ieの条件の接続 |
| ih | 各区間の数値が指定した共通値に等しい |

ifの初期状態は「出発点にいる」という場所の性質である。各区間を処理するたびに、現在の性質がその区間の始点で成立し、評価する場所が終点に等しい、という新しい性質へ更新する。最後に到着点で評価する。空列は同じ出発点・到着点だけを結ぶが、idが空列を除外するため、igでは空列を移動した時計として扱わない。

各区間の進み率を4/5、時間を3、2、5とすれば、全時間10、経過8、遅れ2となる。同じ三角経路を二度並べれば20、16、4になる。区間を並べ替えても時間の和は変わらないが、終始点がつながらなければifは偽になる。区間ごとに進み率が異なる場合はそれぞれの積を加え、先頭の率で全体を代用しない。

この草案は原文u0126〜u0128の折れ線・帰還経路に必要な表現の一部である。**区間の代数的条件を加算しただけで、加速点の時計の法則を導出したとはしない。** 同一の時計・基準系・時間単位・連続した指示への接続、幾何学的な速度と区間変位の結合、曲線への極限、地球上の比較は残る。これらの前提を原文に明示された事実として無断で補わない。以前のhnによる単一区間の観測接続も、今回のigへまだ全区間で統合していない。

```powershell
python -S -m scripts.compose_finite_paths

python -S -m noema parse --input examples/v014/einstein-finite-paths.noema --output artifacts/finite-paths-v014.json

```
