# 語彙数に依存しない共通判定器の結果

**概念ごとの分類クラスを増やさずに、新しい定義を候補にする小型判定器を実装した。** 学習に使わない50概念の試験では、3係数だけの方式が日本語66%、英語70%だった。未学習の文脈比較の60%から改善したが、意味解析器を置き換えられる精度ではない。

## 何を学習したか

固定MiniLMから、対象語の文脈ベクトル、対象語だけのベクトル、全文のベクトルを取り出す。候補はNoemaの既存の日英定義であり、概念IDは候補の識別にだけ使う。モデルへIDや正解の型を入力しない。

二つの共通スコアを比較した。線形方式は3種類のコサインの係数だけを学ぶ。双線形方式は、それに階数32の射影を加える。パラメーター数はそれぞれ3と49,155で、候補を15個から91個へ増やしても変わらない。単語ごとの別モデルや出力重みはない。ただし教師データを不要にしたわけではなく、既存12概念の注釈を対応付けの学習に使った。

[事前条件](shared-matcher-protocol.md)、[コード](../noema/shared_matcher.py)、[新しい確認資料](../data/definition-probe-v3.json)を、予測前のコミット `daf1f2c` で固定した。既存コーパスから学習3,072範囲、開発288範囲を抽出した。鳥・助ける・公園を含む文を学習から除き、この3概念でepochを選択した。開発時の候補は既存15概念。追加76概念の定義は学習損失の正例にも負例にも使っていない。

## 学習に使わない50概念での確認

新資料v3は、それまでの定義照合資料に出ていない50概念の日英50組と、対応外8組である。対象語の範囲は正解を与える。91概念すべてから選ぶため、型の正解による候補絞込みはない。

| 方式 | 日本語 | 英語 | 日英とも正解 |
|---|---:|---:|---:|
| 未学習・文脈の範囲平均 | 30/50（60%） | 30/50（60%） | 28/50 |
| 未学習・対象だけを符号化 | 25/50（50%） | 34/50（68%） | 25/50 |
| 未学習・全文平均 | 17/50（34%） | 19/50（38%） | 16/50 |
| 共通の3係数 | 33/50（66%） | 35/50（70%） | 32/50 |
| 共通の双線形射影 | 31/50（62%） | 33/50（66%） | 30/50 |

これは各言語50例の探索結果であり、広い入力分布での改善を確立した値ではない。3係数方式は日英43組で同じ候補を返したが、両方正解は32組だった。言語間の一致と意味の正しさは引き続き区別する。

## 開発成績と確認成績の差

開発用3概念では、未学習時の正解率は日本語75.0%、英語81.94%だった。3係数方式はepoch 10を選び、85.42%・100%。双線形方式はepoch 1で両言語100%となった。しかし、新しい50概念では双線形方式の方が低かった。開発用概念の少なさと候補数の違いに注意が必要である。

選択後の診断として、同じ開発入力の候補を91個へ増やすと、3係数方式は日本語123/144・英語132/144、双線形方式は123/144・118/144まで下がった。この診断でepochやモデルを選び直してはいない。15候補での満点は、候補を増やした後の正確さを示していない。

3係数方式の学習値は、文脈1.1135・対象だけ0.3416・全文−0.3897だった。全文との類似を差し引く成分が得られたことは観測事実だが、これが文脈から対象の意味を正しく分離できた証明にはならない。

既存資料も回帰として保存した。以下は各方式の先頭候補が正解だった割合である。

|---|---|---:|---:|
| v1・40概念 | 未学習の文脈比較 | 70.0% | 72.5% |
| v1・40概念 | 3係数 | 77.5% | 85.0% |
| v1・40概念 | 双線形 | 75.0% | 80.0% |
| v2・26概念 | 未学習の文脈比較 | 46.2% | 61.5% |
| v2・26概念 | 3係数 | 50.0% | 69.2% |
| v2・26概念 | 双線形 | 53.8% | 57.7% |

## 残った誤り

3係数方式の新資料で、型別の正解数は次のとおりだった。これは事後の内訳であり、型の正解は推論へ与えていない。

| 正解概念の種類 | 日本語 | 英語 |
|---|---:|---:|
| 対象 | 14/18 | 14/18 |
| 場所 | 6/7 | 7/7 |
| 出来事 | 11/15 | 11/15 |
| 状態 | 2/10 | 3/10 |

「含む」は中にある本へ、「教える」は先生へ、「働く」は職場へ寄った。文中で関係する概念と、対象語が表す概念の区別が弱い。「乗り物」を自転車へ限定する誤りもあり、近い概念だから許容してよいわけではない。

対応外の「根を含む花の株」は、定義で株全体を除外している花の構造へ寄った。3係数方式で英語のスコア0.880は、この資料の既知正解の最高値0.832を上回る。候補選択のスコアを確信度として扱ったり、単純な高スコアだけで確定させたりはできない。未知判定の閾値は調整していない。

## 検証と次の判断

全184テストを通過した。候補の並べ替えがスコアの対応だけを変えること、候補を追加しても既存候補のスコアとパラメーター数が変わらないこと、留保概念を含む文を学習へ入れないことを検査した。固定特徴から両方式の学習を再実行し、選択epoch・全履歴・保存重みが完全一致した。固定エンコーダーの16文の反復も完全一致した。[再現確認](../reports/shared-matcher-v1/reproducibility.json)

語彙の拡張を出力クラスの追加から切り離す実装はできた。ただし、現在の12概念には状態が空腹の1種類しかなく、場所・主体・出来事・状態を幅広く見分ける学習資料にはなっていない。今回の結果からは、層を増やすことより、関係する物と述語・状態を区別する共通の判定と、開発資料の概念・候補数の範囲を見直す必要がある。

この試験は正解範囲を使っており、意味役割、否定、時間、数量の抽出を含まない。確定率80%・意味構造完全一致率95%の条件は引き続き未達である。結果を見て確定範囲を狭めたり、本番の翻訳画面を切り替えたりはしていない。

## 再実行と記録

```powershell
python -m noema.shared_matcher --output artifacts/shared-matcher-reproduction
python -m scripts.verify_shared_matcher artifacts/shared-matcher-reproduction --output artifacts/shared-matcher-check.json
```

固定MiniLMのキャッシュと既存 `artifacts/corpus-v9.jsonl` が必要。`--corpus` で別パスを指定できるが、同じ実験の再現には記録したSHA-256と一致するコーパスを使う。既存の出力先は上書きしない。
