# 型付きの記述合成（0.16試作）

人物ごとの判断から主張と吟味目的を組み立てるため、閉じた式の記述を合成する二つの操作を追加した。入力の型を検査し、正規化したNoemaの構文を作る。合成した内容を実行するかどうかは、従来の評価操作で別に指定する。自然言語の生成や推測、対訳辞書は使わない。

この機能が必要になったのは、公的提示の資格条件を本文へ接続する作業で、内容の一致を確認する方法に問題があったためである。有限の検査状況で真偽が同じでも、別人の主張や別の目的記述を同じものとして扱うことはできない。そこで、判断の構文から主張を、その同じ主張の構文から目的を直接構成する方式を実装した。

## 記述の適用と引用

試作の版記号は `p:`。`Dᵣ(T)` は「型Tの閉じた式を記述する、層rの値」を表す説明用の略記である。

| 構文 | 入力と結果 | 操作 |
| --- | --- | --- |
| `o a[関数記述][引数記述…]` | `Dᵣ(T₁…Tₙ→R)` と各 `Dₛᵢ(Tᵢ)` から `Dmax(r,s₁,…)(R)` | 関数の式に引数の式を適用する構文を作る。 |
| `o r[記述]` | `Dᵣ(T)` から `Dᵣ(Dᵣ(T))` | 入力の記述を引用する構文を作る。 |

例えば、次の二つの記述は正規化後に一致する。

```text
o a[r[p relation]][r[k subject[]]]
r[c[p relation][k subject[]]]
```

左側の操作は `relation` や `subject` を実行しない。関数記述と引数記述の個数・型が合わなければ解析時に拒否する。入力は同じ評価器が発行した記述値に限り、外部で偽造した値や、別の評価器が発行した記述値を受け入れない。

合成では、引用の内部に自由変数を捕獲させない。閉じた式同士を適用構文で結び、束縛名を正規化する。引数の代入結果を実行して簡約する操作ではないため、式の参照先や構造を保持する。結果の層は入力の最大層とし、引用する操作でも入力の層を下げない。これは前版の保守的な引用検査を保つ規則である。

従来の `o[発話]` は発話内容を取り出す構文のままである。新しい二操作は `o a`・`o r` と明示し、旧版では受け付けない。

## 判断から主張と目的を作る

[人物ごとの主張と目的の例](../examples/v016/personal-message-purpose.noema)には、三つの定義を追加した。

- `rqa`：引数列から内容を作る基準の記述から、同じ論点を一要素の引数列として与え、その内容を主張する発話関数の記述を作る。
- `rqb`：受け手・論点の記述と、同じ主張の記述から、既存 `hzx` の「公衆による吟味」を目的内容として記述する。主張の記述を引数に渡すため、二つ目の引用操作を使う。
- `rqc`：与えられた主張と目的が、この二つの構成で得られる記述とそれぞれ一致することを確認する。

二人に異なる基準の記述を渡し、それぞれの主張と目的が異なる構文として得られることを確認した。目的の式には同じ主張の構文がそのまま入り、別の内容へ差し替わらない。構成と一致検査だけでは、基準内容、受け手、論点、目的の真偽を評価しない。

また、二人の基準をともに偽とする有限モデルでは、発話の内容が一致しても、他人の主張を `rqc` が拒否する。二つの受け手の式が同じ対象を指し、目的内容の真偽も同じモデルでも、別の受け手の式から作った目的記述への置換を拒否する。この検査は、記述の取り違えを防ぐための厳しい構文一致であり、任意の同義表現を認める意味判定ではない。

## 実装と検査

追加51テストが通過した。型と引数数、束縛名の正規化、自由変数を捕獲しない適用、層の保持、記述値の発行元、旧版の拒否、従来の発話内容構文との区別を検査した。8種類の高階呼出し経路についても、実行時の評価層の制限が維持されることを確認した。

合成した構文の大きさも評価回数上限に算入する。同じ式を繰り返し複製する入力は、全体を展開し終える前に上限で停止する。前版の制限付き評価器と評価層の状態を共有し、両評価器間の同期呼出しでも上限をリセットしない。

標準CLIと過去の文法・評価器は変更していない。専用入口を選んで実行する。

```powershell
python -X utf8 -m noema.constructed parse -i examples/v016/personal-message-purpose.noema
python -X utf8 -m noema.constructed format -i examples/v016/personal-message-purpose.noema --script
python -X utf8 -m noema.constructed render -i examples/v016/personal-message-purpose.noema -o personal-message-purpose.svg
python -X utf8 -m scripts.check_constructed_purposes --verify-only
python -X utf8 -m pytest tests/test_quotation_construction.py -q
```

[検査記録](../reports/constructed-purposes-v1.json)には二人の構成結果の実際の構文と、真偽の一致だけでは置換できない五つの結果を保存した。長形式・短縮形式・固有文字の往復、CLI解析、SVGのXML検査も通過した。SVGの目視検査は行っていない。既存0.15の二文書が同じ構造で解析され、明示的な版移行でも宣言と文を変更しないことを確認した。

## 本文への統合で残る点

今回は判断・主張・目的の接続を、式の構成として実装した。公的提示の行為全体の記述をこの操作から作り、前回の一般許可文の資格条件へ渡す作業は残る。既存のカント本文と著者帰属文は今回変更していない。

記述を構成できることから、その内容の真理や、原文との同義性は導かない。任意の関数について実行前に評価層の違反を検出する仕組み、無矛盾性・停止性の証明、無限領域の評価も未完である。Pythonの解釈関数は信頼するモデル実装であり、外部プログラムを隔離する機構ではない。
