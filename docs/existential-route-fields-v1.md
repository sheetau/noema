# 伝達経路の役割と時点を存在で述べる

各段階の送信者・受け手・行為・時点を、受け手ごとの経路の中で存在量化した。これまで文全体の外部指定に含めていた四つの対応関数を、伝達の具体例として扱う。許可条件と将来予測へ渡す供給関数は17から13になる。

`hzr3` は、四関数と既存の五つの経路条件（最初の段階、残りの列、取得過程、開始点、終了点）を存在で述べる。指定した関数から選んだ人物・行為・時点が、実際の提示・受領・時間順序・中継来歴と一致することを、既存の定義で検査する。受け手の理解、同じ性向の因果的な取得と持続も必要である。

`hzr4` は受け手ごとにこの条件を使う。四関数は全域関数だが、使用する段階について伝達条件を要求する。全受け手に同じ対応表を使うことや、段階のラベルが文書全体で唯一の通信記録を指すことは追加しない。実際の行為は提示・受領の関係で拘束する。

一方、発信者の自己離脱は全受け手で共有する。`hzr5` は自己離脱の行為と前後点を受け手範囲の外側で一度量化し、`hzr4` に渡す。受け手ごとの経路に合わせて別の自己離脱を選び直すことはできない。周囲の範囲と、条件を満たす受け手の正確な範囲も保持する。

`hzr6` は同じ本人の独立判断への性向を結び、`hzr7` は将来の各機会にいる複数人と指定部分集団を結ぶ。`rqt7` は同じ許可期間から機会範囲と順序を作り、残る13供給関数を同じ候補へ適用する。`rqu2` はその内容族を許可条件へ接続する。受け手の性向記述には前段の `hzr2` を使用する。

具体例の検証には既存の存在証人APIを使う。関数参照や閉じたラムダ式を含む九つのNoema項を渡し、型を確認してから存在命題の本体を評価する。成功は指定した解釈内での存在を示す。失敗はその具体例の不成立であり、他の経路も存在しないという証明ではない。

経路の長さには固定上限を設けていない。全関数表と任意長の列を列挙する手続も加えていない。既存の有限評価器が関数表の列挙上限に達した場合は、エラーとして返す。探索できた経路だけから、受け手全体についての存在命題を確定することはしない。

四項目のテストで次を確認する。

- 実際の自己離脱・受領・取得・持続を実行する十対照。開始点より前から伝達が始まっていても、取得完了が開始点より後なら許す。
- 四つの対応関数の取り違え。誤った具体例を棄却した後にも、正しい具体例を検証できる。
- 五つの未知入力、関数の結果型の不一致、全関数表の列挙を明示的に拒否すること。
- 13供給関数での閉じた著者帰属、同じ主張と期待背景、受け手の局所的な経路と共有された自己離脱、既存の34文と七つの意味確認の保持。
