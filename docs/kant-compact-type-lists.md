# 継続記号を繰り返さない型列

型列は「型をゼロ個以上、その後に終端」とする。各型の前にあった `types_more` は新しい描画では省く。終端は `types_end` のままなので、空の型列も表せる。型、引数順、束縛、関数の結果型は変えない。

一つの型の範囲は、先頭の構成語から決まる。基底型はそこで完結し、sequenceとdescriptionは後続の型を一つ読む。questionは型列を一つ、functionは型列と結果型を一つ読む。descriptionの順位接頭語はdescriptionにだけ続く。各型を再帰的に読み終える位置が決まるため、型列には要素ごとの継続印が不要である。型の先頭語と列の終端は異なり、終端を結果型やlambda本文の一部として消費しない。この読取規則は、既存の入れ子深さ・順位の資源制限の範囲で適用する。

旧図形を保持するため、読取器は継続印付きの型列も受け入れる。一つの型列の最初の要素で形式を決める。継続印付きで始まれば全要素に印が必要で、型から始まればその列に継続印を混ぜてはいけない。入れ子の型列はそれぞれ独立して読む。空列は両形式で同じである。旧継続印の字形を別の意味へ再割当てしない。

検査は、保存済みの型付き束縛26例、関数適用15例、引用操作16例、既存定義の本体2例を対象とする。保存SVGの内容ハッシュと元構文を確認し、新旧の型列表記による描画指示が変わる例だけを描き直す。新旧双方の実図形から、同じnative構文を復元する。配置変更による型や意味の再審査は行わない。定義本体の検査用wrapperは新しい意味主張ではない。

円数と幅を別々に記録する。継続印一つにつき二円を除けるが、配置や経路の変化により幅の減少率が同じになるとは限らない。一部の枝の縮退、他の型語による大円反復、未対応構文、宣言、行頁の復元は別の残件である。比較画面は同じ倍率で示し、利用者の確認前に外観を固定しない。
