# 能力の評価範囲と、成功の可能性・保証

[評価範囲を引数に取る7定義](../examples/v013/contextual-ability.noema)を追加した。既存の量化・関数・命題内容だけを使い、基本記号や構文を増やしていない。人や装置、目的、利用できる方法、想定結果、評価に採る結果を引数で与える。

以前のカント草案は「自分の理解力を使えない」を「全ての想定結果で、その使用を保証する方法がない」としていた。しかし、この条件では例外的な失敗も能力の否定につながる。新しい草案では、何を評価対象の結果としたかを明示し、全結果の保証と区別する。カントの能力概念について唯一の正しい定義を確立したとは扱わない。

## 三つの異なる条件

| 定義 | 条件 |
| --- | --- |
| xb：成功の可能性 | 利用できる方法があり、その想定結果の一つで目的が成立する |
| xc：全結果での保証 | 利用できる方法があり、空でない想定結果の全てで目的が成立する |
| xd：指定範囲での達成 | 利用できる方法があり、空でない評価対象の全結果で目的が成立する。評価対象はその方法の想定結果に含まれる |

例えば、ある操作が通常条件では成功し、例外条件では失敗するとする。両方を想定結果に含め、通常条件だけを評価対象に採ると、xbとxdは真、xcは偽となる。例外条件も評価対象に含めるとxdも偽になる。この違いを成功例だけから自動推定せず、選んだ範囲として保持する。

同じ構造は、装置の動作条件にも使える。目的を測定の成功、方法を操作手順、評価対象を定格内の結果とすれば、定格外で失敗し得ることと、定格内で動作することを両立して述べられる。ただし、今回の定義には確率、成功頻度、定格そのものの物理的定義を含めていない。

選択関数は人・方法・開始状況・結果を引数に取り、目的内容は受け取らない。同じ関数を保持して目的だけを変えることができる。ただし、関数の引数型だけで、恣意的な選択や事後的な基準変更を防げるわけではない。採用基準の妥当性は別の課題である。

## 未評価と不可能を分ける

xaは、一つの方法について評価対象が空でなく、想定結果の部分集合であることを確認する。xeは、利用できる全方法についてxaが成立する条件である。

能力があると言うには、xdを満たす方法を一つ確認すればよい。他の方法の評価が未完でも、その達成方法は失われない。一方、能力がないというxgには、全方法の評価範囲が整合するxeと、達成方法がないことの両方を要求する。

| 状態 | xd：達成方法あり | xg：達成方法なしと確認 | xf：判定できる |
| --- | --- | --- | --- |
| 達成方法を一つ確認した | 真 | 偽 | 真 |
| 全方法を評価し、達成方法がない | 偽 | 真 | 真 |
| 達成方法を確認できず、未評価の方法がある | 偽 | 偽 | 偽 |

実行できる方法が一つもない場合は、全方法の評価条件xeは成立し、xgも成立する。これと、利用できる方法はあるがその結果の評価範囲が空の場合を区別する。言語の真理値を三値へ変更したわけではなく、「評価が整った」という別の条件を記述している。全ては与えた解釈内の判定であり、現実に利用できる方法を検査器が発見する機能ではない。

## カント冒頭への接続

[新しい冒頭草案](../examples/v013/kant-contextual-ability.noema)では、bcにある未成熟の条件を、人でありxgに該当することへ変更した。評価対象の関係apを明示し、自立的使用bb、原因説明bd、定義の提示や呼びかけの参照へ接続した。旧文書と旧条件baは比較用に保持している。

離脱を表すbeも変更した。変化後に単に「bcでない」だけでは、評価範囲の欠落が離脱の達成に見えてしまう。そのため、変化後にはxdを満たす達成方法があることを要求する。評価範囲が空になった場合や、想定していない結果を選んだ場合を、離脱したことには数えない。

apはこの読解の評価基準を与える関係であり、原文が結果の集合を明示的に列挙したとは主張しない。原因の説明、決意と勇気の不足の範囲、離脱という語の全容、ラテン語の独立した意味確認は引き続き残る。六区間への接続は保持したが、確認済みの全文単位はカント0/20・アインシュタイン0/282のままである。

## 検査と再現

一方法・二結果について、方法の利用可否、想定結果、評価対象、目的の成立を組み合わせた128解釈を全て検査し、独立した集合演算の結果と照合した。二方法や例外を含む11対照例と、カント草案の能力・離脱に関する6例も検査した。これは指定した有限解釈の検査であり、全領域の定理証明や自然言語との完全な同義性の証明ではない。

本文への帰属は、能力条件を実際に評価せずに六つの記述を参照できることを確認する。正規化、固有文字、SVGも既存機能で処理する。

```powershell
python -S -m scripts.compose_contextual_ability
python -S -m scripts.check_contextual_ability --verify-only

python -S -m noema render --input examples/v013/kant-contextual-ability.noema --alphabet v2 --output artifacts/kant-contextual-ability.svg

```
