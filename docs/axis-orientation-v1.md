# 平行な軸と正方向の一致を区別する

二つの方向が平行でも、正の向きが同じとは限らない。既存の軸配置の記述は逆向きも許していた。今回、非零の平行な二方向の内積が正であるという条件を合成し、密度式の標準配置に使う三つの対応軸へ接続した。

これは配置全体の完成ではない。方向記録の物理的な取得と校正、共通原点、時計の原点、慣性系などの説明は残る。元の配置関係も要求し続ける。

## 方向の条件

有理数の条件`sexa`と、実切断の条件`sexd`は、次の三点を要求する。

1. どちらの方向も零ではない。
2. 外積の三成分が零であり、平行である。
3. 内積が正であり、向きが一致する。

実切断側では六つの成分の有効性も確認する。`sexb`が内積、`sexc`が向きを問わない平行条件を担う。数値方向の比較を実際の軸の配置と同一視しない。

| 二つの方向 | 同じ正方向か |
| --- | --- |
| `(1,2,3)`と`(2,4,6)` | はい。長さは異なってよい |
| `(-1,-2,-3)`と`(-2,-4,-6)` | はい。成分自体が正である必要はない |
| `(1,2,3)`と`(-2,-4,-6)` | いいえ。平行だが逆向き |
| `(1,0,0)`と`(1,1,0)` | いいえ。内積は正だが平行ではない |
| 零ベクトルを含む組 | いいえ。方向を特定しない |

方向の長さを一に揃える必要はない。有理数の演算では、正の倍率を片側に掛けても条件が変わらないこと、双方の反転では条件が変わらないこと、片側だけの反転では成立しなくなることを機械的に検証した。方向の一致から長さの一致を導く主張には具体的な反例を確認した。実切断側の有限検査は構成した有理数埋込みに限定し、実数全域の演算法則の証明とはしていない。

## 記録と本文の接続

`sexe`は、同じ座標・単位・状況に属する二対象の方向記録を比較する。両側に少なくとも一つの記録が必要で、選ばれた全記録対が同じ正方向でなければならない。別名の記録や正の倍率だけが異なる記録は許すが、一つでも逆向きの記録が混じれば満たさない。三成分の役割も互いに区別する。

記録の帰属`zsa`と成分値`zsb`は今回追加した二つの原始記号である。帰属には対象軸・共通の観測座標・長さ単位・状況を含める。軸の正の座標増分に沿う変位を、共通の直交座標で表すという意味規約を付けた。数値だけが一致しても、別の単位や状況の記録は比較に流用しない。記録の具体的な取得・校正・時刻の選び方は未構成であり、新しい記号を与えただけで説明済みとはしない。

`sexf`は、二系で同じ役割を持つ実際の軸割当てを要求し、候補軸の記録を比較する。`sexg`は三つの対応軸すべてについて、静止系`ra`の共通座標と長さ単位`ta`を用いる。最後の`sexh`は、前版の二系・符号付き速度への参照と物理的配置`sewz`を保ちながら、この方向条件を加える。

原文の§3冒頭の「平行」という語だけから正方向の一致を読み取ったとはしない。密度式に至る標準配置の座標規約を、今回の改訂では同方向として明示した。旧関係が許した配置を狭め得るため、新旧の無条件の意味一致は未証明として残す。

[累積本文](../examples/v014/einstein-axis-orientation.noema)の206文を保持し、密度式を引用する一文の配置引数だけを変更した。他の205文と既存の宣言は変えていない。[抽出本文](../examples/v014/axis-orientation-manuscript.noema)と[汎用の方向定義](../examples/v014/oriented-directions.noema)も保存した。汎用条件は物理軸に限定されず、三成分で表した量の増減などにも使える。その場合の成分の意味・共通尺度は呼び出し側で定める。

## 検証と残る課題

数値10例と無効成分、五つの代数検証、本文と抽出本文それぞれ20例で確認する。三軸それぞれの反転、零方向、鋭角だが非平行、記録の欠落・矛盾・別名、単位・座標・状況の取り違え、軸割当ての欠落、元の配置の不成立を区別する。未知の帰属や成分を補完せず、評価を拒否する。

著者への提示・先行箇所への説明・本文順序を変える8例では、引用内容の方向記録を実行しない。旧引用と新引用の違いも保持する。通常表記・短縮表記・固有文字の往復、CLI解析、意味基盤の署名と文書化、入力ハッシュも検査する。

```powershell
python -X utf8 -m pytest tests/test_axis_orientation.py -q
python -X utf8 -m scripts.check_axis_orientation --verify-only
```

共通原点や時計原点の一致を方向から導くことはできない。物理的な配置、記録の完全性と校正、適用範囲、電気的帰属、全文の意味一致は未完である。[意味確認記録v8](../data/density-formula-review-v8.json)へこの限界を記録し、原文対応範囲と意味確認済み区間数は増やさない。
