# 既存の語義モデルを追加学習せず使った結果

**語彙ごとの分類器を作らずに91概念を候補にできたが、今回の既存BEMモデルでは精度が不足した。翻訳画面の解析器は置き換えない。** Noema向けの訓練例・追加学習・生成処理は使っていない。

## 比較条件

[手順](bem-probe-protocol.md)、[新資料](../data/definition-probe-v2.json)、実行コードを、予測前のコミット `3bf91c6` で固定した。既存のv1は回帰比較、新しいv2は26概念と対応外8組の日英資料である。正解の文字範囲を与え、すべての91概念から選ぶ。範囲抽出や役割推定の成績を含まない。

[UCRELの多言語Small BEM](https://huggingface.co/ucrelnlp/PyMUSAS-Neural-Multilingual-Small-BEM)は、文中の語と定義の対応を事前に学習した非生成モデルである。Noemaでは固定重みのまま使い、候補を既存USAS語義からNoemaの英語定義へ交換した。実測のパラメーター数は140,493,696。公開元は、別の語義体系への転用を検証済みとはしておらず、日本語も掲載評価に含まれていない。[公開実装の説明](https://github.com/UCREL/WSD-Torch-Models)

BEMは定義と対象トークンの平均ベクトルの内積、MiniLMは前回と同じ日英定義の平均とコサインを使う。定義言語やスコアも違うため、下表は実装した二つの構成の比較であり、事前学習方式だけの優劣ではない。

## 結果

| 資料 | 構成 | 日本語の概念選択 | 英語の概念選択 | 日英とも正解 |
|---|---|---:|---:|---:|
| v1・回帰 | BEM | 9/40（22.5%） | 18/40（45.0%） | 6/40 |
| v1・回帰 | MiniLM | 28/40（70.0%） | 29/40（72.5%） | 26/40 |
| v2・新しい文脈 | BEM | 5/26（19.2%） | 6/26（23.1%） | 3/26 |
| v2・新しい文脈 | MiniLM | 12/26（46.2%） | 16/26（61.5%） | 12/26 |

v1のMiniLMは前回の先頭正解件数を再現した。v2には既存15概念を含めていないため、v1との百分率の差をそのまま性能低下量とは解釈しない。v2は同じ作成者と概念群による小規模資料であり、外部による独立評価でもない。

BEMは「開けなかった／did not open」を閉じた状態へ寄せ、英語の「closed」では扉や窓などを選ぶ例があった。変化、状態、否定を分けるNoemaの規則を、定義照合だけで扱える状態ではない。MiniLMでも、飲む→コップ、買う→店、閉める→閉じた状態という誤りが新資料で残った。

対応外8組にも両構成は必ず候補を返す。MiniLMでは英語の悲しい意味の「blue」に色の青を選び、そのコサイン0.577は新資料の既知正解の多くを上回った。BEMでも正解と対応外の最高スコアの範囲が重なる。候補選択のスコアを確信度として扱わず、閾値をこの資料に合わせて調整していない。ここには確定／棄却処理がないため、本番解析器の未対応誤確定率として集計しない。

## 実装の確認

重みは固定リビジョンのsafetensorsを厳密に読み込み、未知の追加層は拒否する。生成ヘッド・USAS辞書・外部Pythonコードは読み込まない。日本語と英語の短文で、別途導入した公開実装 `wsd-torch-models==0.1.3` と照合した。同じバックボーンを使ったトークン・範囲・定義平均の最大差は0、内積の最大絶対差は0.000244（相対許容差1e-6以内）だった。[照合記録](../reports/bem-probe-v1/adapter-parity.json)

両モデル・両資料で最初の16文を同じバッチ形状で再推論し、トークンベクトルの完全一致を確認した。全180テストも成功した。反復一致は今回のCPU環境での結果であり、別のハードウェア間の保証ではない。

## 設計への反映

「既存モデルをそのまま使えるか」には、**実装上は使えるが、Noemaへの転用精度を検証する必要がある**と答えられる。語彙の追加に分類器のクラス追加が必須という制約は、この候補選択方式にはない。一方で、このモデルの語義学習をNoemaの意味区別へそのまま移せるという仮説は支持されなかった。

この失敗を理由に固定91クラスへ拡大したり、生成方式へ変更したりはしない。概念定義を入力する共通の対応判定と、範囲・役割・否定・時間の構成を分離する方針を維持する。対応範囲内の確定率80%以上・確定出力の意味構造完全一致率95%以上は引き続き未達の課題である。

## 再実行

```powershell
python -m noema.bem_probe --download --output artifacts/bem-reproduction
python -m pip install --no-deps --target artifacts/wsd-reference wsd-torch-models==0.1.3
python -m scripts.verify_bem_adapter --output artifacts/bem-adapter-parity.json
```

初回だけ `--download` で公開重みを取得する。通常は固定リビジョンのローカルキャッシュを使う。既存の出力先は上書きしない。公開実装の比較用パッケージは `artifacts` の中だけへ導入し、アプリの依存関係には加えない。
