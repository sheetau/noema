# 共通の候補評価と能力

## 共通化する関係

二作品の現行稿を照合すると、同じ名前と宣言を持つ記号でも意味が一致しない場合がある。`zac` はカント稿では物理的な接続、アインシュタイン稿では時計の照合記録を指す。このような記号を名前や型だけで統合しない。作品の文ごとの基本記号も新設しない。

両作品の `s5k` は、内容・評価文脈・候補を選ぶ関係を引数に取り、「候補が非空で、全候補でその内容が成立する」と定義する。定義本体と意味規約が一致しており、この定義を共通モジュールの `candidatenecessary` として再利用する。元の稿、記号名、意味判断は変更せず、対応表で由来を保存する。

同じ候補選択から、候補の有無、少なくとも一つでの成立、全候補での不成立、成立と不成立の両方がある場合を構成する。現実の成立は評価文脈で内容を評価する別の条件とし、全候補で成立することから補わない。

能力については既存の `contextual-ability` の7定義を再利用する。方法を実行できること、想定結果、評価対象の選択、目標内容を分ける。単に成功する状況があることと、本人が実行できる方法を通じて成功に至れることを同一視しない。

## 読み方と適用範囲

候補関係の引数は、順に内容・評価文脈・候補状況である。どの候補を選ぶかには根拠が必要であり、共通モジュールが現実から候補を自動発見するわけではない。物理的に可能な状況、証拠と両立する状況、規範に適合する状況は、別の選択関係として渡す。一つの候補範囲の評価だけで、他の範囲での可能性・能力・許可を認定しない。

| 関数 | 成立条件 |
| --- | --- |
| `candidateexists` | 選択した候補が一つ以上ある |
| `candidateempty` | 選択した候補がない |
| `candidatepossible` | 成立する候補が一つ以上ある |
| `candidatenecessary` | 候補が非空で、全候補で成立する |
| `candidateexcluded` | 候補が非空で、全候補で不成立である |
| `candidatecontingent` | 成立する候補と不成立の候補が両方ある |
| `necessaryactual` | 全候補で成立し、評価文脈でも成立する |

候補が空なら、`candidatenecessary` と `candidateexcluded` はどちらも偽になる。「候補がまだ分からない」という情報不足を空集合へ変換してはいけない。関係を与えていないことと、関係が全候補を除外することを区別する。

| 関数 | 成立条件 |
| --- | --- |
| `assessmentvalid` | 指定方法の評価対象が非空で、想定結果の部分集合である |
| `methodpossible` | 実行可能な方法があり、その想定結果の少なくとも一つで成功する |
| `methodguaranteed` | 実行可能な方法があり、想定結果が非空で全て成功する |
| `assessedability` | 実行可能な方法があり、妥当な評価対象の全てで成功する |
| `methodsassessable` | 実行可能な全方法について評価対象が妥当である |
| `assessmentdecisive` | 成功する方法を確認できるか、全方法の評価対象が妥当である |
| `assessedinability` | 全方法の評価対象が妥当で、評価対象の全てで成功する方法がない |

評価対象の選択は社会的・実践的な基準を含み得る。単なる目標の否定や、未評価の方法の存在から能力の欠如を結論しない。これらは明示したモデル内の関係であり、能力という自然言語の語の全用法を一つに還元した定義ではない。

## 保存と検査

共通モジュールは定義だけを持ち、基本関係を追加しない。既存定義の名前と参照を一貫して変更した部分は、逆変換によって元の定義本体へ戻ることを検査する。二作品の共通化候補の分類は意味規約と本体を読んだ判断であり、型一致だけの自動同義語判定ではない。

有限モデルでは候補の空・単一・複数、内容の真偽、現実と候補の不一致を比較する。日常の移動と装置操作という二つの文脈に同じ定義を適用し、可能でも本人の実行方法がない場合、可能だが保証されない場合、評価不足と能力欠如の違いを確認する。有限の診断を無限領域の真理の証明へ読み替えない。

この段階の共通語はNative Noemaの名前で提供する。円文字の共有辞書への導入、他の意味領域、同義語・多義語一般、学習者による読解は残る。

成果物は[14定義のモジュール](../examples/v016/shared-modality-v1.noema)、[型・引数の役割・意味規約](../data/shared-modality-basis-v1.json)、[検証報告](../reports/shared-modality-v1.json)である。公開する意味規約には、引数として残す解釈条件と旧定義からの名前の対応を含めた。引数に関係を受け取ることを、その関係の意味の説明が不要になったこととは扱わない。

候補評価32モデル、方法の評価128モデルに加え、候補選択の3引数と想定結果の4引数を、一つずつ変える2値の結合診断を行う。構文として同じ定義であること、有限モデルで期待した値になること、自然言語の適用が妥当であることは別々の判断として保持する。

```powershell
python -X utf8 -m noema.meaning_catalog explain --basis data/shared-modality-basis-v1.json --symbol candidatenecessary
python -X utf8 -m scripts.project_work check --module scripts.check_shared_modality --tests tests/test_shared_modality.py --verify reports/shared-modality-v1.json
```

二作品の由来検査では、現行登録簿が指定する全文の意味カタログを読み、`s5k` が実際の本文から参照されることを確認する。過去の大量の意味規約を新しい報告へ複写せず、カタログが読んだ各ファイルのハッシュを既存の全体監査v432と照合する。新報告には全体監査への参照とハッシュ、共有対象の出典・本文の参照位置、意味が異なる衝突例を保存する。
