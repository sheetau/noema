# 共通の時間範囲・出来事・基準時

## 構成する意味群

時間の前後、出来事の範囲、完了条件、発話の基準時を別の引数で表す。既存の `persistence` の `ta/tb/tc` と `transitions` の `tg/th` を名前だけ変更して再利用する。追加するのは、範囲の前後・重なり・包含、基準時での進行と完了、出来事の一回性と期間ごとの反復である。新しい基本関係や文ごとの演算子は作らない。

共通定義は[Native文書](../examples/v016/shared-time-v1.noema)に保存する。型、引数の役割、解釈条件と旧名対応を[意味規約](../data/shared-time-basis-v1.json)に公開する。既存稿の宣言・意味判断は変更しない。

## 時間範囲と基準時

`chronology` は、空でない履歴内の厳密な全順序を検査する。`timewindow` は、その履歴に含まれる空でない凸な範囲を要求する。「凸」は、範囲の二点の間に履歴上の点があれば、その点も含むという条件である。数値的な長さや最初・最後の点の存在は要求しない。分岐する可能世界を一本の時間的履歴へ混ぜず、各履歴と様相上の候補選択を別々に与える。

`windowbefore` と `windowafter` は範囲の全点と基準時の厳密な前後、`windowat` は基準時の範囲への所属を表す。基準時も同じ履歴に属する必要がある。`windowoverlap` は二範囲の共通点の存在、`windowwithin` は第1範囲全体の第2範囲への包含である。境界の一点を共有する場合は重なる。この規約で境界を除きたい場合は、範囲を指定する関係で明示する。

発話時と、引用・報告の内部で採用する基準時は異なる引数値にできる。例えば「そのとき走っていた」では進行の判定へ当時の基準時を渡し、その基準時と発話時の前後を別に記す。発話が後になっただけで、過去の進行状態を現在の進行状態へ変更しない。これは時間参照の規約であり、誰が発話したか、どの発言を引用したかという帰属は既存の発話記述で接続する。

## 進行と完了

出来事は個体として識別し、その出来事が実際に進行する各状況を `trace(event, point)` で指定する。同じ人物による別々の走行は、別の出来事にする。主体・対象・内容の関係は呼出側の出来事の選択で保持し、時間が一致しただけで別の行為者や出来事の記録を混ぜない。

`eventunderway` は、出来事の時間範囲が整合し、基準時がその範囲に含まれ、範囲内に基準時より前の点があり、その基準時までに指定の完了条件が成立していないことを要求する。これは「すでに始まり、まだ完了していない」という進行の読みである。将来の終了点の存在は要求しない。後で中断した出来事でも、過去の進行を記述できる。

`eventcompleteby` は、同じ出来事の範囲内に完了条件が成立する点があり、その点以降に出来事の進行点がなく、完了点が基準時以前であることを要求する。単に観測が途切れたことや動作が停止したことを完了へ置き換えない。たとえば一周する走行では一周の達成、文書作成では対象の文書の完成を完了条件にする。条件と出来事の同定は解釈入力であり、全活動に共通する自然な終点を自動発見する関数ではない。

この進行と完了を、すべての日本語の「ている」「た」へ機械的に対応させない。結果状態や習慣の読みにはそれぞれ状態の持続や反復を使う。`holdsall` は空でない範囲の全点で内容が成立すること、`becomes` は同じ過程の前で偽、後で真となることを表す。過程の存在と二つの真理値を結ぶが、過程の因果機構までは与えない。

## 一回性と反復

`eventonce` は、指定範囲と時間的に重なる該当出来事がちょうど一つあるという読みである。全該当出来事の時間範囲の整合性も要求し、不正な範囲を持つ別の出来事を数から消して一回と判定しない。時間点の数を出来事の回数へ換算しない。範囲の指定は「これまでに一度」「この朝に一度」などの違いを保持する。

`eventevery` は、対象の期間が空でなく、各期間に全体が含まれる該当出来事があるという読みである。毎朝の期間、該当する人物の走行、各出来事の時間をそれぞれ関係で与える。空の期間一覧から「毎朝走った」を真にせず、長い一回の出来事が各期間と少しずつ重なるだけでも成立させない。各期間の出来事の一意性は要求しない。期間同士が重なるなら同じ出来事が両方へ含まれ得るため、異なる日を意図するときは期間の同定と分離も解釈規約に含める。

## 検査範囲

時間範囲と順序の有限モデル、進行と完了の独立した組合せ、主体・出来事・時点の結合、基準時の変更、空範囲と空期間、否定の作用範囲を検査する。走行と文書作成の二題材に同じ定義を適用する。原定義の本体保存、Native構文の往復、公開意味規約の対応を確認する。

有限モデルは連続時間全域の証明ではない。履歴の完全性、状況の粒度、出来事の境界、完了の達成基準、期間の選定は引き続き明示的な解釈入力である。共通定義の円文字での語彙登録と学習者の読解は、このNativeモジュールの検査とは分ける。

[基準時の対照文書](../examples/v016/temporal-anchor-contrasts-v1.noema)は、同じ文書内で報告内の基準時と発話時を別々に参照する。三つの問いは、順に「基準時は発話時より前で、その基準時に進行中か」「発話時に進行中か」「発話時までに完了したか」である。完了せず中断した場合、後で完了した場合、二つの時点を逆に渡した場合を[検証報告](../reports/shared-time-v1.json)へ記録する。`input` で始まる基本記号はこの対照文書の解釈入力であり、14定義だけの共通モジュールには含まれない。

19テストに、64順序、24範囲・基準時、64範囲対、192進行・完了、64一回性、256期間反復の有限モデルを含めた。10件の引数結合診断では、他の値を固定し、過程の三引数、時間範囲と完了の各二引数を2値の領域で一つずつ変更する。大きな直積全体の証明とは数えない。
