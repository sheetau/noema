# 共通辞書を増やさずに専門定義を使う

数学の専門概念を使うたびに、全読者が学ぶ共通辞書へ語を追加する必要はない。本実装では、既存の第12版375語を読む側の共通基盤とし、必要な専門定義を型・引数・本体とともに文書へ組み込む。文書内で新しく名付けた定義も同じ書式で書く。375語は既存の利用可能な構成であり、最小語彙数や将来の固定上限を意味しない。

| 区分 | 読む際の意味の根拠 | 今回の構成 |
| --- | --- | --- |
| 共通基盤 | 公開辞書の語義と型 | 第12版375語。実際に使う語と依存先だけを取り込む |
| 専門ライブラリ | 文書に展開された型付き定義 | 切断・積・解析・ベクトルの既存49定義 |
| 文書内定義 | 文書で導入した型付き定義 | 同じ内容を持つ異なる二つの名前 |

専門ライブラリは書き手が再利用する部品である。読む側は専門辞書や文書専用の名前表を渡されなくても、共通基盤と見える定義から文書を復元できる。既刊の第13〜16版辞書と証拠は保持し、今回の方式でそれらの語義や綴りを変更しない。新しい辞書版・基本関係・基本字形は追加しない。

## 組み込みの規則

`scripts.visible_library_linker.link` は、本文の全宣言を保持し、文と定義から参照される専門定義を依存順に追加する。使わないライブラリ項目は追加しない。ライブラリ全体を刊行する場合は `roots` で保持する語を指定する。名前は既存の可逆な可視綴りであり、登録順・番号・ハッシュから生成しない。

型・引数・束縛・引用を保ったまま組み込み、同じ本体を持つ別名を統合しない。二つのライブラリが同じ名前に異なる定義を割り当てた場合、共通語の意味を変更した場合、参照先が不明または循環する場合は拒否する。ライブラリ中の主張を利用文書の主張として黙って追加することも禁止する。共通基盤にないprimitiveは、この仕組みだけでは導入できない。意味規約や指示対象の扱いを先に確定する必要がある。

Python APIは依存先をライブラリに置いた未結合の本文を受け取る。CLIのNative入力は既存パーサーが受理する閉じた文書であり、可視名の依存を解決・検査する。同じ名前の定義を再利用するだけでは、その意味を新たに査読したことにはならない。

## 検証資料

[専門ライブラリ](../examples/v016/visible-mathematics-library-v1.noema)には49定義と有理算術の4基本宣言がある。[文書例](../examples/v016/visible-specialist-document-v1.noema)にはそれら全てに加えて二つの文書内定義と8質問を含めた。円文字は `output/visible-specialist-library-v1/` に保存する。専門定義はimportではなく、本体まで図形に書かれる。

共通辞書だけを渡して保存済みSVGの図形から全文書を復号し、型付き構造の一致を確認する。質問では空列・単成分・重複成分・異なる二成分、同義の別名の値、別名への引用と二重引用、有理数の大小を扱う。1個体と2個体の診断は、全実数上の解析・ベクトルの定理を証明するものではない。

```powershell
python -X utf8 -m scripts.project_work check --module scripts.check_visible_specialist_library --prepare --tests tests/test_visible_library_linker.py --verify reports/visible-specialist-library-v1.json
python -X utf8 -m scripts.visible_library_linker examples/v016/visible-specialist-document-v1.noema
```

[報告](../reports/visible-specialist-library-v1.json)は旧語義と証拠のハッシュを確認し、文書・図形・処理系を記録する。これは専門語を共通辞書へ昇格させずに公開する経路の検証である。二論文全体の可視化、残る基本関係と文脈上の名前の接続、第三者による読解は引き続き必要である。自然言語の全単語を辞書へ登録することを完成条件にはしない。
