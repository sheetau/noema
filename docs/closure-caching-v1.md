# 有限診断での字句的な関数の再利用

本文の因果条件を接続した検査では、前件が成立しない場合の探索が40,000,000評価ステップを超えた。仮定世界を増やした有限解釈で、同じ履歴を参照する関数が、関係しない量化変数の値ごとに作り直されていた。関数を引数にする式のキャッシュも別の関数と扱うため、同じ判定を繰り返していた。

旧評価器を保存し、任意選択の後継評価器 [constructed_closure_semantics.py](../noema/constructed_closure_semantics.py) を追加した。`memoize_closures=True` の場合だけ、字句的なラムダ式と定義・基本関係への関数参照を再利用する。再利用のキーは、同じ構文木の節、自由変数の値、生成時の引用評価上限である。関係しない外側の変数はキーに入れない。

任意の関数を結果として返す呼出し全体を記憶する方式ではない。別の構文節、異なる捕捉値、異なる評価上限、別のモデルや評価呼出しを混同しない。記述の引用は引き続き実行せず、発行元が異なる記述への制限と、低い引用階数から高い階数を実行できない制限を保存する。

通常のキャッシュと同じ純粋性に加え、基本関係の実装には**関数のPython上の同一性を意味判断へ使わない**ことを要求する。Noemaの関数の等値は従来どおり有限領域の各引数に対する値で比較する。診断用の呼出し回数の観測はできるが、回数やオブジェクトIDに応じて真偽を変える実装にはこの最適化を使わない。新オプションの既定値は偽で、CLIの既存評価器も切り替えていない。

102件の検査で、捕捉値の区別、不要な外側の量化変数による再生成の削減、モデル間の分離、引用の実行制限96通り、キャッシュを先に温めた場合の制限、未知入力・予算・未対応の量化領域を確認した。小例では同じ判定の呼出しが9回から3回になり、結果は一致した。

これを明示的に使った因果条件の45件の検査は、元の40,000,000ステップ上限のまま全て通過した。前件が偽の反例や仮定世界を削除してはいない。旧評価器では1件が上限に達して全体214.33秒、後継評価器では45件が20.75秒で終了したという今回の診断記録であり、一般の処理時間や全ての解釈での性能を保証するものではない。

```powershell
python -X utf8 -m pytest tests/test_constructed_closure_cache.py tests/test_caused_choice.py -q
```

保存したNoemaの文法や意味の定義はこの最適化では変更しない。純粋で外延的な有限解釈のための実行上の改良であり、未知の内容を真偽へ補完する機能ではない。
