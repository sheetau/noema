# 名称の表記と、文書の著者表示

カント末尾の署名を、本文で既に使っている著者参照へ接続した。名称を示す文字列、名称という対象、その名称で指す人物、著者として表示される役割を分ける。同じ綴りの別人や、複数の表記を持つ一つの名称を扱うためである。

## 名称の適用はNoemaで記述する

既存の `rnh` は、提示者が同じ提示行為で名称を対象へ適用することを表す。新しい `rqqw` は、その名称使用が同じ文書で同じ対象を著者として表示するという関係も要求する。名前が出てくるだけでは著者表示にならず、別文書の署名を引用した場合も当該文書の著者表示へ移さない。

提示者と、著者として示される対象は別引数にした。編集者による著者表示も表せる。本文の接続 `hzil` では、末尾の署名を著者自身の提示として読む。原稿を本人が手書きした、現存媒体が自筆である、署名が真正である、といった事実は追加しない。

名称 `hzif` と人物 `wa` は別の個体であり、本文ではその区別も明示する。名称使用 `hzig`、文書 `hzik`、末尾の提示文脈 `hzim` を固定し、冒頭段落の文脈 `wh` を使い回さない。二つの基本関係は、名称適用 `hzih` と、文書の著者表示 `hzij` である。

## 綴りは意味本体と別に保持する

[識別表記の別添え](../data/author-signature-identifiers-v1.json)は、名称個体 `hzif` へ以下の形を付ける。

| 表記 | 扱い |
| --- | --- |
| `I.[mmanuel] Kant.` | 固定した電子版の転記。括弧内の展開と終端の句点を含む。 |
| `I. Kant` | 省略された名前の識別形。本文全体の文字列変換規則ではない。 |
| `Immanuel Kant` | 電子版の展開に基づく識別形。原刊にこの綴りが印刷されたとは認定しない。 |

この別添えには人物への参照先を格納しない。名称が誰を指すかと、その人物が何として表示されるかはNoemaの関係で記述する。語の意味や自然言語の段落を文字列へ保存して表現済みとする方法ではない。[完成条件](language-completion.md)で認めた人名・書名などの識別表記に限って使う。

`noema.identifiers` は、意味規約と文書のハッシュ、名称記号が閉じた個体値であること、表記の形式を検査する。同じ綴りを持つ複数の名称個体を許し、一つへ統合しない。検索はUnicodeの符号位置列の完全一致で、大文字小文字の変換、正規化、音訳、言語間の翻訳を行わない。言語ラベルは利用者が明示する識別用の文字列であり、言語タグ規格への適合を認定するものではない。

```powershell
python -X utf8 -m noema.identifiers show --basis data/author-signature-basis-v1.json --annotations data/author-signature-identifiers-v1.json
python -X utf8 -m noema.identifiers find --basis data/author-signature-basis-v1.json --annotations data/author-signature-identifiers-v1.json --text "Immanuel Kant" --language de
```

結果にある `symbol` は名称個体を指す。検索結果から指示対象を選んだり、同姓同名の人物を統合したりしない。文書の意味説明や原文との意味一致を、この注記検査だけで認定しない。表記はUTF-8で保持し、Noema本体の32文字の字形や文法は変更しない。

署名の本文式、追加した宣言、識別形そのもの、注記ファイルの長さは検査報告の `size_accounting` へ別々に記録する。短い式だけを数えて圧縮したとは扱わず、初回の定義・注記の費用を含めて今後の冗長さを評価する。

## 本文と検証

[改訂本文](../examples/v016/kant-author-signature.noema)は266基本記号・1,120合成定義・17文となる。既存の全宣言と16文を保存し、最後に署名の一文を追加した。[独立文書](../examples/v016/author-signature.noema)は基本記号を持たず、既存 `rnh` と一般形 `rqqw` の二定義からなる。[意味規約](../data/author-signature-basis-v1.json)は前版を継承する。

識別表記の18テストでは、同名の複数候補、複数表記、日本語・アラビア語・結合文字・絵文字、大小文字や空白の保持、重複キー、無効なUnicode、未宣言記号・引数付き関数への不正な付与、文書変更の検出、CLIと上書き拒否を確認する。

署名の6テストでは、四条件16組合せ、本文と独立文書での対象・名称・行為・文書・文脈の取り違え、名称と人物の潰し込み、未知の関係の拒否を調べる。短絡変換とキャッシュは使わない。通常・短縮・固有文字の往復とCLI解析、転記の全文範囲、旧本文の保存も検査する。

```powershell
python -X utf8 -m pytest tests/test_identifiers.py tests/test_author_signature.py -q
python -X utf8 -m scripts.check_author_signature --verify-only
```

[意味確認記録](../data/author-signature-review-v1.json)は電子転記と、そこから採用した署名の読みを明示する。固定原文には括弧内の編集上の展開があり、原刊画像の綴り・組版との照合は今回完了していない。大学図書館の画像閲覧先は自動取得時に確認画面を返したため、画像を読んだとは記録しない。今回は署名の原文単位への部分対応を追加し、意味確認済み区間には加算しない。日付・地名・著者注と、二作品全文の記述を続ける。
