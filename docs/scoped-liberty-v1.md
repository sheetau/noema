# 活動範囲への許可と、それを対象にする規範

職務上の使用に制限があること、公的な使用の全活動が許可されること、その許可状態を成立させてはならないという別の要求を、同じ本人について書き分けた。カントの自由の概念全体を確定したものではなく、活動範囲と規範を明示する操作的な読みである。原文との対応表にも解釈注記であることを記録する。

既存の型・量化・引用・規範の構成で13定義を追加した。新しい原始概念と著者の主張は追加しない。親文書の宣言と15件の主張を保持する。

| 構成 | 意味 |
| --- | --- |
| `rhi` | 範囲内の全活動に実行への積極的な許可があり、不実行要求と衝突しない |
| `rhj` | `rhi`に加え、範囲に分類される活動の候補がある |
| `rhk` | 範囲内に、実行要求・実行許可と衝突しない明示的な禁止がある |
| `rhl` | 範囲内に規範の衝突がある |
| `rhm` | 範囲内に、規範は解釈済みだが許可にも禁止にも分類できず、衝突もない活動がある |
| `rhn` | 非空の範囲の全活動について、実行と不実行の両方が積極的に許可される |
| `rho` | 同じ本人について、一方の役割の範囲に制限があり、他方には`rhj`の許可がある |

規範の出所、本人、役割、活動、実行記述、評価文脈を保持する。活動ごとに異なる閉じた記述を割り当てられるため、異なる発言内容を一つの真偽や固定の記述へまとめる必要はない。ただし、その割当自体の適切さは明示した意味規約に依存する。

例えば、二つの活動のうち一つだけが禁止される場合、全称許可は成立せず、明示的な制限は成立する。一方、どちらにも許可も要求もない場合には、全称許可も制限も成立しない。後者を禁止と補わない。範囲が空なら全称条件`rhi`は成立するが、存在を含む`rhj`は成立しない。

実行してよいことと、実行しないことも選べることを分ける。`rhn`は両方の許可を要求するが、原文の公的使用へこの強い条件を無断で追加しない。また、`rhi`は実行許可と不実行要求との衝突を除く条件であり、実行要求と不実行許可との別の衝突まで排除しない。衝突は`rhl`で別に確認できる。

原文への接続では、私的使用の分類`zzp`と公的使用の分類`zzo`を使い、実行記述`zzq`への規範を量化する。職務内の全称許可が`hzb6`、明示的な制限が`hzb7`、非空の公的活動範囲への全称許可が`hzca`、両役割の対比が`hzcb`である。活動を実行したかどうかは範囲を選ぶ条件にしない。禁止されて実行されなかった活動も検査対象になる。

`hzcc`は内側の規範の出所・本人・役割を取る、`hzb6`の内容記述である。`hzcd`は、この内容を成立させないよう、外側の出所が規制者にその職務で要求することを述べる。外側の要求を調べるとき、内側の許可状態を実行評価しない。「そうあるべきだ」という規範を述べただけで、現にその状態にあるとは断定しない。

ここで外側が求めるのは全称許可の不成立であり、内側の明示的な禁止の存在そのものではない。内側に許可が欠けるだけでも全称許可は偽になりうる。このため、`hzcd`から`hzb7`を導かない。カントの「自由でない」「そうあってはならない」という一節への部分接続であり、自由・裁量・権利・自律の全意味との同一性は未確認である。

検査対象は二活動の規範256通り、対象範囲の選択64通り、内外の規範16通り、対象の別名・出所・本人・役割・文脈・極性・引数順序などの取り違えである。内容が同じ真偽を返す別名でも、引用した規範対象は別に保持する。未解釈の規範・範囲・記述の割当は拒否し、現実の実行や内側の政策を要求の存在で補わない。

追加分9件と既存の規範・進捗集計37件、計46テストは通過した。3文書のCLI解析結果が直接解析と一致し、通常表記・圧縮表記・固有文字の往復が成立することも確認した。抽出文書のSVGはXML構造を検査したが、字形の見た目の検査は今回の対象に含めない。進捗集計の監査も通過している。
