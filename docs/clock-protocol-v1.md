# 時計の読みと同期条件の接続

[時計同期の草案](../examples/v011/einstein-clock-protocol.noema)を追加し、前回の差の等式を、時計・出来事・場所・基準系・時間単位へ接続した。文法は0.11のままで、物理的な条件と数式を同じ文書の定義として組み合わせる。

今回の草案は一回の光の往復についての条件である。その成立だけで、二つの時計が全時刻にわたり同期していることや、任意個数の時計を矛盾なく同期できることを主張しない。原文の全文対応状態は引き続き部分草案である。

## 一往復の設定

定義`da`は、次の条件を全て要求する。

- 時計Aと時計Bは同じ構造・性状を持ち、同じ基準系に対して静止している。
- 時計Aは場所A、時計Bは場所Bにある。
- 出発と帰着は場所A、反射は場所Bで起きる。
- 同じ光信号が出発から反射へ、反射から帰着へ伝播し、指定された反射の出来事で反射される。
- 時間単位を明示し、出発時は時計A、反射時は時計B、帰着時は時計Aの読みを用いる。
- 三つの読みは同じ基準系・時間単位の指定を共有する。

読みは`ce(clock,event,frame,unit,value)`という関係にした。全ての時計・出来事について値を必ず返す関数にはせず、読みが存在しない場合に値を補わない。時計ごとの原点が既に一致しているという前提も置かない。数式によって比較する対象だからである。

定義`db`は、この設定`da`、三つの値が実数の切断である条件`ba`、差の等式`bi`を合わせる。等式の引数順は、出発時のA、反射時のB、帰着時のAである。物理的な関係を追加しても、式の出発と帰着を取り替えたり、反射時刻を別々の値として扱ったりしない。

[物理的な関係の意味規約](../data/clock-physical-basis-v1.json)と[統合した意味規約](../data/clock-protocol-basis-v1.json)を保存した。ただし時計・場所・基準系・光・伝播・時間単位は、意味を説明した基本関係を置いた段階である。これらを共通の基礎概念から定義し終えたわけではない。

## 単位と原点の変更

追加の定義`bj(scale,L)`は、切断Lを正の有理数scaleで拡大する。具体的には、Lの元xがあり、`q<scale*x`となる有理数qを含む性質とする。scaleが0以下なら結果は空の性質となり、実数の切断条件`ba`を満たさない。これは実数の一般的な乗法ではなく、向きを保つ座標尺度の変更である。

`bk(scale,offset,L)`は拡大した切断にoffsetを加える。規約は次のとおり。

```text
新しい読み = scale × 古い読み + offset
```

尺度と原点を三つの読みに共通に適用した場合、同期の差の等式が保たれることを、倍率1・60・1/60について検証した。読みとoffsetは特定の試験値に固定せず、全有理数を量化し、それを切断へ埋め込んで調べた。この自動検査は、任意の実数の読みや、任意の正の倍率について機械的に証明した結果ではない。

片方の時計だけに別のoffsetを加える操作は区別する。同期条件を満たす任意の有理数の読みについて、反射時のBの時計だけをずらした後にも同期条件が成り立つことと、そのずれが0であることの同値性を検証した。元の読み0・1・2のうち反射時刻だけを2にする具体例でも、同期条件は成り立たなくなる。

単位を混ぜた読みをそのまま受け入れる処理はない。換算を行うなら、値の変換と、読みを表す関係の単位の指定を整合させる必要がある。個々の物理単位の定義と、換算係数を結び付ける一般的な体系はまだ残る課題である。

## 検証で確かめた範囲

物理的な関係の検査には14の具体的な解釈を用いた。正しい結び付けが1件で、残る13件は、帰着場所・基準系・反射イベント・伝播方向・時計の構造・光かどうか・単位・読みの欠落などを変えた反例である。いずれも期待した真偽になった。

この検査で値の引数に使った切断は、0・1・2の3種類に限る。値の引数の取り違えは、この3種類を区別できる有理数での評価によって確認した。任意の実数の同一性を有限個の値で検査するアルゴリズムではない。実数値の条件と等式は前回の切断の定義をそのまま参照し、数値側の性質は別の線形算術の検査で確認している。物理モデルから原文の事実を推定した結果でもない。

座標変更に関する検査は10件で、9件が成立、片方の時計だけをずらしても常に同期が保たれるという1件は不成立となった。倍率0と負の倍率の結果が切断にならないことも、この9件に含む。Z3の未決定を成立として扱わず、式と結果を記録した。

原文との[対応表](../data/clock-protocol-alignment-v1.json)は`einstein-1905:u0013`と`u0014`を参照する。座標変更の式は定義の整合性を調べる追加例であり、原文のその段落に書かれた主張として扱わない。観測者による時間評価、追加の規約を必要とする論述、定義を採用する発話、任意個数の時計についての仮定などは未記述である。確認済み全文単位数は0のままである。

## 再現

```powershell
python -S -m scripts.compose_clock_protocol
python -m scripts.check_clock_protocol --verify-only
python -S -m noema parse --input examples/v011/einstein-clock-protocol.noema
python -S -m noema render --input examples/v011/einstein-clock-protocol.noema --alphabet v2 --output artifacts/clock-protocol-v1.svg
```

合成スクリプトは、実数の定義、物理的な関係、座標変更の定義断片を、単独で解析できるNoema文書へ組み合わせる。`examples/fragments/clock-coordinate.noema.inc`は既存の実数定義を前提にする断片で、単独のNoema文書ではない。生成済み文書と意味規約は、内容が異なる場合に勝手に上書きしない。

解析・整形・固有文字表示はモデルもZ3も不要。座標の証明には`proof`追加依存を使う。[検査記録](../reports/clock-protocol-v1.json)に具体的な解釈の結果、数値側の式、原文対応、入力ハッシュを保存した。別プロセスで同じ記録を再現し、全570テストが通過した。
