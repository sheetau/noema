# 定義名と展開形を、内容を実行せず比較する

従来の `rqrz` は引用した構文の同一性を調べる。そのため、同じ定義を名前で書く場合と本文を展開して書く場合にも、不一致を返していた。新しい `DefinitionComparator` は、同じ宣言環境の閉じた記述について、定義の展開、関数適用の代入、束縛変数の正規化を行い、展開形を比較する。自然言語の単語・例文・対訳表は参照しない。

引数を代入する際は、内部の束縛変数に新しい名前を与える。外側の人物を指す変数が、定義内の「全ての人物」の変数に取り込まれることを防ぐ。主語と対象、肯否、全称と存在、否定の作用域、条件の向き、主張・質問・指示は構造に残る。対象型を持つ問いや順序付き列にも同じ機構を使える。

比較対象の内側にもう一段ある引用は、そのまま保つ。たとえば「この定義名という表記」と「この展開式という表記」は、定義の指す内容が同じでも別の表記である。引用の構文同一性を観察する文まで書き換えてしまうと、意味が変わる。

結果は二種類である。

- `same_definition_expansion`: この宣言環境で同じ展開形になる。
- `not_established`: この方法では同じと確認できない。意味が異なるという判定ではない。

不正な型、自由変数、未宣言の記号、異なる引用階層は拒否する。計算量・入れ子の上限を超えた場合も例外を返し、不一致という意味判断へ変換しない。入力と展開結果を保持するため、使った定義と比較の範囲を確認できる。

この比較が前提とするのは、定義を透明な略記として使い、基本関係に純粋で全域的な解釈を与え、高階引数はその外延で扱う場合の定義的な同一性である。有限評価器の実行最適化ではない。たとえば使われない引数に未知の値がある場合、元の厳密評価は失敗しても代入後の式は成功し得る。副作用、Python関数の個体識別、実行上限、所要時間の保存は主張せず、実行本文の書き換えには使わない。

[比較例](../examples/v016/defined-thought-comparison.noema)は、既存の `rqsa` と、基準を明示した問い `hzll` にこの確認機構を接続する。定義名と展開形について、旧構文基準は偽、展開基準は真となる。否定形など同じと確認できない場合には、接続先も未知を返し、偽の意味対応を確定しない。偶発性・因果寄与・可能な状況が欠ければ、内容が対応しても問いの候補条件は成立しない。

問い全体の検査には、既存の診断用短絡変換を明示して使う。標準の厳密評価では、論点に帰属しない項目の未知の記述まで要求するためである。直接の構文比較と `rqsa` 接続は、保存した通常グラフでも検査する。新しい比較機構自体は、いずれの検査でも記述内容を実行しない。

これは全ての思想の一致を決定する機構ではない。原文で適切な同義関係を、この有限な正規化だけへ狭めることはしない。実文献の未記述項目を補わず、現行カント本文42文・十単位604文字の意味判断は保持する。原文対応範囲も増やさない。

## 偶発性について残る判断

[著者注](https://korpora.org/Kant/aa08/042.html)では、他方の回答をまだ受け取っていないことに続けて、思想の一致がどこまで生じ得るかを問う。意図的な内容調整を追加しない読みはこの文脈に適合するが、非調整だけを偶然の十分な説明とはしない。

[AdelungのZufall](https://lexika.digitale-sammlungen.de/adelung/lemma/bsb00009134_9_1_1075)では、予想外の出来事と原因の不明が説明に含まれる。[zufällig](https://lexika.digitale-sammlungen.de/adelung/lemma/bsb00009134_9_1_1077)には日常用法に加え、必然や本質との哲学的な対比もある。これをカントのこの一文の唯一の理論とは扱わず、単なる非意図性・確率的独立・無原因性への置換を見送った。[読解記録](../data/chance-reading-v1.json)に、文脈的な偶発性と、展開で判定できない内容対応が残ることを記した。
