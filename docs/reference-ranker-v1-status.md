# 共通の参照判定器の実装と特徴抽出

**撤回:** 以下の評価と学習は、主辞タグのないKWDLCで句の先頭語を正解主辞としていた。[正解位置の不備と修正](corpus-reference-v2-correction.md)を参照。v1の重み・選択は無効化し、読込みを拒否する。以下の数値は旧実験の記録であり、現在の有効な精度や改善の証拠ではない。原文保存と固定特徴の抽出記録は維持する。

語彙ごとの分類クラスを増やさずに、語句が以前のどの対象を指すかを学習する部品を追加した。公式train3,915文書とdev512文書の特徴抽出・保存検査、両方式の20エポックの学習が完了した。devでは文脈方式の10エポック目を選択した。test700文書では参照ペアF1が59.44%→60.89%になった一方、主辞と参照の文書完全一致は43→40件へ後退した。総合的な改善や翻訳精度の目標達成とは判断しない。

[固定した実験条件](reference-ranker-v1-protocol.md)に従い、比較する方式は5個の数値特徴を使う線形方式と、文脈ベクトルを共有の64次元へ射影する方式である。現在の768次元エンコーダーでは学習するパラメーター数は6と115,201で、語や概念を追加しても出力層は増えない。基盤モデルは固定し、生成処理・対訳表・語別の修正は使わない。

候補は予測された全ての先行主辞と「先行対象なし」である。複数の先行語句が同じ正解対象を指す場合は、そのどれかを選べる損失を使う。正解の候補が上流で欠けた場合や、予測主辞の範囲が正解と一致しない場合は、誤った負例を作らず損失から外して件数を記録する。開発評価では欠落した正解も分母に残す。複数対象・曖昧な参照はまだ単純な同一性グループで扱えず、未対応として保持する。

## 実装済みの操作

```powershell
artifacts/kwja-venv/Scripts/python.exe -m scripts.cache_reference_features --resume
artifacts/kwja-venv/Scripts/python.exe -m scripts.verify_reference_features --split train --output reports/reference-ranker-v1/train-feature-verification.json
artifacts/kwja-venv/Scripts/python.exe -m scripts.verify_reference_features --split dev --output reports/reference-ranker-v1/dev-feature-verification.json
artifacts/kwja-venv/Scripts/python.exe -m scripts.train_reference_ranker
artifacts/kwja-venv/Scripts/python.exe -m scripts.cache_reference_features --resume --splits test
artifacts/kwja-venv/Scripts/python.exe -m scripts.evaluate_reference_ranker
artifacts/kwja-venv/Scripts/python.exe -m scripts.verify_reference_ranker
artifacts/kwja-venv/Scripts/python.exe -m scripts.diagnose_reference_ranker
```

抽出は公式train3,915文書とdev512文書が対象で、実行環境はCPU・float32である。各文書のJSONを、予測と特徴ファイルの保存が完了した印として最後に書く。再開時には、原文・注釈・モデル・コード・特徴ファイルのハッシュを検査し、完了済み文書を再推論せずに読み込む。OSのファイルロックで同じ保存先への同時抽出を防ぐ。

学習コマンドは全train・devの抽出完了を要求する。20エポックの学習後、devの参照ペアF1と損失で方式・エポックを選び、モデルと選択記録を保存する。testの特徴抽出は選択記録が作られるまで実行できない。全資料学習と選択記録の保存を完了してから、test700文書の抽出を開始した。

最終評価の処理は、選択済みの重みと学習記録・判定方針を照合してから動く。学習本文と重複する文書を除いた結果も集計するが、解析できなかった文書や欠けた正解ペアは分母に残す。保存特徴からの開発・最終評価の再計算、最終評価先頭8文書の原文API照合、既存の参照12文の回帰確認を実装し、全資料で学習した保存モデルで実行した。

選択済みモデルを使う研究用APIとして`ReferenceRankerAnalyzer`も実装した。原文解析を`analysis`へ保持し、参照だけを再判定した解析と各候補の確率を別に返す。候補確率は全文の意味が正しい確率ではない。

## 完了した検査

- 最初のtrain4文書とdev4文書で抽出・保存・再読込みを確認した。各splitの先頭2文書は原文から再推論し、特徴と予測が完全一致した。
- 保存済みのtrain先頭64文書を検査し、既存モデルが採用した158の参照リンクについて、保存した照応スコアと採用先が一致した。[検査記録](../reports/reference-ranker-v1/feature-smoke.json)は64文書のみの検査であることを明示している。
- 続いて[train全3,915文書](../reports/reference-ranker-v1/train-feature-verification.json)と[dev全512文書](../reports/reference-ranker-v1/dev-feature-verification.json)を検査した。特徴の有限性・保存ハッシュと、既存モデルが採用した参照リンク8,974件・970件のスコアとの対応を確認した。解析失敗は両splitとも0件で、dev全件の原文解析は以前の固定した結果と一致した。生成・辞書の禁止経路の呼出しは全て0回だった。
- trainでは78,019主辞に監督信号を与えられ、そのうち正解の先行対象がある主辞は6,881件だった。予測主辞の範囲不一致7,438件、正解候補の欠落299件、未対応注釈の文書内主辞7,179件は損失から外して記録した。これらを正解率の改善と数えず、評価では欠落を分母に残す。
- 候補の自己参照・未来参照を禁止すること、複数正解の損失、欠落主辞を負例にしないこと、特徴の保存破損の検出、中断した保存と完了済み保存の区別を検査した。
- 小さな固定特徴で文脈方式を二度学習し、選択・履歴・重み・評価の完全一致を確認した。これは全資料で学習したモデルの精度や再現性の検証ではない。
- 重複本文の除外で解析失敗を消さないこと、保存済みの選択・重み・判定方針の不一致を拒否することも含め、全316テストが通過した。特徴のスカラー計算より前に実行条件を固定し、学習と再評価で同じ数値条件を使う。
- [保存モデルの検査](../reports/reference-ranker-v1/verification.json)では、dev512文書とtest700文書の再評価が一致した。test先頭8文書の原文APIが保存特徴からの予測・全候補確率と一致し、原文の反復推論も一致した。生成・辞書の禁止経路は全て0回だった。
- [従来12文の回帰結果](../reports/reference-ranker-v1/regression.json)は全区分で既存方式と同じだった。正解範囲を与えた参照グループ完全一致は10/12、予測範囲を使うと8/12で、既知の取り違えも残っている。
- 上流の主辞欠落と判定ミスの分解、失敗文書を含む分母、未対応注釈の扱いをテストし、全319テストが通過した。

## 開発用資料での結果と限界

[選択記録](../reports/reference-ranker-v1/selection.json)と[学習記録](../reports/reference-ranker-v1/training.json)を保存した。以下は選択に使ったdevであり、独立した最終評価の成績ではない。

| 方式 | 参照ペア適合率 | 再現率 | F1 | 主辞と参照の文書完全一致 |
| --- | ---: | ---: | ---: | ---: |
| 固定した既存モデル | 47.54% | 58.80% | 52.58% | 58/512 |
| 線形方式・20エポック目 | 54.36% | 50.11% | 52.15% | 55/512 |
| 選択した文脈方式・10エポック目 | 52.57% | 56.74% | 54.57% | 58/512 |

保存済みの両重みを再読込みし、512文書の評価と全候補確率が完全一致することを確認した。参照ペアは明示的な文書内同一参照だけを対象とし、モード付き参照を持つ40文書は未対応として記録している。KWJA自身もKWDLCを利用しているため、完全に未知の文章全般への性能とは呼ばない。

[失敗の分解](../reports/reference-ranker-v1/development-diagnostic.json)では、正解920ペアのうち160ペアで片方以上の主辞が上流の予測から欠けていた。現在の候補を固定する限り、参照先の判定だけを完全にしてもペア再現率の上限は82.61%である。残る760ペアのうち238ペアは候補があるのに選択した方式で再現できていない。

文脈方式は既存モデルの余分な169ペアを取り除く一方、43ペアを新しく誤って追加した。正解ペアの改善は29件、後退は48件で、正解数自体は541→522と減った。F1の上昇を意味保持全体の改善とは扱わず、候補抽出と判定の両方を次の改善対象とする。主辞集合の完全一致は100/512で、参照だけを改めても文書全体の一致には限界がある。

## 最終評価

選択を固定した後でtest700文書を処理した。全件で解析が完了したが、モード付き同一参照を持つ46文書は今回のペア評価では未対応である。[最終評価記録](../reports/reference-ranker-v1/test.json)では、それらも文書数に保持し、学習本文と重複する既知の1文書を除く集計を併記している。

| 対象 | 方式 | 参照ペア適合率 | 再現率 | F1 | 主辞と参照の文書完全一致 |
| --- | --- | ---: | ---: | ---: | ---: |
| 全700文書 | 既存モデル | 57.75% | 61.24% | 59.44% | 43/700 |
| 全700文書 | 選択した文脈方式 | 63.19% | 58.74% | 60.89% | 40/700 |
| 学習本文重複を除く699文書 | 既存モデル | 57.69% | 61.18% | 59.38% | 43/699 |
| 学習本文重複を除く699文書 | 選択した文脈方式 | 63.13% | 58.68% | 60.82% | 40/699 |

全700文書では正解ペア1,226→1,176、余分なペア897→685となった。誤った結合を減らす一方で正しい参照も取り逃しており、主画面の翻訳器へ採用する根拠にはしない。これはNoemaの全文意味構造の評価ではない。

全文意味構造95%以上、広い日英翻訳、辞書に依存しない逆変換、文字数の膨張の課題は維持する。参照先の判定だけに改善を集中せず、上流の語句範囲・主辞候補の欠落を次の課題とする。
