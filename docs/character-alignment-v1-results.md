# 原文の文字位置を保つ修正

**評価の訂正:** この資料の原文保存・文字位置対応・反復一致の検査は有効だが、後述する主辞位置と参照ペアの精度は[正解位置の不備](corpus-reference-v2-correction.md)により撤回した。文字位置の修正が、旧コーパスの正解主辞の妥当性を保証するものではなかった。

モデル内で文字が展開・合成されても、原文の範囲を保って解析する処理を追加した。前回「…」の展開で失敗した4文書を解析でき、KWDLCの開発資料では512/512文書から出力を得た。以前成功していた508文書の出力は全て完全一致した。これは入力と位置対応の改善であり、全文を正しくNoemaへ変換できた件数ではない。

## 実装

[位置対応の仕様とAPI](source-alignment.md)を追加した。原文をUnicodeの正規化で書き換えず、文字モデル内の正規化後の位置と対応させる。展開・合成の範囲の先頭に分割ラベルを戻し、原文範囲の途中に境界を作らない。元の語の文字列と位置は、後段でも保持する。

新しい`AlignedJapanesePAS`は、固定した既存の文字モデル・語モデルを使う。語別の補正、追加学習、生成処理は行っていない。旧`JapanesePAS`と以前の実験記録は変更せず、同じ原文で結果を比較した。

別の合成入力で、全角空白の語が語トークナイザーから消え、上流のバッチ処理で語番号がずれる問題も見つかった。符号化されなかった語だけにモデル既定の未知語トークンを割り当てる処理を追加した。語番号と原文を維持し、既に符号化できていた語のトークン列が変わらないことを検査する。文字別の変換表は持たない。初回の512予測と停止ログを`artifacts/character-alignment-v1-first-attempt`に保持し、修正後に全資料を再実行した。

## 結果

| 測定 | 修正前 | 修正後 |
|---|---:|---:|
| 原文解析成功 | 508/512 | 512/512 |
| 主辞範囲の一致 | 9,771/11,019 | 9,836/11,019 |
| 同一参照ペアの一致 | 539/920 | 541/920 |
| ペア適合率 | 47.57% | 47.54% |
| ペア再現率 | 58.59% | 58.80% |
| 主辞集合と参照ペアが完全一致 | 58/512 | 58/512 |

ペアの定義は[前回の公開文章評価](corpus-reference-v1-results.md)と同じである。AND・OR・曖昧な同一参照を含む40文書は、単純な参照グループで評価できず、引き続き未対応として保持する。原文解析に成功しても、参照・概念・否定・数量等が正しく確定できたことにはならない。

全512文書で、文字モデルに渡したテンソルは旧方式と一致した。修正したのは出力ラベルから原文への位置対応である。以前解析できた508文書について、原文解析全体の出力が一致した。今回のコーパスでは、消えた語への未知語トークン割当ては0回だった。

展開文字、結合文字、合字、全角文字、空白、全角空白、特殊トークンに見える文字列、未知文字を含む[12例](../data/character-alignment-v1.json)も検査した。全例で原文の保持、語と文脈ベクトルの行の対応、反復一致を確認した。全角空白の例では、内部のトークナイズ呼出しで合計6回、消えた語への未知語トークン割当てを行った。これは6文の回復を意味せず、同じ例の反復とデータ準備での呼出し回数である。
