# 二作品の文書統合と検証

意味判断の正本は `data/work-state.json` が選ぶ登録簿と本文である。出版用の名前の対応、明示定義の先頭展開、原文順への並べ替えは逆変換を保存し、元の構文へ戻ることを確認する。原文の再翻訳や、新しい意味判断の付与は行わない。

`two_work_plan` は保存された橋渡しと語義を収集し、`two_work_assemble` は未出版部分の依存閉包を既存宣言のまま接続する。新しい綴りを割り当てても基本関係を新設したことにはしない。`two_work_presentation` は本文先頭の明示された零引数定義だけを展開する。`two_work_edition` は原文単位の保存済み対応から掲載順を作り、本文と著者脚注を区別する。複数の原文単位に共通する意味群は最初の掲載箇所へリンクする。補助注記は別に保存する。

## 本検証

```powershell
python -X utf8 -m scripts.two_work_run --run .noema-project/runs/two-work-final-v1 --out output/two-work-final-v1
```

二作品を同じ入口で順に処理する。各作品の辞書は空から始め、復号器へ渡すのは実際のSVGと先行して回収された宣言だけである。回収後の構文を準備済み文書と照合する。既に一致した同一の図形は、構文・綴り列・推移的な依存・実装・行幅・SVGの内容ハッシュがすべて一致するときだけ再利用できる。再利用は構造検証の継承であり、意味判断ではない。

1記録1SVGを最初から物理行に分けて描画する。途中の巨大な一行を作らず、幾何検査の対象を行に限定する。宣言が失敗した場合、その依存先だけを保留し、独立した項目と次の作品を処理する。`scan_complete` と `validation_success` は別に記録する。出版ページにも未確認箇所を明示し、全件一致するまで回収済み全文として書き出さない。

全体の `status.json`、各作品の `status.json`、`events.jsonl` と `steps.sqlite` はrunディレクトリにある。heartbeatは15秒、現在の項目と完了数を保存する。出力側の `<work>/ink/status.json` は項目集計、`<work>/ink/report.json` は走査終了時の詳細である。終了時には原文対照、辞書、補助注記、識別表記、MathMLを含む静的HTMLと報告を自動生成する。

## 中断と修正

同じ入力・実装で中断した処理は同じ引数に `--resume` を追加する。完了済みの各記録は現在のSVGハッシュを確認して復元し、中断中の記録は最初から再実行する。協調停止は対象runまたは子runに `PAUSE` ファイルを置く。goalの停止と検証プロセスの停止は別である。

入力を修正する場合、既存runのpinを更新しない。新しいrunと出力先を使い、以前の出力を `--reuse` で指定する。保存済みの成功だけを条件付きで引き継ぎ、失敗・欠損・変更部分とその依存先を再処理する。

```powershell
python -X utf8 -m scripts.two_work_run --run .noema-project/runs/two-work-final-v2 --out output/two-work-final-v2 --reuse output/two-work-final-v1
```

実装変更がキャッシュ識別子へ影響する場合は、その範囲の再検査が必要になる。保存した意味監査の入力は内容ハッシュで確認し、図形変更だけを理由に全意味モデルを再実行しない。
