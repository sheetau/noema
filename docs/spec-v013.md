# 文語0.13：式の記述と、その評価

0.13では、Noemaの式そのものを型付きの値として言及できる。式の記述が同じか、その式の評価結果が同じかを区別する。例えば「2＋2」と「4」は異なる記述であり、加算の解釈では評価結果が一致する。32文字のアルファベットは増やさず、版指定を`m:`または`noema m m`とする。

この区別は、ある内容が真であることと、本人がある記述を認識していることを分けるために使う。論理的に同じ内容を持つ表現でも、本人が両方を認識しているとは限らない。可能状況と認識の関係を分ける設計は、[Fagin・Halpernの論文](https://www.cs.cornell.edu/info/people/halpern/papers/awareness.pdf)を参考にした。Noemaの実装は、その論文の体系全体や知識の一般理論を実装したものではない。

## 型と構文

| 記法 | 意味 |
| --- | --- |
| `i[T]` | 結果型Tの式を記述する型 |
| `r[式]` | 式を評価せず、その記述を得る |
| `s[記述]` | 記述された式を、同じ文書と解釈で評価する |

構文上の位置で識別するため、文書先頭の基本記号宣言`r 名前[...] 型.`や主張`s[真理値].`とは混同しない。JSONでは型を`{"kind":"description","result":型}`、引用を`{"kind":"quote","body":式}`、脱引用を`{"kind":"disquote","description":式}`とする。

```text
m:
r aa[b b] b.
d ba[] i[b][r[k aa[n p c b n p c b]]].
d bb[] i[b][r[n p e b]].
s[u[e[k ba[]][k bb[]]]].
s[e[s[k ba[]]][s[k bb[]]]].
```

[この例](../examples/v013/descriptions.noema)で、aaを有理数の加算と解釈すると二つの主張はともに真になる。aaの宣言だけから加算の意味は得られない。従来どおり、基本記号の意味は解釈が明示する。

命題内容なら`i[e]`、有理数から有理数への関数なら`i[h[b] b]`となる。数値、内容、関数、質問、発話などを記述できるが、引用した発話を構成しただけで発話を実行することはない。脱引用の型は記述型のTに一致し、真理値の主張へ暗黙変換しない。

## 引用の範囲と同一性

引用対象は、自由変項を持たない閉じたNoemaの式に限る。引用の外側にある変項を捕捉しない。引数を持つ記述が必要なら、引用の中で関数を定義する。例えば`r[i[x b][v x]]`は有理数の恒等関数を記述する。宣言済みの名前への参照は許すが、未宣言・前方・再帰参照は従来どおり拒否する。自然言語の文字列を入れる構文はない。

記述の同一性は、正規化した構文木の一致である。束縛変項の名前は引用ごとに独立して正規化し、外側の束縛変項の個数で記述が変わらないようにした。有理数の分数表記も従来どおり既約化する。空白・変項名・分数の別表記は区別しない。一方、定義の展開、関数適用の計算、論理同値への書換えは行わず、異なる宣言名も保持する。したがって原綴りの保存機構でも、任意の概念の捉え方を完全に表す機構でもない。

引用対象には、脱引用`s[...]`を直接にも、参照する定義を介しても含められない。この制約は、式の評価を再び自分自身の真偽へ向ける構成を無制限に許さないためである。閉じた式と評価演算を含まない引用の扱いは、[Farmerの型理論の論文、§3.3](https://imps.mcmaster.ca/doc/qe-in-church-ss.pdf)を参考にした。Noema独自の体系全体について、無矛盾性や完全性を証明したという主張ではない。

この制約により、今回の脱引用を使った認識条件seなどを、さらにそのまま引用することも拒否する。知識についての知識、式の一部分の組立て、自由変項を持つ引用、置換を含む一般のメタ言語は今後の課題である。

意味上の記述領域は、固定した文書の宣言環境で型が合い、上記の制約を満たす閉じた式の正規形とする。宣言環境を変えれば参照名の意味も変わり得る。記述だけを別文書へ持ち出して同じ対象を指すとは扱わず、必要な宣言とともに再検査する。記述可能な値を持たない型の記述領域は空になり得る。このため、記述型について無条件の存在を仮定しない。

## 認識と候補状況

[認識の定義群](../examples/v013/epistemic.noema)は2基本記号・7定義からなる。基本記号raは主体・現在の文脈・候補状況の関係、rbは主体・記述・文脈の認識関係である。どちらも資料や推論から自動抽出するものではなく、検査時に明示する仮定である。

| 定義 | 条件 |
| --- | --- |
| sa | 候補が一つ以上ある |
| sb / sc | 内容／記述の内容が、空でない全候補で真 |
| sd | 記述を認識しており、scが成立 |
| se | sdに加え、現在状況自体が候補に含まれる |
| sf | 内容が空でない全候補で偽 |
| sg | 候補はあるが、真にも偽にも決着していない |

sdは誤った信念に相当する解釈でも成立し得る。seは現在状況での真理を含むが、証拠の正当性や推論の信頼性を定義したわけではない。seを知識の一般的な十分条件とはしない。候補が空の場合を「全て知っている」と数えず、「真だと認識していない」と「偽だと認識している」も区別する。両者の区別を含む9つの解釈を検査した。

## 原文のφへの部分適用

[アインシュタインの統合草案](../examples/v013/einstein-epistemic.noema)は、従来の座標・数量の定義に認識の定義群と四つの定義を追加した。12基本記号・61定義となる。原文u0085の「暫定的に未知である速度の関数」の部分に対応する試案であり、全文の完成ではない。

familyは、候補状況から有理速度の関数φを得る引数である。sqは指定した速度において二候補のφ値が異なること、spはそのような有理速度が存在することを表す。ある速度で値が一致しても、関数全体が同じとは限らない。srは、現在状況を含む全候補で、φがあるNoema記述の関数と全有理速度にわたり一致することを表す。ただし、その記述の認識や証明を意味しない。

suは、現在状況でのφを既存の四座標の条件ehへ渡す。φを1に固定せず、実際の関数を変えたときに四式の結果が変わることを検査した。familyは同じ基準系・単位の規約内で比較する。実数全域の関数、単位変更を含む一般の知識状態、著者への帰属と後続の導出は未記述である。

spの候補の複数性は、数学的に一意でも本人が式を認識していない場合を含まない。従ってspだけを原語unbekanntの完全な意味としない。認識と内容を分ける基盤を追加した段階であり、確認済み全文単位はアインシュタイン0/282、カント0/20のままである。

## 検査器と再現

引用の構成は式を実行しない。有理数全体への量化を含む式も記述できるが、脱引用したときに有限検査器の範囲を超えれば拒否する。記述領域も一般に無限であるため、見つかった引用だけを全領域として列挙する処理は行わない。記述を答える質問や、記述を引数とする関数の全域比較も同じ制限を受ける。

実装は、型検査済みの記述を一回の解釈内で共有し、その解釈が発行した値だけを脱引用する。外部の基本関係から渡された未検査の構文木、偽造した値、別の解釈から持ち越した値は評価しない。Pythonコードのevalや外部のプログラム実行は使用していない。通常の評価と同じステップ上限・型検査を保つ。

```powershell
python -S -m scripts.compose_epistemic
python -S -m scripts.check_epistemic --verify-only
python -S -m noema parse --input examples/v013/einstein-epistemic.noema --output artifacts/einstein-epistemic-v013.json
python -S -m noema render --input examples/v013/descriptions.noema --alphabet v2 --output artifacts/descriptions-v013.svg
python -m pytest -q
```

[検査記録](../reports/epistemic-v1.json)は、認識の9解釈、φの8具体例と全有理数の探索・比較を拒否する2例、通常記法・短縮記法・固有文字の往復、原文範囲と入力ハッシュを含む。φの一点での検査を全域の証明として数えていない。解析・表示・今回の反例検査には学習モデルや数式ソルバーを必要としない。0.8〜0.12の既存文書は0.13へ変換できるが、新しい記述型を使う文書の旧版への変換は拒否する。
