# 能力を評価する方法の範囲

既存の能力条件は、利用できる方法で目標を達成できるかを評価する。そこへ準備や学習を含む方法を渡した場合、学習後の達成も能力の根拠になる。本人の状態を候補場面の始点で保持する条件だけでは、方法の途中の学習を排除できない。

[一般構成](../examples/v016/method-scope.noema)の `rqve` は、実行できる方法を、明示した方法の範囲で制限する。引数は基準状況、範囲を判定する関数、利用可能性を判定する関数である。返す関数は、同じ本人・方法・実行状況について両方の条件を要求する。仮定する実行状況が変わっても、範囲の判断へ渡す基準状況は保つ。

この関数を既存の `xd`・`xg`・`xf` や能力保持のプロフィールへ渡せる。能力ごとに新しい判定の定義を複製せず、一つの合成定義を加えた。基本関係と文法は増やしていない。方法の制限と、結果の評価範囲の選択も分ける。含めた方法の失敗結果を取り除き、成功だけを残す処理は行わない。

[比較例](../examples/v016/method-scope-example.noema)では、カントの自立的な理解力使用 `bb` を同じ目標にした。診断用の解釈では、準備的な習得を含む方法だけが成功し、既有の状態で行う方法は失敗する。この場合、全方法では達成可能だが、後者の範囲内では達成方法がないと記述できる。現在は機会がないが、機会を与えた場面では後者の方法で成功する例も別に検査する。

例中の `zscope` は、どの方法がこの範囲に入るかを明示的に与える入力である。方法の内部構造から学習の有無を判定した結果ではなく、学習そのものの説明でもない。既存の経験による能力取得の構成との接続、どの準備を許すか、課題に対する範囲の妥当性は残る。範囲が空なら「この範囲内に方法がない」は成立し得るが、それを範囲外も含めた不能とは扱わない。未知の区分も範囲外へ補わない。

[原文の後続段落](https://korpora.org/Kant/aa08/036.html)は、当面の不能と、それまで試みを許されなかったこと、自己の精神への働きかけによる離脱を述べる。この区別を検討する動機になるが、今回の方法範囲をそのまま原文の能力の定義として採用したわけではない。現在のカント本文・意味規約・意味確認の登録簿は変更しない。

検査では、二方法の利用可否・範囲・成功を独立に変える64組合せ、11の範囲・評価対照、四つの未知入力、実際の `bb`・`bc` と能力プロフィールを使う六つの比較を扱う。範囲内の方法が未評価なら不能を確定せず、範囲外の未評価方法を除外できた場合も結論を指定範囲内に限定する。通常記法・短縮記法・固有文字の往復を確認する。本文への採用と段落全体の意味確認は残るため、原文の対応範囲や確認済み文字数は増やさない。
