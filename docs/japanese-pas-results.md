# 日本語の学習済み解析器から関係を取り出す

**KWJAの分類器を、生成と辞書による意味補完を通さずに動かす解析部品を実装した。** 日本語の基本句、述語項の関係、時間・否定等の特徴を元のラベルで取り出せる。ただし、出力する格とNoemaの意味役割は同一ではない。受動態の役割対応と省略の扱いは未解決であり、翻訳器として主画面には接続していない。

## 使う部分と省く部分

[KWJAの公開実装](https://github.com/ku-nlp/kwja/tree/821df300630b4d05c38406945536eaac848619da)からcharとwordのbaseモデルを使う。[論文](https://aclanthology.org/2023.acl-demo.52/)で説明される、既存の日本語解析タスクを共同学習した分類器であり、Noemaの語彙ごとに学習し直していない。

charは文字ごとの文・語の境界を予測する。wordはその語列から品詞・基本句・関係先等を予測する。typoとseq2seqのモデルは作成せず、文章生成も呼ばない。チェックポイントは固定し、勾配とドロップアウトを無効にしたCPU・float32で推論する。

標準の `WordModuleWriter` にはJumanDicによる語義・原形の検索と活用処理があるため使わない。公開の分類器と、品詞の整合性・基本句の組立て・関係の選択に必要な処理を再利用する。内部形式で要求される原形欄には原文の表層形を保持し、辞書の意味属性を付けない。charの正規化用分類結果も採用しない。読みや正規形の復元を実現したとはしていない。

自然文の単語を照合する辞書や翻訳表を追加していない。一方、モデル自身のトークナイザー語彙と、学習済みの品詞・関係ラベルの集合は持つ。モデルの予測を読み取るためのこれらの在庫を、自然言語とNoemaの対訳辞書とは区別する。

## 既存24文の診断

[条件](japanese-pas-protocol.md)を `1c4d5dc` で予測前に固定した。前回までの日本語24文を再利用しており、新しい独立評価ではない。正解の述語位置・分かち書き・関係先は渡していない。

元の資料で指定した55の項範囲のうち、36が予測した述語から関係付けられた基本句に含まれた。この集計は**役割を問わない範囲の包含**であり、A0/A1の正解率や全文意味構造一致率ではない。従来のSRLの範囲・役割完全一致の数字と比較して改善率を求めない。

確認できた関係は次のとおりである。

| 原文の例 | 取り出した関係 | 判断 |
| --- | --- | --- |
| 犬が猫を追う。 | 追う→ガ:犬が、ヲ:猫を | 能動文の項を取得 |
| 猫が犬に追われる。 | 追われる→ガ:猫が、ニ:犬に | 対象は得られるが、能動文とラベルが変わる |
| 小説を書いた女性が賞を受賞した。 | 書いた→ガ:女性が、ヲ:小説を。受賞した→ガ:女性が、ヲ:賞を | 関係節内から修飾先への項関係を取得 |
| 記者が大臣が辞任したと報じた。 | 辞任した→ガ:大臣が。報じた→ガ:記者が、ト:辞任したと | 二つの述語と節間の関係を取得 |
| 猫を追う。 | 追う→ガ:著者、ヲ:猫を | 原文で確定できない主体を推測している |

受動文のガをNoemaの主体へ固定対応させると、猫が追う側になってしまう。この結果を受動態の解決とは扱わない。意味役割へ変換するための学習された関係判定が別に必要である。

省略した翻訳者も「著者」と予測された。実装ではこの値を `external` として保存し、原文の文字範囲を持つ項と分けた。Noemaの意味本体へ確定した人物として埋めない。

数量付きの項は「二匹の」と「犬が」の別の基本句となり、単一の基本句だけでは項全体を表せない。また「三匹の」が犬と関係付く誤り、「写真家」が「写真」「家」に分かれる例も残る。基本句を抽出できたことと、修飾・数量を含む一つの事物を構成できたことは別である。

## 検証

全24文の推論で、文章生成・辞書初期化・標準WordModuleWriter・seq2seqモデル・typoモデルに到達すると失敗する検査を有効にした。呼出し数はすべて0だった。[実行結果](../reports/japanese-pas-v1/summary.json)

分類器は公開クラスのforwardを直接呼ぶ。再利用したソース7ファイルが固定した公開ソースと一致することを検査し、全重みを厳密に読み込んだ。Transformersで非永続になった位置IDバッファだけを公開実装と同様に除いた。charの文・語の分割は、正規化を無効にした公開の組立て処理と24文すべてで一致した。辞書を使う標準出力全体との同値性を主張する検査ではない。

チェックポイントは `weights_only=True` で読み、既知のOmegaConf設定型だけを許可してsafetensorsへ変換した。旧設定内のキャッシュ用defaultdictは通常のdictへ読み替える。別の変換実行で重み・設定・来歴の5ファイルのハッシュが一致した。char・wordの長さ制限を超える入力は、切り捨てずにエラーになることも確認した。[検証記録](../reports/japanese-pas-v1/verification.json)

原文位置、文外参照の分離、診断の再集計を含め、全220テストが通った。同一プロセスで反復した結果も一致した。[全予測](../reports/japanese-pas-v1/predictions.json)、[診断](../reports/japanese-pas-v1/assessment.json)、[実行条件](../reports/japanese-pas-v1/run.json)を保存した。

別プロセスでも2回再実行し、全予測・診断・集計・実行条件の4ファイルが一致した。初回の再実行はPowerShellの標準エラー出力のリダイレクトがNativeCommandErrorを記録したため、子プロセスの終了コードを直接取得して再確認した。終了コードは0だった。[再現性の記録](../reports/japanese-pas-v1/reproducibility.json)

## 再実行

今回のKWJAはPython 3.14を対象外とするため、既存のNoema環境を変更せずPython 3.12の別環境を使う。依存ライブラリは[実行時の固定一覧](../reports/japanese-pas-v1/requirements.txt)に記録した。

```powershell
py -3.12 -m venv artifacts/kwja-venv
& artifacts/kwja-venv/Scripts/python.exe -m pip install -r reports/japanese-pas-v1/requirements.txt
& artifacts/kwja-venv/Scripts/python.exe -m scripts.prepare_japanese_pas
& artifacts/kwja-venv/Scripts/python.exe -m scripts.probe_japanese_pas --output reports/japanese-pas-reproduction
```

準備済みの重みがある場合はprepareを再実行しない。推論はローカルファイルだけを読み込む。辞書・生成の経路を通さないことの検査もprobeコマンドに含む。新たなモデル・概念の選択や学習を、今回の成績に含めてはいない。
