# 型・役割制約による概念と役割の同時選択

概念と役割の候補を一つの出来事ごとに比較する処理を実装した。既存18文では、述語・役割・範囲・概念の全フレーム一致が5文から12文へ増えた。今回予測する前に用意した別の14文では4文から6文だった。型と役割の不整合は解消したが、型に合う誤った概念や、必要な項を捨てる誤りが残った。全文の意味構造を確定する段階には達していない。

## 固定したスコアの組合せ

[前回の独立選択](lexical-frames-v1-results.md)と同じモデル・重み・定義を使い、再学習は行っていない。概念判定は語彙によらない3係数を共有し、91概念の全候補を比較する。Noemaの概念定義と役割の型を制約として使い、個々の自然言語表現に対応する補正は加えていない。

[事前条件](joint-lexical-v2-protocol.md)に従い、概念スコアを学習時の倍率10でlog-softmaxへ変換し、役割のlog-softmaxと重み1ずつで足す。述語の候補ごとに、各役割へ割り当て済みかどうかを状態とする動的計画法で最大値を求める。省略された役割は補わず、採用しない句にも潜在的な概念スコアを含める。これは固定した目的関数の最適化であり、校正済みの意味一致確率ではない。

推論には原文だけを渡す。正解の句範囲や概念は評価時にのみ使う。出来事の採否と句範囲は既存ヘッドの予測のままであり、複数の出来事にまたがる照応や節の作用範囲はまだ同時に推定していない。

## 既存18文と新規14文の結果

以下の「全フレーム一致」は、述語・役割・原文範囲・概念だけの一致である。否定、時間、数量、節関係などを含む全文の意味構造一致率とは区別する。新規14文も少数の手作業例であり、広い自然文の独立した採用試験ではない。英語は今回測定していない。

| 指標 | 既存18文：独立→同時 | 新規14文：独立→同時 |
| --- | ---: | ---: |
| 述語概念の一致 | 11→18 / 19件 | 8→8 / 15件 |
| 役割・範囲の一致 | 37→37 / 40項 | 30→32 / 36項 |
| 役割・範囲・概念の一致 | 32→34 / 40項 | 29→31 / 36項 |
| 欠落した役割・範囲・概念の組 | 8→6 | 7→5 |
| 余分な役割・範囲・概念の組 | 7→3 | 6→3 |
| 全フレーム一致 | 5→12 / 18文 | 4→6 / 14文 |
| 型・役割が不整合のフレーム | 12→0 / 19件 | 7→0 / 15件 |
| 確定した全文翻訳 | 0→0 / 18文 | 0→0 / 14文 |

既存の読書文や受動文など7文、新規の疲労状態と数量・否定を含む飲水文の2文でフレーム一致が改善し、今回の全フレーム一致判定では悪化した文はなかった。ただし、数量・否定を含む例でも抽出できたのはフレーム要素までである。[全件の評価](../reports/joint-lexical-v2/evaluation.json)に不一致と余分な割当ても残した。

## 型に合っていても誤る例

未知概念を含む3文では、同時選択後も全て既知概念へ誤対応した。「診断した」は「見つける」、「ロボット」は「鍵」、「翻訳した」は「話す」になった。いずれも型の不整合は検出されない。未知例で全文を誤確定した件数は0件だが、これは全件を研究用の未確定結果としているためであり、未知判定が成立したことを示さない。

既知概念間の区別にも失敗した。新規資料では「買った」「売った」を「渡す」、「聞いた」を「話す」と判定し、「開いている」では状態と動作を取り違えた。「メッセージ」を「電話」とする誤りも残る。これらには型制約だけで候補を分けられないものが含まれるため、次の改善は共通の概念照合器の識別性を検査する必要がある。今回の14文を係数選択に使ってはならない。

必要な項を捨てる場合もあった。「本は青い」「本は赤い」では、独立方式が本を対象役割へ割り当てていた。同時方式では不適合な対象役割を除いたが、主体へ変更するより非採用のスコアが高く、本の項が消えた。型不整合の減少だけを改善指標にすると、この欠落を見逃す。

「犬と猫」ではグループを一つの犬へ縮め、「ペンで書いた」の道具役割は抽出できなかった。現在の役割ヘッドは主体・対象・受け手・場所だけであり、グループの構築と追加の役割を扱う処理が必要である。同一の原文範囲に複数フレームで違う概念を割り当てた競合は今回0件だったが、異なる範囲間の同一参照を解決した結果ではない。

## 検証と再計算

小さな人工スコアでは、同点、非採用、役割の競合を含む60条件で全探索と最適解が一致した。先に現れる句へ貪欲に役割を割り当てると失敗する例と、上流処理の失敗時にフックを解除する検査も含め、全409テストが通過した。

原文からの推論では、全32文で元の構造解析と同じ出力を維持し、既存18文の独立方式の出力も前回と完全一致した。全スコアを取得するバッチと独立方式の共通範囲では、上位3候補とそのスコアが差0で一致した。先頭4文の反復一致、保存した全スコアからの32文の再計算を確認し、生成・辞書等の禁止経路5種の呼出しは全て0回だった。

推論環境はPython 3.12.10・PyTorch 2.13.0 CPU。モデル・重み・ソース・入力・出力のハッシュと実行条件は[記録](../reports/joint-lexical-v2/run.json)、再計算結果は[検証記録](../reports/joint-lexical-v2/verification.json)に保存した。全候補の生スコアはローカルの`artifacts/joint-lexical-v2`にあり、Git管理には含めていない。

```powershell
artifacts/kwja-venv/Scripts/python.exe -m scripts.probe_joint_lexical
artifacts/kwja-venv/Scripts/python.exe -m scripts.probe_joint_lexical --verify-only
```

コマンドは初回結果を上書きしない。`noema.joint_lexical.JointLexicalAnalyzer().analyze(text)`は比較用の独立結果、同時選択結果、全スコアを返す研究用APIである。`confirmed: false`と`document: null`を維持し、主画面の翻訳器には採用していない。確定率80%・確定出力の意味構造一致率95%は未達であり、文字数の膨張と広い対応範囲も引き続き[必須課題](open-problems.md)として残る。
