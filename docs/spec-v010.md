# 文語0.10：発話の働きと言及、仮定の範囲

0.10では、主張・質問・呼びかけを内容と組み合わせて文中の対象にし、言及と発話の実行を区別する。仮定を適用する文の範囲も明示できる。版指定は`j:`または`noema j j`。0.9までの構文と意味は保持する。

## 発話を対象にする

新しい型`f`（JSONでは`message`）は、発話の働きと命題内容の組である。発話の発生そのものや原語の綴りではない。

```text
j s[内容]     主張の内容を対象として作る
j q[内容]     肯否を尋ねる質問の内容を対象として作る
j m[内容]     その内容の実現を促す呼びかけを対象として作る
o[発話]       発話から命題内容を取り出す
```

3つの`j`構文は型`e`の命題内容を受け取り、型`f`を返す。現在の真理値を直接渡すことはできない。`o`は型`f`から型`e`への明示的な射影であり、発話を実行しない。

例えば、`aa(w)`が状況wで窓を閉めることなら、`j m[b w[k aa[v w]]]`は窓を閉めるよう促す呼びかけを表す。この式だけでは、窓を閉めたという主張も、読者への呼びかけの実行も生じない。標語・報告・約束などを説明する関係の引数として使える。

発話の意味領域は`{assert, ask, direct} × (W → {真,偽})`である。同じ内容でも働きが異なれば別の発話となる。同じ働きで全状況の真偽が等しければ、この型では同一である。言い回し・発話回数・話者・証明方法まで同一という意味ではない。それらを区別する場合は、発話の意味とは別の対象・関係を記述する必要がある。

型`f`の変項・関数・量化・同一性も利用できる。定義の引数を内側の内容式で参照でき、正規化は束縛名だけを変更する。前方参照・再帰定義・自由変項は禁止したままである。

## 言及と実行

```text
l[発話].
```

`l`は、構成した発話を文書のその位置で提示する。主張なら内容へのコミットメント、質問なら肯否の問い、呼びかけなら実現の促しとなる。話者・受け手・評価状況の具体的な同定は、この構文だけでは補完しない。発話の働きには、命令・依頼・助言・奨励の細別や、権限・強制力も自動では含まれない。

`s[真理値の式].`と`q[真理値の式].`は従来どおり使える。`l`の本体は発話型に限り、命題内容や真理値を暗黙に発話へ変換しない。

`s[k motto[j m[内容]]].`のような文は、呼びかけを引数にした関係を主張する。内側の呼びかけは実行されない。また、`l[j m[内容]].`から内容が既に真であることは導かれない。実現を促すことと実現したことを区別するためである。

この仕組みで引用された発話の意味を対象にできるが、原語の正確な字面を引用する構文ではない。原文の文字列をそのまま入れて意味の記述を済ませる方法も提供しない。

## 仮定の範囲

```text
a[真理値の式][文. 文. …].
```

`a`は、条件を仮に採用して後続の角括弧内を述べる。本文全体で条件が真だと断言しない。範囲の外にある兄弟の文には仮定を持ち出さない。内側にさらに仮定を置くと、両方の仮定の下でその内側の文を読む。

例えば「雨だという仮定の下で、窓を閉めるよう促す」と、その外に置いた「窓を閉めているか」という質問を別々に記述できる。[別分野の例](../examples/v010/conditional-directive.noema)では、`aa(w)`を雨、`ab(person,w)`を窓を閉める行為、`ac()`を受け手、`ad()`を現在の状況と解釈する。

仮定の式の中の存在量化は、括弧外で使える個体名を導入しない。文書内の宣言・定義は先頭に置く規則を維持し、仮定の中に局所宣言を置く構文はまだない。仮定の範囲は空にできず、入れ子の上限は128である。

この構文は議論の前提を記録する。結論が前提から証明できるかは別の問題で、型検査や構文解析の成功を証明と扱わない。仮定された呼びかけを実質含意の真理値へ変換することもしない。

## カントの標語への適用

[標語の部分草案](../examples/v010/kant-motto-draft.noema)では、自分の理解力を自立的に使う内容`bb(person)`を0.9の草案から引き継いだ。勇気の関係`al(person,goal,situation)`には、向かう先の内容を引数として渡す。勇気一般を持つこと、実行すること、成功することを区別する。

`bg(person)`は、この内容に向けて行動する勇気を持つよう促す発話を作る。文脈上の受け手を代入した`bh()`を標語関係の対象にする。本文の文はその位置付けの主張1件であり、呼びかけの実行文`l`は含めない。

[基本関係の規約](../data/kant-motto-basis-v1.json)を記録したが、啓蒙を指す対象と先行定義との接続、標語の一般的な意味、ラテン語とドイツ語の関係、帰結を示す`also`は未完成である。「他者の指導なし」という先行定義をドイツ語の呼びかけにも含める文脈解釈も明示しており、原文との同義性を確認済みにはしない。

[追加対応表](../data/kant-motto-alignment-v1.json)を前回の冒頭対応表に重ねると、6区間のうち部分草案が5、未記述が1となる。これは完成した訳文5区間という意味ではない。全体としてカント0/20、アインシュタイン0/282の確認済み単位数は変わらない。

## 検証と互換性

有限解釈器は発話を`Message(force, Content(...))`として返す。主張・質問・呼びかけの違いを残し、呼びかけを真偽値として返さない。仮定は`condition_value`と内側の結果を持つ階層として返す。指定したモデルの条件が偽でも、その条件を勝手に真へ書き換えず、内側の文をモデルどおりに評価して仮定の下に保持する。これは仮定からの推論や実世界の事実判定ではない。

発話型への量化では、3つの働きと全ての内容を列挙する。内容型と同じく検査器では8状況までに制限し、数値領域への量化は拒否する。言語の意味領域を有限標本へ縮める規則ではない。

0.8・0.9からの明示的な版変換を提供する。古い版へ戻すときは、新しい型・構文が一つでもあれば拒否する。発話を真偽に変えたり、仮定を外したりして変換を成功させることはない。

```powershell
python -S -m scripts.check_written_v010 --verify-only
python -S -m noema parse --input examples/v010/kant-motto-draft.noema
python -S -m noema script --input examples/v010/kant-motto-draft.noema --alphabet v2
python -S -m noema render --input examples/v010/kant-motto-draft.noema --alphabet v2 --output artifacts/kant-motto-v010.svg
```

[検査記録](../reports/written-v010.json)にモデルなしの往復、具体的な解釈、原文対応範囲と入力ハッシュを保存した。23件の新規テストで発話の働き・内容の取り出し・束縛・仮定の範囲・型エラー・版変換などを検査し、全527テストが通過した。過去のハッシュ付き記録は当時の実装の記録として保持し、新版の結果で上書きしない。
