# kant-page生成規則から組み直す復号設計

基準は [当初の依頼と追記](../concept/alphabet-concept.md)、[文頭規則](kant-page-script-v3.md)、および実際にkant-pageを生成したコードである。構造木案とflow横書き案は利用者が却下した。新しい承認候補はまだ作成していない。ここでは、元の形を維持して読むための実装済み部分と、意味を一意に対応させるために必要な設計を分ける。

## 描画規則とコードの対応

| 規則 | 元コードでの実装・検査 |
| --- | --- |
| 円は三サイズ。中小円が隣接段で接し、サイズ差が等しい | circle_contact_scriptのPITCH・RADII。段間32、中円32/√2、小円32−中円、大円2×中円−小円。 |
| 円中心と横線は三段、大円は中央段 | balanced_circle_script.geometry_check、circle_contact_script.line_error |
| 線は水平・垂直・45度。円への接続は中心方向 | line_error。円周への接線接触や斜めの侵入を拒否する。 |
| 小円の中心に線を通さない。各中心では一方向だけ | geometry_check。複数方向の中心線と直径を拒否する。 |
| 一円の相手は最大一円。同心・限定した接触・小円中心と大円周の重なり | 元の検査にkant_geometry_rulesを加える。三円の入れ子と偏心包含を拒否する。[利用者の指摘を受けた訂正](kant-circle-pair-rule.md)参照。 |
| 大円の45度線は自由終端。中心から出る形と円周から出る形を各四方向で許す | nucleus、geometry_check。終端は大円の上下端の高さ。途中で曲げず、他へ接続しない。 |
| 円周から曲げるまでの長さを確保 | MIN_RUN=16、radial_clearance |
| 他の構造への過剰な接近・接触を避ける | MIN_GAP=32/3、spacing_check |
| 線だけの輪・矢印・連続した直角を作らない | line_topology、_check_joined_turns。線を別のSVG要素へ分けても同じ規則。 |
| 分岐は実際の依存から作る。定型的・対称的な枝の反復を避ける | eventsが構文の終端引数を横枝にする。compile_expressionが非対称の候補を選ぶ。 |
| 上下の重さを長い範囲で釣り合わせる | 各円の面積に比例する重みと中央段からの距離を累積し、過剰な偏りを配置の費用に加える。 |
| 半径線・円同士の接触・上下段の飛越・スペースの頻度を抑える | stroke_mode、profile、配置候補の費用と回数制約。これらの頻度要件は単独の幾何合否と区別する。 |
| スペースも円中心同士の直線接続として扱う | 元生成器は引用入口にinvisible辺を記録する。新しい読取器はこの記録を受け取らず、実図形の連結成分から接続を回収する。 |
| 許容している形が生成不能になっていないか調べる | 新しい二円配置一覧と、八方向の半径・接続、四方向の円周外斜線の小例で調べる。 |

点は当初から任意であり、現在の生成器は使っていない。点を導入する場合の「円中心に置き、線を接続しない」という条件も残る。使わない任意要素と、許容したのに実装で到達できない形を同一視しない。

元のgeometry_checkをそのまま呼ぶ。ただし、これが成功しただけで、語・文法の一意性、頻度の適切さ、見た目の承認まで済んだとはしない。

## 前案で失った条件

flow案の行番号は小円の中心に線を入れ、文法合字は一つの中心から二方向へ線を出していた。型の合字には三円の入れ子もあった。これらは元の幾何検査が拒否する。前案の復号テストが通ったことは、当初規則への適合を示していなかった。

短い二叉を機械的に挿入したことも、実引数から横枝を生成する元の方法とは異なっていた。新しい実装では、枝を置いてから意味を探すのではなく、枝へ出す引数と、その引数を戻す位置を文法規則として決める。

## 実図形から読めた構造

scripts/kant_geometry_reader.pyは円・線だけを受け取り、次の情報を回収する。入力に構文木、語の番号表、出現位置、SVGの付属属性、invisible辺を渡さない。

- 各円のサイズ・高さ・中心線の方向と、中心まで入らない外部接続。
- 大円の中心から出る自由斜線と、円周から出る自由斜線。
- 同心、円周接触、片方の中心と他方の円周の一致。
- 線の分岐点、実際に接続している円と線、可視の連結成分。

SVGの要素順と線分の区切りは意味を持たない。同一直線上の線分を統合してから、円中心・円周・接続点で線を分けて読む。元の40主張の629円を、実SVGへの変換を介して検査した。可視の分岐点は99か所、中心と円周の重なりは50組、同心は12組ある。このページには円周接触の例がないため、接触は別の小例で確認する。

引用入口の不可視接続には、公開できる一つの構成規則が見つかった。円中心の左→右、同列は上→下の順で、連結成分同士が入り交じらないように配置する。前の成分の最後の中心と、次の成分の最初の中心を結ぶ直線が水平・垂直・45度なら、それを継続接続とする。入り交じる成分や、許容方向で結べない成分は推測せず拒否する。

この規則で元の14接続をすべて回収できた。単に同じ軸にある円同士を候補にすると41通りあり、一意でなかった。これは既存40主張で一致した構成規則であり、どんな空白でも補ってよいという規則ではない。引用の意味と範囲は、さらに公開文法で決める必要がある。

## 生成時のラベルと見える区別

元コードのstroke_modeを、そのまま読取器の文字種にすることはできない。radiusとして生成した主円のうち46個は、同方向の外部線とつながり、見える一本の線としては中心から外へ続いていた。incoming、entry、radiusの違いには、生成手順だけに残るものがある。

小円と中円が上下で接する場合にも同じ問題がある。小円の円周から中円の中心までの線は、長さだけなら中円の半径線と同一である。接触した相手の円まで読めば、その線が相手へ接続していることは分かる。局所的な線の形だけで意味を決めず、円の関係と接続を組として解釈する必要がある。

語の識別には別の欠落がある。元の生成器を実際に呼ぶと、同じ参照順の下でもrain(town)とrain(home)が同じSVGになる。付属の辞書番号や構文木を見れば区別できるが、図形の復号には使えない。円を読めるだけで語が読めると扱わず、公開した語の構成的な綴りへ接続し直す。

andの融合も未解決である。調べた左右結合の対照例は異なるSVGになったため、「融合すると結合順が常に消える」とは言えない。一方で元コードは復元用のfused_pathsを付属情報として保持しており、図形だけからそれを回収する文法はない。配置の偶然の差を構文規則として採用せず、局所的に逆変換できる融合に限定して設計する。

## 許容配置と元生成器の到達範囲

円のサイズ・高さ・接触条件から決まる二円の配置を、水平移動と円の列挙順の違いを除いて調べた。以前の41配置には禁止された偏心配置10件を含めてしまっていた。訂正した検査では31配置となり、そのうち16配置は元のnucleus関数と接触用の横枝規則から直接は生成されない。

例として、小円を含む同心円、中央段と上下段をまたぎ小さい円の中心が大きい円の円周に乗る配置がある。大円と小円が同心の場合は、小円の中心に線を入れられないため、大円の円周外の終端斜線で条件を満たせる。中円と小円が同心の場合は、中心に線を入れない形が許容される。逆に大きい円の中心を小さい円の円周へ置くことで、内側に偏った円を許可することはしない。

この一覧は、すでに語義を持つ文字表ではない。離れている円の無限の距離、線の全組合せ、三つ以上の独立した円の合成を列挙したものでもない。「このページに出ていない」「生成器に候補がない」「規則が禁止している」を分けるための資料である。

## 次に接続する意味・構文の依存群

文頭、引数、引用、共有、束縛を一つの依存群として組む。既存の語義・定義・参照先を使い、一文ごとのprimitiveを追加しない。次の対応は設計候補であり、まだ言語の確定規則ではない。

| 見える構造 | 接続する情報 | 一意性のために必要な条件 |
| --- | --- | --- |
| 最初の意味要素とその接続 | 文頭の構文種別 | 通常主張に共通ヘッダーを付けない。結合・引用引数・関数参照・評価の差を元のopening_formから引き継ぎ、語の識別と衝突しないようにする。 |
| 主な連なりと非対称の横枝 | 引数の役割と順序 | 横枝へ出す位置を公開規則で固定する。たとえば引数列の中央位置が終端項ならそこを横枝とし、それ以外は連なりに残す。元の「終端候補の中央」は、見えない構文を先に知る必要があるため、そのまま復号規則にはできない。 |
| 同心の円 | 作用範囲を導入する要素と内部の要素 | 最大二円を守り、引用・束縛等の構文を区別できる接続条件を用意する。すべての範囲を同じ同心円一種類に割り当てない。 |
| 中心と円周の重なり | 同じ内容・参照先を共有する二つの役割 | 共有する対象と参照範囲を公開文法で決める。生成器の辞書順位やfused_pathsを要求しない。 |
| 二円の接触 | 一つの引数を直接付ける、または型の合う項を局所的に結合する操作 | 接触の相手は一つだけ。線が両円に触れる場合は両中心を通る向きに限る。元の構文へ戻せる局所合成にする。 |
| 円周で止まる線、中心まで入る線 | 語の構成要素・引数の適用状態 | 内部線と外部線を別の描画要素として区別しない。実際の接続先を含めた図形の状態を使う。 |
| 一意に回収した不可視接続 | 引用等の境界 | 引用頭を識別した後、一つの完結した式として範囲を読む。空白だけから引用だと決めない。 |
| 短い従属項と局所的な共有 | 変数の使用 | 最寄りの適合する束縛を基本に、外側・別引数を参照する場合を見える形で区別する。引用内では外の束縛を引き継がない。 |

向きや上下位置を、語の識別と配置の自由度の両方へ無条件に使うと再び衝突する。同じ語の異体を許す範囲と、意味を区別する形の差を公開表で分離する。幾何配置はその範囲内で元の重心補償と衝突回避を使う。許容形の未使用をなくすために乱数や文番号で形を割り当てない。

検証は、語の衝突対照、二・三引数の順序、引用の内外、内外の束縛、共有前後の構文を最初の対象にする。まず一群を逆変換できる形で接続し、その後に構文種を広げる。元の二作品の意味確認を再実行する工程ではない。

## 現段階の再現

調査ページは output/kant-generator-analysis/index.html。元の通常文六例と、カントの五種類の文頭を元生成器で再生成し、カントは保存済みの図形と一致することを確認する。二円配置の一覧もここに置く。

観測層は、公開された32単位の罫線と円サイズで表された、一文の折り返し前の図形を扱う。任意倍率の校正、改行・改頁、完全な語・構文の復元はまだこの層に含めていない。新案の完成や見た目の承認を求める段階ではない。

```powershell
python -X utf8 -m scripts.project_work check --module scripts.check_kant_geometry_reader --tests tests/test_kant_geometry_reader.py --prepare --verify reports/kant-observable-geometry-v1.json
```
