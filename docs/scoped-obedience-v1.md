# 要求の出所・範囲と履行による服従内容

前段の引用作例では、服従の成否を `jdobeys` という一つの入力で渡していた。今回の[後続作例](../examples/v016/scoped-obedience-example.noema)ではその入力を除き、要求の記録、記録の網羅性、記述された行為の履行から指令内容を構成する。許可側の定義は保持し、服従を許可の成立条件へ付け加えてはいない。

ここで説明するのは、指定した出所からの要求への全面的な適合である。要求されたから従うという意図、権威の正当性、心理的な服従まで同じ条件で定義したものではない。

## 誰の要求を、どの状況で満たすか

`rtw` は既存の要求検査 `rpl` と履行検査 `rpm` を使う。同じ出所・受け手・基準文脈について、一覧の各項目が、指定した役割・活動・行為記述・肯否への要求であることを確かめる。そのうえで、同じ記述を同じ受け手と活動に適用し、評価状況で要求の肯否と一致することを求める。

例えば、ある行為の実行と別の行為の不実行を要求された場合、前者を行い、後者を行わない状況だけが両要求を満たす。要求が存在すること、現在満たしていること、後の状況で満たしていることを別々に記述できる。後の状況で要求が新設・免除されたという別の規範へ、評価中の要求をすり替えない。

要求の出所は共通の引数に固定する。同じ人の行為であっても、別の出所、別の役割、別の記述、別の基準文脈の要求を使って一致を補うことはできない。真偽が同じ別名の記述も、自動では同じ要求と扱わない。

## 一覧から要求を消しても網羅したことにしない

`rtx` は、同じ出所・受け手・基準文脈について、指定役割範囲の全活動・全ての型に合う行為記述・両極性の要求が、一覧の項目として存在することを要求する。別の出所や範囲外の役割の要求を混ぜない。

`rty` は網羅性と、一覧の妥当性・履行を合わせた内容である。空の一覧は、それだけなら一覧項目への適合を満たすが、範囲内に未記載の要求があれば `rtx` を満たさない。要求が存在しない範囲でだけ、空一覧を完全なものとして扱える。

同じ行為記述の実行と不実行の両方が要求される場合、両方を記録して網羅性を満たすことはできる。しかし、同じ状況で両要求を履行することはできない。この矛盾を解消する優先順位・例外・正当性の規則は加えていない。

## 指令を引用する際に履行を要求しない

`rtz` は、`rty` の各引数の閉じた記述から、内容の閉じた記述を構成する。作例ではこれを既存 `rtv` の二番目の指令へ渡す。命令の実行や、網羅性を判定するための全記述域の列挙は、引用の構成時には行わない。

したがって、要求の有無や実行の状況が未知でも、何を指令するかを記述し、引用として保持できる。引用された指令を理解可能な式にすることと、実際に命令が守られたと判断することは分かれる。

## 検証した範囲

[定義文書](../examples/v016/scoped-obedience.noema)は6宣言・本文0文で、既存の2定義と新しい4定義からなる。新しい原始関係や文法演算子は加えていない。後続作例は44宣言・6質問である。

108テストが通過した。二つの要求の有無、二つの行為の現在と後の成否を変える64組合せで、引用と現在の適合、後の適合を区別した。要求の各参照の取り違え、一覧にない要求、対象外の出所や役割、空一覧、矛盾する要求も検査した。許可側の既存定義と再利用した要求・履行定義が変わっていないことを確認した。

全行為記述への量化はNoema本文に残している。有限評価器による直接評価は拒否される。診断用の複製では記述の量化だけを三つの閉じた記述に限定し、一覧の網羅性と履行の組合せを検査した。これは全記述域の網羅性を証明した結果ではない。二つの定義が同じ真偽を返しても、別名の要求を未記載のまま満たしたことにしない例を含む。

長形式・短縮形式・固有文字の往復、文書と検査記録の再現、二文書のCLI解析、作例のSVGのXML検査も通過した。SVGの目視検査は行っていない。
