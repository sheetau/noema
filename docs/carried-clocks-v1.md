# 動く時計の指示と、その場所の静止系時刻

アインシュタイン§2の `u0035` をNoemaへ部分接続した。棒の両端へ時計を取り付け、それぞれの指示を現在位置の静止系時刻へ一致させる思考上の設定を記述する。時計が静止系に対して静止していることとは区別した。

## 動く時計の場所を出来事ごとに指定する

既存の `qt` は、その場所に静止する局所時計と共通の参照時計によって出来事の時刻を付与する。そのまま棒と共に動く時計へ適用すると、動く時計にも静止を要求してしまう。

新しい `sct` は、時計が指定出来事でその場所にあることと、同じ出来事・基準系・時間単位での読みを結ぶ。時計の静止は要求しない。`scu` は二つの読みの記録と値の一致をまとめる。

`scv` では、棒端点と取り付けた時計の現在位置を同じ出来事へ結び、時計自身の読みと、そこに静止する局所時計による `qt` の時刻を比較する。静止時計だけが参照時計との同期条件を満たせばよい。動く時計を局所時計や静止する参照時計と同じ対象にすることは許さない。

## 移動に伴って比較先が変わる

`scw` は、一つの時計について非空かつ完全と指定した全照合記録へ `scv` を適用する。時計と取り付け先の端点は同じだが、出来事・現在位置・その場所の局所時計は記録ごとに変えられる。移動後にも最初の場所の時計を比較先として使う条件にはしない。

`scz` は、同じ棒の異なる二端点へ異なる時計を結び、両方の全記録にこの条件を要求する。両端の記録を勝手に同時刻とは決めない。`scy` で先行する棒の運動設定と、実切断の有効性・値の一致・静止時計の同期へ接続した。

この設定を先行する棒の想定へ追加する関係と、条件 `scx` を満たす時計を「静止系において同期している」と呼ぶ規約も記述した。いずれも著者への帰属であり、引用する際に物理内容を実行しない。

ここで述べるのは、動く時計の表示を静止系の時刻と一致させる思考上の条件である。補正していない移動時計が自然にその表示を保つという法則や、調整の機構は含まない。また、離れた二つの移動時計に光往復の中点条件を適用して得る判定とは分ける。後者は続く原文の課題として残す。

## 検証と残る課題

新規7件を含む関連33テストが通過した。読みの結合64組合せ、原文接続29例、追加想定と呼び方の帰属7例を検査した。基準モデルでは両端の時計がそれぞれ二地点へ移動し、比較先も別の静止時計へ変わる。動く時計は静止時計の集合に含めていない。

途中の表示のずれ、誤った指示の記録、別の出来事や場所、古い場所の時計、同期していない局所時計、同じ時計や端点の二重使用、別の棒への取り付け、片方の記録の欠落を拒否した。両端で別々の時刻の照合記録を持つ場合は成立する。

全記録の完全性は明示的な前提である。記録を減らしただけでは、実際の全時刻で一致した根拠にならない。有限検査では実数の有効性・値の一致・静止時計の同期を、作成した整数の切断と明示的な関係に限る判定で与えた。実切断全域の条件を有限標本で代用する評価は拒否する。連続する全時刻の物理モデルや自然な時計の進みを検証したという意味ではない。

標準表記・圧縮表記・固有文字の構文往復、CLIのJSONと構文木の一致、SVGのXMLとしての妥当性、入力ハッシュと検証記録の再現、進捗集計の整合性を確認した。SVGの目視確認と全テストの再実行は今回の検証に含めていない。
