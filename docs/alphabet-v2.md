# 文字版2：文法上の働きから字形を構成する

文字版2は、文法標識としての働きが近い文字に、共通の骨格を持たせる。時間方向の違い、役割の接続、状態変化への使役の追加を字形の部分に対応させた。32文字という個数は試作上の既定値を維持し、概念ごとに新しい文字を作る方式にはしていない。

このページは旧32文字の互換仕様です。現行の円と線の字体は[固定した書記体系](writing-system.md)を参照してください。旧構成表SVGは作業場所から整理済みです。以下の白・青の説明は当時の構成表についての記録です。

白が共通骨格、青が機能を区別する線である。文章では単色でも読めるよう、色を意味の区別には使わない。図中の英数字は入力用の別名であり、字形の設計元となる英語の文字や単語ではない。

## 構成の規則

| 群 | 共通部分と区別 |
|---|---|
| 役割 | 対象を示す菱形を共有する。接続の向き・位置・支えを区別し、場所・出発地・到着地には上下の空間枠を加える。 |
| 時間 | 基準点のある横線を共有する。過去は左、未来は右、現在は中央。昨日・今日・明日は対応する方向の字形に日単位の印を加える。 |
| 対象の指定・参照 | 上が開いた囲いを共有する。数量・名前・参照の登録・参照の使用を内部の線で区別する。 |
| 論理・作用範囲 | 両側の括りを共有する。否定、両方、少なくとも一方、条件を内側の線で区別する。 |
| 発話・未確定 | 上部でつながる囲いを共有する。質問、尋ねる役割、依頼、肯否未指定を区別する。 |
| 状態の変化 | 状態を移る段差と矢印を共有する。使役変化には、外から変化へ入る線を追加する。 |
| 補助の3字 | 共通の折れた線に区別線を加える。現在の文語0.5には、これらに対応する単独の文法標識を割り当てていない。語根・数量・参照名の綴りに使う。 |

手書きでは共通骨格を先に書き、区別線を加える順を基本とする。各線の形と接続はSVG資源に固定している。筆圧や丸め方による変形をどこまで許せるか、実際の筆記速度や混同率はまだ測っていない。

これらの対応は、文字を**文法標識として使う位置**に適用する。例えば `i` が役割の位置にあれば主体を表すが、基本語 `sai` の最後の文字には主体という意味を追加しない。数量や参照名も同様である。字形の構成だけから、未知の基本語の意味を復元できるとはしない。

状態からの語形成は[文語0.5](writing-v05.md)の規則を使う。`5-sam` と `6-sam` は状態語を共有し、先頭の字形でも変化と使役変化の共通部分が見える。意味の規則と見た目の構成を対応させた部分であり、基本語全体の合理的な分解は引き続き設計課題である。

## 文字版と文法版の独立

文法は0.1〜0.5、文字はv1・v2として別々に管理する。文字版を変えても、意味・役割・参照・数量・引用された名前は変わらない。

| 表記 | 符号位置 | 読込み |
|---|---|---|
| 代用表記 | `a–z, 2–7` と構造記号 | 継続して対応 |
| 旧字形v1 | U+E000〜U+E01F | 継続して対応 |
| 新字形v2 | U+E100〜U+E11F | 新たに対応 |

符号位置は私用領域であり、UnicodeでNoemaが標準化されたという意味ではない。配布するTrueTypeフォントに新旧両方の字形を含め、旧文字を別の形で上書きしない。フォントがない環境へ渡す場合は、代用表記か字形を内蔵するSVGを使える。

画面とCLIはv2を表示する。Pythonの既存の `encode()`・`render()` は互換性のため既定値をv1に保ち、`alphabet="v2"` で新字形を指定する。読込みは両方に対応する。混在入力も意味を保って正規化できるが、引用文字列内の字形・英数字・エスケープは変換しない。

```powershell
python -m noema script --input examples/state-change.noema --alphabet v2
python -m noema render --input examples/state-change.noema --alphabet v2 --output artifacts/state-change-v2.svg
python -m noema alphabet --alphabet v2 --output artifacts/alphabet-v2.svg
python -m noema script --input examples/state-change.noema --alphabet v1
```

## 描画で分かった限界

16・24・36pxで通常表示と0.6pxのぼかしをかけた計6条件を比較した。どの条件でも32文字は異なる画素集合になり、文字の欠けもなかった。最初の試作では16px・ぼかしありの「主体／到着地」「対象／出発地」の重なりが93.75%あり、方向の違いだけでは区別が弱かった。空間枠を追加した後、最も近い組の重なりは84.31%になった。

一方、同条件の旧字形では最大71.43%だった。新字形は文法の関係を共通の形で示せる分、似た形の組が増えている。画素の区別がつくことから、人が誤読しないとは結論しない。文字の記憶、単語としての読み取り、手書き、長い文章での負担を利用者の確認で測る必要がある。

旧試作の定義と結果は[最初の試作記録](../reports/alphabet-v2-prototype-1.json)、新旧を同条件で測った結果は[描画比較](../reports/alphabet-v2-proof.json)に残した。これは改良時の形の比較に使う資料で、言語理解や人の認識精度の成績には数えない。

## 学習記録と再現

練習画面は新字形を使い、結果に文字版・字形定義のハッシュ・フォントのハッシュを保存する。同じ問題でも字形が違えば読みやすさの条件が変わるため、問題の版だけで結果をまとめない。既存の練習は文語0.4の内容であり、状態変化の理解の評価は0.5の練習と分ける。

字形は `scripts/build_alphabet_v2.py` の共通部品と機能線から構成し、`alphabet-v2.json` に定義を保存する。フォントは `scripts/build_font.py`、図と描画比較は `scripts/proof_alphabet_v2.py` で再作成できる。フォントのビルド結果のバイト一致、新旧の文字を通した意味の往復、ブラウザー上の変換を検査している。生成モデルやプロンプトを使う処理は追加していない。
