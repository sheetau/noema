# 物と人の対応を保った足枷の比喩

カント第三段落の足枷の描写を、規定・定型表現とその利用者、拘束する物体とその被拘束者、という二つの位置を持つ関係として記述した。前後で同じ位置の対象を保持し、実際に物理的な足枷を装着しているという主張とは区別する。

原文の対象語は[電子本文の AA VIII 36、10行](https://korpora.org/kant/aa08/036.html)で確認した。固定本文と電子本文の比較であり、原刊画像の照合ではない。道具の使用が依存状態の持続に関わるという読みを明示して構成したが、唯一の解釈や原文全体の意味一致を確定したものではない。

## 関係の位置を保つ

`rbt` は、個体の列を引数とする二つの内容記述を、非字義的な描写として結ぶ関係である。同じ列を双方へ渡し、対応する位置が同じ対象を指す。`rbu` は二つの記述が異なることも要求する。対象側・描写側の内容を評価して真にする条件はない。

列を使うため、参加者数ごとに別の比喩関係を増やさず、各記述の定義で必要な位置と役割を決められる。今回の接続用の `rbv` は二項関係を列引数へ変換する。長さを厳密に二つとし、0番目を第一、1番目を第二の引数へ渡す。欠けた要素や余分な要素は拒否し、順序を入れ替えない。同じ個体が二つの役割に入ることは、型だけでは禁止しない。

| 位置 | 対象側 `h2a` | 描写側 `h2b` |
| --- | --- | --- |
| 0 | 使用される規定・定型表現 | 足側を拘束する物体 |
| 1 | その利用者 | その物体に拘束される人 |

これは個体の役割を並べる接続であり、あらゆる型の引数を個体へ読み替えるものではない。対応関係を与えただけで比喩の評価的な効果や全含意を判定できるわけでもない。

## 描写側の身体拘束

`rbx` と、その原文側の接続 `h2j` は、同じ人の足または足首側の部位に同じ物体が留められ、その部位への固定で、本人の身体運動の少なくとも一つが制限されることを要求する。制限のない場合に可能だった運動と比較し、背景は固定する。

別の人の部位、別の物体、別の運動の制限を混ぜない。物体が近くにあるだけ、身体を支えるだけ、元からその運動ができないだけでは、この条件は満たされない。全く移動できないこと、脱出の試み、恐怖、許可の有無も補わない。

身体部位の分類、固定、制限なしの場合の運動可能性、物理的な制限自体は明示的な意味規約を持つ基本関係である。歴史的な足枷の全形態、材質・施錠・設計目的や、運動の物理的な基礎までを構成し終えたとはしない。

## 対象側の使用と持続

`h26` は、本人について選んだ残る生涯の範囲が、履歴内の非空で途中を省かない区間であり、基準時を含み、その全点で既存の依存状態 `bf` が続くことを表す。全点を基準時以降に限定し、使用より前の状態までその使用の結果としない。

`h27` は既存の規定 `hd2` または定型表現 `h22` に該当するものを表す。`h2i` は、その同じものを本人が用いる生起する活動が、本人について `h26` の状態を生じさせ、その状態も成立することを要求する。既存の結果生成の構成 `raa` と基本関係 `g3` を再利用し、単なる同時成立から因果を導かない。

これは指定範囲内の持続である。範囲外で状態が変わることは許す。「無期限に続く」という強さを有限の範囲から推定せず、原文の持続を強める修飾部は、今回の対応範囲に加えていない。範囲を過不足なく選べたか、因果関係の根拠があるかは、別の意味確認を要する。

`h2c` を追加した本文の主張とした。これは著者による関係的な比喩の帰属一件であり、`h2i` や `h2j` の現実の成立を断言するものではない。既存の全宣言と10主張は保持した。

## 検証と残る作業

位置・列長の6例と、同一個体が二役を占める例を検査した。身体拘束の16条件と15の取り違え、持続の10例、談話箇所・著者・向き・文脈の7例も検査した。対象内容・描写内容・比喩帰属を変えた8例では、それぞれを独立に扱えることを確認した。

持続の検査では、途中だけ状態が途切れる場合、範囲の中間を省く場合、基準時を欠く場合、別の人の範囲を使う場合、過去まで範囲に入れる場合を区別した。範囲外で状態が変わっても、範囲内の持続は成立できることも確認した。これらの有限モデルを、現実の時間全体の検証とは扱わない。

比喩帰属の検査では、内容に関する基本関係を実行すると失敗する解釈を使い、引用内容を実行していないことを確認した。規定・定型句の一般分類 `h27` は式記述への量化を含むため、有限検査器は評価を拒否する。その一般分類や因果的な対象関係全体を有限モデルで検証したとはしていない。

関連33テストが通過した。検証記録の再生成一致、通常・短縮記法と固有文字の往復、CLIのJSONと構文木の一致、SVGのXML形式を確認した。今回、字形の目視確認は行っていない。
