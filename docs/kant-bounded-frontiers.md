# 接続元を長く待たせない配置

枝の内部を優先して置くと、主列の次の円を置くまでに長い枝全体が並ぶことがある。その場合、親円から主列へ戻る線は枝全体を迂回する。一枝にも共通の線を使う規則で短くできる例は増えたが、枝をすべて先に置く順序では大きな上方への張り出しが残った。

まず従来どおり内側の枝を優先して配置する。線が三段の外へ二段間隔を超えて張り出す場合に限り、接続元を長く待たせない別の順序を試す。その順序では、未完の経路の接続元と配置済みの右端の間に大円二個とそれぞれの最小間隔が入る距離ができたら、最も古い接続元の続きを先に置く。判定距離は `2 × (2 × LARGE + MIN_GAP)` とする。これは配置の選択基準であり、意味、引数順、受理する言語を変える制約ではない。

枝の最初の円を先に置く順序と、語内の連続配置は優先する。これらを途中で中断して距離条件を適用しない。別の順序を採用するのは、図形の張り出しが実際に減った場合だけとし、減らない場合や配置に失敗した場合は従来の図形を保持する。従来の順序で配置できない場合にも別の順序を試し、両方とも置けない場合に限って既存の枝数調整へ進む。復号結果を見て配置を差し替える処理は設けない。

読取器、字形、幾何制約は変更しない。新旧SVGから元構文を回収し、円数と枝数を照合する。三段の外への張り出し、幅、線の総延長は別に測る。大きな迂回を分けると線の総延長や幅が増えることもあるため、張り出しの減少だけで外観完成とは判断しない。

検査用の再描画は影響範囲に絞る。通常の配置順で成功し、追加の経路探索を使わなかった例には、新しい順序条件が適用されない。また、すべての枝が一語または一個の核だけなら、強制された入口・語内の配置が終わるたびにその枝も完了する。主列は最後の枝の入口を待つため、自由に選ぶ時点で競合する未完の枝がない。この場合も配置順は変わらない。保存時から変更された依存ファイルが配置器だけであること、元構文と語の分解が同じであることを確認してSVGを再利用する。一つの小さな対照例は実際に描き直し、同じSVGになることも確認する。
