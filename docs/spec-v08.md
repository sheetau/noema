# 文語0.8：文書内の定義と一般量化

0.8は、固定された概念IDを増やさずに、新しい述語・関係・関数・定数を文書内で定義する版である。文書は`h:`または`noema h h`で始まる。名詞は「その種類である」という1引数の述語として定義でき、関係は複数引数の述語になる。定義には他の定義を使える。

この版は論文を記述するための基盤であり、論文全文を表現済みではない。0.7の出来事・役割の記法を暗黙に解釈し直さず、独立した文書スキーマにする。0.1〜0.7は既存の解析器で引き続き読める。相互変換は未実装で、旧文書を0.8へ変換済みとはしない。

## 型と意味の前提

| 型文字 | 意味 | 意味JSON |
| --- | --- | --- |
| `a` | 個体・対象。非空の領域。物体に限らず、文書で扱う抽象的対象も含められる | `individual` |
| `b` | 有理数。分子は整数、分母は正整数 | `number` |
| `c` | 真理値。真と偽の二値 | `truth` |

述語は真理値を返す関数として扱う。宣言された関数は、指定された引数領域上で値が一意に定まる全域関数とする。不定・未定義・部分関数を勝手に補完する意味はない。部分性を表すには定義域の条件や関係を別に述べる必要があり、そのための短い記法は後続課題である。

基本記号の具体的な解釈は、言語の基礎概念の意味規約または文書の前提として必要になる。型が正しいことは、その解釈が与えられたことや、主張が事実として正しいことを保証しない。

## 宣言と定義

```text
r 語 [ 引数型 ... ] 結果型 .
d 語 [ 変項 型 ... ] 結果型 [ 本体 ] .
```

`r`は基本記号の型宣言で、意味の説明ではない。`d`は本体を持つ定義である。文書中で同じ語を再定義できず、定義は先に導入した語だけを使える。自己参照、相互循環、後方の定義への参照は拒否する。定義を有限回展開すれば、その文書の基本記号と論理演算へ戻る。

定義のパラメーターは本体だけで有効で、同じ定義内のパラメーター名は重複できない。引数が0個なら定数を定義できる。意味JSONでは宣言と定義をそれぞれ`kind: primitive`、`kind: definition`とする。

定義は略記の導入であり、対象の存在を主張しない。「条件Pを満たす対象をNと呼ぶ」と定義しても、Nが存在するという命題は自動追加しない。存在は別の式で述べる。

## 式

| 記法 | 意味 |
| --- | --- |
| `v 名前` | 束縛された変項 |
| `k 語 [ 式 ... ]` | 宣言または定義した語の適用 |
| `n p 分子 分母` | 非負の有理数 |
| `n u 分子 分母` | 負の有理数。分子の字面は絶対値 |
| `e [式][式]` | 同じ型の値の同一性 |
| `u [命題]` | 否定 |
| `w [命題][命題]` | 論理積 |
| `x [命題][命題]` | 包含的論理和 |
| `y [命題][命題]` | 実質含意 |
| `z [命題][命題]` | 同値 |
| `f 変項 型 [命題]` | その型の領域全体に対する全称量化 |
| `g 変項 型 [命題]` | その型の領域に対する存在量化 |

数の字面は従来と同じ32進法で、`a=0`、`b=1`、`c=2`。例えば`n u b c`は−1/2である。正規化は約分し、負のゼロを0へ統一する。分母0、先頭ゼロのある多桁表記、浮動小数点数は受け付けない。非常に大きな整数でも丸めない。

`k`の角括弧は引数列全体を囲む。論理演算の角括弧は各オペランドを個別に囲む。各式の開始文字から読み方が決まるため、引数列にカンマは不要である。

実質含意は、前件が偽または後件が真なら真になる。因果・反事実・時間的な前後を意味しない。`c`は真理値であり、引用された命題の内容や「ある人が信じること」を表す内包的な対象ではない。これらを二値論理で同一視して省略することはせず、後続の拡張として扱う。

## 量化の順序と局所性

```noema
h:
r aa[a a] c.
s[f x a[g y a[k aa[v x v y]]]].
```

各xに対して、それぞれaa(x,y)を満たすyが存在する。次の式とは異なる。

```noema
h:
r aa[a a] c.
s[g y a[f x a[k aa[v x v y]]]].
```

こちらは、すべてのxについてaa(x,y)を満たす共通のyが存在する。例えば対象領域が2要素でaaを同一性と解釈すると、前者は真、後者は偽になる。

変項は最も内側の同名束縛に対応する。内側の量化を終えると外側の束縛へ戻る。自由変項、量化の外へ持ち出した変項、型の異なる適用は拒否する。正規化では束縛名を順に変更するが、束縛の参照先と量化の順序は保持する。定義された語そのものの綴りは変更しない。

## 発話と具体例

`s [命題].`は主張、`q [命題].`はその命題の真偽を問う質問である。質問を主張へ変換しない。宣言・定義を全て先に置き、その後に発話を並べる。

[実行可能な例](../examples/v08/definitions.noema)では、例の解釈として`aa(x)`を「xは人」、`ab(x,y)`を「xはyに依存する」とする。この2語は今回まだ基礎概念として確立したものではなく、型宣言だけの例示用記号である。

- `ba(x)`は「xは人であり、x自身とは異なる依存先が存在する」と定義する。
- `bb(x,y)`は「xがyに依存し、yがxに依存する」と定義する。
- `ba(x)`を満たす人には依存先が存在すると主張し、相互依存する対象の組があるかを質問する。

「依存する人」という語を個別の組込み概念へ追加せず、変項・関係・同一性・否定・存在量化の組合せで定義している。一方、依存の社会的意味や文化固有の概念を説明し終えた例ではない。実際の論文では、使用する基本記号の意味規約と、より細かな定義が必要になる。

## 実装と検査

`noema.discourse.definition_audit(document)`は、基本記号の一覧と、各定義・発話が最終的に依存する基本記号を返す。説明されていない基本記号を隠すための監査ではなく、未説明の依存を明示するための機能である。

```powershell
python -m noema parse --input examples/v08/definitions.noema
python -m noema script --input examples/v08/definitions.noema --alphabet v2
python -m noema render --input examples/v08/definitions.noema --alphabet v2 --output artifacts/definitions-v08.svg
```

解析・意味JSONの整形・固有文字との往復・SVG表示に接続した。自然言語の翻訳器には接続していない。0.8の文書編集用GUIと旧版からの意味変換も、この段階では未実装である。

検査は、定義の展開との一致を2要素領域の全16通りの二項関係で確認する。量化順序・否定・変項の隠蔽・束縛名変更・型違反・循環・未定義語・分数の約分・大整数・過剰フィールド・深さ制限・固有文字の往復を対象とする。有限の解釈による検査は一般の定理証明でも、論文の意味一致の保証でもない。

この版には、文書内の概念定義と一般量化を導入した。実数・極限・微分などの数学理論、物理量と単位、時制と時刻の関係、命題内容への態度、規範と可能性、仮定の局所範囲、談話上の論証関係を含む言語体系は、引き続き設計・実装が必要である。
