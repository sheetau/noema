# 意味の表現幅を保つ共通規則

この仕様は、Noemaの意味としての表現力を完成させるための補強である。実際の会話や読解で生じる心理的効果、読みやすさ、韻律の効果は完成条件に含めない。[共通仕様](general-language-v1.md)の36分野と既存の二作品を保ち、意味の組合せで区別が失われない規則を加える。

新しい構文・基本型・基本宣言・字体は追加しない。既存の型、量化、関数、引用、列から43定義を構成する。[定義と型・役割](../data/semantic-boundaries-basis-v1.json)、[Noema本文](../examples/v016/semantic-boundaries-v1.noema)、[追加辞書と例](../output/semantic-boundaries-v1/index.html)を参照する。統合カタログは[第2版](../data/general-language-catalog-v2.json)で、旧1,909項目の意味・型・綴りをそのまま保持する。

## 何を表現できればよいか

内容を表現できることと、その内容の真偽や値を計算できることは別である。「この条件を満たす数が存在する」と記述する際に、その数を計算済みである必要はない。「この文は偽だ」を記述する際にも、必ず真か偽かを決定する必要はない。未解決の参照や相反する資料を記録した内容を、偽へ置き換えてはならない。

表現幅の判断では、次の構成を任意の適格な型と必要な引数数へ広げられることを基準にする。

- 対象・出来事・数・状況・性質・関係を結び、同一性、否定、論理結合、量化の範囲を保持する。
- 内容そのもの、誰かに帰属する内容、その表し方、引用や仮定の範囲を区別する。
- 関数、列、記述を引数に渡し、定義した概念を別の定義や文の中で再利用する。
- 未定義、不存在、情報不足、複数候補、相反する根拠を明示して保存する。
- 反復や循環を関係・制約として記述し、計算や解決を記述の成立条件にしない。

有限長の文書は有限の構文からなるが、内容が有限の対象だけに制限されるわけではない。例えば全ての数についての量化、数から値を返す関数による列や過程、関数や関係についての量化を記述できる。実行器が無限領域の量化を拒否することは、その量化を有限の標本に置き換えてよいという規則ではない。

この構成原理と、確認した意味の区別を合わせ、明示的な意味を表すという完成条件に必要な基盤を満たすと判断する。あらゆる自然言語の文を列挙した証明や、任意の意味の同値性を自動判定する仕組みを、この判断の条件にはしない。

## 対象、記述、実在を分ける

個体として参照できることだけでは、現実に実在すると認めたことにならない。構想中の家、仮定上の物体、物語中の人物を指す場合は、その枠と実在条件を明示する。実在は同じ状況に関する関係として別に記述する。

`actualtargetwitness` は、記述された性質と同じ状況での実在を共に満たす対象である。`actualtargetexists` はその対象の存在を述べる。設計や信念に対象の記述が現れただけでは、これらの条件は成立しない。

| 表したい内容 | 構成上の区別 |
| --- | --- |
| まだ存在しない家を設計する | 設計の対象となる性質・構成の記述を保持し、現実の実在条件を要求しない |
| 誰でもよいから医師を探す | 目的内容の内部で医師の存在を求める。特定の対象を外側で固定しない |
| 特定の人を探す | 外側で固定した対象を目的内容の引数として保持する |
| その人が医師だとは知らない | 対象の同一性と、その性質に関する信念・認識を別に帰属させる |
| 状況ごとに条件を満たす人がいる | 状況の量化の内側で対象を選ぶ |
| どの状況でも条件を満たす同じ人がいる | 対象を先に選び、その同じ対象について状況を量化する |

同じ対象を指す二つの名前があっても、引用された二つの記述は同じとは限らない。`anchoredcontent` は内容関数の記述と対象記述から構文を組み立てるため、名前による捉え方を保持できる。確認例では、二つの名前の指示先と内容の真偽は同じでも、一方の記述についてだけ信念を持つ状態を表せる。

名前のない対象を量化した場合は、引用の中へ自由変数を入れない。`boundcontent…` に、閉じた内容関数の記述と型付きの引数値を組として保存する。対象の値として渡す場合と、対象を指す記述を渡す場合を区別する。任意の有限な型列に同じ構成を適用でき、公開例は個体一つと、個体・数の組を持つ。

組の作成と照合は、内容の評価を含まない。`boundcontentholds…` で初めて、保存した関数に同じ引数値を適用し、指定状況で内容を評価する。引数の型・順序を保持し、別人・別の値・別の関数記述へ交換しない。

## 値がないことと、情報がないこと

値を扱う際には、適用条件、候補の条件、候補範囲が完全であるという保証を分ける。保証を与えていないことから、範囲が実際に不完全だとも、対象値が存在しないとも結論しない。

| 状態 | 例 | 保持する内容 |
| --- | --- | --- |
| 適用条件が成立しない | 分母0の通常の除算、存在しない人物の年齢 | 適用条件の不成立。代わりの数値を埋めない |
| 適用できるが値がない | 指定範囲に条件を満たす解がない | 適用可能・範囲が完全・候補なし |
| 値が未確認 | 人物はいるが年齢不明 | 情報の取得や候補範囲の保証が未完。空の候補列でも不存在とはしない |
| 複数候補がある | 年齢は20歳か21歳 | 候補が複数。どちらかを勝手に選ばない |
| 資料が衝突する | 同じ時点の年齢を、一方は20歳、他方は21歳と断定 | 出所ごとの断定と、同じ項目・状況での値の一意性 |

`uniquevalue…` と `missingvalue…` は、適用条件と完全性を前提に、型全体に対する候補関係から唯一値または候補の不在を述べる。これらの否定は、その前提を含む判定の不成立であり、「実際に値が複数ある」などの強い主張へ置き換えない。

有限列が適切な場合は `listeduniquevalue…`、`listedmissingvalue…`、`listedalternativevalues…` を使う。重複は別候補を増やさない。列が完全であるという保証は別途必要であり、有限列を連続的な候補範囲の代用にはしない。

これらは型を変えて同じ式から構成できる。公開した特殊化は個体・数・内容記述で、列、内容、関数の型への特殊化も型検査した。型全体を量化する仕様と、実行可能な有限列用の手順を分けている。既存の `rationaldivisionorzero` は明示的な補助関数の規約を保持し、その戻り値を通常の除算が定義されたことの証拠にはしない。

適用条件そのものが未確認なら、その条件についての情報状態を別に保存する。未確認の条件を真や偽に補って、値の判定へ進めない。

## 相反する情報を保存する

`reportedsupport` は、指定した出所が同じ内容記述について支持を記録していることを表す。肯定・否定の支持を別々に集めることで、肯定のみ、否定のみ、両方、どちらもない、の四状態を表せる。四状態は根拠の状態であり、新しい四値の真理体系へ言語全体を変更するものではない。

肯定と否定の支持が同時にあることは、内容とその否定を同時に真と断定することではない。未知の支持関係を偽に補わない。出所の範囲を限定した場合、その外にも支持がないとは結論しない。

異なる値を述べる資料には `valueconflict…` を使える。同じ項目・同じ状況が高々一つの値を持つという条件と、各出所の断定を結ぶ。「話せる言語」のように複数値を許す性質では、異なる二値の報告だけで矛盾としない。候補が複数あることと、互いに両立しない断定があることも別である。

信念についても、非空の候補状況を使う `beliefaccepted` は一つの明示された読みであり、全ての信念の必須定義ではない。矛盾した信念や、同じ真偽でも片方の表し方だけを受け入れる状態には、記述を保つ `nonfactivecontentbelief` を使える。その場合、信じている内容を脱引用して事実にしたり、全ての論理的帰結を本人の信念として追加したりしない。

## 説明した意味と、解釈入力の境界

新語や新しい読みを導入するときは、次の順で意味を説明する。

1. 必要な対象・状況・引数の役割と型を列挙する。
2. 既存の概念から構成できる内容をNoemaの定義として書く。
3. 残る経験的関係や文化的規約について、何を認め、何を認めないか、どの文脈で判断するかを説明する。
4. 結論が同じになるよう入力を選んでいないか、別の対象・順序・時点・記述へ交換すると意味が変わるかを確認する。

例えば「この人は二つの集団を結ぶ橋だ」の特徴対応を使う場合、源の意味には異なる二地点の間を結ぶ物理的な経路、先の意味には異なる二集団の間の情報伝達の仲介を置ける。双方の内容関数、対象、対応させる関係を示す。人が物理的な橋であることや、橋の全ての性質が人に当てはまることは加えない。

`readingconstruction` は、字義と意図した内容の両方が、明示した関数記述と対象記述から実際に構成されたことを確認する。関数の内容も公開例では定義として示し、異なる二つの端点とその接続を構成する。物理的な接続と情報伝達という基本関係の解釈、特徴対応をこの出現で採用する根拠は別に保持する。

「適切な比喩である」という一つの判定を渡すだけでは、具体的な読みを説明したことにしない。一方、経験的な関係が解釈入力として残ること自体を言語の表現不足とはしない。どの言語でも基本的な語の意味を全て循環なく別の語だけで説明することを要求すると、説明の開始点がなくなる。Noemaでは、その開始点と、そこから合成した部分を区別する。

## 反復する関係と循環する内容

`relationreachable` は、与えた辺を全て含む任意の推移的関係において、始点から終点へ結ばれることを定義する。これで、関係を何回たどるかを先に固定せず、長さ1以上の有限経路による到達を表せる。親から祖先へ、引用元から間接の出所へ、といった構成で再利用できる。

この対応は小さなモデルだけに依存しない。有限の経路があれば、辺を含む推移的関係は全てその両端を結ぶ。逆に経路がなければ、有限経路による到達関係そのものが、辺を含み推移的でありながら両端を結ばない反例となる。関係型の量化をその型の全関係として解釈するという仕様の下で、再帰的な宣言を使わずにこの意味を定められる。零歩の自己到達は別途同一性を加えて表す。

無限に続く過程も、数から状態への関数と、全ての自然数nについてn番目とn+1番目が次段階の関係にあるという条件で記述できる。自然数の条件は「長さがnの有限列が存在する」で構成できる。Noemaの個体域が非空であるという前提の下で、列の長さに上限を置かなければ非負整数をちょうど表す。この構成の型と書出し・再読を検査し、有限の段数の試験を無限過程の証明と呼ぶことはしていない。

自己言及は、内容の節点と参照先を明示した制約として記述する。例えば節点Aが「Aは偽だ」と述べる場合、Aの真理値を反転したものがA自身の真理値に等しいという式を置く。これは一段上の記述として有限に書ける。実行中の引用へ無制限に戻る処理を設ける必要はない。

| 記述 | 二値の解についての判定 |
| --- | --- |
| AはAが真だと述べる | 真・偽の両方の解がある。どちらかに確定しない |
| AはAが偽だと述べる | 式を満たす二値の解がない。Aを単に偽とは判定しない |
| AとBが互いを偽だと述べる | 複数の解があり、追加条件なしに各値を確定しない |
| 固定された真理値と参照式が衝突する | 同じ制約全体に解がないことを保持する |

`truthgraph…` は同値・否定・固定値による簡単な参照形の共通構成である。複合した自己言及には、通常のNoema式で割当てへの制約を組み立て、`constraintsolvable`、`constrainttrue`、`constraintfalse` を使う。「Aは、AかつBが偽だと述べる」という例も確認した。解がない場合、空虚な全称から任意の真理を取り出さない。

これはNoemaの全構文について同じ階層で無制限に真理を返す評価器ではない。内容を表す式、対象の真理値、真理値への制約、その解の有無を区別する。既存の引用階層と実行上限を保持する。より多様な型の反復的条件も、型付き関数の値への条件として記述できるが、無限領域の解を有限実行器が必ず求められるとはしない。

## 確認した範囲と完成判断

[意味診断](../reports/semantic-boundaries-v3.json)には、個体・数・記述の候補状態、名前と指示先の区別、実在の有無、状況ごとに変わる対象と固定対象、型の異なる値の束縛、四つの支持状態、資料の値の衝突、読みの構成、経路、循環する真理参照、複合した自己言及を保存する。追加試験では、束縛の各欄、支持の出所・記述・状況、範囲外参照、矛盾した信念の報告、無限の数の量化を有限標本に置換しないことを確認した。

今回の不足探索では、新しい基礎構文を必要とする未解決の意味構造は残っていない。未登録の概念は、ここで定めた意味導入の手順で拡張できる。個別の経験的事実や文化規約の真理、任意の定理の証明、あらゆる内容の計算、人の受け取り方までを言語の完成条件にしない。既存二作品の判断と固定字体を保持したまま、成果物と証拠の最終確定へ進める。
