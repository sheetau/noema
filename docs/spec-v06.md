# 文語0.6：複数対象の結合と再参照

文語0.6では、複数の対象を一つの役割の参照先として保持できる。基本語91個と32文字は増やさず、既存の結合標識`w`を対象の位置でも使う。文書の先頭は`noema f f`、短縮記法では`f:`とする。0.5までの語形成、否定、時間、数量、発話、参照を継承する。

## 書き方と意味

対象を書く位置で`w [ 対象 ] [ 対象 ]`と書く。成員は2個以上で、3個以上なら角括弧を続ける。短縮記法は`w[対象][対象]`となる。

```noema
f:po w[mu][si].
```

これは犬と猫を結合した複数対象を主体にする、一つの睡眠の記述である。構文上の結合は、集合全体に適用するか各成員へ分配するかを追加指定しない。この版は「共同で」「それぞれ」「少なくとも一方」を明示する量化・分配演算子をまだ持たない。自然言語からその区別を抽出できた場合に、この結合だけへ置き換えてよいとはしない。

次は二つの命題の論理積であり、上の意味構造へ自動でまとめない。

```noema
f:w[po mu][po si].
```

`w`の文字は結合を示す。述語が期待される位置では命題の結合、役割の対象が期待される位置では複数対象の結合となる。固有文字の同じ単位を使い、英語や日本語の語を登録する翻訳規則にはしない。

## 集合と成員の参照

`o`を閉じ角括弧列の後に置くと、結合した対象全体へ参照名を付けられる。角括弧内の対象にも別の参照名を付けられる。

```noema
f:po w[mu o dog][si]o pets.
no p pets p dog.
```

二文目の主体は先に書いた複数対象全体、対象はその成員である犬を指す。二文目で新しく`mu`と書くと別の参照対象を導入する。同じ概念・名前を持つ対象を勝手に同一視しない。参照名は任意の代用文字列で、`dog`や`pets`を英単語として解釈しているわけではない。

集合を成員として含む入れ子も保存する。入れ子を平らにしたり、別の集合と同一だと推定したりしない。成員の列挙順は記録・正規化で保持するが、優先順位や出来事の順序を意味しない。成員順を入れ替えた表現の同義性まで正規化が保証するわけではない。

同じ参照IDを一つの集合に二度直接入れること、循環した成員関係、存在しない参照、0個・1個の成員は不正とする。2匹を表したいときは、同じ参照を二度書くのではなく、既存の数量指定を使う。

```noema
f:po w[mu m c][si].
```

上の犬には数量2があるが、猫の数量は未指定のままである。集合の成員欄が2個あることから、生き物の合計を2や3へ確定しない。集合自体に`m`や`n`を付ける構文はこの版では定義しない。数量・名前・性質は個々の対象に保持する。

## 型と作用範囲

役割の型制約は全成員へ適用する。場所役割には場所だけの集合を使える。対象型だけを許す主体役割に、場所を含む集合は置けない。入れ子の内部も検査する。未指定`?`や質問用の`c`は集合の成員にできず、役割全体への従来の使い方を保つ。

```noema
f:u[t 6-sam w[qo n"葵"][qo n"Jun"] w[maj-sai][maj-saj]].
```

この例は、主体と対象の両方を複数対象とした、明日の使役変化の否定を表す。各主体についての別々の否定や、各ドアの状態否定へ展開しない。集合の導入を否定・条件・質問の外へ独立した主張として出力する処理も行わない。

## 意味JSONと往復

文書の`schema_version`と`lexicon_version`は`0.6`。既存の対象ノードは0.5のままで、結合した対象にだけ次の形を使う。

```json
{"id": "na", "kind": "group", "members": ["nb", "nc"]}
```

この3フィールド以外は拒否する。`members`は対象・場所・別の集合への参照IDの配列である。集合に概念IDや既知の数量を補わない。最大の入れ子は64段で、循環を拒否する。共有された集合を何度も展開せずに型を検査する。

正規化は役割の順に参照を付け直し、集合の成員も同じ写像で変更する。集合全体への参照と個々の成員への参照は区別したまま保持する。保証する往復は従来どおり`parse(format_graph(document)) == normalize_document(document)`で、固有文字・短縮記法・SVGの元になる文も同じ意味構造を使う。

0.1〜0.5から0.6へは、旧版の意味を保って変換できる。集合のある文書を0.1〜0.5へ戻すとエラーになり、成員を一つだけ残したり複数の命題へ分割したりしない。集合を使わない文書は、変換先にない他の意味要素がなければ戻せる。

自然言語の自動解析器と逆変換は、この集合構文へまだ接続していない。人が直接書いたNoemaの解析・編集用API・CLI・固有文字表示が今回の対象である。自然文全般への対応という完成条件を、この直接記述機能の完成へ縮小しない。

## 検証

全358テストで、集合と成員の同一性、共有・入れ子、循環の拒否、数量・名前、否定・時間・派生述語、旧版との往復、意味を失う変換の拒否を確認した。資料中の実行例も解析と往復の対象にしている。CLIはモデル依存ライブラリなしで動作し、実HTTPの編集用API、既存英語解析器の回帰、実ブラウザーでの固有文字の再解析も検査した。

[記録した5例](../reports/written-v06.json)では、ヘッダー・空白を含む完全記法が合計212文字、同じ意味の短縮記法が118文字だった。これは二つのNoema記法の比較であり、日本語・英語より短いことや人にとっての読みやすさを示した結果ではない。
