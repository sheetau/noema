# 未知個体の導入と作用範囲を持つ参照

## 導入から後続の記述まで同じ個体を保つ

「ある来訪者が来た。その人は座った」を表すには、後半の「その人」が前半で導入した個体であることを保つ必要がある。前半と後半を別々の存在量化で書くと、来訪した人と座った人が異なっていても成立してしまう。名前を持つ既知個体の別名を定義するだけでも、この未知個体の導入にはならない。

今回の[共通19定義](../examples/v016/shared-discourse-v1.noema)は、既存の個体・有限列・型付き関数・存在量化から参照状態を構成する。新しい基本関係や文法演算子は加えない。個体を導入する時点では一意性を要求せず、その同じ個体を後続の記述へ渡す。二つの記述は `sequencediscourse` の前項・後項として本文に残る。

必要な関係を、個体の導入、同じ参照位置への述語適用、二位置の主体・対象、明示的な別個体、別名、作用範囲の閉鎖、候補の保持、同定、後続の質問に分けた。参照候補と一意性の区別は[指示と前提の共通規約](shared-reference-v1.md)を引き継ぎ、有限列の操作には0.14の構文を使う。[型・役割・意味規約](../data/shared-discourse-basis-v1.json)に各引数を公開する。

## 参照状態と更新

参照状態は、現在参照できる個体を並べたNoemaの有限列である。位置は0から数え、導入時には列の末尾へ個体を加える。位置の数字は局所的な束縛を指定する構文情報であり、語の意味を対応付ける辞書番号ではない。列そのものと位置の使用を本文へ記述し、復号器に見えない指示表を渡さない。

更新は「後続の検査・現在の参照状態・評価状況」を受け取り、その後続まで成立するかを返す型付き関数である。`introducereferent` は、指定性質を満たす個体を存在量化し、その個体を加えた状態で後続を検査する。`sequencediscourse` は、前の更新から渡された同じ状態で次の更新を評価する。中間状態の有限列全体を量化する必要はない。

たとえば空の参照状態から、`introducereferent(来訪した)` と `discoursetest(referenttest(0, 座った))` を順に適用する。成立条件は「来訪し、かつ座った同じ個体が存在する」となる。後続を一つの段落として結ぶ必要があり、独立した二つの `discourseholds` を論理積にしても参照の結合を代用できない。

| 定義 | 役割 |
| --- | --- |
| `referentat` / `referentavailable` | 指定位置の個体、または位置の存在を検査する |
| `referenttest` / `referentrelation` | 同じ参照位置の性質、または二位置の主体・対象関係を検査する |
| `discoursetest` | 参照状態を変更せず、条件と後続を検査する |
| `introducereferent` | 性質を満たす個体を存在量化して追加する |
| `distinctreferent` | 現在の列にある全個体と異なることも要求して追加する |
| `aliasreferent` | 既存位置の同じ個体を、新しい位置からも参照できるようにする |
| `sequencediscourse` | 前後の更新を同じ参照状態でつなぐ |
| `discourseholds` | 指定の初期状態と状況で、更新全体が成立するか検査する |

新しい言及が新しい個体を指すとは限らないため、普通の導入では既存個体との差異を加えない。「別の人」のように異なる個体が必要なら `distinctreferent` を使う。別名は `aliasreferent` で同じ個体を保持する。存在しない位置、負数、分数、範囲外の位置から参照先を補うことはない。

参照位置で述べる性質の否定は、同じ `referenttest` へ否定した性質を渡す。位置がなければ肯定もこの否定も成立しない。検査全体を外から否定すれば「参照位置がない」場合も含む別の条件になるので、両者を同じ読みとして使わない。必要なら `referentavailable` で参照の成立条件を別に明示する。

## 否定・選択肢・条件の作用範囲

`closeddiscourse` は内部の更新の成立を検査してから、元の参照状態で後続を評価する。内部で新しく導入した参照は外へ出さない。`negateddiscourse` は内部更新が成立しないことを要求する。`alternativediscourse` は左右の内部更新のどちらかが成立することを要求し、どちらの枝の新規参照も外へ出さない。これらの区間へ入る前からあった参照は保つ。

`conditionaldiscourse` では、前件が作るすべての成功状態について後件を検査する。前件で導入した個体は同じ条件の後件内で参照できるが、前件・後件での新規参照は条件全体の外へ出ない。来訪者を導入する前件と、その人が座る後件を組み合わせると、来訪者が二人いて一人だけが座るモデルでは不成立になる。来訪者がいない場合は条件が成立しても、外側で参照できる個体は増えない。

これは前件の全成功状態に関する条件の読みである。反事実には[比較候補の共通規約](shared-norms-v1.md)を使う。枝の内部で導入した個体を後に再導入する読みや、自然言語の代名詞のアクセス条件を自動選択する仕組みは、この構成に含めない。

## 候補の保持と同定、質問

`discoursecandidate` は、更新が成功する状態のいずれかで指定位置に現れる個体を調べる。`discourseunique` は候補が存在し、一つの個体に限られることを要求する。`discourseidentified` は、指定個体がその唯一の候補であることを検査する。存在の成功だけでは一意性を認定しない。

追加の観測や記述は、同じ位置への後続検査として候補を絞る。同定の根拠も保持する場合は `identifyreferent` を使う。同じ参照個体と提示対象の同一性に加え、出所・理由・両対象・評価状況に結び付いた根拠を要求する。別人を提示対象へ置き換えたり、他の同定の根拠を流用したりしない。根拠の十分性そのものは明示した入力規約であり、自動証明ではない。

`referentquestion` は、同じ更新と参照位置について、どの個体が候補なのかを尋ねる既存の型付き質問を作る。空・一候補・複数候補をそのまま扱い、質問することから答えの存在や一意性を導かない。更新は新しい無条件の個体定数を文書全体へ追加する処理ではなく、明示した範囲と履歴の下で参照を保つ構成である。

## 保存した例と検証範囲

[Native例文](../examples/v016/scoped-referents-v1.noema)は、来訪者と着席、荷物の到着と開封を扱う。どちらも最初は二候補があり、後続の記述によって一候補に絞られる。条件内の参照、別名、同定と、その参照に関する二つの質問も含む。検査用の個体ラベルはモデルの値であり、導入する個体を名指す新しい基本語を共通モジュールへ追加してはいない。

[検査報告](../reports/shared-discourse-v1.json)には、二題材の導入32モデル、主体・対象と差異の256モデル、作用範囲の16モデルを記録する。同定根拠の五項目は一項目ずつ変える6件の結合診断を行い、全組合せの証明とはしない。未知入力、参照位置の欠落、別々の存在証人、句の順序、初期状態、結合の括り方、評価状況、質問の空・一・複数回答もテストする。

```powershell
python -X utf8 -m noema.meaning_catalog explain --basis data/shared-discourse-basis-v1.json --symbol introducereferent
python -X utf8 -m scripts.project_work check --module scripts.check_shared_discourse --tests tests/test_shared_discourse.py --prepare --verify reports/shared-discourse-v1.json
```

更新を任意の高階関数として入力しただけでは、後続についての単調性や評価状況の保存は保証されない。ここでは、それらを保つ公開構成子から作った更新を扱う。有限モデルの検査を、全自然言語の指示や無限領域の証明とはしない。円文字への共有語彙登録、局所参照を含む学習用文書、第三者による読解は残る。二作品の本文・意味判断・固定字体は変更しない。
