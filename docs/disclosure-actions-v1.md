# 複数評価を提示する行為の記述と許可

[評価範囲を明示した公的提示](candid-assessments-v1.md)を、実行せずに許可対象として記述できるようにした。肯定・否定を含む複数の判断について、同じ本人・提示行為・話題・文脈への結び付きを保持する。既存26宣言を保持して8定義を加えた[定義文書](../examples/v016/disclosure-actions.noema)と、[許可と実行を別に尋ねる作例](../examples/v016/disclosure-actions-example.noema)を保存した。新しい文法演算子やライブラリの原始関係は追加していない。

従来の `rsf`・`rsg` は、渡された基準や肯否の記述を評価して提示の成立を検査する。これをそのまま引用すると評価を含む記述となり、既存の許可関係 `rdm` が受け取る行為記述の型に収まらない。今回は、閉じた記述の合成によって、各基準の関数・判断対象の記述・同じ肯否の発話を組み立てる。引用の評価制限を緩めず、許可を調べる際には基準や発話を実行しない構成にした。

## 同じ記録から行為全体を構成する

| 定義 | 働き |
| --- | --- |
| `rsh` | 一つの本人の評価と、その同じ内容の公的提示を、人・行為から状況ごとの内容を返す関数にする。 |
| `rsi` | 同じ基準と肯否の記述から、`rsh` の関数・判断対象・発話を構成する。 |
| `rsj`、`rsk` | 二つの行為条件を同じ人・行為・状況で結合し、その閉じた記述を作る。 |
| `rsl` | 記録の記述の列から、順序と重複を保った個体列の記述を作る。 |
| `rsm` | 記録列と明示範囲の一致を検査する。批判を指定した場合には否定評価の存在も要求する。 |
| `rsn` | 同じ記録列の肯否から、少なくとも一つが否定であるという条件の記述を作る。 |
| `rso` | 範囲条件と全項目の提示を一つの閉じた行為記述にまとめる。 |

範囲の検査に使う列と、各項目の提示に使う列を別に渡さない。同じ記録の記述から両方を構成するため、ある項目を範囲検査にだけ残して、その項目の提示を省くことはできない。空の列の記述自体は作れるが、実行条件は非空を要求するため成立しない。

記録列と各項目の基準・肯否は、構成時に選んだ閉じた記述に固定する。提示を評価する状況で選び直す関数との一般的な同値性は主張しない。今回の比較例では、各記録に同じ基準と肯否が選ばれる条件を置き、元の `rsf`・`rsg` と結果を照合した。範囲への所属、本人の判断、伝達の成立は、実際に行為を評価する状況で調べる。

構成時には記録の記述を選ぶ関数を呼ぶ。その選択関数が不明なら構成を拒否する。一方、選択した記述が指す個体、評価基準の真理、本人の判断候補、実際の提示が未解釈でも、行為記述の構成と許可の照合はできる。それらを実行評価する段階では未解釈のまま真偽を補わず拒否する。

## 許可と実行の検証

作例は69宣言・3質問である。質問は、複合した提示への許可、実際の提示、従来の `rsg` による提示の成立をそれぞれ尋ねる。許可は既存の `rdm` を使い、同じ出所・本人・役割・行為・記述・肯否・文脈への許可と、反対要求の不在を確認する。許可されていても提示していない場合と、提示していても許可されない場合をどちらも表せる。

102テストが通過した。本人の判断候補での評価、二項目の伝達、許可、反対要求の64組合せに加え、空の列、項目の欠落、範囲外の混入、順序、重複、肯否の組合せを検査した。別人・別の話題・別名の基準・異なる肯否・提示行為・帰属先の混同も、元の提示条件と同じ結果になることを確認した。実際の基準の真偽から、本人の評価や許可を推定しない。

構成された記述は、合成器を使わずに別途書いた閉じた式と一致した。提示の成立条件が同じでも、記録順序の異なる記述に与えられた許可を自動では流用しない。これは現在の許可関係が記述自体を識別するためであり、意味の同値性に沿った規範推論を完成させたことではない。

未知の基準・範囲・判断候補・提示・記録を実行しない検査、未知の選択関数の拒否、キャッシュあり・なしの結果一致を確認した。長形式・短縮形式・固有文字の往復、検査記録の再現、両文書のCLI解析と作例のSVGのXML検査も通過した。SVGの目視検査は行っていない。

```powershell
python -X utf8 -m scripts.compose_disclosure_actions
python -X utf8 -m pytest tests/test_disclosure_actions.py -q
python -X utf8 -m scripts.check_disclosure_actions --verify-only
python -X utf8 -m noema.constructed parse -i examples/v016/disclosure-actions-example.noema
```

## 本文へ接続する際の課題

これはカント本文の「批判を公に示してよい」へ接続するための行為記述であり、本文の方針にはまだ組み込んでいない。明示範囲から評価を省かないことだけで、率直さや誠実さの語義全体を定義したとはしない。批判対象が「すでに与えられた法」であること、本文の統治者と立法範囲への照応、強調と他の発言の許可との関係を保った統合が残る。新たな原文対応範囲や意味確認済み区間は加算していない。

[意味条件](../data/disclosure-actions-basis-v1.json)と[再現可能な検査記録](../reports/disclosure-actions-v1.json)に、構成時の選択と実行時の評価の区別、既存定義の保持、有限の検査範囲を記録した。
