# 同じ指揮者・集団・計画の要求を、共同保護へ結ぶ

前段の共同保護では、構成員の目標内容を引数として受け取っていた。今回は、指揮者に帰属する各構成員への要求、その記録、指定された行為記述の実際の履行から目標内容を構成した。共同体の活動可能性と保有を保つという前段の目的も、そのまま接続している。

## 要求を計画に結び付ける

`rvf` は、指揮者・集団・構成員・計画・基準文脈に対応する役割範囲と要求記録を、既存 `rty` へ渡す。要求関係には、集団と計画を追加で固定する。要求の出所、受け手、役割、行為、行為記述、肯否、基準文脈も同じ対象に照合する。

各記録が実際の要求に対応していることと、指定役割に属する要求が記録に全て含まれることを、両方検査する。一部の要求を一覧から落として適合したように見せることはできない。閉じた行為記述を評価し、肯定要求なら真、否定要求なら偽となることを履行条件にする。

要求の照合は基準文脈、履行の評価は各結果の状況に対して行う。将来になって別の要求が出された場合や、別人が同じ行為を実行した場合を、指定した要求の履行として流用しない。

## 人数・全計画の適合・保護計画の存在

`rvg` は `rvf` を各構成員の目標として、前段の記録整合性付き共同保護へ渡す。同じ要求への適合内容が、共同計画の評価結果と、保護機構で集団活動を切り替える比較で使われる。保護の目的は、同じ共同体の各人の活動可能性と保有の維持である。

`rvh` は三つの条件を組み合わせる。

- 指定範囲の構成員を過不足なく数え、その人数が指定した基準を満たす。
- 利用可能な計画が少なくとも一つあり、全計画で評価範囲が非空かつ整合し、その全結果で全構成員が同じ計画の要求に適合する。
- 共同体を保護し、評価結果の記録も機構と整合する計画が少なくとも一つある。

人数の基準は明示的な引数であり、「多数」の普遍的な閾値を二人などに固定しない。また、一計画の成功と全計画での適合は別条件のまま保持する。

作例には、第一計画では指定行為が履行されるが、第二計画では別の行為が要求され、その行為は履行されない場合を置いた。第一計画による保護が成立しても、全計画での適合を含む `rvh` は成立しない。

## 空の要求と、因果的な保護を区別する

既知の役割範囲と要求がともに空なら、要求への適合は空虚に成立する。この状態を、命令が出された事実や、命令を理由に行動したという意図へ読み替えない。

共同保護は、その適合内容と介入モデルの保護要因を照合する。常に真となる空の適合内容を、保護要因が偽となる比較状況へも対応させることはできない。そのため、作例では空の要求に対する適合が真でも、保護条件は不成立になる。

## 検査と限界

[定義文書](../examples/v016/commanded-protection.noema)は46宣言・本文0文で、新規定義は三つ。[作例](../examples/v016/commanded-protection-example.noema)は88宣言・13質問である。

28テストが通過した。要求の有無と二人の履行の8組合せ、要求の出所・集団・計画・受け手・文脈・記述・極性の取り違え、記録の欠落を検査した。共同体の保護まで接続した例では、人数基準の不足、空の要求、別計画での不履行も区別した。

有限診断は14個体・11状況を使う。単独の構成員の適合判定は、評価キャッシュの有無でも一致した。通常表記・短縮表記・固有文字の往復、保存文書と検査記録の再現、CLI解析、SVGのXML検査も通過した。SVGの目視検査は行っていない。

保存文書の要求網羅性は、全行為記述への量化として残す。有限診断では `rtx` の記述量化だけを、同じ意味を持つ二つの異なる記述へ限定したコピーで検査する。保存文書をその有限範囲へ書き換えず、全域の直接評価は拒否する。引用の構築は、要求や履行の未知の値を評価せずに行える。

```powershell
python -X utf8 -m scripts.compose_commanded_protection
python -X utf8 -m pytest tests/test_commanded_protection.py -q
python -X utf8 -m scripts.check_commanded_protection --verify-only
```

軍隊という名詞の完成定義ではない。軍事的な役割、身体的強制の能力、訓練、指揮系統と命令の伝達、指揮権の正当性は残る。全計画での適合という強い条件を、信頼性や規律の全語義とも同一視しない。公的平穏の全体と、カント本文の上位主張への接続は未完であり、原文対応範囲と意味確認済み区間数を据え置く。
