# 証拠受領と信念・情報の更新

証拠を受け取ったことから、その内容を信じたことや、正しい情報を得たことは導けない。この語彙群は、受領、採用、候補集合の変更、固定した評価状況での情報増加と誤り除去を別々に記述し、同じ項目・主体・前後段階で接続する。

[共通Native本文](../examples/v016/shared-revision-v1.noema)は27定義と1基本宣言を含む。[意味規約](../data/shared-revision-basis-v1.json)に各引数の役割を記した。既存の情報比較7定義を名前だけ変更して共有し、信念・証拠語彙の8定義を保持し、新12定義を加えた。共通定義の増分は19である。

## 同じ項目の内容と前後状態

`beliefcorpus`は項目の記述、主体、段階に同じ`beliefaccepted`を適用する。`claimcontents`は項目の閉じた記述から内容を取り出す。`evidencebasis`は、その主体がその段階で利用できる同じ記述の記録が、その段階の有限証拠列で認定されるかを調べる。受容・支持・真理を同じ関係にはしない。記録の所有者と利用者の同一性も要求しない。

これらの関数を旧定義に渡すことで、内容を受け入れている項目の集合、支持された真の情報、その前後の包含・真の増加、偽内容の種類の減少・除去を比較する。主体、項目範囲、項目の内容、評価状況、比較状況を前後で固定する。同義の偽内容を別名へ置き換えるだけでは、誤り除去にならない。比較状況が評価状況を含まない場合や前後段階が同じ場合は、旧来どおり情報保存・増加を認めない。

`informationlinked`は、前の更新記録の後状態と次の記録の前状態について、主体・境界段階・指定範囲の項目記述・受容・支持の一致を要求する。候補集合全体や証拠グラフ全体の一致まで主張する条件ではない。以前の状態を別の関数値として保ち、新しい状態で上書きしない。

## 受領・採用・変更

| 定義 | 成立する条件 |
| --- | --- |
| `evidencereceived` | 異なる前後段階の先行関係、同じ記録と記述、主体・出所・出来事・前後段階の受領関係、後の利用可能性 |
| `evidenceused` | 受領に加え、同じ記録・記述・理由の採用、後の証拠列の認定、後の信念受容 |
| `beliefupdated` | 採用に加え、候補集合または対象記述への認識状態が変化 |
| `beliefadopted` | 採用に加え、前には同じ記述を受容していなかった |
| `candidatefiltered` | 後候補が「前候補と、その内容が真の状況との交差」に一致 |
| `evidencefiltered` | 採用と交差による候補変更の双方が成立 |

`candidatesincluded`は後候補が前候補に含まれること、`candidatesame`は一致を表す。集合条件だけなら空の後候補も許すが、受容には非空候補が必要となる。交差による変更は一つの方式であり、前候補が新情報と両立しない場合の全面的な訂正まで禁止しない。先行関係の入力には厳密な時間順序を要求するが、この二点の呼出しだけで全履歴の順序を検査したことにはしない。

## 内容記述の選択

[`claimchoice`](../data/shared-claim-choice-basis-v1.json)は、既知の真偽値に応じて二つの閉じた段階0の内容記述の一方をそのまま返す基本関数である。項目ごとに異なる記述を選び、前後で同じ対応を保つために使う。既存の型付き演算に、任意の型の条件分岐があるとは仮定しない。

この選択は内容の実行、真理の判定、同義記述への置換を行わない。条件と両記述の構成には既知の値が必要だが、引用された内容の真偽が未知でも記述自体を保持できる。基本関数の解釈は明示的入力であり、型検査だけで任意の外部実装が選択規約を守ると保証するものではない。検査用の解釈では、既に構成された二つの記述の一方だけを返す。

## 接続した五つのNative例

各例は、受領・採用・候補・認識・利用可能性・証拠列・支持・内容比較をNativeで定義する。外部入力は対象・段階の識別値と上記の記述選択である。証拠の局所認定条件は例の明示的な設定であり、ここで観察の正しさを証明したとはしない。観察・伝聞・推論の依存列は[先行する証拠語彙](shared-evidence-v1.md)で別に接続している。

| 例 | 信念状態の変化 | 情報増加 | 誤り除去 |
| --- | --- | --- | --- |
| [候補を絞る](../examples/v016/revision-filter-v1.noema) | 両候補から真の候補へ | あり | なし |
| [誤信念を訂正する](../examples/v016/revision-reversal-v1.noema) | 偽の候補から真の候補へ。交差だけでは成立しない | あり | あり |
| [同じ根拠を再受領する](../examples/v016/revision-repeat-v1.noema) | なし | なし | なし |
| [既存の信念に根拠を得る](../examples/v016/revision-supportgain-v1.noema) | なし | あり | なし |
| [誤った内容を採用する](../examples/v016/revision-misleading-v1.noema) | 両候補から偽の候補へ | なし | なし |

各例には14判定があり、内容の現在の真理と、受容・支持・更新の成否を区別する。最後の例では証拠の認定と候補の絞込みが成立しても、内容が現実に真であるとは限らない。

## 検証範囲

[検査報告](../reports/shared-revision-v1.json)は、二状況の候補・内容真理・前後の認識の256モデル、二項目の受容・内容・支持変化の1,024モデル、段階ごとの利用可能性と証拠認定の256モデルを、別に書いた集合の比較と照合する。記述選択18例、固定した他の引数の下での21単枠診断、Native五例の70判定を含む。有限領域の網羅検査と引数の結合診断であり、任意の領域における一般定理の証明とは区別する。

旧情報比較と先行証拠の報告が固定した入力ハッシュを再確認する。円文字への接続、一般的な情報構造・同義／多義、第三者による読解は、この検証の達成範囲に含めない。
