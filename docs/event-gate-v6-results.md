# 文脈から出来事の候補を判定する

固定モデルの述語候補を、その文で出来事として扱うかを学習する共通判定器を追加した。新規12文では正しい16出来事をすべて残し、不要な21候補を除外した。余分な役割は51→0件になり、正しい37/38項を保持した。全項一致は11/12文であり、全文意味構造95%以上の達成とはしていない。

## 変更と選択

[事前に固定した手順](event-gate-v6-protocol.md)に従い、v5の範囲・役割モデルと学習80文・開発20文を維持した。今回学習したのは出来事／出来事ではない、の二値判定器だけである。候補主辞、基本句、主辞の前後の語の文脈ベクトルと積・差を入力する。語名や辞書項目による除外は行わない。

正例は正解の出来事と対応する候補である。負例は、文中の全出来事を注釈した資料で、正解に対応しない候補だけとした。一つの出来事しか注釈していない旧資料の未注釈候補には、負例の教師を与えていない。学習には正例96・負例10、開発には正例24・負例1があった。

線形・64次元tanhを比較し、開発平均交差エントロピーでMLP200エポックを選んだ。判定は二値のargmaxで、評価後の閾値調整はしていない。選択の保存後に、新しい6述語群を含む12文を解析した。

## 新規確認の結果

12文は主節だけの8文と、主節・修飾節を含む4文からなる。「料理人／料理した」「研究者／研究した」「運転手／運転した」「指導者／指導した」のように、同じ語を含む名詞と出来事を同じ文に入れた。

| 指標 | 判定器なし | 選択した判定器あり |
|---|---:|---:|
| 正解の出来事を保持 | 16/16 | 16/16 |
| 不要な述語候補を保持 | 21 | 0 |
| 正しい範囲と役割 | 37/38 | 37/38 |
| 出力した役割 | 88 | 37 |
| 余分な役割 | 51 | 0 |
| 文中の全項一致 | 1/12 | 11/12 |

役割の適合率は37/88＝42.0%から37/37＝100%へ上がり、再現率37/38＝97.4%は保たれた。正しい出来事を落としてこの値を得たわけではない。上流の述語候補の検出漏れも、この12文では0だった。

残った失敗は「料理人が料理した野菜を給仕が盛り付けた」の、盛り付ける主体「給仕」の範囲が出なかったことである。出来事の判定を加える前からの欠落で、今回固定した範囲モデルに残る。

線形判定器も、この確認資料の候補判定と役割集計はMLPと同じだった。小規模な同型の例文における結果であり、広い自然文のあらゆる名詞・機能表現・出来事の区別を実証したわけではない。開発の負例も1件しかなく、方式選択の根拠は限定的である。

## 既存資料への影響

前回の複数出来事の確認8文では、正しい16出来事と33/38項を保持し、余分な役割が25→5件、全項一致が3/8→4/8文になった。出来事の候補を正しても、正しい出来事に付いた別の主体・場所、受動態の誤分類、範囲欠落は残る。

一出来事の既知評価64文では、注釈した出来事を落とさず、役割一致156/170も維持した。ただし、これらの文の未注釈候補を除外したことが正しかったかは判定できない。未注釈候補の除外を、負例の正解として数えていない。

原文と元の解析はAPIの`analysis`に残し、候補ごとの採否を`event_decisions`に分離した。たとえば「によって」の一部を出来事として採用しなくても、その表現が示す原因や役割の関係まで不要としたことにはならない。その関係をNoemaの意味構造へ確定する処理は別に必要である。`event_score`も二値分類器の値であり、文全体の意味の正確さを表す値ではない。
