# 変化過程と、前後に成立する内容

前段ではカント冒頭の離脱を本人へ結んだが、その本人の別の性質が変わる過程でも、能力の前後状態がたまたまそろえば条件を満たせた。今回は、過程の構成内容を、同じ本人の「自己に原因が帰せられた未成熟」から「自立的使用の能力」への変化へ結んだ。

## 過程の内容を二つの記述で指定する

一般的な基本関係 `hzid` を一つ加えた。引数は対象・過程・前状態の性質記述・後状態の性質記述・先行状況・後行状況である。指定した前後内容への移行が、その過程の構成内容であることを表す。単に同じ時点で別の変化が起きたこと、二つの状態が前後に成立することだけでは、この関係は成立しない。

この関係は対象を人や啓蒙に限定しない。物の温度や組織の構成などについても、前後の性質をNoemaで定義した記述として渡せる。ただし、その性質を原語の名札だけで代用したり、構文の型が合うだけで特定の過程へ適用したりはしない。適用される関係は、意味規約に従って解釈モデルへ与える。

前後の内容をNoemaで記述することと、その内容が実際の両端で成立することを分けた。`hzid` だけでは両端の真理を代行しない。冒頭の `be` では、従来の実際の過程 `ag`、前状態 `bd`、後状態の能力 `xd`、本人への関与 `la` を保持し、同じ引数で `hzid` も要求する。

前状態の記述には既存の `bp`、後状態には既存の `up` を使う。`bp` は `bd` を状況ごとに評価する内容であり、`up` は人であることと同じ `xd` を結ぶ内容である。前状態の `bd` が既に人であることを要求するため、この接続で別の人物条件や、より強い能力条件は追加していない。

## 因果・真理・引用の区別

ある変化過程そのものと、その変化を引き起こした活動は異なる場合がある。そのため、既存の因果生成関係を自動的に転用せず、過程の構成内容を表す関係として規約を定めた。本人の意図的行為、本人だけで達成したこと、唯一の原因や恒久的な状態を条件にしない。

前後の記述は引用として保持する。同じ対象・状況で同じ真理値を持つ二つの記述でも、どちらの記述で過程を指定したかは区別する。別名であることから引用を自動的に置き換えず、別の記述もその過程へ適用されるなら、その関係を別途与える。これはどの記述を適用したかを保持する規約であり、同じ実在の過程に複数の記述を適用することを禁止しない。

表題の問いと冒頭の回答は、改訂した `be` から構成する同じ `bi` を参照する。著者がその内容を定義として提示する際には、変化過程の関係や内容の真理を評価しない。現実に啓蒙の事例が存在するという別の主張を追加しない。

## 成果物と検査

[本文](../examples/v016/kant-described-transition.noema)は259基本記号・1,116合成定義・16文となった。変更した既存定義の本体は `be` のみで、前後の記述 `bp` と `up` を参照箇所より前へ移動した。本文16文の構文は保持している。[独立文書](../examples/v016/described-transition.noema)は `bi` の依存先を抽出したもので、[完全な意味規約](../data/described-transition-basis-v1.json)と照合できる。旧版は変更せず、改訂元と未解決事項を記録した。

検査では五条件の32組合せ、両文書それぞれ11対照例、前段からの14対照例を確認する。同じ本人の別の性質、前後の逆転、より弱い前状態、別の対象・過程・両端、記録の不在など、旧版で成立していた十例が改訂版では成立しない。等しい値を持つ別名の記述については、その別名に対応する関係を与えたときだけ適用が成立する。

二例は短絡変換とキャッシュを無効にして照合する。内容との接続が未知なら評価を拒否し、提示の処理では未知の内容を実行しない。型、通常・短縮・固有文字の往復、専用CLI解析、原文範囲とハッシュも確認する。

```powershell
python -X utf8 -m pytest tests/test_described_transition.py -q
python -X utf8 -m scripts.check_described_transition --verify-only
python -X utf8 -m noema.meaning_catalog explain --basis data/described-transition-basis-v1.json --symbol bi --output artifacts/described-transition-explanation.json
```

[意味確認記録](../data/described-transition-review-v1.json)と[検査報告](../reports/described-transition-v1.json)を保存する。今回解消したのは、既に説明した前後内容と過程を結ぶ条件の欠落である。`hzid` が現実に成立するかの認識方法を自動化したわけではない。能力評価の結果範囲、原因説明と自己責任の関係、決意と勇気の不足の読み、過程全体と第一段落全体の意味確認は残る。原文の新しい範囲や意味確認済み区間は加算しない。
