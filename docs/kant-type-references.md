# 完結した引数型への参照

## 先行計画

宣言を直接書けるようになったが、同じ複合型を繰り返す型列が長い。保存定義 rqwd では、第1引数型 description(function(individual → content)) が第3引数の関数型の引数にも二度現れる。必要なのは新しい語義ではなく、既に読めた型を再利用する表記である。既存の bound0 / bound1 / bound_shift を、型を読む位置でも使う。

## 範囲と復元

型列では、完結した各要素を順番に参照環境へ加える。bound0 は直前の要素、bound1 はその一つ前を表す。それより外側は bound_shift で直前の要素を一つ除き、最後に bound1 で指定する。shift の後に bound0 を書く冗長形は採用しない。

関数・質問型の内側の引数型列は、外側で完結した要素を引き継ぐ。内側で新たに完結した要素は内側だけに加える。関数の結果型も、その関数の引数型を参照できる。関数・質問型を閉じると内側の環境は終わり、外側には完成した型全体だけが加わる。description と sequence は参照環境を変えない。未完成の現在要素や後続要素を参照できないため、参照の循環は作れない。

宣言の引数型列、lambda の引数型列、量化変数の型、列の要素型、原始語の結果型は、それぞれ独立した読取開始点である。前の宣言・本文・別の型ヘッダの環境を持ち越さない。変数の bound0 等とは読取位置が違い、型ヘッダの後に型参照が残ることもない。

生成では通常表記よりトークン数が厳密に少ない場合だけ参照形を使い、同じ型が複数あれば最も近い要素を参照する。基底型一つの表記を同じ長さの参照へ置換しない。完全に展開した旧表記も引き続き読める。旧型文法の実装を保存し、新しい型参照処理を別モジュールに置く。

復号時には参照先を展開して native の型へ戻す。各読取開始点の展開後の型ノード数を4096以下、型の深さを128以下に制限し、複製前に参照先の大きさと深さを確認する。これは処理資源の上限であり、語義の変更や有限試験による一般的意味同値証明ではない。

## 確認する差分

直前・一つ前・さらに外側への参照、内側から外側への参照、内側環境の終了、関数結果型、引用の階数、未束縛・前方参照、展開上限を小さい型と実図形で区別する。その後に保存宣言 rqwd を一度描画し、対象本体・型を読取側から外して元宣言と一致すること、円数・幅・反復の変化を確認する。保存図形は再描画せず読む。文書全体の外観は別途確認し、これだけで固定しない。
