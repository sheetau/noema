# 句全体を抽出する学習済みモデルの検証

**語別の追加学習や補正規則を使わず、述語に対する句の範囲を取得する処理を実装した。** 指定した役割と句の文字範囲が完全一致した数は、日本語24/36、英語35/36だった。英語の受動態や授与文では前回の前置詞だけの出力を改善できたが、日本語の受動態・従属節と、語単位のラベルの整合性には問題が残る。

これは解析部品の試験であり、Noemaの意味構造一致率95%以上を満たした結果ではない。主画面への接続は行っていない。

## 構成

原文をStanzaで分割し、前回の固定Unify-SRLのEN側で述語位置を予測する。その全位置について、固定した[LIAADのsrl-en_xlmr-base](https://huggingface.co/liaad/srl-en_xlmr-base)で各サブワードのBIOラベルを分類する。BIOは役割の開始・継続・範囲外を示すラベルである。モデルへは原文と位置情報だけを渡し、生成モデル・指示プロンプト・質問文は用いない。

[著者の公開実装](https://github.com/asofiaoliveira/srl_bert_pt)では、Hugging Faceのエンコーダーと別配布の線形分類層を組み合わせる。今回は両方の版を固定し、学習済みのまま使用した。Noemaの語彙で候補を制限せず、新しい日英文を対訳表に追加してもいない。日本語のSRLで学習済みとする資料はないため、日本語は転用試験である。

英語学習データにはポルトガル語の役割体系へ合わせる前処理がある。元の英語SRLとの違いもあり、今回の数字を既存の標準ベンチマーク成績と直接比較しない。

## 条件と結果

[条件](srl-span-protocol.md)と[句の注釈](../data/srl-span-v1.json)を `030b055` で予測前に保存した。原文は前回と同じ16組であり、新しい独立確認資料ではない。正解の述語位置は与えていない。前回の解析器が出した余分な述語も除外せず処理した。

句の注釈には、限定詞、修飾、数量、格を示す語を含めた。「犬が」「猫を」、`The dog`、`by the dog` などが対象である。元の注釈を結果に合わせて変更していない。

| 指定条件への一致 | 日本語 | 英語 |
| --- | ---: | ---: |
| 役割と句の文字範囲の完全一致 | 24/36 | 35/36 |
| 文内の指定条件がすべて完全一致 | 7/16 | 15/16 |
| 前回の内容語を正しい役割の範囲に含む | 28/34 | 33/34 |

前回は内容語そのものに役割が付いた数が日本語13/34、英語31/34だった。今回の最下段は予測した句の中に内容語を含むかという弱い条件なので、その差をそのまま精度向上の幅にはできない。主要な測定は上段の句の完全一致である。

全範囲が注釈されたコーパスではないため、この表は全文意味構造一致率でも、すべての余分な予測を罰する精度でもない。例えば条件文の条件、関係節の全関係などは上表の対象を網羅していない。各述語の語義が正しいことも保証しない。

## 改善できた点

英語の受動文では `by` だけだった主体側の出力を `by the dog` として取り出せた。授与文でも `to` だけでなく `to the student` という受け手の範囲になった。

日本語の授与文では「先生が」「生徒に」「本を」を別の役割として取得できた。数量・時間の例も「二匹の犬が」「三匹の猫を」「明日」を保存した。これは数量や時間を原文範囲に含められた結果であり、数値や基準日時を解釈してNoemaの意味構造へ変換できたという結果ではない。

## 残る問題

日本語の単純な追跡文では、対象の範囲が「猫を」ではなく「猫」となった。内容語は得られたが、指定した範囲とは一致しない。省略文も同様で、主体のA0は両言語で追加しなかった。

日本語の受動態では、主体と対象を正しく区別できず、「猫が」と「犬」の両方をA1にした。従属節でも、「辞任」を述語位置として渡した際に項の範囲が得られなかった。述語位置や語義を誤る前段の限界も引き継ぐ。

条件文の日本語では2つの述語位置で不正な語単位BIO列が生じた。サブワード列の制約は満たしていても、各語の先頭ラベルだけを選ぶ公開処理では、開始ラベルが脱落して `O, I-A1` のようになる場合がある。これらは不正と明示して範囲を返さず、先頭をBに変えるなどの補正はしていない。生のラベルは全予測に保存した。

次の改善対象は、サブワードと語の境界を一貫して扱う系列推定と、日本語の受動・従属関係である。語の前後を拾う規則では解決しない。句が取得できた例でも、その句内の事物の概念、否定の作用範囲、数量・時間の意味、文間参照が必要になる。

## 互換性と検証

公開ソースの前処理、述語の0/1位置情報、BIOの開始・遷移制約、推論関数と照合した。同じ固定モジュールを使う条件では、入力と制約が一致し、分類ロジットの差は0だった。旧AllenNLP環境全体を起動した検証ではない。[互換検査](../reports/srl-span-v1/compatibility.json)

Viterbi計算は公開コードに合わせて確率値の和を最大化する。対数確率への置換は行っていない。小さな系列について全候補を列挙するテストで最適解を確認した。原文の絶対位置、述語を構成する全サブワードの指定、512サブワードの上限を超えた入力の拒否、不正BIOの明示も検査した。

同じ述語検出結果に対する範囲抽出を全32入力で反復し、出力が一致した。述語検出の結果は前回の保存値とも一致する。評価用の文字列を推論へ渡していないことは、原文→述語予測→範囲分類の呼び出し経路でも確認した。

別プロセスで述語検出から再実行し、全予測・句の判定・内容語の判定・集計・互換検査・実行条件の6ファイルが一致した。全212テストも通過した。[再現性の記録](../reports/srl-span-v1/reproducibility.json)

## 再実行

前回の[意味役割モデルの準備](srl-transfer-results.md)に加え、分類層を含む公開ソースと固定エンコーダーを取得する。すべての重みはGit管理外である。

```powershell
git clone https://github.com/asofiaoliveira/srl_bert_pt.git artifacts/span-srl-source
git -C artifacts/span-srl-source checkout 634d145cdca1aa2dfb0cf66143e3a358ac6e56fd
python -c "from huggingface_hub import snapshot_download; snapshot_download('liaad/srl-en_xlmr-base', revision='55387c653aba11f0025a2f7089435c11c4c583f6', allow_patterns=['*.json','*.model','pytorch_model.bin'])"
python -m scripts.probe_srl_spans --output reports/srl-span-reproduction
```

推論時はローカルのキャッシュだけを読み、外部へ原文を送らない。チェックポイントは重みのみの読込みを使い、外部のモデルコードは実行しない。互換検査ではハッシュを確認した公開ソースの関数を取り出して実行する。既存の結果は上書きしない。
