# 順序付きの発言の実現と、発言できる条件

カント第17区間の引用を「言える」と評価するため、引用内容を真にすることと、引用した内容を発言することを分ける基盤を追加した。前段の実際の引用ひな形を作例に使い、その発話記述列を話者・聞き手・出来事・順序に結ぶ。新しい文法演算子やライブラリの原始関係は追加していない。

## 発言することと内容が成立すること

`rud` は、非空の発話記述列と同じ長さの出来事列を各位置で対応させる。各出来事が生起し、同じ話者によるもので、指定した非空の聞き手範囲全員へ提示され、その位置の内容記述を伝えることを要求する。引用内容の真偽や、引用された指令の達成は調べない。

列の出来事は相異なり、全ての先行出来事が後続出来事より前にある。自己順序と逆向きの順序は許さない。同じ内容を二度述べる場合は、同じ発話記述を二つの異なる出来事へ対応させればよい。実装は既存の有限列・順次集計・関数だけを用い、有理数の全域量化や新しい組の型を導入していない。

`rue` は、この提示を状況ごとに判定する内容である。作例では、許可を述べる発話と服従を求める発話を、前段の本文ひな形 `hzsquotation` から構成する。規範の内容を評価する入力を与えなくても、何が発言されたかを検査できる。

## 評価範囲に相対的な能力

`ruf` は既存の能力条件 `xd` を使う。利用できる方法があり、その非空の評価対象が想定結果に含まれ、全評価対象で同じ発話列を提示できることを要求する。現在既に発言していることは要求しない。

`rug` は既存 `xg` を使い、利用できる全方法の評価範囲が整合することを確認したうえで、評価範囲全体で提示を達成する方法がないことを述べる。方法の結果を評価していない場合を、発言が不可能な場合として扱わない。

これは明示した方法・想定結果・評価基準に相対的な記述である。政治的に支障なく発言できること、発言する正当な権限、全言語の「できる」の語義を同じ条件で説明したとは扱わない。

## 必要条件と十分条件を区別する

`ruh` は、指定範囲で `ruf` が成立する人が全員、指定条件を満たすことを述べる。条件を満たす人なら必ず発言できるという逆向きの含意や、発言できる人が存在することは補わない。

`rui` は、それより強い確認条件である。指定条件を満たさない全対象者について、`rug` による不可能が確認されることを要求する。評価対象が未指定で能力を確認できない人について、単に `ruf` が偽だから限定が検証できた、と扱うことを避ける。二つの条件を同義にはしていない。

| 評価状態 | `ruh` の必要条件 | `rui` の確認条件 |
| --- | --- | --- |
| 条件を満たさない人が発言できる | 不成立 | 不成立 |
| 条件を満たさない人について、発言できないと確認 | 成立 | 成立 |
| 条件を満たさない人の評価範囲が未指定で、達成方法も未確認 | 採用した `ruf` の含意として成立し得る | 不成立 |
| 条件を満たす人が発言できない | それだけでは不成立にしない | それだけでは不成立にしない |

## 検証と残る接続

[定義文書](../examples/v016/utterance-ability.noema)は10宣言・本文0文で、既存4定義と新規6定義からなる。[作例](../examples/v016/utterance-ability-example.noema)は97宣言・7質問である。

166テストが通過した。方法の利用可否、二つの想定結果、評価対象、各結果での発言の実現を変える128組合せを、独立に書いた真偽条件と照合した。話者・聞き手・発話記述・順序の取り違え、空列、長さの不一致、出来事の重複、双方向の順序も検査した。二種類の発話記述を使った長さ0〜3の全ての列と、4項目の作例で、同じ内容の反復を別々の出来事に結べることを確認した。

未知の出来事や方法を含む実現目標を、実行せずに引用できることを検査した。能力があっても現在の発言は成立しない例と、必要条件から能力を逆算できない例を含む。長形式・短縮形式・固有文字の往復、文書と検査記録の再現、CLI解析、SVGのXML検査も通過した。SVGの目視検査は行っていない。
