- Read PowerShell text explicitly as UTF-8. Preserve existing encoding/newlines; new text is UTF-8 without BOM. Prefer `apply_patch` for non-ASCII text; PowerShell-to-Python pipes also require UTF-8 output encoding.
- Start with `python -X utf8 -m scripts.project_notes brief`, then fetch only relevant note keys/files. `.noema-project/ledger.sqlite` is the authoritative handoff, not disposable cache; see [record commands](docs/project-records.md). [WORKFLOW](docs/WORKFLOW.md) gives commands; `data/work-state.json` selects the active manuscript/index explicitly. Never infer the active version from filenames or reread the complete history on every turn.
- The two source works are complete under explicit readings; preserve that baseline. Translation-engine work is deferred. Preserve [completion criteria](docs/language-completion.md) and [semantic review requirements](docs/semantic-review-v1.md). Test success, draft coverage and semantic equivalence are distinct. Never add a primitive per source sentence to evade composition.
- The circle writing style is frozen in `data/writing-freeze-v1.json`; follow `docs/writing-system.md` and `docs/language-readiness-handoff.md`. Do not confuse AST/legacy-font round trips with visible decoding. Keep runtime assets and historical validators; do not regenerate retired previews routinely.
- Plan one sentence or coherent semantic dependency group before coding: list missing relations, reuse existing definitions, then connect and check the whole selection. Keep only unresolved decisions in the current handoff.
- Use `project_work check` for local tests and report production in one process. Run `project_work audit` at sentence/paragraph integration, registration changes or handoff; avoid a full corpus audit after every helper edit. Use `--full` after validator/cache changes or to diagnose a mismatch, then compare with the cached result. Run proportionate regression tests; do not rerun passing checks without changed inputs or a concrete concern. For existential tuple-binding tests, use a small distinguishing domain (usually two values) and test every slot; check the native body separately instead of enumerating a large domain to the tuple's arity. For many witnesses, instantiate the others and vary one binder at a time; label this as binding diagnostics, not a proof over the full domain.
- Rebind unchanged judgments with `project_work register`. Preserve original judgments, evidence, source files and old validators. A changed statement, dependency meaning or relevant identifier needs review; never refresh hashes merely to hide stale evidence.
- SQLite under `.noema-cache/` is disposable acceleration, not authoritative evidence. Keep it separate from the authoritative `.noema-project/` ledger, archives and backups. Cache hits must hash content and track validator versions. Never trust only mtime/size, cache test outcomes as semantic judgments, or bypass unknown-input rejection.
- Update the same ledger note with its expected revision at meaningful boundaries; keep earlier revisions and take a ledger backup. Do not duplicate handoff prose into Markdown. Keep `data/work-state.json` for evidence selection and STATUS as a small curated checkpoint. Search retired documents with `project_notes search` / `document`; inspect `why` before removing retained files. Do not append another changelog paragraph to README or duplicate evidence into every inherited review.
- Inspect Git and active processes before resuming interrupted work. Preserve unrelated edits/processes. Commit coherent verified changes locally; push only on request. Do not resume a stopped goal unless asked.
